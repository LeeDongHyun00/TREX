# UI 복구와 폴더블 적용

2026-09-12. 배포 기반 `edf5641`에서 §50의 미커밋 UI 작업을 이어 수정했다. 별도 폴더블 브랜치 전체를 병합하지 않고 조사 자료와 배치 정책만 현재 세션 구조에 맞게 적용했다.

## 화면과 조작

- 홈: 날짜/실제 운동일 표시, 섭취 카드, 운동·끼니 기록 카드, 운동 소모 추정·연속 운동 카드를 복구했다. 탄단지의 값/목표·비율·서로 다른 진행 색과 작은 남은 kcal 문구를 제공한다. 인사 제목, 주간 목표, 명언은 추가하지 않는다. 기존 하단 내비게이션의 기능과 위치를 유지한다.
- 운동: 개별 카드를 짧게 탭하면 해당 운동 설정을 연다. 연필은 제거하고 자세 교정 스위치는 독립 조작으로 유지한다. 길게 누르기/드래그/왼쪽 스와이프 삭제/삭제 확인은 기존 ID와 입력 소비 정책을 사용한다.
- 기록: 날짜를 펼치면 운동 목록 위에 중심 운동과 요약을 표시한다. 저장 시점 카테고리와 실제 운동 시간 비중으로 분류한다. 구 기록은 정확히 일치하는 카탈로그 종목명으로 보완한다. 베타·유보·TRACK을 정상 판정으로 해석하지 않으며 자료가 없으면 평가 부족을 명시한다. 기존 주간 그래프를 유지한다.
- 식단: 끼니 카드 왼쪽에 네 종류의 장식 이미지를 넣었다. 탭하면 기존 수량 수정/추가/제거 시트로 이어진다. 진행 색은 탄수화물 초록, 단백질 연두, 지방 주황이다.
- 로그인: 720×1280 투명 원본 전체를 정사각형으로 크롭하던 문제였다. 애니메이션 16장에 동일한 `(180,180)–(540,540)` 원본 영역을 표시해 캐릭터가 중앙에 유지된다. 고불투명도 로고 범위는 전체 프레임에서 `(195,200)–(505,517)` 안이다. 원본 파일은 변경하지 않았다.
- 말투: `TrexText`와 TTS 출력 경계에서 설명 어미를 `~룡`으로 바꾼다. 버튼명·단위·종목명·저장된 관측 원문은 유지한다. 판정의 부정/유보/검증 중 표현은 없애지 않는다.

## 실제 데이터

새 사용자의 운동 기록과 식단은 빈 상태로 시작한다. `seedFoods`와 `seedWorkoutHistory`를 제거했다. `LegacyDemoData`에는 정리 대상으로만 쓰는 구버전 전체 지문을 고정했다. 날짜별 항목·시간·칼로리·가짜 평균까지 일치해야 제거한다. 사용자 추가 필드가 있거나 일부만 일치하면 보존한다.

정리는 원본 JSON을 `before_demo_cleanup_history/diet`에 백업하고, 제거할 날짜만 걸러 나머지 JSON 필드를 유지한다. 백업·결과·일회성 표식 `demo_cleanup_v2`는 같은 SharedPreferences 저장으로 반영한다. 수정된 샘플 식단과 사용자가 실제로 저장한 데이터는 임의로 구분해 지우지 않는다.

세트별 `workMillis`는 가동 중 경과 시간만 누적한다. 준비·휴식·일시정지는 제외하고 회전/배치 변경에도 상태를 유지한다. 기록에는 실제 초와 당시 카테고리를 저장한다. 소모 kcal는 기존 종목군별 분당 계수에 실제 초를 적용한 **추정값**이며 센서 측정값이 아니다. 구 기록에서 실제 시간을 복원할 근거가 없으면 새로 만들지 않는다. 가짜 평균 차이인 ‘평소보다 …’ 문구를 제거했다. 연속 운동 표시는 보존된 최근 7일 기록에서 계산한다.

사진 식단에도 고정 음식 3개·고정 정확도·가짜 분석 지연이 남아 있었다. 실제 분석기와 사진 입력이 연결되지 않은 코드여서 제거했다. 사진 기록 버튼은 미연결 상태를 알리고 직접 음식 선택으로 이어진다. 가이드북의 사진 분석 완료 약속도 함께 수정했다. 음식 검색용 영양 DB, 수정 가능한 영양 목표, 운동 카탈로그는 사용자 관측을 꾸미는 데이터가 아니므로 유지한다.

## 폴더블

[조사 자료](FOLDABLE_LAYOUT_RESEARCH.md)와 [Android 공식 접힘 가이드](https://developer.android.com/develop/adaptive-apps/guides/foldables/make-your-app-fold-aware)를 바탕으로 WindowManager 1.5.0의 실제 창/힌지 경계를 사용한다.

- 일반 화면 최대 폭 840dp, 로그인/입력 600dp. 실제로 분리하거나 가리는 힌지를 피해 한 영역에 배치한다.
- 자세 화면은 같은 두 자식(카메라·조작부)을 측정해 재배치한다. 펼친 넓은 창은 좌우, 가로 힌지는 위아래, 세로 힌지는 좌우로 분리한다. 힌지의 창 좌표를 컨테이너 좌표로 변환하므로 비대칭 힌지도 처리한다.
- 화면 크기 변화만으로 카메라/엔진을 새로 생성하지 않는다. 프리뷰는 FIT_CENTER, 분석 프레임 전체는 유지한다. DisplayListener로 180도 회전과 디스플레이 변경을 받고 Preview/ImageAnalysis 회전을 갱신한다.
- 시스템 안전 여백과 실제 측정된 하단 메뉴 높이를 콘텐츠 여백에 반영한다. 시트는 폭 제한/IME 여백을 적용하고 큰 글씨에서 버튼 높이가 늘어난다. 홈의 좁은 창은 카드와 영양 정보를 세로로 배치한다.
- 물리 폴더블 미연결: 실제 센서 이벤트, 접고 펼 때 CameraX 재연결 및 관절 좌표 정확도는 미검증이다. 합성 힌지 검사는 이를 대신한다고 주장하지 않는다.

## 이미지와 검증

끼니 이미지는 §52에서 시간대 상징으로 교체했다: 아침 해돋이·점심 해·간식 티타임·저녁 달을 앱의 벡터 아이콘으로 표시한다. 음식 예시 PNG는 배포하지 않는다. 여섯 운동 이미지는 유지한다.

JVM 260건 통과. Android 검사 10종이 통과했고, 마지막 수정 영향을 받는 6건도 모두 통과했다. 마감 조정은 탄단지 비율을 같은 줄에 놓고 소모 그래프를 저장된 칼로리 기준으로 맞춘 것이다. 일반 앱 설치 후 실행 화면을 확인했다. Android에서는 독립 `.replay` 앱으로 합성 창/힌지의 카메라 인스턴스 유지, 큰 글씨 가이드, 로그인 입력 유지, 데이터 정리/원본 백업, 홈·식단 카드, 운동 드래그·스와이프·수정, 기록 요약, 준비 건너뛰기·기록 모드를 확인한다. 검사 결과·화면·APK 해시는 `research/aihub_fitness/outputs/ui-restoration/`에 보관한다. 일반 앱과 테스트 앱의 DEX/이미지 자산 일치도 검사한다.

이 문서는 §51 검증 시점의 기록이다. 후속 §52 변경과 커밋·푸시·APK 배포는 [Android 체험판 배포 문서](ANDROID_PREVIEW_RELEASE.md)를 따른다.

최종 일반 앱 설치: Note10+ (`com.example.trex_kotlin`), APK SHA-256 `16965ddf9bb2754875c134a2da97f83a05d14e9cb30a10d7f91ca1f93f3c4d10`. 설치 전후 설정 파일 3개가 일치했다. 첫 실행의 샘플 정리 표식을 확인했고 기존 식단은 그대로 보존됐다. 기존 기기의 가짜 출석은 저장된 운동 기록이 아니라 초기 시드였으므로 빈 초기값 적용으로 사라졌다. 사용자가 수정한 계획·식단은 유지했다. `outputs/ui-restoration/verification.json`, `migration-on-device.json`, `device-install-verified.json`에 증빙을 둔다.
