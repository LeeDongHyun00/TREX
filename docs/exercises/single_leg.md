# 한 다리 계열 — 함정 (크로스 런지 · 사이드 런지 · 스탠딩 니업 · 스탠딩 사이드 크런치)

> 설계는 `docs/SINGLE_LEG_FAMILY_DESIGN.md`(v3), 구현은 spec §97(v2)·§98(v3). 이 종목을 만지기 전에 읽는다. 공통 원칙·함정은 `CLAUDE.md`.

- **네 종목은 엔진 하나다(`posture/LegCycle.kt`).** 횟수 = **다리 기하의 사이클** — 사이드 런지는 무릎각(굽힌 무릎 ≤ 95°·골반 높이 ≤ 0.82 다리·반대 무릎보다 30° 이상 굽음·골반이 그 발 쪽 ≥ 0.58·**무릎이 발 방향으로 0.6 정강이 넘게 나가면 안 됨**, §98b), 크로스 런지는 발목 교차 `leg_cross`(≤ −0.2 로 교차·더 굽은 무릎 ≤ 110°·골반 높이 ≤ 0.80), 니업은 허벅지각(≤ 110°·극점 무릎 ≤ 110°·발 들림 ≥ 0.6), 크런치는 허벅지각(≤ 115°) + 극점 무릎 ≤ 110° + 무릎이 옆으로(`knee_lat` ≥ 0.35) + **같은 쪽 팔꿈치–무릎 닿음 ≤ 0.30 몸통**(관절 중심끼리라 0 이 아니다). 측굴은 beta 참고. 네 종목 모두 **허리 숙임**(`torso_pitch` 기준 대비: 니업·크런치 10°, 런지는 출발 22·최대 32)은 세지 않는다.
  **발 위치의 앵커는 쓰지 않는다** — v1(§96)이 그걸로 사이드·크로스 런지를 0회로 셌다(사용자는 발을 옮기며 한다, 설계 §1). 쪽 = 움직인 다리(크로스는 뒷발 = 반대 발목보다 0.15 몸통 위).
- **얕은 회·다리만 올린 회·교차 없는 회·허리 숙인 회·편 다리·앞으로 올린 무릎은 세지 않는다(두 모드)** — 사용자 결정 2026-10-06 저녁·밤(설계 §1a). `reps.rejected[].feature` 에 사유(`shallow`·`torso_bent`·`knee_straight`·`no_abduct`·`no_crunch`·`no_cross`·`no_descent`·`squat_like`·`no_shift`·`foot_lifted`·`no_direction`·`no_lift`·`both_legs`·`no_elbow`·`timeout`),
  `LegCycleTracker.cueFor` 가 이유를 말한다(6 s 간격, `REJECT_CUE_GAP_MS`), HUD "세지 않은 동작 n". **사유는 첫 것만 말하므로 `identity` 의 순서가 우선순위다**(설계 §4): 니업·크런치는 편 다리를 높이보다 먼저(편 다리 킥은 허벅지도 얕게 읽힌다), 사이드 런지는 얕음을 비대칭보다 먼저(얕은 회는 비대칭도 작다).
- **v2 띠가 놓친 것(2차 세트, 설계 §1a)**: 사이드 런지 무릎 115 는 98~100° 회를 지나쳤고, 크런치 팔꿈치–무릎 1.0 은 다리를 높이 들면(앞으로·편 다리) 다 지나갔고, 허리는 beta 창 검사(B/D)뿐이라 정면에서 전부 유보였다. 띠를 늦추기 전에 §1a 표를 본다.
- **크런치의 닿음은 85 ms 프레임에서 읽는다 — 판정 격자 300 ms 의 유일한 예외(§98a, `posture/ContactMinimum.kt`).** `PostureLive` 가 추론 프레임마다 팔꿈치–무릎을 모아 판정 프레임의 `elbow_knee_min_L/R` 로 얹고(세트 로그에도 남는다), 추적기는 그 값이 있으면 `elbow_knee` 대신 쓴다. 연속 세 표본의 가운데가 국소 최소이면 대칭 V 로 표본 사이의 꼭짓점을 추정한다(순간 접촉이 표본 사이에 있을 때). 가려진 프레임은 닿음으로 읽지 않는다. 재생기 `.cap` 경로에는 이 값이 없어 300 ms 값으로 후퇴한다 — 오늘 2차 세트의 닿은 8회는 300 ms 값으로도 0.06~0.23 이라 같다.
- **크로스 런지의 오른발 뒤 회가 전부 얕게 읽혔다**(무릎 107~117·골반 높이 0.80~0.82 vs 왼발 뒤 89~100·0.72~0.77) → v3 로 오른쪽 0짝. 좌우 비대칭인지 가려진 뒷다리의 3D 편향인지 3차 세트(설계 §7)에서 가장 먼저 확인한다. 무릎 발끝 넘김(`knee_fwd_foot` > 0.6)은 사용자 결정(밤 3)으로 횟수 게이트 `knee_over_toe` 다 — 발끝 관절 z 편향 때문에 발끝 자체와 비교하지 않고 발 방향 진행 ÷ 정강이로 재며, 바닥 프레임(무릎 최소 + 15°)의 중앙값으로 잰다. 2차 세트 재생에서 세진 14회 중 10회(0.61~0.70)가 걸려 4회만 남는다 — 깊을수록 더 나간다. 3차 세트 라벨로 띠 확정.
- **네 종목 모두 왼 1 + 오른 1 = 1회**(`RepUnit.SIDE_EACH`, `ExerciseProfiles.SIDE_EACH_EXERCISES`, `SideStepCounter.strictUnknown`). §92 의 "니업·크런치는 한쪽 올림·복귀 = 1회" 는 뒤집혔다. 목표 10회 = 왼 10 + 오른 10. `WorkoutPacing` 도 두 배.
- **기준(서 있음)은 정지에서 잡고 복귀마다 재기준한다.** 준비 카운트다운(`prepare`, `RepCounter.standingSeedFrom`) 이 먼저고, 없으면 세트 중 0.4 s·3프레임·퍼짐 ≤ 12° 의 정지. 재생에는 준비 프레임이 없어 첫 회를 놓칠 수 있다(12° 로 넓힌 이유). 로그 `reps.config.standing`(v3 부터 `torso_pitch`·`lat_flex_L/R` 도 담는다 — 허리·측굴은 기준 대비), 재생기 `restoreStanding`. 몸통 기준이 없으면 허리는 묻지 않는다.
  관절 누락 프레임은 건너뛰고, 750 ms 공백은 진행 후보만 버린다. 두 다리가 함께 움직여도 각자 판별한다(스쿼트는 비대칭 조건이, 점프는 발 들림이 거른다).
- **자세 검사는 기존 `RepFormEvaluator` 그대로**(`RepFormSpecs.legCycle`, `{moving}`/`{support}` 치환). 전부 beta 라 '정확' 은 0, 로그 `form_state: UNJUDGED`. `hip_drop` 은 추적기 `annotate()` 가 기준 대비로 더한다(`rf.onFrame` 앞). 쪽 미확인 사이클은 전부 "좌우 미확인" 유보.
  사용자 교정 항목의 대리: 가슴 펴기(`torso_pitch` 시작 대비 ±15°), 골반 균형/고정(`hip_hike_{moving}`), 지지 무릎 잠김(> 176°)/굽힘(< 150°), 반동(올리는 동안 `torso_pitch` 상단 대비 −12°), 가슴 정면(`rel_yaw` ±20°), 머리 당김(`head_lean_{moving}` > 15°). 힘의 출처(아랫배·옆구리·반동)는 못 본다 — `legScopeRules`.
