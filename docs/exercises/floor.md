# 바닥 계열 — 함정 (플랭크 · 크런치 · 라잉 레그 레이즈)

> 설계는 `docs/FLOOR_FAMILY_DESIGN.md`(v1), 구현 기록·재생 수치는 spec §99. 이 종목을 만지기 전에 읽는다. 공통 원칙·함정은 `CLAUDE.md`. 앱 이름 '레그 레이즈' = AIHub·엔진 이름 '라잉 레그 레이즈'(규칙·카운터·세트 로그의 `exercise`).

- **엔진은 셋, 관측 층은 하나다.** `posture/FloorChain.kt`(관측 층 `fc_*`) → 크런치·레그 레이즈 `posture/FloorCycle.kt`(`FloorCycleTracker`, `floorcycle_v1_beta`, 사용자 결정 Q12) / 플랭크 `posture/PlankHold.kt`(`PlankHoldClock`, `plankhold_v1_beta`). 다섯 파일(`PlankGeometry.kt`·`PostureFloor.kt` 포함)은 재생기 `replay-jvm/build.gradle.kts` 의 `engineFiles` 에 있어 **안드로이드 없이 컴파일돼야 한다** — `PoseSample`·`PostureRule`·`org.json` 을 참조하면 재생기가 깨진다(`PlankAlignment.kt` 가 못 들어가는 이유). 앱 배선은 `posture/FloorLive.kt`(순수)·`PostureFloorLive.kt`(`FloorLiveState` = `refs.floorLive`). `PostureLiveSessionScreen` 에 상태를 더할 때는 `FloorLiveState` 에 둔다(지역 변수 → 기기 `VerifyError`, CLAUDE.md).
- **중점 피처로 세거나 재지 않는다.** 레거시 `FloorFeatureExtractor.compute` 의 중점 피처는 좌우 관절이 **모두** 가시성 ≥ 0.35 여야 계산돼, 측면 폰에서 먼 쪽이 가려지면 카운트 신호가 절반가량 빠진다(09-23 플랭크: 중점 `hip_ang` 69 %·`head_ground` 55 % vs 한쪽 `hip_ang_L` 100 %). 중점 피처는 로그·TRACK 비교 지표(`head_ground`·`hip_ang`, 단위 유지)·레거시 규칙 호환용으로만 남는다. 세 종목의 횟수·시간·판별은 `fc_*` 만 쓴다.
- **보이는 쪽 한 사슬.** 어깨·골반·무릎·발목을 그 쪽 하나로 본다(AIHub C 사슬 통과 99.9 %, 양 무릎을 요구하면 66~73 %). 쪽은 세트 첫 1.5 s 의 최소 가시성 중앙값으로 잠그고, 반대쪽이 0.2 넘게 큰 상태가 2 s 이어져야 바꾼다(`PlankAlignmentTracker` 가 쪽이 바뀌면 상태를 끊는다 — 깜빡임 금지, 교체 수는 로그 `floor_chain{switches}`). 먼 쪽 외삽 좌표는 평균하지 않고 `fc_yaw`(≥ 0.2)·두 다리 확인(≥ 0.35)에만 쓴다. `fc_*` 는 **보이는 쪽 몸통이 관측된 프레임에만** 붙는다 — 관절 11개짜리 프레임도 피처 맵이 비지 않아 '검출 = 측정 가능' 함정(§31a)으로 돌아갔었다.
- **위와 수평은 중력으로 정한다(롤 보정).** 폰을 가로로 눕히면(09-27 푸시업 롤 90.7°) 화면 '위 = +' 부호가 깨진다. 좌표는 돌리지 않고 중력 up 의 화면 성분(`LegGeometry.rollDeg` 와 같은 식)으로 부호·수평만 정한다. 앱 `checkUpSanity` 는 '골반이 발목 아래' 면 up 을 뒤집는데 **레그 레이즈 상단이 정확히 그 배치**라 누운 종목에서는 믿을 수 없다 — `FloorChain.gravityUp` 이 원래 중력으로 되돌리고, 세트 로그 프레임 `floor_up` 이 실제로 넘긴 값(재생기 U 줄의 정본)이다. up 을 믿을 수 없으면(중력 없음·화면 성분 < 0.3, `fc_up_ok` = 0) 절대 수평이 필요한 `fc_axis_h` 만 유보하고 부호 피처는 화면 위 기준(종전 규약)으로 낸다 — 사이클은 up 없이도 돌아야 한다. 수평 대비 각은 부호 없는 축각(0~90°)이라 180° 튐에 둔감하다.
- **접지선 자기참조.** 레거시는 골반(또는 손목)·발목 이력의 prefix 중앙값을 지면으로 썼다 — 레그 레이즈는 발목이 움직여 지면이 스윙 중간으로 끌려간다. `fc_*` 는 **프레임마다 몸 선분**(크런치 발목→골반, 레그 레이즈 어깨→골반 연장선, 플랭크 어깨→발목·팔꿈치→발목)을 기준으로 한다. "MP 는 어깨–지면을 못 잰다(ρ≈0)" 는 prefix 접지선에서 잰 옛 결론이다(설계 §1.3). 연구 `floor_2d_rules.head_ground` 는 뷰 C 에서 앱 정의와 부호가 반대다(Spearman −0.875) — 대조에는 `export_floor_rules.dev_up`.
- **AIHub 바닥 GT 2D 다리는 붕괴돼 있다.** 클립 안 허벅지·정강이 길이 CV 가 GT 0.2~0.5(MP 0.04~0.06), 레그 레이즈 GT 무릎 최솟값 중앙값 4~11°(물리적으로 불가능). GT 로 맞춘 바닥 임계(rules_floor v0.1~0.4, REP_VALIDITY 0.2953·119.5°)를 믿지 않는다 — 띠는 앱 모델 재추출(`data/floor_family/aihub_local_agent/mp_full`, C·E 33,248장)로 잰다. 바닥에서는 **C 가 진짜 측면**이다(서서 C 와 뜻이 다르다, §39).
- **AIHub '회 단위' 수치는 분할 의존이다.** 바닥 클립은 16프레임·시각 없음(600 ms 는 가정)·서 있는 높이 카메라·연기된 위반이라, 같은 크런치 θ=4° 가 분할에 따라 1.8 % 도 27.3 % 도 된다. 판별 띠는 실제 엔진으로 재생해 **엔진이 나눈 회**로 다시 잰다(`floor_replay_tables.py`) — 분모는 측면 판정 회(유보는 통과라 전체 회 분모는 측면 아닌 촬영을 좋아 보이게 한다), 수행자별 최댓값·95 % CI 를 함께. 레그 레이즈 C 는 416클립 중 198이 0회라 검출률은 하한이고 **연속 레그 레이즈 데이터는 어디에도 없다**(폰이 유일한 시험). MM-Fit 윗몸일으키기는 크런치의 대리이고 크런치 폭은 w20 한 명뿐이다.
- **플랭크 `hips_low` 문턱은 0.15 몸통, 재개는 0.20(이력), 확정은 최근 1 s 의 70 % 다수결(2026-10-08, spec §99 후속 2).** 0.10 은 폰에서 골반을 바닥에 댄 값(0.086~0.107) 한가운데였고, '1 s 연속' 확정은 한 프레임만 문턱 위로 튀어도 리셋돼 7.5 s 를 유지로 적립했다(`docs/PHONE_REPORT_2026-10-07_DESIGN.md` §3.5). 끊김 안의 정상 칸은 회복되면 적립하고 멈춤으로 끝나면 확정 사유의 멈춤 시간이다. AIHub 카메라는 서 있는 높이라 이 값의 절대 분포가 폰(바닥)과 다를 수 있다 — 확정은 폰 2명 이상의 골반 내림 블록.
- **무릎을 대면 골반 오프셋이 양쪽으로 오독된다.** AIHub 진입·이탈의 무릎 댄 프레임은 +0.18, 폰 09-23 은 −0.12~−0.18. 그래서 플랭크 멈춤 사유는 `knees_down`(무릎 < 145°)을 `hips_low`·`pike` 보다 먼저 묻고, 정렬(골반 띠 [−0.08, +0.16], beta)은 시계가 HOLD 인 칸만 본다. 무릎 플랭크는 멈춤, 팔 편 플랭크는 센다(Q3 기본 — `fc_elbow` 는 게이트가 아니라 로그).
- **레그 레이즈 머리 방향.** AIHub 위반 '고개 위로 젖히기' 는 데이터상 **머리를 바닥에서 든 쪽**이다(귀가 몸통선 위 52° vs 정상 23°). 할로우 코칭은 반대로 머리를 들라고 한다 — 지금은 '머리는 바닥에 둔다'(AIHub 따름, Q11 확인 대기). 옛 window 규칙(`head_trunk_ang__mean < 73.08`, MP 측면 정상 오탐 17.3 %)은 floor_v0.5 에서 exclude, 대체 검사 `fc_head_lift` 회 중앙값 > 40° 는 8단계(ship 1순위)라 **지금 레그 레이즈에는 '참고' 자세 항목이 0개**다. 플랭크 고개는 |값| > 90° 를 관측 실패(얼굴 방향 뒤집힘, 09-23 −154.88°)로 버린다 — worst 에도 남기지 않는다.
- **플랭크 시간 = 카메라가 확인한 시간(Q2)**, 벽시계가 아니다. HOLD 조건 1 s 연속이면 확정하고 그 1 s 를 소급 적립, 깨진 칸은 1 s 보류 뒤 멈춤 — **단조 증가**(`SessionProgress.tick` 이 음수 증분을 0으로 잘라 되돌림형 시계는 맞지 않는다). 남은 시간은 분석 스레드 → `HoldBridge`(WorkoutSession.kt) → TrexApp tick 루프 → `tick(heldDeltaMs)`. 사람이 없어도 판정 칸(300 ms)마다 `onFrame(t, null)` 을 불러야 한다(750 ms 넘는 공백 = `out_of_view`). 일시정지는 `pause/resume` 으로 시계 밖. 처음 버티기 전(WAIT) 시간은 멈춤이 아니라 `wait_ms`. 세트 가동 시간(기록의 플랭크 초·근육 부하)도 인정 시간이다. 경과는 HUD 에 작게.
- **폴백은 촬영 실패에만.** WORK 20 s 동안 한 번도 확인 못 했고 **그동안 대부분(대기 시간의 과반) 화면 밖**이고 HOLD 후보를 확인하는 중이 아닐 때만 시계로 넘긴다(한 번 말함, `hold.source = clock`, 리포트 '카메라 미확인 · 시계 기록'). 무릎·골반·솟음·서 있음으로 기다린 세트는 폴백하지 않고 사유를 5 s 뒤 한 번 말한다(HINT) — 무릎 플랭크를 시계로 플랭크 시간에 넣지 않는다(Q3·원칙 #1). 그래서 무릎 플랭크로 끝까지 하면 목표에 닿지 않는다(✓ 로 끝냄). 폴백 뒤에는 폴백 안내만 말한다(벽시계로 줄어드는데 '멈췄어요' 라고 하면 시간이 멈춘 줄 안다). 분석 소식이 20 s 끊겨도 다리가 벽시계로 넘어간다(`HoldBridge.clockFor`·`hudNow`).
- **판별 기각 음성은 `rf` 밖이다.** 바닥 세 종목은 `RepFormSpecs` 가 0개라 평가기 `rf` 가 늘 null — 옛 기각 블록(`if (rf != null && …)` 안의 `legTracker`)에 두면 판별을 만들어도 틱도 이유도 안 나간다. 경로는 `RejectionCues.handle`(평가기는 있을 때만 창 소비) + `IdentityCueSource`(`RepCounter.cueSource`), 바닥은 사유별 6 s(`RejectCueGate`), 검증 모드·일시정지·음소거는 침묵. `FloorWiringTest` 가 잠근다. `timeout`·`exit`(세트 끝 동작)은 기각이 아니라 `reps.discarded` — 틱도 없다.
- **바닥에는 beta 음성이 없다(Q1).** `FloorFeedback` 의 확인 필요·범위 복귀·플랭크 정렬·배치 음성은 null — 화면 '참고' 칩과 provisional(호박색) 강조뿐, 빨강은 ship 전용. 세트 시작에 범위 문장(`PostureScope.FLOOR_LINES`)으로 못 보는 것과 '참고로만 보이는 것' 을 30분에 한 번 말한다. 들리는 것은 숫자·시간·판별 사유·관측 안내(신호 결측은 빠진 관절로 — 크런치 현 들림은 발목, 레그 레이즈 허벅지는 무릎이 있어야 계산된다)뿐이다. 바닥 발화는 `speakLatest`, 숫자·시간 읽기는 `speak` 대기열.
- **사유 목록의 순서가 음성 우선순위다(첫 사유만 말한다).** 크런치 `sit_up`(> 80°, 켬) → `neck_only`(귀 탐침, 켬) → `shallow`(끔). 레그 레이즈 `trunk_up`(> 30°, 켬) → `knee_bent`(끔, Q10 대기) → `shallow`(< 30°, 켬) → `one_leg`(끔) → `feet_touch`(끔) — 무릎을 굽히면 허벅지가 오히려 더 높이 올라가므로 굽힘을 얕음보다 먼저. 플랭크 `out_of_view` → `not_prone`(틱 없음, 5 s 뒤 한 번) → `knees_down` → `hips_low` → `pike`. 판별은 정점 `fc_yaw` ≤ 0.15(측면)일 때만, 아니면 유보하고 센다(`identity_abstain`) — 시간·사이클은 측면을 요구하지 않는다. **뷰 E(머리·발 쪽)에서 측면 게이트가 샌다**: `fc_yaw` 가 몸통축 성분만 봐 게이트를 통과한 크런치 42회 중 7회가 투영 붕괴(현 들림 107~155°)로 `sit_up` 기각됐다 — 열린 문제.
- **`neck_only` 는 회를 지우지 않는다.** 주 신호(현 들림)가 출발하지 않은 동작에만 나서 켜든 끄든 그 동작은 세지 않는다 — 2 % 입장선(원칙 #7)은 회를 지우는 판별의 장치라 여기 쓰지 않는다. 엔진 재생 4.5 % 는 '세지 않은 동작에 이유를 말한' 비율이다. 끄면 그 동작이 틱도 이유도 없이 사라져 "카운터가 죽었나" 로 읽힌다. 쉬며 화면을 보려고 고개를 드는 동작이 오발화할 수 있다(폰 '쉬며화면보기' 블록).
- **누운 기준은 정지를 요구하지 않는다.** 최근 1.5 s 의 누운 영역(어깨→골반 축 ≤ 30°, 레그 레이즈는 허벅지 ≤ 25° 도) 프레임 **≥ 2** 의 중앙값 — 3 이면 쉬지 않는 MM-Fit w06·w14 6세트가 0회였다(§96 '움직임 전제' 와 같은 함정). 준비 카운트다운 마지막 1.6 s 가 누운 영역이면 `prepare()` 로 심고(앉아 있으면 심지 않음), 로그 `reps.config.lying` 의 `prep`·`min` 으로 재생기가 같은 상태를 만든다. 복귀는 진폭 60 % 되돌아옴 — 회 사이 바닥이 기준보다 3~4.5° 위인 사람(w20)도 닫힌다. 출구(크런치 현 > 50°·레그 레이즈 상체 > 45° 가 1.5 s)는 세트 끝 일어나기를 회로 세지 않으려는 것이고, 판별 사유가 있던 후보는 5 s 보류해 돌아오면 그 사유로 말한다.
- **첫 회 잠정은 세트에 한 번.** 확인 창 = max(8 s, 최대 사이클 + 2 s) — 크런치 8 s, 레그 레이즈 12 s. 기각·일시정지도 확정한다. 재무장하면 9 s 간격 레그 레이즈가 회마다 앞 회를 거뒀다. 거둔 회는 표시 원장에서도 뺀다(`RepUnitAccumulator.onCounterRetracted`).
- **판정 격자 300 ms 그대로**(§96). 바닥에는 85 ms 예외(§98a 접촉 최솟값)를 늘리지 않았다 — 300 ms 대 100 ms 정점 손실 p50 2.7 %.
- **띠는 전부 잠정**이다(AIHub 분할 의존 수치·MM-Fit 5명·레그 레이즈 연속 데이터 0). 폰 세션(설계 §7.2 CSV, 블록 이름 = 기각 사유)으로 확정한다. 로그 재생: `research/external_rep_replay/setlog_captures.py <로그> --out <캡처>` → `.cap`(U 줄 = `floor_up`) → 재생기 바닥 경로(메타 `floor=1`, `--floor-clips` 는 클립마다 새 엔진). 회별 극점·사유 표는 `floor_diag.py <로그> [종목]` 또는 `floor_diag.py --cap <캡처> [--reasons default|all|none|사유,…]`. 모집단 표는 `aihub_floor_captures.py` → `floor_replay_tables.py`(`data/floor_family/replay/`).
