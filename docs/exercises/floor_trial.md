# 크런치 · 레그 레이즈 · 플랭크 — 자세 교정 시험 단계

*사용자 결정 2026-10-08. 코드 정본은 `posture/PostureTrial.kt`(앱 이름·규칙 이름 두 집합과 문구), 표시는 운동 목록(`WorkoutListScreen` 스위치 아래 "시험 단계")·운동 편집(`WorkoutEditor` "자세 교정 시험 단계 · 촬영 방향")·세트 시작 안내와 소개 3줄(`PostureScope.startLine` 첫 문장)·운동 카드 부제(`PostureScope.cardLine`). 테스트 `PostureTrialTest`.*

## 왜 시험 단계인가

2026-10-07 폰 보고(`docs/PHONE_REPORT_2026-10-07_DESIGN.md`)에서 세 종목은 **틀린 동작을 세고 교정을 말하지 않았다.**

| 종목 | 보고된 것 | 로그로 확인한 원인 |
|---|---|---|
| 크런치 | 어깨만 들어도 횟수 인정 | 사이클 출발 문턱 4.5° 가 '움직임' 수준, 얕음 사유(`shallow`)는 꺼짐, 폰이 비스듬하면(`fc_yaw` > 0.15) 판별 전체가 조용히 유보 |
| 레그 레이즈 | 오른 다리만·무릎 접기·절반 높이가 횟수 인정 | `one_leg`·`knee_bent` 사유가 위반 표본이 없어 꺼짐, 얕음 문턱 30° 는 절반 높이를 통과, 먼 다리만 든 동작은 무음 |
| 플랭크 | 골반을 바닥에 붙여도 시간 인정, 교정 없음 | 멈춤 문턱 0.10 이 골반 내림 값(0.086~0.107) 한가운데라 7.5 s 를 유지로 적립, 정렬 검사는 beta 라 무음 |

이 바닥 엔진(`floorcycle_v1_beta`·`plankhold_v1_beta`)은 작업 폴더 `exercise-form-correction-5fe80e` 에서 왔고 2026-10-08 에 이 브랜치로 합쳤다. 설계 중 **플랭크 멈춤 문턱(0.15 · 재개 0.20 · 1 s 70 % 다수결)은 구현했다**(spec §99 후속 2) — 10-07 세트 재생에서 버틴 시간 15.0 → 5.5 s. **크런치·레그 레이즈도 구현했다**(spec §99 후속 3, 2026-10-08 2차 보고 뒤): 더 올라간 허벅지 신호(좌우 이름 뒤바뀜의 유령 회 제거), `one_leg`·`knee_bent`·`shallow` 켬, 출발 프레임 측면 판정, 튐 버림 — 폰 세트 재생 10-07 레그 레이즈 12 → 2(양다리 회만), 10-08 레그 레이즈 12 → 0, 크런치 15 → 7·15 → 6. 발화 로그와 폰 블록 검증은 아직이다 — 시험 단계 유지. 그동안 사용자가 횟수·시간·교정을 믿지 않도록 앱이 먼저 밝힌다(원칙 #2).

## 시험 단계에서 앱이 하는 것

- 카메라와 횟수·시간 세기는 **켤 수 있다.** 꺼 두면 세트 로그가 안 쌓이고, 승격 조건이 폰 블록 세트다.
- 운동 목록 스위치 아래 "시험 단계", 편집 화면 "자세 교정 시험 단계 · 몸 옆 · 낮게", 세트 시작 안내 첫 문장 "이 종목의 자세 교정은 시험 단계예요. 틀린 동작이 세지거나 교정이 빠질 수 있어요."
- 그 외 동작은 종전과 같다 — beta 는 무음, 화면 '참고', 세트 끝 리포트는 "검증 중 기준".

## 해제 조건

설계 문서 §5 의 폰 블록 세트(두 세트씩, 가능하면 다른 날 한 번 더)에서 **오류 블록 검출 ≥ 80 %, 정상 블록 오탐 없음**, 횟수·시간 ±1 안.

```
크런치,1,정상:5 어깨만:3 정상:2
라잉 레그 레이즈,1,정상:4 한다리:3 무릎접기:3 절반:2 정상:2
플랭크,1,버팀:10s 골반내림:5s 버팀:5s
```

통과한 종목만 `PostureTrial.appNames`·`ruleNames` 에서 뺀다(두 집합을 함께). 세트 로그 회수는 `research/aihub_fitness/pull_logs.py`.
