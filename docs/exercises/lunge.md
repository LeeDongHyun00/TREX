# 런지류 — 함정

> `CLAUDE.md` 에서 옮긴 종목별 함정(2026-09-27, 글자 그대로). 이 종목을 만지기 전에 읽는다. 공통 원칙·함정은 `CLAUDE.md` 에 있다.

- **런지(앱 "런지")는 쪽별로 따로 센다(§63 후속 1, 사용자 결정 2026-09-26).** `RepUnit.SIDE_EACH` + `SideStepCounter`(`LungeSides.kt`) — 걸음마다 앞다리 쪽(`Lunge2d.stepSide`: 3D 발목 전후, 무릎 신호로는 못 가른다 — 두 무릎이 다 굽는다)으로 쪽마다 목표까지 세고, 화면은 쪽마다 남은 수, 한쪽을 다 채우면 반대쪽 안내, 진행 = min(왼, 오른). **차감(쌍 − 사이클)은 쓰지 않는다** — 두 풀(TRACK·COACH)에서 다시 센다. 반복 뷰·방향 안내는 어깨선만의 요(`view_cos_sh`), 걸음 검사 4개(깊이 차단 90° — 사용자 결정 예외, 숙임 2단, 무릎 쏠림 코칭 전용 `gates = false`, 어깨 기울기 beta — 폰 검출률 없음), 놓친 얕은 걸음(`missedDipEvent` — 자기 구간 뷰로, 스플릿 자세 복귀도 인정), 걸음 아닌 사이클(`notStep`). **런지 걸음 검사는 옆(SIDE_B/SIDE_D)·A 에서도 ship 이다** — 뷰별 MM-Fit 정상 걸음과 폰 SIDE_B 세트 검출로 올렸다(§63 후속 2, 원칙 #2). '옆은 어떤 규칙도 허용하지 않는다' 의 두 번째 예외다. 쌍은 절대값으로 진행에 보낸다(쪽마다 목표에서 멈춰 증가분을 잃으면 되찾지 못한다). 쪽을 모르는 걸음은 걸음 흐름(몰아서/번갈아)에 채운다. 한 걸음의 말은 한 문장으로 이어 한 번에 보낸다. 새 엔진 파일(`Lunge2d.kt`·`LungeSides.kt`)은 replay-jvm `engineFiles` 에 있다.
- **런지류는 카운터 사이클과 화면 횟수의 단위가 다르다(§59).** 런지·바벨 런지·사이드 런지·크로스 런지는 카운터가 **걸음마다** 한 사이클을 세지만 앱은 **왼 + 오른 한 쌍 = 1회**로 보이고·말하고·진행한다(사용자 결정, 목표 10회 = 20걸음, `RepUnit.SIDE_PAIR`). 세트 로그 `reps.count`·렙별 배열과 재생·채점 도구(`research/external_rep_replay`)는 **사이클**을 세고, `reps.completed`·완료 화면 자가 라벨(`rep_truth.csv`)은 **쌍**이다 — 견줄 때 `reps.cycles_per_rep` 로 바꾼다(키가 없으면 이전 로그 = 표시도 사이클). 쌍은 교대를 가정한 floor(걸음/2)라 '반대쪽 차례' 는 화면 전용이다(쪽을 모른다 — 설계 §18). 컬·니업은 평균 신호라 사이클 = 1회.

- **바벨 런지도 쪽별 카운트·걸음 검사를 그대로 쓴다(§66 계열 파일럿).** `RepFormSpecs.STEP_LUNGES`·앱 `SIDE_EACH_LUNGES` — 카운트 신호는 `knee_minside`(런지는 `knee_mean`). 사이드·크로스 런지는 딛는 방향이 달라 쪽 기하가 없어 아직 두 걸음 = 1회다.
