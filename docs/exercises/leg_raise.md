# 라잉 레그 레이즈 — 함정

> 구현은 spec §99. 근거 자료는 `research/external_rep_replay/results/legraise_datasets_survey.md`(데이터 조사)와 `results/fms_aslr/README.md`(FMS 재생)다. 이 종목을 만지기 전에 읽는다. 공통 원칙·함정은 `CLAUDE.md`.

## 등급과 경로

- **C 등급이다**(`docs/EXERCISE_TIERS.md`). 사용자에게 주는 것은 횟수와 못 보는 것 문장이다. 반복 검사는 없고(`RepFormSpecs` 에 이 종목 항목이 없다), 바닥 규칙은 beta '고개 숙임 여부' 하나다.
- **바닥 경로다.** 3D·중력 피처가 아니라 2D 이미지 기하(`PostureFloor.kt`)를 쓴다. 뷰 게이팅이 없다(`CLAUDE.md` 의 뷰 함정 — 방향 피처가 없으면 게이팅하지 않는다).

## 카운터

카운트 신호는 `hip_ang`(어깨 중점–골반 중점–무릎 중점의 2D 각), 최소 스윙 25°, ROM 은 없다. 복귀형(`ReturnRepTracker` v1)이다 — 기준 ±5.5°(0.22 × 25°) 안으로 돌아와야 복귀라, 내린 다리가 시작보다 6° 넘게 더 펴지면(FMS s03: 시작 171°, 내린 다리 177°) 세트 끝까지 0회다. 깊이의 2/3 복귀(v2)로 고쳤다가 사용자 결정(2026-10-07)으로 되돌렸다 — spec §99 ①, 패치 `research/external_rep_replay/results/return_v2.patch`.

> **주의(2026-10-07).** 그날 폰에 설치돼 있던 빌드는 이 문서의 경로가 아니라 다른 작업 폴더(`.claude/worktrees/exercise-form-correction-5fe80e`)의 바닥 엔진 `floorcycle_v1_beta`(`posture/FloorCycle.kt`, 신호 `fc_thigh`)였다. 그 빌드에서 본 문제(한 다리 회·무릎 접은 회·절반 높이 회가 세짐)의 원인과 설계는 `docs/PHONE_REPORT_2026-10-07_DESIGN.md` §3. 두 경로를 합칠 때 이 문서의 양다리 판별(`hip_ang_maxside` 20°)과 그 엔진의 `one_leg`(`fc_knee_gap` 0.45, 기본 꺼짐)은 같은 질문이다.

## 양다리 판별 (§99a → 합친 뒤에는 §99 엔진의 `one_leg`)

- **한 다리만 든 회는 세지 않는다(두 모드)** — 양측 중점은 한 다리만 들어도 25° 넘게 움직인다(FMS 66 %).
- 2026-10-08 합치기 전 이 폴더의 판별은 `hip_ang_maxside`(더 편 쪽 고관절각, 20°)였다 — 근거: 양다리 기각 AIHub 416클립 측면·사선 뷰 0~0.2 %(95 % 상한 ≤ 1.1 %), 한 다리 기각 FMS 90회 중 96 %. 합치면서 **카운터 등록은 뺐다**(크런치·레그 레이즈는 `FloorCycleTracker` 의 `fc_thigh` 사이클). 피처 `hip_ang_maxside` 는 `PostureFloor.compute` 에 남아 로그·대조에 쓴다.
- 지금 앱의 판별은 `FloorCycleTracker` 의 `one_leg` — **2026-10-08 부터 켬**(spec §99 후속 3): 정점 두 허벅지 차 > 35°, 먼 허벅지가 안 보이면 두 무릎 간격 > 0.45, 둘 다 없으면 판정하지 않는다. 사이클 신호가 더 올라간 허벅지라 먼 다리만 든 동작도 같은 사유로 말한다. AIHub 양다리 정점 차 > 35° C 1.9 %, FMS 한 다리 90/90. 10-07 폰 세트 재생 12 → 2.
- 먼 무릎이 안 보이면 판정하지 않고 센다(원칙 #1) — 옆모습에서 다리가 겹쳐 먼 무릎이 사라지는 사람은 못 보는 범위다.

## 준비 기준 (§99)

준비 카운트다운의 누운 자세로 카운터 기준을 심는다(§89 후속 2 를 바닥에도). 그래서 카운트다운 직후 바로 다리를 들어도 첫 회를 센다. FMS 흉내에서 첫 회를 센 열은 드는 쪽 신호 기준 0/30 → 20/30 이다.

- 준비 프레임은 준비 전용 추출기(`LiveSessionRefs.prepFloorRef`)로 만든다.
- 준비 1.5 s 동안 신호가 5.5° 넘게 흔들리면 심지 않는다(종전처럼 스스로 잡는다).

## 촬영

- **몸 옆에서, 몸 전체가 가로로 보이게 찍는다.** FMS 의 측면 낮은 카메라는 ASLR 에서 몸을 발·머리 쪽 끝에서 봤다. 이 구도에서는 다리를 드는 동안 무릎이 가려져 신호가 수 초씩 비고, 60회 중 몇 회만 센다. 표의 큰 스윙은 동작이 아니라 좌표 튐이었다.
- AIHub 정면 뷰 C 는 양다리 판별의 기각이 4.1 % 다. 같은 이유(몸의 길이 방향 시점)라 안내 밖으로 둔다.
- 96 cm 높이에서 내려다본 옆모습(FMS 후면)에서 검출은 100 % 였다. 바닥에 둔 폰의 낮은 옆모습은 아직 안 쟀다.

## 못 보는 것

- **허리 뜸(골반 말림)** — 레그 레이즈의 핵심 오류다. 2D 옆모습의 골반점으로는 요추 곡률을 못 잰다. AIHub '허리 지면 고정' 조건은 규칙이 없다(요추 아치는 몇 픽셀, AUC 0.57 — `FLOOR_POSTURE_DEFINITION.md` '규정만').
- 무릎 굽힘 — '허벅지와 종아리 각도 고정' 은 측면 투영에서 붕괴했다(`FLOOR_RULES_V03.md` 미채택).
- 얼마나 높이 들었는지 — ROM 문턱이 없다. FMS 전문가 점수(0~3)가 들어 올린 높이 등급이라 나중에 '덜 올림' 을 만들 때 근거가 된다.

## 남은 것

- **폰 세트가 없다.** C 등급 완료 기준(폰 한 세트로 횟수 확인)이 남았다. 양다리·바닥 높이 폰·실사용 템포에서 판별(20°)과 복귀 띠를 확인한다.
- 판별 문턱은 AIHub 연기자(키프레임)와 FMS 한 다리(96 cm 카메라)에서 정했다. 폰 세트에 일부러 한 다리만 드는 블록을 넣어 검출률을 다시 잰다.
