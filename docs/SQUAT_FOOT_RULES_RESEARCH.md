## 2. 발끝 방향

### 2.1 판독은 무엇을 따라가나 (A7a, AIHub 정면 서 있음 n 1341)
- 2D 발목→발끝 각은 실제 발 방향을 기울기 0.93 으로 따라가고, 정강이 기울기·발 너비 의존이 0 이다(사람 주석과 같다). 실제 15° 변화의 판별력 d′ 1.53.
- **앱이 쓰는 월드 3D 각은 기울기 0.57, d′ 0.93** — 2D 의 6할. z 가 관측이 아니라 GHUM 추정치이기 때문이다(A7c).
- **바닥 프레임에서는 발끝을 읽지 말 것**: MediaPipe 가 발끝을 무릎의 가로 위치 쪽으로 끌어 놓는다(무릎÷발목 1.0 당 +27°, 사람 주석엔 없음). 사선 뷰(B/D)는 기울기 0.26~0.75 로 읽지 말 것.

### 2.4 사용자 규칙 ① 판정
- **60° 절대 임계 — 반박.** 이 사용자의 판독은 정상 18~34°, 실제로 벌림 42~55°, 넓게만 서기 41~54°, 모음 −15°/+7°. 60° 는 벌림을 전부 놓치고, −60° 는 모음을 전부 놓친다. 정상 범위 자체가 바깥쪽으로 치우쳐 있어(모집단 서 있음 13~46°) 대칭 임계는 맞지 않는다.
- **'현재 몸 방향' 기준 — 조건부.** 옳은 발상이지만 3D 로 잡으면 중력 센서에 기댄다(16:13 세트는 up 이 틀려 발끝이 162° 로 읽혔다). 2D 로 시작 자세와 비교하면 몸 방향 추정이 필요 없다.
- **횟수에서 뺌 — 지지(COACH 한정).** 단 위의 2D 판독으로, 발 너비 변화 시 유보, 모집단 오탐률로 입장 조건을 통과한 뒤.

## 3. 발 너비

### 3.1 현재 방식의 결함 (오늘 오탐 2건)
- 분모 = 그 프레임의 2D 어깨 간격. 어깨는 서 있는 동안에도 변동계수 0.17, 한 프레임 26 px(정상 90) → 3세트 2회 ×3.21.
- 반복 앞뒤 서 있는 프레임의 극값 + 직전 창 이월 → 5회(넓게) 뒤 발을 모으던 프레임이 6회에 들어가 ×1.90. 이 오탐이 6회 발끝 판정까지 유보시켰다.
- 시작 기준 = 첫 상단 창 5프레임. 16:13 처럼 발을 모은 채 섰다가 넓히고 바로 앉으면 기준이 60 px 로 잡혀 21회 전부 '넓음'.

- 16:13 세트는 (b) 로도 18/21 이 ×1.4 를 넘는다(시작 기준이 발 모은 자세). 시작 기준 정의를 바꿔야 한다(§3.4).

### 3.3 사용자 규칙 ② 판정
- **어깨 너비 기준 — 지지, 단 척도로만.** 어깨 간격은 세트 시작 1 s 중앙값으로 고정해 절대 비율의 분모로 쓴다. 프레임마다 다시 재면(안 (d)) 오탐 16~45 %.
- **계속 비교 — 지지.** 매 반복 바닥 구간에서 잰다(서 있는 프레임 기반은 빠른 템포에서 22~28 % 유보, 바닥 기반은 0~2 %).
- **절대 비율 단독 판정 — 반박.** 카메라 높이에 따라 영점이 움직여(A1: 바닥 폰 +0.12~0.14) 오탐 6~16 %. IMU 피치 회전 보정으로 줄일 수 있지만 폰에서 미측정.

### 3.4 대안 규칙 (beta 로 시작)
```
시작 기준  : 첫 하강 직전의 마지막 안정 구간(≥1 s, 발목 간격 변동 ≤ 8 px) 중앙값 — 발목 간격 A0, 어깨 간격 S0(IMU 피치 회전 보정 후)
            안정 구간이 없으면(발을 옮기고 바로 앉음) 첫 반복의 바닥 발목 간격을 A0 로 쓰고 "첫 반복을 기준으로 잡았어요" 라고 밝힌다
발 너비(반복): 바닥 구간(무릎각 ≤ 최소 + 진폭/3) 2D 발목 간격 중앙값 A
            위반 = A/A0 ≥ 1.4  그리고  A/S0 ≥ 1.5   (둘 다 — 상대는 '바뀌었다', 절대는 '어깨 너비를 넘었다')
            좁아짐 = A/A0 ≤ 0.7 (참고, 게이트 아님 — 스타일일 수 있음)
            유보 = 정면(C) 아님 · 발목 vis < 0.5 · 바닥 프레임 0개
발 너비(시작): A0/S0 가 0.7~1.8 밖이면 세트 전 안내만 ("발을 어깨 너비로")
```
- 둘 다(AND)의 근거: 상대만 쓰면 16:13 처럼 시작 기준이 어긋날 때 세트 전체가 위반이 되고, 절대만 쓰면 카메라 높이에 흔들린다. 오늘 넓힌 7회는 절대 1.66~3.0 으로 모두 통과하고, 16:13 은 6회만 남는다.
- 절대 띠 1.5 는 잠정값이다(폰 1명 정상 1.05~1.36, 모집단 p95 1.42~1.65 — 카메라 높이 의존). 피치 보정 후 폰 세트를 모아 확정한다.

## 4. COACH 모드 횟수 게이트 — 설계 (사용자 결정 반영)

1. **카운터는 그대로 사이클을 센다**(반복 판별 게이트 = 양 무릎 굽힘, spec §62). 자세 검사는 그 뒤에서 회를 '정확 / 위반 / 유보' 로 표시한다.
2. **COACH 표시·음성·목표 진행 = 정확 횟수만.** "정확 5" 처럼 보이고, 뺀 회는 그 자리에서 이유를 한 문장으로 말한다("발이 시작보다 넓어졌어요 — 이 회는 세지 않았어요"). 침묵하면 사용자가 카운트가 죽은 줄 안다. 같은 검사 문장은 12 s 쿨다운, 반복당 한 문장(우선순위: 발끝 → 발 너비 → 무릎 → 상체).
3. **TRACK 은 변경 없음.** 세트 로그에는 두 값(사이클, 정확)과 회별 판정을 모두 남긴다 — 재생·라벨 대조용.
4. **유보는 통과**(원칙 #1). beta 검사는 게이트에 못 들어간다(원칙 #2). 게이트 입장 조건(사전 등록): 모집단 정상 반복 오탐률 ≤ 2 %(정면, 진짜 300 ms), 폰 지정 오류 세트 검출 ≥ 80 %(사람 3명), 오늘 오탐 2건 재생에서 0.
5. **연쇄 유보를 끊는다.** 발 너비 위반 회는 발끝을 유보한다(판독이 오염됨). 그 회는 이미 발 너비로 빠지므로 손해가 없다. 반대로 발끝 위반은 발 너비를 유보하지 않는다(2D 발목 간격은 회전에 ±5 % 만 흔들림, §21.9).
6. **측정 신뢰 조건.** 중력 up 이 검증되지 않은 세트(16:13)는 월드 기반 검사(무릎 안쪽 모임 등)를 전부 유보하고, 2D 검사(발 너비·발끝)만 돌린다. 이 두 검사를 2D 로 두는 이유이기도 하다.
7. **오탐 안전장치.** 같은 검사가 3회 연속 같은 값으로 위반이면 "시작 자세를 다시 잡을까요?" 를 묻고, 사용자가 '지금 자세가 기준' 을 고르면 기준을 갱신한다(스타일 vs 오류를 사용자가 정한다 — 원칙 #3).

현재 코드와의 거리: `RepFormSpecs` 의 발 간격(`stance_2d`, STANDING·EXTREME·START_RATIO ×0.6~1.5)과 발끝(`toe_out_maxside`, 월드, ±15°)을 위 규칙으로 바꾸고, `RepFormEvaluator` 에 바닥 구간 2D 발목 간격·시작 기준 갱신·절대 척도(S0)를 더하는 일이다. 정확 횟수 표시는 이미 있다(HUD "반복 N · 정확 M") — COACH 에서 큰 숫자를 정확으로 바꾸는 것이 남는다. 구현 뒤 파리티 확인에는 `A7b_lib.py` 의 에뮬레이션을 쓸 수 있다 — 폰 4세트의 앱 사이클 시각·시작 자세·검사 값을 소수 3자리까지, MM-Fit 64세트의 JVM 재생 결과를 그대로 재현했다.
