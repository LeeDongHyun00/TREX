# 루틴 공유 설계 (2026-10-29 — 사용자 승인 전)

## 1. 왜

사용자가 처음 구상한 루틴 공유는 **메신저(카카오톡 등)로 내 운동 루틴을 보내는 것**이다. 받은 친구가 링크를 누르면 루틴 이름과 운동 목록을 미리 보고, 그 루틴을 앱에 저장하거나 바로 자기 루틴으로 쓸 수 있어야 한다(사용자 2026-10-29). 같은 방식으로 **커뮤니티 게시글도 메신저로 공유**하고 싶다(사용자 질문 → 결정 §3).

앱은 웹사이트가 아니지만, 운영 서버(`https://trex-api.duckdns.org`, Spring + Caddy)가 짧은 링크와 작은 웹 페이지를 직접 내려줄 수 있다 — 별도 웹사이트 없이 된다. 마감은 2026-11-11.

## 2. 목표 · 비목표 · 반목표

**목표**
- 운동 탭에서 지금 루틴(또는 보관함의 루틴)에 이름을 붙여 메신저로 보낸다. 받은 사람은 링크 하나로 루틴 이름·운동 미리보기를 보고 **"오늘 루틴으로 바로 적용"** 또는 **"내 루틴에 저장"**을 한다.
- 이름 붙은 루틴 여러 개를 모아 두는 **내 루틴 보관함**(지금 앱에는 이름 없는 "오늘 루틴" 하나뿐이다).
- 카카오톡에 링크를 붙이면 루틴 이름·운동 수·시간이 미리보기 카드로 보인다.
- 앱이 없는 사람도 링크를 열면 루틴 일부를 보고 앱을 열거나 설치하러 갈 수 있다.
- 커뮤니티 게시글도 같은 링크 방식으로 메신저에 보낸다.

**비목표(이번에 안 함)**
- 링크를 누르면 웹 페이지 없이 곧바로 앱이 열리는 것(Android App Links·iPhone Universal Links). 빌드 PC마다 서명이 달라 Android 검증이 일부 빌드에서만 되고, iPhone 은 동현님 개발자 계정 설정이 필요하다. 웹 페이지의 "앱에서 열기" 버튼을 기본으로 한다.
- 앱을 새로 설치한 뒤 그 루틴이 저절로 열리는 것(지연 딥링크). 설치 뒤 링크를 한 번 더 누른다.
- 카카오 개발자 SDK(카카오톡 공유 API). 폰의 기본 공유 창을 쓴다.
- 공유 링크 회수·수정, 조회 수, 루틴에 댓글·좋아요.
- 오운완 카드 게시글에서 루틴 저장(나중 아이디어).

**반목표(이렇게 되면 실패)**
- 웹 페이지에 loginId·이메일·실명이 나온다.
- 확인 없이 받는 사람의 오늘 루틴이 덮인다.
- 숨김·삭제된 게시글의 내용이 링크로 새어 나간다.
- 아무나 무제한으로 루틴을 올려 서버에 스팸이 쌓인다.

## 3. 정해진 것

| 항목 | 결정 | 누가 |
|---|---|---|
| 받는 사람 화면 | 루틴 이름 → 운동 미리보기 → "오늘 루틴으로 바로 적용" / "내 루틴에 저장" | 사용자 |
| 앱이 없을 때 | 서버가 만든 웹 페이지(이름, 운동 일부, "T-REX 앱에서 열기", "앱 설치하기") | 시안 확인(사용자 "나쁘지 않다") |
| 공유하는 사람 | **로그인한 사람만**. 받는 사람은 로그인 없이 보고 저장·적용한다 | 사용자 |
| 보내는 흐름 | 운동 탭 오른쪽 위 공유(↗) → 이름 정하는 창(처음엔 "하체 중심 루틴"처럼 채움, "링크를 받은 사람은 누구나 루틴과 내 닉네임을 볼 수 있어요" 안내) → 폰 공유 창. 같은 창에 "내 루틴 보관함에도 저장" | 시안 확인(사용자 "좋은 것 같다") |
| 내 루틴 보관함 | 운동 탭 📁. 저장한 루틴과 받은 루틴("○○님이 보냄")이 함께, 루틴마다 오늘 루틴으로·공유·삭제. "오늘 루틴으로"는 한 번 확인 | 시안 확인 |
| 게시글 공유 | 같은 링크 방식, **내용은 앱 안에서만**(웹 페이지·카드에는 "○○님의 T-REX 커뮤니티 글"과 앱 열기·설치만). 지금 약속("커뮤니티 회원에게 공개")을 지킨다 | 사용자(B안) |
| 앱 바로 열기 | 비목표 — 웹 페이지 → "앱에서 열기" 버튼이 기본 | 사용자 동의(제안 수락) |

## 4. 동작

### 링크 모양
- 루틴: `https://trex-api.duckdns.org/r/{code}` — `code` 는 추측하기 어려운 무작위 8자(영문 대소문자·숫자).
- 게시글: `https://trex-api.duckdns.org/p/{postId}` — 내용이 공개되지 않으므로 번호 그대로 쓴다.
- 앱 안 주소(웹 페이지의 "앱에서 열기"가 연다): `trex://r/{code}`, `trex://p/{postId}`. Android 는 카카오톡 안 브라우저에서도 동작하는 `intent://r/{code}#Intent;scheme=trex;package=com.example.trex_kotlin;S.browser_fallback_url=<설치 주소>;end` 를 쓴다.

### 서버 (`server/`)
- **공유 루틴 저장**: 새 테이블 `shared_routines` — 코드(유일), 올린 회원, 이름, 운동 목록 JSON(아래 모양), 만든 시각.
- `POST /api/routines/share` (로그인 필요): `{name, exercises:[…]}` → `{code, url}`.
  - 보낸 사람 이름은 **커뮤니티 닉네임**이다. 커뮤니티 이용 준비(닉네임·이용규칙 동의)가 안 된 회원이면 거절한다(앱이 먼저 안내).
  - 검사: 이름 1~30자·금칙어(`BannedWords`), 운동 1~30개, 운동 이름과 문자열 칸 길이 제한. 정지된 회원은 거절.
  - 속도 제한: 회원마다 10분에 10개.
- `GET /api/routines/shared/{code}` (로그인 없이): `{name, senderNickname, exercises, createdAt}`. 없으면 404.
- `GET /r/{code}` (로그인 없이): HTML 한 장.
  - `<head>` 에 카카오톡 카드용 정보: 제목 = 루틴 이름, 설명 = "운동 N개 · 약 M분 · ○○님의 루틴", 대표 그림 = 서버의 공룡 그림(`/share/og.png`).
  - 본문: 이름, 운동 수·시간, 운동 앞 3개 + "…N개 더", "T-REX 앱에서 열기", "앱 설치하기".
  - 없는 코드면 "없어졌거나 잘못된 링크예요" 페이지(404).
- `GET /p/{postId}` (로그인 없이): "○○님의 T-REX 커뮤니티 글 · T-REX 앱에서 볼 수 있어요" + 같은 두 버튼. 숨김·삭제·없는 글이면 "볼 수 없는 글이에요". **글 본문·사진은 넣지 않는다.**
- 사용자가 넣은 글자(루틴 이름·운동 이름·닉네임)는 HTML 과 `<head>` 속성에 넣기 전에 반드시 이스케이프한다.
- 설치 주소는 설정값: Android = GitHub 최신 릴리스 페이지, iPhone = App Store 주소(출시 전에는 비워 두고 "App Store 출시 준비 중"으로 보인다).
- 회원 탈퇴 때 그 회원의 공유 루틴도 지운다.
- 보안 설정: `/r/**`, `/p/**`, `/share/**`, `GET /api/routines/shared/**` 만 로그인 없이 연다.

### 운동 목록 JSON(공유·보관함 공통)
지금 저장하는 오늘 루틴(`TrexStore` 의 plan)과 같은 칸에서 기기 전용 칸(`id`, `done`)만 뺀 모양: `name`, `reps`, `duration`, `posture`, `category`, `alt`(선택), `secondsPerRep`·`restSeconds`·`targetKind`·`targetAmount`(선택).

### 앱 (공유 Kotlin — iPhone 도 같은 코드)
- **내 루틴 보관함**: 기기 저장소에 이름 붙은 루틴 목록(이름, 운동들, 받은 경우 보낸 사람 닉네임, 저장 시각). 계정 백업 항목에 넣는다(`SyncRules.KEYS` 에 `routines` — 서버는 바꾸지 않는다, D5).
- **공유 버튼(운동 탭 ↗, 보관함의 "공유")**
  - 로그인 안 했으면 "공유하려면 로그인이 필요해요" + 로그인 창(아이디·Apple·Google).
  - 커뮤니티 준비(닉네임·이용규칙)가 안 됐으면 그 이유와 커뮤니티 탭으로 가는 버튼.
  - 이름 창 → 서버에 올림 → 폰 공유 창에 글("{이름} — T-REX 루틴" + 링크)을 넘긴다.
- **받은 루틴 화면**(전체 화면): 링크로 앱이 열리면 서버에서 루틴을 받아 이름·보낸 사람·운동 목록을 보인다. "오늘 루틴으로 바로 적용"(확인 뒤 오늘 루틴을 바꾸고 완료 표시는 모두 지운다), "내 루틴에 저장". 운동 이름은 앱의 개명 규칙(`WorkoutNames.canonical`)으로 맞추고, 자세 교정 표시는 받는 앱이 아는 종목만 켠다.
- **게시글 "공유하기"**: 게시글 메뉴에 추가. 서버를 부르지 않고 `https://trex-api.duckdns.org/p/{id}` 를 공유 창에 넘긴다. `trex://p/{id}` 로 앱이 열리면 커뮤니티 탭으로 가서, 이용 준비가 되어 있으면 그 글 상세를 연다(안 되어 있으면 커뮤니티 안내를 보이고 준비가 끝나면 연다).
- **플랫폼 짝**(Android `PlatformUi.kt` / iPhone `ios-ui/.../PlatformUi.kt`): 공유 창 열기(Android `Intent.ACTION_SEND`, iPhone `UIActivityViewController`), 앱 주소 받기(Android `trex` 스킴 intent-filter, iPhone URL Types + `onOpenURL` → Kotlin).

### 개인정보 처리방침
2-1 근처에 한 항목 추가: 공유한 루틴(이름·운동 목록·닉네임)은 링크를 가진 누구에게나 보인다, 탈퇴하면 지운다. 게시글 링크 페이지에는 닉네임만 보인다.

## 5. 지켜야 할 것
- 저장소는 공개다 — 설정값에 비밀값을 넣지 않는다(설치 주소는 비밀값 아님).
- 공유 Kotlin 파일은 `android.*`·`java.*` 를 쓰지 않는다(`ios-ui/android-sources.txt` 에 새 파일 등록).
- 앱 문구는 공룡 말투 변환(`TrexText`)을 그대로 탄다. 사용자가 적은 루틴 이름은 변환하지 않는다(`UserText`).
- 서버 `@Enumerated` 칸을 새로 만들거나 enum 값을 더하면 운영 DB 검사 규칙도 바꿔야 한다(런북 8절 함정).
- iPhone 쪽 파일(URL Types, `onOpenURL`)은 바꾼 사실을 동현님께 알린다.

## 6. 빌더에게 맡기는 것
- 웹 페이지 모양(앱과 같은 초록 톤, 휴대폰 폭), 공룡 대표 그림 고르기(기존 기본 아바타 그림 재사용 가능).
- 서버 HTML 을 만드는 방법(템플릿 엔진 없이 문자열로 충분).
- 보관함 화면의 정렬(최근 저장 순 권장)과 빈 화면 문구.
- 이름 창의 기본 이름 규칙(지금 루틴의 중심 부위 + "루틴").

## 7. 순서
1. 서버: 공유 루틴 저장·조회 API, `/r`·`/p` 웹 페이지, 탈퇴 정리, 보안 설정, 테스트 → 운영 배포.
2. 앱 공유 코드: 보관함 저장·백업, API, 앱 주소 해석, 받은 루틴 화면, 공유 창, 보관함 화면, 게시글 공유하기.
3. 플랫폼 짝: Android 공유·intent-filter, iPhone 공유 창·URL Types.
4. 개인정보 처리방침(gh-pages) 한 항목.
5. 실기기: 카카오톡으로 보내기 → 카드 → 링크 → 앱 열기/웹 페이지 → 적용·저장.

## 8. 내 판단으로 정한 것(사용자 확인 전)
- 보낸 사람 이름 = 커뮤니티 닉네임, 그래서 공유하려면 커뮤니티 이용 준비(닉네임·이용규칙 동의)가 끝나 있어야 한다.
- 루틴 이름 금칙어 검사, 속도 제한 10분 10개, 운동 최대 30개, 이름 최대 30자.
- 공유 링크는 만료 없음(탈퇴하면 지움).
- 보관함을 계정 백업에 넣는다.
- 게시글 링크는 번호를 그대로 쓴다(내용이 공개되지 않으므로).
- "약 M분"은 앱이 계산해(`RoutineOverview` 의 총 시간) 공유할 때 함께 보내고 서버는 그대로 저장·표시한다(틀려도 해가 없는 값).
- 링크로 앱이 열렸는데 아직 시작 화면·온보딩이면, 그걸 마친 뒤 받은 루틴 화면(또는 게시글)을 띄운다. 운동 세션 중이면 "운동을 마친 뒤 적용할 수 있어요"로 적용만 막는다(저장은 된다).
- Android "앱 설치하기" = `https://github.com/LeeDongHyun00/TREX/releases/latest`(저장소가 공개, 조원이 서명한 릴리스 APK).
- 보관함은 최대 50개 — 넘으면 "보관함이 가득 찼어요. 안 쓰는 루틴을 지워 주세요".
