# 커뮤니티 탭 1차 설계 (2026-10-28)

담당: Yoonsung(음식·서버·커뮤니티 트랙). 상태: **설계 — 사용자 승인 전, 구현 전.**

## 1. 무엇을, 왜

팀이 "보편적으로 말하는 커뮤니티"를 **별도 탭**으로 넣기로 정했다(2026-10-28 팀 확정, 사용자 전달). 10-24 에 정했던 "공개 피드 없이 메신저 공유·루틴 링크로 대체" 안은 폐기됐다.

- **기준은 인스타그램이다**(사용자: "인스타처럼 벤치마킹해"). 사진 중심 게시물이 세로로 흐르는 피드, 좋아요, 댓글, 프로필.
- 사용자가 예상하는 글: 오운완, 루틴 추천, 운동 질문, 운동·마라톤 대회 정보. **글 종류(카테고리)는 나누지 않는다** — 무엇이든 자유롭게 올린다(사용자 결정).
- **게시물 사진은 서버에 저장한다**(팀 결정 "이미지 저장").
- **사진 없이 글만 올리는 것도 허용한다**(사용자 결정 — 질문·대회 정보를 생각해서. 인스타와 다른 점).

이 앱의 중심은 기기 안에서 도는 카메라 자세 코칭이다. 커뮤니티는 그 옆에 붙는 **자발적 공개 공간**이고, 자세 영상·관절 기록·음식 인식 사진이 몰래 올라가는 통로가 되면 안 된다.

## 2. 목표 · 비목표 · 반목표

### 목표(1차)
1. 하단 바에 **"커뮤니티" 탭**을 추가한다.
2. **피드**: 모든 사람의 글을 최신순으로 보여 준다. 게시물 카드 = 닉네임·프로필 사진 / 사진(여러 장이면 옆으로 넘김) / 하트·댓글 버튼, 좋아요 수 / 본문 / "댓글 n개 보기" / 올린 시각. **사진 두 번 탭 = 좋아요.** 글만 있는 게시물은 사진 자리 없이 본문 카드로 보인다.
3. **글쓰기**: + 버튼 → 사진 고르기·찍기(0~5장) → 본문 → 올리기. 올리기 화면에 "서버에 저장되고 모든 사용자에게 공개돼요"를 밝힌다.
4. **오운완 올리기**: 운동 완료 화면에 버튼을 둔다. 누르면 그날 기록 카드(운동·세트·시간·kcal 등 완료 화면 정보)를 그림으로 만든 것이 첫 사진으로 붙은 글쓰기 화면이 열린다.
5. **댓글**: 한 단계(답글 없음). 글 상세 화면에서 보고 쓴다.
6. **프로필**: 닉네임, 프로필 사진, 게시물 수, 그 사람의 글 격자(인스타 프로필 모양). 피드의 닉네임을 누르면 그 사람 프로필로 간다. 내 프로필에서 닉네임·사진을 바꾸고 차단 목록을 관리한다.
7. **안전 장치(스토어·법 필수, §4)**: 첫 글 전 이용규칙 동의, 글·댓글·사용자 신고, 사용자 차단, 내 글·댓글 삭제, 금칙어 필터, 관리자 숨김·삭제·정지, 탈퇴 시 커뮤니티 데이터 삭제.

### 비목표(1차에 하지 않는다)
팔로우·팔로잉 피드, 스토리, 릴스·동영상, DM, 탐색·해시태그·검색, 푸시 알림, 저장(북마크), 답글, 글 수정, 루틴을 글에 붙여 "내 루틴으로 가져오기", 이미지 자동 검사(Rekognition), CDN.

### 반목표(기능이 돌아가도 이러면 실패)
- 자세 영상·관절 좌표·음식 인식 사진이 사용자가 고르지 않았는데 올라간다.
- 화면 문구 "사진은 기기 안에서만"과 커뮤니티 업로드가 구분되지 않아 사용자가 헷갈린다.
- 구글 실명이나 이메일이 다른 사용자에게 보인다.
- 신고·차단 없이 공개 피드가 열린다.
- 계정 없이 쓰던 사람의 기존 기능(운동·식단·자세)이 커뮤니티 때문에 막히거나 바뀐다.

### 코드
- **iPhone 도 같은 화면을 컴파일한다.** 새 화면 파일은 `ios-ui/android-sources.txt` 에 올리고 `android.*`·`java.*`·`BuildConfig`·`@Synchronized` 를 쓰지 않는다. 플랫폼 기능은 `AppPlatform`·`HttpTransport`·`PlatformUi` 짝으로 받는다(CLAUDE.md, `docs/IOS_PORT.md`).
- **`HttpTransport` 는 지금 글자만 주고받는다**(`TrexApi.kt:25,28`). 사진 올리기(바이너리 본문)와 받기를 두 플랫폼 구현(`AndroidPlatform.kt`, `ios-ui/.../UrlSessionTransport.kt`)에 더해야 한다. 이미지 로더(캐시·축소 디코딩)도 없다.
- **화면은 서버를 직접 부르지 못한다** — `AppViewModel`(`TrexAppState.kt`)에 메서드를 더해 노출한다. 401 은 기존 `onSessionExpired` 흐름을 탄다.
- **계정 여부는 `app.account != null`** 로 가린다(`loggedIn` 은 "로그인 없이 사용"도 true).
- **하단 바 `MorphNav` 는 탭 4개를 전제로 한 숫자가 박혀 있다**(`TrexApp.kt:702-721` 리모컨 인덱스·아이콘). 5개로 바꾸고 폰 폭·글자 1.3배에서도 깨지지 않게 한다.
- 사진 고르기·찍기는 음식 경계(`PhotoFoodApi.kt` 의 갤러리·카메라·`FoodPhoto`)를 다시 쓸 수 있지만 JPEG 바이트를 꺼내는 기능이 없다 — 경계에 인코딩을 더하거나 일반 이름으로 뺀다.
- **iPhone 은 구글 로그인이 아직 없다**(`IosPlatform.googleWebClientId = ""`). 그래서 iPhone 커뮤니티는 iOS 구글 로그인(별도 작업, iOS 클라이언트 ID 발급·서버 허용 목록 반영 완료 2026-10-28)이 먼저다. **Android 를 먼저 완성한다.**

### 서버·인프라
- Spring Boot, 운영은 `ddl-auto: update`(Flyway 없음) — 새 테이블 추가만 하고 기존 테이블은 바꾸지 않는다.
- EC2 t4g.micro, 앱 힙 384MB — 서버에서 이미지를 디코딩·리사이즈하지 않는다. multipart 크기 제한을 명시한다(장당 2MB, 요청당 10MB 수준).
- RDS 무료 20GB — 사진은 DB 에 넣지 않는다.
- S3 와 IAM(EC2 인스턴스 역할)을 새로 만든다. 비밀값은 `.env` 에만.
- **AWS Free plan 은 가입 6개월 뒤 정지된다** — 데모데이 전 만료일을 확인한다(사용자 몫).
- 회원 탈퇴(`AuthService.deleteAccount`)는 테이블을 손으로 지운다 — 커뮤니티 테이블과 S3 사진을 같이 지운다.
- 예전 앱 버전도 계속 쓰인다 — 기존 API 는 그대로 두고 새 경로(`/api/community/...`)만 더한다.

## 5. 동작

### 처음 들어올 때
1. 계정이 없으면: 탭에 "커뮤니티는 구글 계정으로 로그인하면 쓸 수 있어요"와 로그인 버튼(내 정보의 계정 연결로). 다른 탭은 그대로.
2. 계정이 있고 커뮤니티 프로필이 없으면: 닉네임 정하기(2~12자, 중복 불가, 금칙어 불가) → 이용규칙 동의(무관용·신고 처리 절차·만 14세 이상 확인, 전문 링크) → 피드.
   - 보기만 하는 사람도 닉네임을 정한다(차단·신고 대상이 되고, 좋아요·댓글을 남길 때 이름이 필요하다) — **내 판단.**

### 피드·상세
- 최신순, 20개씩 이어 불러오기, 당겨서 새로고침. 실시간 갱신은 없다.
- 차단한 사람의 글·댓글은 보이지 않는다(서버가 거른다). 숨김 처리된 글은 작성자 본인에게만 "숨김 처리됨"으로 보인다.
- 카드의 ⋯ 메뉴: 내 글이면 삭제, 남의 글이면 신고·차단(따로), 관리자면 숨김·삭제·작성자 정지 추가.

### 글쓰기
- 사진 0~5장 + 본문(최대 2,000자). 둘 다 비면 올릴 수 없다.
- 앱이 사진을 긴 변 1080px JPEG(품질 85 안팎)로 다시 만든 뒤 올린다.
- 금칙어가 있으면 서버가 거절하고 앱이 이유를 보여 준다.
- 너무 자주 올리면 서버가 막는다(예: 1분 1개, 하루 30개 — 숫자는 구현에서 정한다).

### 신고·차단·관리
- 신고 사유: 스팸·광고 / 욕설·혐오 / 음란·폭력 / 개인정보 노출 / 권리 침해 / 기타. 같은 사람이 같은 대상을 두 번 신고할 수 없다.
- 신고 3건이 쌓이면 자동 숨김, 관리자가 확인해 복구 또는 삭제. 관리자는 신고를 24시간 안에 처리한다(운영 몫 — 사용자).
- 차단은 즉시 반영, 내 프로필의 차단 목록에서 푼다.
- 관리자 정지: 정지된 계정은 글·댓글·좋아요를 못 하고, 기존 글은 숨겨진다.

### 탈퇴
- 회원 탈퇴 시 그 사람의 커뮤니티 프로필·글·사진(S3)·댓글·좋아요·신고·차단 기록을 지운다. 남의 글에 단 댓글도 지운다.

## 6. 서버 초안 (빌더가 바꿔도 된다)

데이터(새 테이블):
- `community_profiles`(user_id, public_id, nickname unique, avatar_key, terms_accepted_at, suspended_at)
- `posts`(id, author_id, body, created_at, hidden_at, hidden_reason)
- `post_images`(post_id, position, s3_key, width, height)
- `post_likes`(post_id, user_id, created_at) — 한 사람 한 번
- `comments`(id, post_id, author_id, body ≤ 500, created_at, hidden_at)
- `reports`(id, reporter_id, target_type, target_id, reason, created_at, resolved_at, resolution)
- `blocks`(blocker_id, blocked_id, created_at)

API(`/api/community`, 전부 인증): 프로필 만들기·바꾸기·내 프로필, 이용규칙 동의, 피드(커서), 글 쓰기(multipart)·삭제·상세, 좋아요·취소, 댓글 목록·쓰기·삭제, 사용자 프로필·글 목록, 신고·내 신고 목록, 차단·해제·목록, 사진 주소(서명 주소, 수명 짧게). 관리자: 신고 목록, 숨김 글 목록, 숨김·복구·삭제, 정지·해제·정지 목록. 신고가 들어오면 디스코드 웹훅(`COMMUNITY_REPORT_WEBHOOK_URL`, 비어 있으면 보내지 않음). 사용자 식별은 `public_id`(구글 sub 가 든 loginId 를 노출하지 않는다).

## 7. 함께 해야 하는 일
- `gh-pages` 에 **이용규칙 페이지**(`terms.html`)를 만든다 — 금지 콘텐츠, 무관용, 신고·임시조치 절차, 연락처. 앱의 동의 화면이 이 페이지를 연다.
- `privacy.html` 에 커뮤니티 항목을 더한다(§4).
- 앱 문구: 사진 식단의 "기기 안에서만" 문구는 그대로 두고, 커뮤니티 글쓰기 화면에 "서버에 저장되고 공개돼요"를 따로 둔다. `AuthScreens.kt` 의 "계정 없이도 모든 기능" 문장은 "커뮤니티를 뺀 모든 기능"으로 고친다.
- README·AGENTS.md 예정 목록 갱신.

## 8. 빌더에게 맡기는 것
- 이미지 로딩 방법(직접 구현 또는 Compose Multiplatform 을 지원하는 라이브러리) — 캐시와 축소 디코딩만 지키면 된다.
- 화면 세부 모양은 기존 테마·`AdaptiveLayout` 을 따른다(폴더블 힌지·최대 폭 840dp).
- 금칙어 목록의 출처와 정규화 방식.

- 테스트 구성: 서버는 기존 `SocialSyncApiTest` 방식(MockMvc + 가짜 구글 검증기), 앱은 순수 로직 JVM 테스트, 화면은 실기기 확인. iPhone 컴파일은 PR CI `shared` 작업.

## 9. 순서(제안)
1. 서버: 테이블·API·S3·관리자·탈퇴 연동 + 테스트 → 운영 배포(`app.jar.prev` 롤백 준비).
2. 앱 기반: `HttpTransport` 바이너리, 이미지 로더, 사진 인코딩.
3. 앱 화면: 탭·피드·상세·글쓰기·프로필·신고/차단·닉네임/동의, 오운완 올리기, 관리자 신고함·내 신고.
4. 이용규칙·처리방침 페이지, 문구 정리.
5. Android 실기기 확인 → iOS 구글 로그인 뒤 iPhone 확인.
