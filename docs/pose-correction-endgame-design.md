# 자세 교정, 완성까지 — 평가와 설계

- 상태: 자문 문서. 계약이 아니며 SHA pin이 없다. 구속력 있는 사다리·게이트는 [서비스 로드맵](pose-correction-service-roadmap.md)(R0~R7, SL-0~SL-3)이 계속 소유한다.
- 작성일: 2026-08-13
- 질문: **"완벽한 자세 교정 서비스"는 무엇이고, 지금 어디에 있으며, 어떤 순서로 무엇을 지어야 하는가.**
- 근거: 이 문서의 모든 수치는 2026-08-13 완료된 광역 브리지 측정(17개 촬영일·137,015프레임·전역 피험자 LOSO, [브리지 오차 카드](mediapipe-aihub-bridge.v1.json) v3)과 저장소 실측이다. 로드맵(8-11 작성)이 계획으로 두었던 것 중 상당수가 이제 측정된 사실이다.

## 0. 요약

1. **"자세 교정"의 본질은 깊이가 아니라 고정이다.** 사용자가 기대하는 교정은 "무릎이 더 굽어야"가 아니라 "팔꿈치가 벌어졌다·허리가 젖혀졌다"다. 데이터도 같은 방향을 가리킨다 — 고정형 조건의 분리도(0.78~0.86)가 가동범위형(0.75~0.86)과 같거나 높고, 이미 게이트를 통과한 고정형 상수 3개가 앱의 표현 수단이 없어 대기 중이다.
2. **관찰 트랙은 천장 근처까지 왔다.** 이 데이터셋·이 센서로 임계값 방식이 도달할 수 있는 상한은 라벨 상한(0.77~0.88)과 단안 오차(중앙값 ~11°)가 함께 정한다. 세 상수(니업 105°·랫풀 67°·딥스 106°)는 그 상한의 88~97%에 있다. 여기서의 개선은 정밀화가 아니라 **표현력 확장**(고정형)과 **도메인 전이 확인**(실기기)이다.
3. **판정(SL-3)은 코딩 과제가 아니라 데이터 수집 프로그램이다.** 필요한 것 전부가 이미 계약으로 준비되어 있고(Gold 프로토콜·연구 계획·서명 스캐폴드), 전부 비어 있다(participantCount 0, trust root NOT_IMPLEMENTED). 시작 버튼은 코드가 아니라 서명 인프라(protocol v2)와 권리 전환이다.
4. **산업은 판정을 안 한다.** Peloton은 반복도 안 세고, Kemtai는 관절 위치만 검증한다. "정직한 관찰 + 좁고 깊은 판정"이 방어 가능한 최종 포지션이며, 전 운동 판정은 목표로 삼을 이유가 없다.

## 1. 평가

### 1.1 "완벽한 서비스"의 분해

"자세를 교정해 준다"는 요구는 서로 다른 네 주장의 합이고, 각각 요구 증거가 다르다.

| 주장 | 예 | 현재 상태 | 요구 증거 (로드맵 게이트) |
|---|---|---|---|
| 관찰 | "무릎이 106도까지 굽혀졌어요" | **제공 중** (베타 고지 하) | 임계값이 아니라 문구가 정확하면 됨 — 각도 자체는 오차 고지 대상 |
| 카운트 | "8회 감지" | 제공 중, **미검증** | SL-1: 실기기 phase Gold, rep F1, negative 구간 포함 |
| 측정 요약 | "이번 세트 평균 ROM 92°" | 미제공 | SL-2: 채널별 오차 데이터 카드 선행 |
| **판정·교정** | "허리가 말렸어요, 이렇게 고치세요" | **봉인** (0-entry allowlist) | SL-3: 외부 실기기 Gold, recall·precision CI, 서명 release |

핵심 관찰: 사용자가 "교정"이라 부르는 것의 대부분은 넷째 줄이 아니라 **첫째 줄의 고정형 버전**으로 충족된다. "팔꿈치가 어깨에서 52도까지 벌어졌어요"는 판정이 아니라 관찰이지만, 사용자에게는 폼 피드백으로 기능한다. 이것이 이 설계의 중심 착상이다.

### 1.2 현재 위치 (실측)

| 축 | 상태 | 증거 |

| 엔진 | 견고 | 16종, 4체인(어깨 신설), 양방향, 홀드, 세트 내 기준선, 기권 규율 |
| 보정 | **3/16, 전부 광역 검증** | 니업 105°/0.813(48명·9일), 랫풀 67°/0.855(32명·4일), 딥스 106°/0.761(32명·4일) |
| 측정 인프라 | **재현 가능한 파이프라인** | 3단 게이트 + 아카이브 제자리 측정(111fps), 클립별 산출물로 재적합 무비용 |

### 1.3 세 개의 벽 (이번 측정으로 정량 확정)

이 벽들이 설계의 경계 조건이다. 셋 다 "더 열심히"로는 안 넘어간다.

**물리의 벽 — 단안 오차.** MediaPipe와 3D 정답의 각도 오차 중앙값 ~11°(문헌 2D 9.3~21.9°와 정합). 임계값을 1° 단위로 다듬는 것은 무의미하며, **관대한 임계값 + 정직한 고지**가 이 센서에서 옳은 설계다. 관절별 충실도 순서는 몸통 중심일수록 좋다: 엉덩이(편차 1.0°) < 어깨(10.9°) < 무릎 < 팔꿈치(14.9°+). 신규 체크를 설계할 때 **어느 관절로 잴지**가 정확도를 좌우한다.

**감각의 벽 — 척추가 안 보인다.** AI Hub의 Back·Waist 관절은 MediaPipe에 대응이 없다. "척추 중립"(스쿼트·데드리프트·굿모닝의 핵심 조건)은 이 센서로 원천 불가시다. TRUNK 프록시(어깨-엉덩이-발목)는 로잉의 "과도한 젖힘"(0.800) 같은 **큰 몸통 기울기**는 잡지만, 굽은 등과 곧은 힌지를 구분하지 못한다. 척추 판정을 원한다면 답은 모델 교체 R&D나 센서 추가이지, 현 스택의 개선이 아니다.

**정답의 벽 — 반복 단위 진리가 없다.** 클립당 16장 희소 키프레임 + 타임스탬프 없음 + 클립 단위 대본 라벨. 반복별 정오는 이 데이터로 영구 측정 불가(phase 재실험은 REJECTED 해시 고정). 카운트·판정의 확증은 **자체 실기기 수집만이 경로**다 — 로드맵이 옳았고, 측정이 재확인했다.

### 1.4 이 아키텍처의 천장

| 운동 | 라벨 상한(3D 정답) | 실측(MediaPipe) | 도달률 |
|---|---:|---:|---:|
| 랫풀 다운 | 0.879 | 0.855 | 97% |
| 스탠딩 니업 | 0.859 | 0.813 | 95% |
| 딥스 | 0.844 | 0.761 | 90% |
| 사이드 크런치* | 0.859 | 0.856 | 100% |
| 로잉머신* | 0.817 | 0.800 | 98% |
| 바벨 컬* | 0.816 | 0.784 | 96% |

(*는 고정형 — 앱 미표현으로 대기 중.) 임계값 방식은 이 데이터에서 이미 라벨 상한에 근접했다. **남은 gap의 대부분은 알고리즘이 아니라 센서와 라벨의 것**이다. 따라서 "더 정확한 자세교정"의 다음 수확은 (a) 표현 못 하는 측정값의 편입, (b) 실기기 도메인 전이, (c) 신규 데이터이지, 분류기 교체가 아니다. 포워드 런지의 교훈(8명 0.927 → 48명 0.746)이 보여주듯, **좁은 표본의 높은 숫자는 성능이 아니라 경고**다.

### 1.5 권리 평가

연구 manifest는 비상업 교육 범위다. AI Hub 이용정책은 학습 산출물(임계값 상수) 배포를 출처 명시 조건으로 허용하고 앱은 이미 §4.5로 이행 중이나, **스토어 배포 전 파생물 조건 서면 확인**이 남아 있다(로드맵 R2b). 정도(正道)는 readiness 문서의 사다리다: 최종 소유권은 `SELF_DEVICE_FIT`(자체 실기기 적합)로 가져가고, AI Hub 유래 상수는 교차검증 참고로 강등한다. 그러면 권리 의존이 문서 근거로 내려간다.

## 2. 설계

### 2.0 원칙 — 이 세션이 증명한 것을 규칙으로

1. **게이트 순서가 방법론이다.** 싼 검증(라벨) → 뷰 선택 → 비싼 측정. 역순은 뷰 아티팩트를 산다.
2. **표본이 좁으면 보정은 거짓말한다.** 전역 피험자 LOSO + 라벨 상한 대조를 채택 조건으로 고정. 측정치가 라벨 상한을 넘으면 축하가 아니라 재조사.
3. **어휘는 검출기가 아니라 해부학을 따른다.** ("모아졌어요" 사건)
4. **봉인은 증거가 아니라 결과에 대한 규칙이다.** 보정이 좋아져도 권유 허용은 별개 결정. (딥스 사건)
5. **고정형과 가동범위형은 반대말이다.** 같은 임계값이라도 "더 가라"와 "넘지 마라"는 정반대 지시. conditionKind가 숫자와 함께 이동해야 한다.

### 2.1 Horizon 1 — 관찰 서비스의 완성 (지금 착수 가능, 수 주)

목표: **판정 없이 도달 가능한 최고의 자세 피드백.** 새 데이터 불필요, 이미 측정된 값의 편입이 중심.

**H1-A. 고정형 관찰(guard chain) — 이 설계의 중심.**

현 엔진은 운동당 체인 1개(driver)로 반복을 세고 극값을 관찰한다. 고정형은 **둘째 체인**이 필요하다: 반복은 driver가 세고, 그동안 고정돼야 할 관절은 guard가 지켜본다.

```
FormCheckExercise에 추가:
  guard: FormCheckGuard? = null
  // FormCheckGuard(chain, limitDegrees, extreme, vocabulary)
  // 예: 바벨 컬 = driver ELBOW(카운트) + guard SHOULDER(max ≤ 52°, "벌어짐")

엔진 변경:
  - 반복 excursion 동안 guard 체인을 병행 샘플링, 작업 구간의 최대 이탈을 기록
  - 반복 완료 관찰에 병기: "팔꿈치가 94도까지 굽혀졌어요 · 위팔이 어깨에서 37도까지 벌어졌어요"
  - guard는 권유를 만들지 않는다(관찰 전용). 권유 추가는 §4.2류의 별도 결정
  - guard 관절 미관측 시 guard 관찰만 침묵(기권 규율 준용) — 카운트는 계속
```

편입 대상(측정 완료·게이트 통과): 바벨 컬 guard=SHOULDER 52°(0.784), 로잉머신 TRUNK 132°(0.800), 사이드 크런치 ELBOW 94°(0.856). 로잉·사이드 크런치는 FormCheckExercise 신규 2종 추가(카탈로그·계획 화면에 이미 존재). 정책 §4에 고정형 표 신설 + 어휘 행("벌어졌어요"/"젖혀졌어요") + SHA 재핀.

**H1-B. 실기기 스모크 (readiness §2-②, 유일하게 촬영 필요).** `DevPoseCapture`로 본인 스쿼트·니업·랫풀 각 1세트 → replay fixture 승격. 확인 질문 하나: **IMAGE 모드·스튜디오에서 적합한 상수가 VIDEO 모드·실환경에서 같은 쪽으로 분리되는가.** 이것 없이 어떤 H2 계획도 세우면 안 된다 — 전이가 깨져 있으면 수집 프로토콜 설계가 달라진다.

**H1-C. 출처 사다리 완성.** `LITERATURE_STANDARD` provenance 신설: 스쿼트(평행=무릎 ~90°+측정된 편차, IJSPT)·푸시업(90° 군 표준)·플랭크는 "근거 없음"이 아니라 "문헌 표준"이다. 16종 전부가 셋 중 하나를 갖게 된다: 문헌 / 브리지 적합 v3 / 휴리스틱. 화면 문구도 3분화.

**H1-D. 세션 UX 마감** (readiness §2-③): 음성 반복 카운트(onAnnounce 배선), 세트 종료 요약 카드(메모리 전용). 고정형 관찰이 요약 카드의 핵심 내용이 된다 — "이번 세트에서 위팔이 평균 12° 벌어졌어요"는 세트 중 음성보다 소화하기 좋다.

**H1 완료 정의**: 고정형 3종 편입 + 16종 출처 전량 명시 + 실기기 스모크 3운동 녹색 + 음성 카운트. 이 시점의 제품이 "정직한 관찰 서비스"의 완성형이다.

### 2.2 Horizon 2 — 검증된 카운터와 개인화 (SL-1/SL-2, 자체 수집 개시)

목표: "감지"가 "검증된 카운트"가 되고, 측정값이 오차 카드와 함께 나온다. **로드맵 R2b(TREX 클래스 권리 전환)가 선행 조건** — 참가자 데이터 보존이 시작되는 순간부터다.

- **수집 프로토콜**(로드맵 R4 준수): ≥12명×2티어×2세션 파일럿, **negative 구간 의무 포함**(휴식·이동·인접 운동 — 히스테리시스 오발화가 harmful cue 경로), 3인 blind 라벨(α≥0.80), 사전등록 역치(rep F1 등) 이후 완화 금지. 파일럿은 GO/NO-GO 전용, 사용자 노출 승격은 검정력 통과 본 표본 후.
- **SELF_DEVICE_FIT 도입**: 실기기 적합값이 상수의 최종 출처가 되고, AI Hub 값은 교차검증으로 남는다(권리 청정 + 도메인 정합). 이번에 만든 3단 게이트·전역 LOSO·라벨 상한 대조를 그대로 회귀 하니스로 재사용한다.
- **개인 기준선의 영속화 — 소유자 결정 필요.** 세트 내 비교(§4.4)는 이미 있다. 세션 간 개인 기준선은 리텐션 가치가 크지만 §5-2(기록 없음)와 충돌한다. 선택지: (a) 운동당 스칼라 각도 1개만 opt-in 저장(§5-2 개정+SHA 재핀 선행), (b) 세션 한정 유지. 권고는 (a)이되, **H2 시점에** 결정 — H1에는 불필요.
- **오차 데이터 카드**(SL-2): 실기기 수집이 생기면 채널별 P95 오차 카드를 만들 수 있고, 그때 ROM 요약 노출이 열린다.

### 2.3 Horizon 3 — 판정(SL-3): 데이터 프로그램으로서의 "진짜 교정"

로드맵 R0~R6이 이미 완전한 계약이다(사전등록 역치, 봉인 규율, 300명급 harmful-cue 상한, 서명 release, kill switch). 이 문서가 더할 것은 세 가지 정직한 갱신뿐이다.

**우선순위가 측정으로 바뀌었다.** 로드맵 R7의 Tier 1 "런지 포워드→백워드→니업"은 이제 증거와 반대다: 포워드 런지는 광역에서 게이트 미달(0.746), 백워드는 라벨조차 0.736. **첫 판정 후보는 스탠딩 니업이다** — 최대 표본(48명·9일), 최소 편차(1.0°, 엉덩이 체인), 최고 도달률. 둘째 후보는 랫풀 다운(0.855, 단 기구 필요). Tier 2 가정도 갱신 필요: 바벨/덤벨 원시 아카이브 8개 촬영일 분이 배포본에 없어 바벨 런지는 측정 불가로 확정.

**척추는 별도 R&D 트랙이다.** SL-3 첫 criterion을 척추류로 잡으면 안 된다(감각의 벽). 현실적 경로: ① 몸통 프록시로 되는 것만(과도 젖힘/숙임 — 로잉이 증명) 좁게 연다, ② 척추 곡률이 정말 필요하면 스파인 키포인트 모델 온디바이스 R&D 또는 웨어러블 IMU를 **별도 타당성 연구**로 분리한다. ①과 ②를 섞으면 ①의 출시가 ②의 연구 일정에 볼모로 잡힌다.

**규모를 숫자로 말하면**: 서명 인프라(protocol v2, 외부 co-signer ≥1) + 전문가 roster(SME 1·blind reviewer 3·adjudicator) + 파일럿 12명 + 본 수집 수백 명(participant-level harmful cue <1% 증명에 ~300명) + 운영 백엔드(signed config·telemetry). 이는 캡스톤 범위 밖이라는 기존 소유자 결정과 정합하며, **그 결정이 옳다**. H1+H2를 완주한 제품은 판정 없이도 경쟁 지형(Peloton·Kemtai)에서 가장 정직한 축에 선다.

### 2.7 소유자 결정 대기

1. **H1 고정형 관찰 착수 승인** — 정책 §4 고정형 표 신설 + SHA 재핀 필요. (권고: 즉시)
2. **§5-2 개정 여부** — 개인 기준선 스칼라 저장. (권고: H2 시점 재론, 지금 아님)
3. **H3 착수 여부** — 캡스톤 밖 유지가 기존 결정. 착수한다면 첫 후보는 런지가 아니라 **스탠딩 니업**으로 로드맵 R7 갱신.
4. **AI Hub 파생물 배포 조건 확인 시점** — 스토어 배포 전 필수(R2b), 사이드로드 시연이면 불요.

## 3. 로드맵 문서에의 정정 제안 (advisory)

로드맵은 8-11 작성이라 이번 측정을 모른다. 개정 시 반영할 사실: ① R3의 브리지 측정은 v3로 완료됨(17일·전역 LOSO) — 단 R3가 요구하는 "비봉인 subject 한정·2트랙(IMAGE/VIDEO)·criterion별 P95 표"와는 목적이 달라 대체가 아니라 선행 참고임을 명시, ② R7 Tier 1 순서를 니업 우선으로, ③ Tier 2에서 바벨 런지 제외(원시 아카이브 부재), ④ 굿모닝 STABILITY 0.677·백워드 런지 0.736은 라벨 수준 확정치로 기록.
