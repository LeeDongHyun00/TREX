# 운동 이해·교정 엔진 M1 구현

2026-09-23 · `codex/aihub-26-exercises` · 엔진 `motion-1`

[설계](POSTURE_MOTION_ENGINE_DESIGN.md)의 첫 실행 단계다. AIHub 연결 **26종목**에서 반복 단계·좌우·측정 근거를 분리해 앱에 연결했다. 동적 25종목은 새 카운터, 플랭크는 기존 유지시간/정렬 추적을 사용한다. 모든 행동 분류기나 모든 자세 오류의 검증이 끝났다는 뜻은 아니다.

## 구현한 동작

| 영역 | 앱의 실제 동작 |
|---|---|
| 반복 계수 | 준비→주동작→방향 전환→복귀/재준비를 추적. 종목 계약에 따라 복귀 또는 힘쓰는 끝점에서 센다. 다음 반복의 하강을 기다리지 않는다. |
| 빠른 움직임 | FULL 모델을 유지한 채 세션 추론 요청 간격을 300→80ms로 낮춤. CameraX 최신 프레임 정책과 열 보호 유지. 실제 처리율은 기기 추론시간에 제한됨. |
| 중복 방지 | 주신호와 보조신호의 이동을 함께 요구. 같은 끝점에 머무르면 추가 계수 없음. 양측 운동은 시작 시각까지 확인해 사건을 짝지음. 런지 뒷다리를 별도 1회로 세지 않음. |
| 좌우 | 덤벨 컬/니업 등은 해당 팔·다리별 사건. 바닥 종목은 필요한 관절의 가시성으로 한쪽을 선택하고 사이클 중간에 다른 쪽과 이어 붙이지 않음. |
| 상태 | 시작 자세 관측·선택 동작 추적·정지·준비/다른 움직임·관절 미확인·일시정지 표시. 준비/다른 움직임은 생활 행동의 이름을 알아낸 결과가 아님. |
| 무릎 방향 | 뒤꿈치→발끝의 수평 방향에 수직인 무릎 위치를 좌우 각각 관측. 발을 바깥으로 돌렸다는 이유만으로 안쪽 말림을 지시하지 않음. 발이 가려지면 방향 안내 유보. |
| 다른 관절 | 실제 피처가 재는 각도·거리·변동에 맞춰 설명. 고개 각도로 등 곡률, 손 위치로 바벨 궤적, 변동 통계로 고정된 이탈 방향을 단정하지 않음. 바닥 전용 피드백은 기존 검토된 설명 유지. |
| 변화 비교 | 같은 반복 지점끼리 비교하고 교대 동작은 좌우 기준을 별도로 보관. 초반 기준은 정자세의 정답이 아니며 자동으로 모집단 임계값을 바꾸지 않음. |
| 음성 | 현재 관측이 유지될 때 안내. 바쁜 음성 채널에는 숫자를 쌓지 않고 짧은 소리로 계수 피드백. 실제 발화할 수 없을 때 규칙 쿨다운을 소비하지 않음. |
| 표시/기록 | 관측 반복·가동범위 참고 기준 충족·미달·미확인을 분리. 미확인 수는 결과 화면, 운동 기록, JSONL까지 보존. |
| 가림·전환 | 측정 누락, 긴 간격, 일시정지, 카메라/회전 변경에서 미완성 사이클을 끊음. 전환 전에 추론을 시작한 프레임은 세대 번호로 폐기. |

종목별 숫자의 의미는 화면의 `1회 기준` 문구를 따른다. 예를 들어 덤벨 컬은 팔마다 1회이고, 바벨 컬은 양팔을 함께 굽히는 동작을 1회로 센다. 이는 사람에 따라 자동 변경되는 기준이 아니다.

## 방향과 정오 판정의 구분

새 `knee_track_L/R`는 발 기준 위치 **관측값**이다. 기존 `knee_out_mean`은 골반–발목 선에 대한 위치라 정의가 다르다. 기존 임계값을 새 피처로 옮기지 않았다.

- 새 안내 예: `참고: 오른쪽 무릎이 발끝을 따라 그은 선보다 바깥쪽에 보여요. 무릎과 발끝의 진행 방향을 확인해 주세요.`
- 양측이 서로 다른 방향이면 각각 참고로 표시. 좌우 평균으로 상쇄하지 않음. 새 방향 관측은 beta이므로 음성 교정에는 사용하지 않음(§60에서 발화 연결 제거).
- 표시 컷 0.15, 지속 220ms/3표본, 무릎 굽힘 조건과 발축 관측 조건은 잡음 억제용 초기값이다. 검증된 해부학적 정상/비정상 경계가 아니다.
- 기존 무릎 규칙의 평균값만으로 `안쪽이니 벌리세요`라고 지시하지 않음. 발 기준 방향이 없으면 측방 위치의 참고 범위 이탈까지만 설명.
- 발 압력·실제 지면 접촉·안구 시선·척추 내부 곡률은 새 엔진에서도 직접 측정하지 않음. 스쿼트 뒤꿈치의 기존 기준선 필수 유보도 유지.

관측 반복은 정자세 인증이 아니다. 가동범위 판정도 해당 피처의 참고 기준에 대한 결과다. 특히 한 팔/한 다리로 바꾼 계수에 양측 평균으로 학습한 ROM 임계값을 적용하지 않는다. 덤벨 컬·스탠딩 니업과 측방 무릎 위치를 사용하던 전방 런지 등의 ROM은 근거가 맞지 않으면 미확인으로 남긴다.

## 코드 경로

- `MotionContracts.kt`: 26종목 계수 지점, 좌우 정책, 주/보조 신호, 화면 기준 문구.
- `MotionRepCounter.kt`: 저지연 인과 필터, 단측 단계, 양측 사건 결합, 바닥 가시 측 선택.
- `MotionObservation.kt`: 카메라 시간 매핑, 통계 표본 주기, 무릎 방향, 측정에 맞는 설명, 상태/음성 정책, 유한 크기 추적 로그.
- `SideMotionComparison.kt`: 교대 종목의 측별 관측 기준.
- `PostureLive.kt`: 고속 계수와 최소 300ms 간격의 기존 통계 경로 연결. 카운트 UI·음성·관절 강조·세트 마감.
- `MotionReplay.kt`, `export_motion_replay.py`: 앱과 같은 Kotlin 카운터를 재생하는 입력 경로.

기존 연구용 `RepCounter`와 그 재생 테스트는 유지한다. 새 세션만 `MotionRepCounter`를 사용한다. 새 관측 피처를 추가했지만 기존 AIHub 규칙 JSON·MediaPipe 모델·모집단 임계값을 개인 로그에 맞춰 변경하지 않았다.

## 시간과 로그

카메라 `ImageInfo.timestamp`의 단조 증가 시각으로 반복 간격을 계산한다. 벽시계는 로그의 기준 epoch에만 사용하며 추론 스케줄은 `elapsedRealtime`을 사용한다. 중복/역순 영상 프레임으로 반복을 만들지 않는다.

세트 로그 `/1`에 호환 필드를 추가했다.

```text
reps.count       전체 관측 반복
reps.invalid     가동범위 참고 기준 미달
reps.unknown     가동범위 미확인
reps.side        반복별 LEFT/RIGHT/BOTH/NONE
motion.version   motion-1
motion.frames    고속 입력 시각, 단계, 필요한 피처/가시성, 완료 수, 관측 코드, 추론시간
motion.dropped   6,000프레임 상한 이후 생략한 프레임 수
```

`motion.frames`의 피처는 Float 왕복이 가능하게 저장하며 영상 파일을 추가로 저장하지 않는다. 기존 일반 프레임에는 실제 표본 시각을 유지한다. 짧은 1회 세트도 기록하지만 자세 규칙의 최소 프레임 수를 낮추지는 않는다. 단계 전환 시각은 관측 시각이며 화면 표시 완료 시각과 같다고 가정하지 않는다.

재생 절차:

```powershell
python research/aihub_fitness/export_motion_replay.py sets.jsonl --out app/build/reports/motion.tsv
$env:TREX_MOTION_REPLAY=(Resolve-Path app/build/reports/motion.tsv).Path
.\gradlew.bat :app:testDebugUnitTest --tests "*.MotionReplayTest" --rerun-tasks
Remove-Item Env:TREX_MOTION_REPLAY
```

이 재생은 입력→계수 시점의 일치를 확인한다. 영상의 관절 추정 정확도나 ROM의 정답률을 검증하지 않는다. 구형 300ms 로그에는 새 측별 피처/중간 프레임이 없으므로 임의 복원하지 않는다. 상한으로 잘린 로그, 반복 입력이 없는 유지 운동, 다른 엔진 버전도 전체 반복 재생의 근거로 쓰지 않는다.

## 검증과 남은 범위

최종 검사: `:app:testDebugUnitTest :app:assembleDebug` 성공. JVM **300건 통과, 1건 건너뜀**(새 실기기 재생 입력 미제공). JSON 직렬화 산출물을 Python JSON 파서/TSV 내보내기로 확인했고 `git diff --check`도 통과했다. ADB 연결 기기가 없어 폰 설치·촬영 검사는 하지 않았다. APK는 `app/build/outputs/apk/debug/app-debug.apk`다.

JVM 회귀시험은 빠른 600ms 반복, 마지막 복귀, 얕은/깊은 구간 분리, 끝점 정지, 단일 신호 잡음, 가림/재시작, 런지 중복, 한쪽 사이드 크런치 중 반대쪽 오계수, 바닥 가시 측 선택, 카메라 좌표 변환·반전, 바깥으로 돌린 발을 따르는 무릎, 측별 비교, 로그 재생을 다룬다. 26종목의 실제 피처 계산 가능성과 선언한 계수 경로도 확인한다.

**이 검사는 실제 사람의 26종목 정확도나 300ms 이내 화면/음성 지연을 인증하지 않는다.** 새 촬영 데이터가 없으므로 실기기 재생 시험 하나는 입력이 제공될 때 실행하도록 두었다. FULL 모델을 80ms마다 요청하더라도 휴대폰이 그 속도를 처리한다고 보장할 수 없다.

남은 연구/검증:

1. 서로 다른 사용자·체형·속도·거치·가림·신발 조건의 반복/단계/측별 방향 라벨로 오계수·누락·방향 오지시·관측 불가율과 지연 측정.
2. 모든 임의 행동을 식별하는 학습된 행동 문맥 모델. 현재 명시적 전이기는 걷기·물 마시기·기구 조절 등을 의미적으로 분류하지 않음.
3. 종목별 오류 후보의 실제 라벨·관측 가능성 검증과 방향별 판정 경계. AIHub가 라벨링하지 않은 모든 변형을 정오 판정으로 확대하지 않음.
4. 같은 단계에서 지속적으로 악화되는 패턴 검증. 단순 초반/후반 차이만으로 피로 원인을 확정하지 않음.

사용자가 제공한 반복 수는 검증용 라벨로만 사용한다. 이 구현은 특정 개인에게 맞춘 모델/임계값 변경을 포함하지 않는다.
