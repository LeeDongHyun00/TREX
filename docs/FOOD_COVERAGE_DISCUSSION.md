# 음식 인식 커버리지 — 다음 방향 논의

작성 2026-09-21, **2026-09-23 정정**. 결정 전 단계의 논의 문서다. 결론이 나면 `FOOD_RECOGNITION.md` 에 반영하고 이 문서는 지운다.

## 정정 — 이 문서의 이전 판은 틀렸다

이전 판은 "현재 구조는 한 사진에서 음식 하나만 잡는다"고 적고 그걸 C안(NMS 도입)의 근거로 삼았다. **코드와 맞지 않는다.** Astra(ChatGPT) 리뷰로 드러났고 `FoodDetector.kt` 에서 확인했다:

- `runInference` 는 임계값 0.40 이상인 **모든 클래스**를 돌려준다(`FoodDetector.kt` 의 `detected` 맵).
- `detect` 는 그것을 합쳐 `MAX_FOODS_PER_ANALYSIS = 5` 까지 넘긴다.

즉 **밥과 국이 둘 다 학습돼 있고 점수가 충분하면 지금도 둘 다 나온다.** "NMS 를 넣어야 여러 음식이 나온다"는 서술은 잘못이었다.

실측 사진(회덮밥+국)에서 `미소된장국 86%` 하나만 나온 진짜 이유:
- **밥**: `01` 묶음을 안 받아 클래스 자체가 없었다 → 2026-09-21 에 받아 342종에 포함됨.
- **회**: `12_13_14_15_16` 묶음(14=회)을 2026-09-23 받았다 → `광어회`·`생선물회`·`육회` 등이 400종에 들어왔다. 다만 **탑재된 모델은 아직 342종**이라 재학습 전에는 못 잡는다.

둘 다 커버리지 문제이고 후처리 구조와 무관하다.

## 현재 구조가 실제로 잃는 것

클래스별 최고 점수만 쓰므로 박스 좌표를 버린다. 그래서 못 하는 것은:

- **위치**: 사진의 어디에 있는 음식인지
- **같은 음식의 개수**: 밥 두 그릇을 2인분으로 세는 것(지금은 사용자가 수량 스테퍼로 맞춘다)
- **공간적 중복 판정**: 같은 영역에서 나온 서로 다른 이름이 실제로 한 음식인지

NMS 는 겹친 검출을 정리하는 처리이지, **없는 클래스나 임계값 미달 점수를 복구하지 않는다.**

## 지금 상태 (사실만)

- 온디바이스 YOLOv8n INT8 3.77MB, **342클래스**(2026-09-23 탑재). 68,176장 학습, 클래스당 최소 155·중앙값 199·최대 239.
- `foodDatabase` 350종 = 실측 342 + 일반 식품 8. 라벨 ⊆ DB 를 `FoodLabelDatabaseTest` 가 확인한다.
- 임계값 0.40, 상위 5종까지 반환. 추론마다 상위 5개 점수를 `FoodDetector` D 로그에 남긴다.
- **2026-09-23 수신 완료**: `12_13_14_15_16`(김치·젓갈·회·떡·한과 58클래스). `dataset.tar` 5.12GB **400클래스** train 67,925 / val 12,006. 학습은 아직 안 돌렸다.

## 방향과 우선순위 (Astra 의견 반영)

| 순서 | 방향 | 판단 |
|---|---|---|
| 1 | **342종 실사용 평가** | 밥 누락이라는 확인된 문제를 해결했으니 실제로 나아졌는지부터 잰다. 아래 평가 절차. |
| 2 | 남은 58종(회·김치 등) 추가 | 클래스 수보다 **자주 먹는 음식의 성공률**이 중요하다. 1의 결과를 보고 정한다. 회는 실측 사진에서 이미 걸렸다. |
| 3 | 박스 단위 처리(구 C안) | 작은 실험 후 결정. 위치·개수·중복 정리에 쓸모가 있지만 **다중 인식의 필수 조건은 아니다.** |

### 3 을 하기 전에 정해야 할 것

**완성 메뉴를 기록하는가, 구성 재료를 기록하는가.** 회덮밥을 인식하면서 회·밥을 각각 더하면 영양값이 이중 계산된다. 현재 설계(모델 클래스 = 완성 메뉴, 영양DB도 메뉴 1인분 기준)에는 **완성 메뉴 기준**이 자연스럽다. 박스 단위로 가면 이 경계가 흐려지므로 먼저 합의할 것.

## (참고) 원래 계획했던 평가 절차

같은 실제 식사 사진 20~30장으로 **214종 모델과 342종 모델을 비교**한다.

- 구성: 단일 음식 / 밥+국+반찬 한 상 / 혼합 메뉴(덮밥류) / 지원하지 않는 음식.
- 사진마다 **기대하는 기록 항목을 사람이 먼저 지정**한다.
- 재는 것: 빠뜨린 음식, 잘못 추가한 음식, **사용자가 수정해야 하는 횟수**.
- `FoodDetector` 상위 5개 점수 로그로 **클래스 누락**과 **임계값 미달**을 구분한다 — 이 구분이 다음 행동(데이터 추가 vs 임계값 조정)을 가른다.
- confusion matrix(`runs/food/confusion_matrix.png`)는 보조 지표다. 한 상 사진에서 실제로 몇 번 고쳐야 하는지를 같이 봐야 한다.

"후처리만 바꾸면 된다"는 **구현 가능성**이지 **쓸 만한 성능 확보**가 아니다. 문서에 이 둘을 구분해 쓴다.
