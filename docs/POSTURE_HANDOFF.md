## 3. 구현된 것

### §30 — 세트/세션 자세 리포트 + 자가 라벨 (`7297c44`)

**문제**: 실시간 음성은 흘러가고 세트가 끝나면 남는 게 없었다. 전반→후반 요약은 개발용 랩 화면에만 있었고, 기록 화면의 정확도 %·"자세 지적"은 하드코딩 목업이었다. 실측 세션을 돌려도 사용자가 다시 볼 결과가 없으니 §9 재보정에 필요한 라벨도 모이지 않았다.

**신규**

- `posture/PostureSetReport.kt` — 세트 전체 집계 판정(`evaluate`)과 초반/후반 창 onset(`summarize`)을 `rule.id` 로 조인해 규칙별 `RuleOutcome` 으로 만든다.
  - 랭킹 5단계: `0` 전체위반+onset → `1` DRIFT → `2` HABIT → `3` 창에서 안 잡힌 전체위반 → `4` RECOVERED → `9` 후보 아님. 동률은 ship 우선 → `cvAuc`.
  - `verdict`: `UNJUDGED`(판정 0건) / `ISSUE` / `RECOVERED` / `REFERENCE`(beta 만) / `CLEAN`
  - `accuracy = round(100 · shipOk / shipJudged)` — **분모는 ship 판정 수**. TRACK 은 항상 null.
- `posture/PostureSetLabel.kt` — `SetSelfLabel`, `SetLabelStore`
  - `labels/set_labels.jsonl` 에 항상 한 줄, `rep_truth.csv` 에는 횟수가 있을 때만.
  - 라벨을 **하위 폴더**에 두는 이유: `SetLogStore.files()/clear()` 가 확장자만 본다(`endsWith(".jsonl")`). 같은 폴더면 랩의 "지우기"가 라벨을 지운다. (`pull_logs.py` 는 이 커밋에서 `sets-` 접두사로 좁혀서 이미 구분한다.)
  - `rep_truth.csv` 헤더는 **7열** `set_id,reps_min,reps_max,exercise,form,source,created_at` — 앞 3열이 `rep_replay.py` 호환이고 뒤 4열은 부가다. 파서를 3열로 짜면 나머지를 잃는다.
  - 렙은 스테퍼로 **고쳤거나**(`edited`) "이 숫자 맞아요"로 **확인했을 때만**(`confirmed`) 정답으로 넘긴다. 폼만 고른 저장이 앱 카운트를 정답으로 흘려 넣으면 재생 검증이 자기 답을 채점하게 된다.

**흐름**

```
PostureLive 의 세트 마감 람다  finalizeRef[0](exercise, workoutName, isFloor)
  ← ✓/✕ 핸들러에서 먼저 호출(멱등), onDispose 는 안전망
  ← 인자는 반드시 **세트 시작 시점 값**: 이 화면은 종목이 바뀌어도 재컴포지션되지 않는다
      ↓ onSetReport
AppViewModel.sessionPostureReports (workoutId → report)
      ↓ 마지막 운동의 nextSession()
recordCompletedSession() → createWorkoutHistoryDay(plan, elapsed, reports)
      ↓
WorkoutHistoryItem.postureCorrection → 기록 화면
```

`onDispose` 만으로는 안 되는 이유: 마지막 운동에서 `nextSession()` → `recordCompletedSession()` → 라우트 변경 → **그 뒤에** onDispose 라, 기록이 이미 저장된 뒤에 리포트가 도착한다.

**부수**: `SpeechCoach` 를 라이브 화면이 아니라 **세션 스코프**(`TrexApp` 소유)로 올렸다. 화면이 소유하면 자세→타이머 전환마다 `shutdown()` 이 세트 요약을 끊는다 — 기본 플랜에서는 매번. 시드 목업 자세 데이터 제거, 구버전 저장 기록의 목업도 로드 시 폐기.

### §31 — 코칭 신뢰성 (`f7be706`)

다섯 가지가 전부 "모르는 것을 아는 것처럼 말한다"는 한 병의 변형이다.

| # | 문제 | 조치 |
|---|---|---|
| 1 | **초반 창 = 준비 동작.** 그게 "정상 기준"이 되면 첫 코칭이 "처음부터 …" 오탐 | `LiveCoach(requireAnchor = true)`. `anchor()` 전에는 프레임을 버리고 판정도 발화도 없다. 첫 렙 완료에 앵커, 폴백은 **첫 측정 가능 프레임으로부터** 렙 신호 없는 종목 4초 / 있는 종목 10초 |
| 2 | **beta 가 ship 과 같은 확신으로 말함.** §28 오탐 3건이 전부 beta·미보정 | `LiveCoach(speakBeta = false)`. **발화 후보에서만** 빠진다 — 판정·`lastStates`·`summarize`·리포트는 그대로. 화면은 붉은색 대신 **호박색**(`0xFFFFC24B`) + "참고 · … 아직 검증 중인 항목이에요" |
| 3 | **못 보는 것을 안 밝힘.** 바벨 데드리프트는 '척추의 중립'이 전부 exclude 라 허리를 말아도 "깨끗" | `PostureScope.of(ruleSet, exercise)` — 조건을 등급별로 묶어 **부위명**으로 압축. 시작 안내 셋째 문장 / 카드 부제 / 카드 "무엇을 보나요?" 3줄 |
| 4 | **음성이 조용히 죽음.** TTS 초기화가 비동기라 시작 안내가 통째로 버려짐 | 준비 전 **대기 큐**(3건·10초 TTL), 오디오 포커스 `TRANSIENT_MAY_DUCK`, `unavailableReason` 패널 표시, 렙 숫자는 TTS 불가 시 짧은 톤 |
| 5 | **권한 거부가 운동을 삼킴.** "타이머로 계속"이 `onNext` 를 불러 그 운동을 **완료 처리하고 건너뛰었다** | `onFallbackToTimer` — 같은 운동을 `TimerSession` 라우트로 다시 연다. ✕ 종료도 완료한 운동이 있으면 "여기까지 기록하고 끝내기"를 묻는다 |

**부수**: 무효 렙 사유 발화는 세트당 **2회 상한** + `romValidated == false` 종목은 침묵. 배너는 앵커 전 "보고 있어요"로 — 판정하기 전에 칭찬하지 않는다.

**API 기본값 주의**: `requireAnchor`(기본 `false`)와 `speakBeta`(기본 `true`)는 **서로 독립**이고 기본값이 종전 동작이다. 랩 화면은 beta 를 일부러 듣는 자리라 그대로 두고, `PostureLive` 만 `requireAnchor = true, speakBeta = false` 로 명시한다. 기본값을 뒤집으면 `PostureCoachTest` 5건 + `FloorCoachHonestyTest` 3건이 깨진다(그 테스트들은 **문구의 방향성**을 검증하는 것이지 beta 발화 정책을 검증하는 게 아니다).

**침묵하는 종목**: 바닥 8종목(14규칙 전부 beta)은 이 변경으로 자세 음성이 사라진다. 서서 종목 중에도 ship 이 0인 것이 있다(바벨 로우, 풀업 — 다만 현재 `postureExerciseMap` 에 없어 앱에 노출되지 않는다). `PostureScope.provisionalOnly` 종목은 시작 안내가 "검증 중이라 지적 없이 횟수와 촬영 상태만"이라고 먼저 밝힌다. **실기기 체감 확인이 아직 안 됐다.**

### §31a — 세트 점수도 앵커 (`5320a31` + 후속 수정)

§4 의 실기기 분석에서 나온 수정. §31 의 앵커가 `LiveCoach` 에만 걸려 있었고 **세트 점수를 내는 `aggregator` 는 첫 프레임부터 계속 누적**하고 있었다.

- 앵커가 잡히는 순간 `aggregator.reset()`. 프레임 기록은 전부 남긴다.
- `SetLog.anchorTMs` → 로그의 `anchor_t_ms`.
  ⚠️ 이 때문에 **로그의 `results` 와 `frames` 는 서로 다른 창을 본다.** 오프라인 재계산에서 `results` 를 그대로 믿으면 안 되고, `anchor_t_ms` 이후 프레임으로 다시 계산해야 한다. 이 필드가 없는 구버전 로그는 전체 창 기준이다.
- 라이브 점수를 리포트와 같은 **ship 전용 분모**로 통일.
- **"67%" → "2/3" 분수 표기.** ship 규칙이 종목당 **0~3개**뿐이라(앱 지원 18종목 중 4종목은 ship 1개 → 한 건 위반이 곧 `0/1`) 퍼센트가 의미를 숨긴다.
  ⚠️ **기록 화면은 아직 %·92% 문턱 그대로다**(`RecordScreen.kt`). 분수 표기는 라이브 패널과 세트 리포트에만 적용됐다.
- 종목 전환 시 이전 운동 점수가 남던 버그 수정.

**후속 수정 (검증에서 발견)**: 앵커 폴백의 기준 시점이 잘못돼 있었다. `PoseSample.detected` 는 **가시 관절 수와 무관하게 항상 true** 라(관절 11개짜리 프레임도 detected), 검출 기준으로 세면 사람이 아직 프레임에 제대로 없는 동안 폴백이 다 흘러간다. 실측에서 앵커가 10.0초에 걸려 43.8초의 준비 동작이 그대로 집계에 들어갔다 — **즉 최초의 §31a 수정만으로는 이 세션이 고쳐지지 않았다.** 기준 시점을 `features.isNotEmpty()` 인 첫 프레임으로 바꿔서 해결했다.

### 5.1 진입 경로 (기준선 · 모드 선택)

**배경 데이터** (재조사 전에 읽을 것)

## 7. 이 세션에서 내린 판단 (재현하기 어려운 것)

- **베타 규칙의 화면 처리**: 음성은 침묵시키되 화면에서는 **지우지 않고 호박색으로 남겼다**. 완전히 지우면 바닥 종목 8개의 라이브가 렙 숫자만 남아 죽고, 붉은색으로 두면 말하지 않기로 한 판정이 화면에서는 확신처럼 보인다. 음성은 사용자가 즉시 몸을 바꾸는 채널이라 더 보수적으로, 화면은 세트 사이에 읽는 것이라 라벨을 붙여 남기는 쪽을 택했다.
- **점수를 분수로**: 퍼센트는 성적으로 읽힌다. ship 규칙이 0~3개인 상황에서 67%는 "3가지 중 2가지"라는 뜻인데 퍼센트가 그 사실을 숨긴다.
- **`feature/posture-correction` 을 fast-forward 하지 않았다**: §31 작업을 별도 브랜치로 분리한 의미를 유지하기 위해.
- **기준선을 모두에게 권하지 않기로**: cross-day 감쇠와 초보의 습관 오류 고착 위험이 이득보다 크다고 봤다.
- **"지난 기록만큼 했어요 + 몸짓으로 더 하기" 기능은 보류를 권고했다**: 렙 카운터가 12개 중 9개를 세고 마지막 렙을 구조적으로 놓치는 상태에서 카운트를 의사결정 근거로 승격시키면 그 오차를 사용자에게 약속하게 된다. 또 COACH = 정의상 초보인데 초보가 렙 기록을 갱신하려 밀어붙이는 것은 전형적 부상 경로다. 만든다면 방향을 뒤집어 **"멈출 때를 아는 기능"**(폼이 깨끗할 때만 제안, DRIFT 감지 시 종료 권고)으로 가야 한다.
