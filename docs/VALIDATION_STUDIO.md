# TREX 검증 스튜디오 — 설계와 사용 계약

## 목적과 범위

같은 실제 운동 영상을 보존하고, 엔진의 예측을 보지 않은 사람이 정답을 표시한 뒤 동일 좌표를 여러 엔진에 재생한다. 26종의 수집·라벨·반복/항목별 평가·내보내기를 Android 앱 안에서 수행한다. 이 도구 자체가 자세 정확도 또는 교정 효과를 인증하지 않는다.

데이터 흐름: 촬영/영상 선택 → 앱 전용 원본 복사와 SHA-256 → 실제 디코더 PTS로 5Hz 표본 선택 → MediaPipe VIDEO 추론 → 좌표 보존 → 독립 라벨 확정 → 동일 입력 재생 → 보고서와 ZIP.

## 결정과 이유

- 촬영은 기기의 카메라 앱에 위임한다. 영상은 그대로 복사하며, 분석은 녹화 종료 뒤 수행한다. 녹화/추론 동시 부하와 라이브 프레임 누락을 비교에서 분리한다. 이 결과를 실시간 지연·TTS 효과 평가로 해석하지 않는다.
- 시간 정본은 MediaCodec 출력 `presentationTimeUs`다. 첫 영상 프레임 PTS를 원점으로 정규화하며 원래 PTS도 저장한다. 고정 FPS로 시간을 생성하거나 가까운 키프레임에 요청 시각을 붙이지 않는다. 촬영 실행/영상 준비 완료 UTC는 범위 정보일 뿐 개별 프레임의 정확한 UTC가 아니다. 가져온 영상의 촬영 UTC는 미상이다.
- 원본 영상은 모델 교체 후 재추론용, 좌표는 판단 엔진만 비교하는 용도다. 모델 좌표는 인체 정답이 아니다. CPU VIDEO 추론을 고정하며 모델 해시·좌표 추출 설정·소스 지문·규칙 해시를 기록한다.
- 검증 APK는 `-PvalidationStudio`로 별도 패키지/이름을 사용한다. 기존 trex_v2 기록을 변경하지 않는다.
- 원본·추론 실행·라벨 개정·평가 실행은 별도 파일이다. 재실행은 새 ID를 만들며 실패한 실행을 성공으로 읽지 않는다. 자동 만료 삭제를 하지 않는다. 동영상과 좌표의 로컬 저장 동의를 받고 내보내기는 사용자가 파일 위치를 선택한다.
- 정답은 수행자 코드·촬영일·평가자·평가 구간·반복 완료 구간/좌우·항목별 정상/오류/판단 불가 구간으로 구성한다. 0회도 검토 확정이 있어야 정답이다. 서로 충돌하는 동일 항목의 겹친 구간은 거부한다. 미라벨·판단 불가는 정상으로 보충하지 않는다.
- 첫 정답 확정 전에는 엔진 예측을 숨긴다. 예측 열람 이후의 정답 수정은 `prediction_exposed=true`로 기록해 맹검 최종 시험과 구별한다. 수행자 단위 train/calibration/test 구분을 고정하고 같은 수행자의 분할 충돌을 거부한다.
- 반복 완료 시각은 기본 ±500ms 안에서 순서를 보존하는 일대일 최적 매칭을 한다. 누락·추가·일치 시각 오차를 각각 표시한다. 500ms는 초기 채점 설정이며 서비스 정확도 보장값이 아니다. 좌우 판정은 별도이며 구형 공통 횟수를 좌우 정확도로 승격하지 않는다.
- 자세는 사람이 라벨한 시간만 평가한다. 예측의 지속은 다음 표본 또는 250ms까지 제한한다. 유보·미지원·누락은 coverage와 missed error 시간으로 남기며 정상 분모에 넣지 않는다. 정상 시간의 잘못된 경고 비율, 오류 시간의 검출률, 판정 시간 비율을 함께 표시한다.

## 비교 대상의 정체

구형 반복 코어는 `v1.1.0-preview.2` 커밋 `3322628a2c58ab3d02266d6e9e824ffb12bfd616`의 RepCounter/ReturnRepTracker를 별도 네임스페이스에 보존한다. v2는 제품과 같은 `PoseEvaluationEngine`과 `V2FormFeedback`을 호출한다. 구형 반복 코어 비교는 기존 APK의 카메라·IMU·화면 전체 재현이 아니다. 자세 비교 기준선은 현행 규칙 평가기의 ship/window 결과이며 구형 APK의 음성 정책을 재현한다고 표현하지 않는다.

## 데이터 묶음

`session.json`, `video.mp4`, `extractions/<id>/frames.jsonl`, `extractions/<id>/manifest.json`, `labels/<revision>.json`, `runs/<id>/predictions.jsonl`, `runs/<id>/report.json`. ZIP은 파일별 SHA-256 목록을 포함한다. 프레임에는 PTS·영상 상대 시각·검출 여부·좌표·visibility·원래 추론 visibility/presence·피처·추론 소요 시간이 들어간다. 저장 실패·지원하지 않는 디코더·용량 부족은 명시적으로 실패하며 원본을 유지한다.

## 검증 및 남는 범위

JVM에서 정답 유효성·일대일 매칭·무정답·유보·미지원·가림·시간 제한을 검사한다. Android 계측에서 합성 MP4의 가변 PTS 디코딩, 저장/수정/내보내기, 실제 모델과 두 엔진의 재생을 검사한다. 합성 영상은 수집 체계 검증이며 사람의 운동 정확도 증거가 아니다.

이 단계에 실제 음성 교정은 실행하지 않는다. 영상 수집 중 행동을 바꾸지 않는 기준 자료를 먼저 확보한다. 교정 전달→후속 동작 효과는 별도 실시간 연구 경로가 필요하다. 대규모 통계·수행자 부트스트랩 신뢰구간·전문가 간 합의는 내보낸 데이터로 후속 수행한다.

## 설치와 실제 사용

```powershell
.\gradlew.bat :pose-engine:test :app:testDebugUnitTest :app:assembleDebug -PvalidationStudio
```

결과: `app/build/outputs/apk/debug/app-debug.apk`. 전달용 복사본은 `build/validation-release/TREX-validation-1.0.0-preview.apk`. 이름은 **TREX 검증**, 패키지는 `com.example.trex_kotlin.validation`, Android 8.0 이상 ARM64/ARMv7 기기를 지원한다. 기존 TREX와 trex_v2를 삭제하지 않고 함께 설치한다. MediaPipe 0.10.14에는 x86_64 JNI가 없어 검증 APK의 ABI를 명시적으로 제한했다.

1. 첫 화면에서 익명 수행자 코드, 실제 촬영일, 학습/보정/최종 시험 분할을 선택한다. 같은 수행자는 날짜가 달라도 같은 분할이다. 첫 시범 촬영은 보정 자료로 두고 수집 경로부터 확인한다.
2. 26종 중 종목, 좌우 수행 방식, 사용자 기준 촬영 방향을 지정한다. 바닥은 측면을 직접 확인한다. 데드리프트는 바닥 출발 여부를 선택한다. 촬영 대상의 동의를 확인한 뒤 **운동 촬영** 또는 **영상 가져오기**를 누른다. 1회 영상은 10분/가져오기 2GB 이내다. 짧은 세트별 영상이 오류 원인을 찾기 쉽다.
3. 카메라 앱에서 영상 녹화를 마치고 저장/확인하면 원본이 연결된다. 취소·앱 재시작 뒤 파일만 남았으면 영상 상세의 **저장된 영상 확인·복구**를 누른다. 가져온 영상은 원래 파일을 수정하지 않고 앱으로 복사한다.
4. **관절 좌표 추출**은 녹화 후 실제 PTS의 5Hz 수준 표본으로 실행한다. CPU 분석 중에는 앱을 전면에 두는 것을 권장한다. 실패/중단된 실행은 입력으로 쓰지 않으며 원본을 사용해 새 실행으로 재추출한다.
5. **영상 보며 정답 표시**에서 평가자 코드와 평가 시작/끝을 입력한다. 재생/정지·슬라이더·±0.2초 탐색으로 확인하고 현재 위치를 시작/끝으로 넣거나 ms를 직접 수정한다. 반복마다 출발→복귀 구간/좌우를 추가하고 전체 검토를 체크한다. 플랭크는 동작 유지 구간을 별도로 추가한다. 자세 항목에는 정상/오류/판단 불가, 단계, 좌우, 근거를 기록한다. 미지원 항목도 이름을 직접 지정해 기록할 수 있다.
6. **정답 개정 저장** 전의 입력은 초안이다. 정답은 자동 횟수를 복사하지 않는다. 기존 행은 삭제 후 다시 추가하여 수정하고 새 개정으로 확정한다. 0회도 검토 체크가 필요하다. 자세 정답이 없는 종목에서 자동 정확도를 만들어 표시하지 않는다.
7. **같은 좌표로 엔진 비교** 후 **비교 결과 열기**를 누른다. 반복 누락/추가/시각 오차, 플랭크 유지 누락/추가 시간, 항목별 오탐·검출·판정 범위를 본다. 이 과정은 음성 재생을 하지 않는다. 정답 수정 후에는 재평가 알림이 나타난다.
8. **영상·좌표·정답·결과 ZIP 저장**으로 Android 파일 선택기에서 원하는 위치에 보존한다. `checksums.json`을 포함해 원본과 개정을 모두 내보낸다. 기기에서 지울 때에는 상세 화면의 자료 삭제를 사용하며 별도로 내보낸 ZIP은 지우지 않는다.

### 해석 제한

- 5Hz 표본은 영상 프레임 전체가 아니다. 빠른 움직임의 미세한 구간/좌표가 필요하면 원본을 다른 추출 설정으로 다시 처리해야 한다. 현재 앱의 추출 설정은 고정되어 있다.
- CPU 추론 시간은 저장하지만 이 수치를 라이브 카메라→음성 지연으로 해석하지 않는다. 촬영 실행/영상 준비 UTC는 프레임 절대 UTC가 아니다.
- 사람 라벨의 전문성·관찰자 간 합의는 도구가 보장하지 않는다. 모델 추정 좌표를 사람 정답으로 자동 승인하지 않는다.
- 기준선은 실제 구형 APK 전체가 아니다. 원본 영상 보존 덕분에 추후 별도 APK/모델의 전체 처리 비교 입력으로 재사용할 수 있다.

실제 시각의 근거는 [MediaCodec 출력 PTS](https://developer.android.com/reference/android/media/MediaCodec.BufferInfo#presentationTimeUs)와 [디코딩 이미지 API](https://developer.android.com/reference/android/media/MediaCodec#getOutputImage(int))를 따른다.

## 이번 빌드의 검증 결과 (2026-09-23)

- JVM **514건 통과**: 공유 엔진 95건 + 앱 419건(이번 채점 계약 검사 23건 포함), 실패 0건.
- Android **5건 통과**: Android 36.1 에뮬레이터의 ARM64 호환 실행. 가변 PTS 합성 MP4의 정확한 시각, 취소, 수행자 분할 충돌, 실제 MediaPipe→좌표→라벨→재생/재실행 동일성→ZIP/해시 변조 거부, 화면의 독립 정답 확정→분석→비교 결과 공개를 확인했다.
- 초기 에뮬레이터 설치는 기존 디스크 용량으로 실패했다. 기존 자료를 삭제하지 않고 작업 전용 데이터 디스크로 검사했다. 초기 x86_64 실행은 MediaPipe JNI 부재로 실패해 APK를 ARM64/ARMv7로 제한하고 재검사했다. UI 검사는 파일 기록 완료와 화면 갱신 완료를 별도로 기다리도록 수정한 뒤 통과했다.
- Android 디버그 서명 검증, 패키지/버전/최소 SDK/ABI, 미추적 `exercise_gifs` 미포함을 검사했다. 전달 파일/해시/상세 이력은 `build/validation-release/BUILD_INFO.json`, `SHA256SUMS.txt`, `android-tests.txt`에 기록한다.
- 연결된 물리 휴대폰이 없어 설치하지 않았다. 실제 카메라 앱에서 사람을 촬영한 정확도·휴대폰 디코더 호환성·장시간 분석/발열은 아직 확인하지 않았다. 처음에는 짧은 영상으로 촬영 저장·정답 시각·내보내기를 확인한 뒤 본 촬영을 진행한다.
