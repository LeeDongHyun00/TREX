| 표기 | 뜻 |

화면 문장 규칙은 CAwiki 를 따른다: 단계 제목은 **'~다'로 끝나는 2~4어절 동사구**(CAwiki 「메모리를 깨우다」 같은 결), 문장(`copy`)은 **'~ㅂ니다' 한 문장** — 주어와 보이는 변화를 말한다, 설명(`detail`)은 **두세 문장 — 쉬운 뜻 먼저, 용어는 나중, 끝은 오해를 막는 문장**. 사이트 화면 문장에는 **마침표를 찍지 않는다**(CAwiki 규칙). 앱 문구 인용만 원문 그대로 둔다.

## 1. 한 줄 콘셉트

> **종이를 찢고 나온 공룡이, 폰 하나로 먹고 움직이는 하루를 '보이는 만큼만' 정직하게 봐 준다.**

페이지를 다 본 사람이 기억해야 할 세 가지:

1. **먹은 것과 움직인 것을 한 화면에서** — 칼로리·탄단지 목표, 오늘의 루틴, 기록.
2. **카메라가 코치가 된다 — 단, 보이는 것만 판정한다** — 자세 교정·자동 횟수·음성 안내, 그리고 '판정하지 않음'.
3. **영상과 사진은 폰 밖으로 나가지 않는다** — 분석은 기기 안에서, 로그인 없이도 전부.

감정의 순서: **신기하다**(3D·공룡) → **믿을 만하다**(정직) → **써 보고 싶다**(체험판).

차별점은 2번의 뒷부분이다. 운동 앱 소개 페이지는 흔히 "AI 가 자세를 완벽하게 교정"이라고 말한다. TREX 는 **"옆에서 찍으면 판정을 멈춘다"를 직접 해 보게** 한다. 정직함을 각주에 숨기지 않고 체험 장면으로 만든다 — `[S-view]`, `[S-modes]`, `[S-blind]`.

### 1.1 이야기 구조 — 들어온 유리로 나간다

```
1막  앱 화면색 종이를 공룡이 찢고 나온다 → 구멍 안으로 들어가면 'TREX의 집'이 조립된다
2막  집을 따라 하루를 돈다 — 07:30 목표 → 08:00 루틴 → 19:00 운동 → 19:40 근육 → 20:10 저녁 사진 → 23:00 거울
끝장 카메라가 폰 유리 밖으로 빠져나온다 — 집 전체가 폰 화면 안에 있었다
     "영상과 사진은 이 유리 밖으로 나가지 않습니다"
```

- **CAwiki 필름의 끝장과 같은 구조다.** CAwiki 는 「카메라가 모니터 밖으로 빠져나오며 메인보드 장면이 화면 안에 나타남」으로 '하나의 컴퓨터'를 말하고, TREX 는 같은 동작으로 **'이 모든 일이 당신의 폰 안에서 일어난다'는 프라이버시 결론**을 말한다.
- 처음 찢은 종이가 앱 화면 배경색(`#EFF1EA`)인 것이 복선이다 — 공룡은 '앱 화면'을 찢고 나왔고, 마지막에 우리는 그 화면 유리 밖으로 나온다.
- 2막을 '하루'로 묶은 것은 Apple 의 「A Day in the Life of Your Data」(하루 이야기로 데이터의 행방을 보여 주는 문서, §13 #9)와 같은 수법이다. 데이터 입자가 장마다 쌓여 끝장에서 "어디에 남는가"로 모인다.

## 2. 관객과 목표 행동

| 관객 | 궁금한 것 | 페이지가 줄 것 |
|---|---|---|
| 처음 보는 사람(홈트·식단 관리) | 무엇을 해 주는 앱인가 | 필름(약 3분) |
| 의심 많은 사람 | 정말 되나, 내 영상은 어디로 가나 | `[S-view]` 직접 조작, `[S-privacy]`, 데이터 라벨 |
| 체험판 설치 후보 | 설치 방법·요구 사항·위험 | `#get` — 버전·서명·체크섬·기록 보존 주의 |
| 발표·평가 청중 ⚑ | 기술의 깊이 | 장면마다 `원리 자세히 ↗` |

목표 행동: ① 필름을 끝까지 본다 ② 체험 장면을 하나 이상 직접 조작한다 ③ 체험판을 받는다.

## 3. 말투와 정직 규칙 (카피 가드레일)

앱의 판단 원칙(`CLAUDE.md` '이 프로젝트의 판단 원칙')을 소개 페이지의 문장 규칙으로 옮겼다. 어기면 페이지가 앱과 반대로 말하게 된다.

1. **판정하지 않은 것을 판정한 것처럼 말하지 않는다.** 금지: "완벽한", "정확한 자세", "모든 자세를", "100%", "AI 트레이너가 대신". 대신: "보이는 만큼", "판정한 항목은", "검증한 방향에서".
2. **검증 단계를 섞지 않는다.** 음성 시연에는 **ship 검사의 대사만** 쓴다(beta 는 앱에서도 말하지 않는다). beta 는 화면 시연에서 '참고'(호박색)로만 보인다. 상태 낱말은 각주가 아니라 **그 기능을 말하는 문장 안에** 쓴다 — "자동 횟수는 참고 측정입니다"(Apple Watch 페이지가 'beta'·'Coming late 2026'을 본문에 쓰는 방식, §13 #4).
3. **숫자는 빌드 때 저장소에서 뽑는다**(§12). 손으로 적은 숫자는 앱과 어긋난다 — 실제로 `app/src/main/assets/models/README.md` 는 아직 음식 모델을 '30클래스'라고 적지만 탑재본은 342클래스다(`docs/FOOD_RECOGNITION.md`). 페이지 바닥글에 "이 페이지의 사실은 TREX `<커밋>` 기준"을 단다.
4. **의료·생리 주장 금지.** "부상 예방", "근육 피로 측정", "회복 완료", "살이 빠지는" 금지. 근육 부하는 '운동 기록으로 추정한 값'이다 — 앱도 「기록 기반 추정 · 0–100점」이라고 쓴다(`MuscleLoadScreen.kt`). 바닥글에 "TREX 는 건강 관리를 돕는 앱이며 의료용이 아닙니다"(Apple Health 의 'not for medical use' 자리, §13 #10).
5. **공룡 말투(~룡)는 앱 화면 속에만.** 사이트 내레이션은 평서. 마스코트 말풍선은 앱에 실제로 있는 '~룡' 문구만 쓴다(§9).
6. **연출임을 밝힌다.** 장면마다 `원리 자세히` 바닥글에 CAwiki 와 같은 자리의 문장: "이 장면은 앱의 동작을 느리게 펼친 재현입니다 / 실제 화면과 판정 간격·숫자는 다를 수 있습니다". 마네킹 동작·예시 숫자는 실제 사용자의 기록이 아니다.
7. **체험판 상태를 기능마다 밝힌다.** 배지 세 종류: `체험판에 있음` / `다음 체험판` / `준비 중`.
   - 계정 백업·동기화, Google 로그인: **preview.7 에 없음**(main 에 병합 2026-10-14). 공개 전에 개인정보 처리방침·동의 화면이 필요하다(`docs/SERVER_SYNC_HANDOFF.md`) → `준비 중`.
8. **'지켜본다'·'감시'처럼 들리는 말을 쓰지 않는다.** 카메라가 '보는' 대상은 늘 관절 위치다.
9. **"아무것도 남지 않는다"고 말하지 않는다.** 영상과 사진은 저장하지 않지만, 세트마다 **관절 좌표 기록**은 폰에 남는다(§8.8). 남는 것을 함께 말해야 남지 않는 것이 믿긴다(Kemtai 의 "영상은 녹화하지 않고 공간 좌표만 저장한다" 문장 짝, §13 #12).
10. **차분한 말씨.** 감탄사·이모지·"충격/진짜 이유/정체"·배수 주장("2배 정확") 금지(CAwiki `docs/title-naming.md`, §13 #17).

## 4. 비주얼 언어

### 4.1 세계관 — "TREX의 집"

앱 가이드북 일러스트 네 장(`app/src/main/assets/guid_img/*.svg`, `GuideBookScreen.kt`)이 이미 하나의 공간과 이야기를 갖고 있다.

1. 나무 바닥 홈트 공간 — 회색 요가 매트, 삼각대 위 폰, 덤벨, 물병 올린 스툴. 공룡이 폰을 세운다.
2. 땀 흘리며 덤벨 컬.
3. 근육 자랑.
4. 펜던트 조명 아래 주방 식탁에서 스테이크를 찍는 공룡(폰 화면에 '400칼로리').

이 공간을 **벽 두 면을 잘라 낸 3D 디오라마**로 만들어 사이트 전체의 무대로 쓴다. 가구 배치(시계 방향): 현관(우편함) → 냉장고·조리대 → 화이트보드 → 매트·삼각대 → 선반(해부 모형) → 식탁·펜던트 조명 → 전신 거울.

### 4.2 재료감 — 종이와 깊이

앱 아이콘과 로그인 애니메이션은 '찢긴 초록 종이 구멍으로 고개를 내미는 공룡'이다(`res/mipmap-*/ic_launcher_foreground.png`, `res/drawable-nodpi/login_animation_frame_01~16.png` — 95 ms 간격 한 번 재생).

- **2D 요소(공룡·표지)는 종이 오림 입간판**으로 3D 공간에 세운다 — 두께 2~3 mm, 가장자리에 흰 종이 단면. 가이드북 그림을 그대로 오려 쓰므로 공룡 3D 모델을 새로 만들지 않아도 된다 ⚑.
- **3D 요소(폰·마네킹·그릇·가구)는 둥근 모서리의 단순한 형태 + 매트 재질** — CAwiki 처럼 코드로 만드는 절차적 모델(런타임 glTF 없음), PBR 재질, 소프트박스 환경광, 따뜻한 키 라이트 + 차가운 림 라이트, ACES 톤 매핑.

### 4.4 판정 표기 — 채움 · 빈칸 · 빗금

Apple 의 심박 정확도 연구 PDF 는 '차이를 확인함 = 채운 원, 판단 못 함 = 빈 사각, 수집 안 함 = 빗금'으로 그린다(§13 #32). TREX 의 판정 상태와 정확히 겹친다. 색만으로 구분하지 않는다.

| 표기 | 뜻 | 앱의 상태 |
|---|---|---|
| ● 채운 원 + 체크(초록) | 판정함 — 정상 | ship 검사, OK |
| ● 채운 원 + 화살표(빨강) | 판정함 — 위반 | ship 검사, 위반 |
| ○ 빈 원(회색 점선) | 판정 안 함 — 유보 | 가림·프레임 부족·촬영 방향 |
| ◌ 호박 테두리 | 참고 — 검증 중 | beta |
| ▨ 빗금 | 못 봄 — 이 앱이 볼 수 없는 항목 | exclude |

### 4.5 신호 — 모양이 뜻이다

CAwiki 는 신호를 모양으로 가른다(고리 = 명령, 타일 = 데이터, 이미지 조각 = 프레임). TREX 도 같은 문법을 쓰되, **'무엇이 집(폰) 밖으로 나갈 수 있는가'**가 모양에 담긴다. 이 표가 끝장 `[F11]` 과 `[S-privacy]` 의 근거다.

| `kind` | 모양 | 무엇 | 집(폰) 밖으로 |
|---|---|---|---|
| `frame` | 반투명 사각 조각 | 카메라 영상·음식 사진 | **못 나간다**(저장도 안 한다) |
| `point` | 작은 점 33개 묶음 | 관절 점 | TREX 서버로 가지 않는다 |
| `data` | 라임 타일 | 각도·판정·영양 숫자 | 기록이 되기 전에는 나가지 않는다 |
| `voice` | 흰 동심원 | 음성 안내 | 스피커로만 |
| `record` | 종이 카드(봉투) | 운동·식단 기록 | 계정을 연결했을 때만 우편함으로 `준비 중` |

### 4.6 사람 — 얼굴 없는 마네킹 + 관절 33점

실제 인물·특정 체형을 쓰지 않는다(CAwiki 도 사람을 얼굴 없는 픽토그램 하나로 그린다). 회색 캡슐 마네킹 위에 MediaPipe 와 같은 관절 점 33개와 뼈대 선 — 사이트 어디서나 같은 33점 그림을 쓴다(§13 #15). 장면에 따라 마네킹은 반투명해지고 점만 남는다.

### 4.7 글자

CAwiki 와 같은 시스템 글꼴 스택(`"Noto Sans KR", "Apple SD Gothic Neo", sans-serif` — 웹 글꼴·CDN 없음, 앱도 시스템 글꼴). 제목은 굵기 400 + 좁은 자간, 장 이름표는 8~11 px 영문 대문자(`05 —— 07:30 TODAY`), 본문 `keep-all`. 워드마크 `TREX` 만 앱처럼 굵게, 넓은 자간.

### 4.8 움직임 원칙

1. **하나의 스크롤 시계** — 모든 변화가 진행률의 함수라서 위로 올리면 정확히 거꾸로 돈다. 손을 떼면 아무것도 계속 움직이지 않는다(자동 재생 없음 — WCAG 2.2.2 의 '멈춤' 요구가 생기지 않는다).
2. **끊지 않는다** — 전환은 카메라 이동이나 물체의 변형으로 잇는다(CAwiki `docs/visual-continuity.md`). 화면 전체 페이드는 reduced-motion 대체에서만.
3. **머문 뒤 이동한다** — 단계 안에서 약 40 % 는 머물고 그다음 카메라가 움직인다. 카메라가 움직이면 물체는 멈추고, 물체가 변하면 카메라는 멈춘다.
4. **안에서 밖으로** — 자세 장면은 폰 렌즈 안에서 시작해 물러나며 사람·점·숫자를 드러낸다(iPhone Pro 카메라 장, §13 #1).
5. **글자는 DOM** — 3D 위에 겹치되 캔버스에 굽지 않는다.
6. **시간은 빛으로** — 2막의 시각은 해의 각도·색온도·창밖 하늘로만 보인다. 시각 숫자는 장 이름표에만.

### 4.9 소리

기본 꺼짐. 머리말의 `소리` 토글을 켜면 `[F07]`·`[S-rep]` 의 음성 대사와 '틱' 효과음이 해당 단계에서 재생된다. 소리가 나는 모든 순간에 같은 문장의 자막이 뜬다. 음원은 실제 앱 음성(기기의 한국어 TTS) 출력을 녹음해 쓴다 ⚑.

- 처음 온 사람의 경로: 필름(끝까지 스크롤) → 끝장의 `TREX의 집 →` → `#house`. 2막의 장마다 `자세히 ↗` → `#story/…`.

- `Esc` 는 한 단계 뒤로: 물체 → 들어온 곳, 장면 → `#house`.
- 페이지 끝(메인 아래)에 **자주 묻는 질문** — 인터넷 없이 되나 · 로그인이 필요한가 · 폰은 어디에 두나 · 어떤 운동을 보나 · 내 영상은 어디로 가나(Apple Fitness+ 의 FAQ 자리, §13 #6). 답은 각 장면의 `detail` 을 그대로 쓴다.

## 6. 필름 `#home`

### 6.0 필름 규칙

- **장 데이터**는 CAwiki `cinema-timeline.js` 와 같은 한 줄 형식: `{id, start, end, label, description, fallback}`. `label` 은 화면에 보이는 유일한 장 글자(영문 대문자), `description` 은 스크린리더 문장이자 연출 지시, `fallback` 은 WebGL 이 없을 때의 정지 화면.
- **장의 폭 = 머무는 시간.** 스크롤 트랙 높이는 데스크톱 약 2200svh · 휴대폰 약 2000svh(CAwiki 14장 2600/2300svh 에 비례). 가장 긴 장은 `[F07]` 카메라 코치.
- **1막은 본문이 없다**(CAwiki 필름과 같음) — 장 이름표, `SCROLL TO EXPLORE ↓`, `건너뛰기 →` 뿐. 예외는 `[F02]` 의 로고 한 줄과, 2막으로 넘어가는 다리인 `[F04]` 의 첫 캡션.
- **2막은 장마다 캡션 하나**를 왼쪽 아래 열(CAwiki 시나리오 캡션 자리: 왼쪽 6vw · 아래 22vh · 최대 430 px, 왼쪽→오른쪽 어두운 막)에 둔다: `시각 · 이름` → 제목 → 문장 하나 → `자세히 ↗`. 3D 주인공은 `setViewOffset` 으로 오른쪽 14 % 에 둔다.
- **2막 장 안의 안무**(CAwiki `compose()` 의 5박자를 옮김): 도착(0–.20, 카메라가 그 장소로 가며 빛이 바뀜) → 펼침(.20–.49, 기능의 핵심 그림이 집 물건에서 펼쳐짐) → 머묾(.49–.69, 쉬는 점 57 %, 캡션 읽는 시간) → 접힘(.69–.90, 그림이 물건 속으로) → 떠남(.80–1, 신호 입자가 다음 장소로 흐름).
- **건너뛰기**: 1막 동안 아래 가운데 `건너뛰기 →` → `[F04]` 의 쉬는 점(조립된 집). 1막의 무거운 장은 렌더 대신 정지 그림 몽타주로 지나간다(CAwiki `film-skip.js` 방식). 2막부터 오른쪽 아래 `TREX의 집 →`.
- **키보드**: ← → 로 장의 쉬는 점 사이를 이동. reduced-motion 이면 스크롤이 쉬는 점에 붙는다.

## 7. 메인 `#house`

CAwiki 의 `#wiki` 자리. 필름 끝장에서 넘어올 때 **CAwiki 의 '위키 도착' 전환을 그대로 쓴다**: 끝 프레임을 2D 배경으로 복사해 흐려지는 동안, 폰은 머리말의 `TREX` 글자 자리로 날아가고 집 안의 물건(냉장고·화이트보드·매트·해부 모형·식탁·거울·우편함)은 각자의 장면 카드로 호를 그리며 날아가 카드 그림으로 바뀐다. 아무 입력이나 들어오면 즉시 끝난다. reduced-motion 이면 바로 목록.

탭 세 개:

- **`장면 9`** — 장면 카드 목록. 카드 = 정지 렌더 그림 + 제목 + 부제 한 줄 + 배지. 처음이면 `rep` 카드에 조용한 "처음이라면 여기서" 표시(CAwiki `docs/wiki-ux.md`). 진행 막대·점수·배지 모으기 같은 게임 요소는 넣지 않는다.

- **`체험판`** — `#get`(§9).

## 8. 장면 `#story/<id>/<n>`

### 8.0 장면 형식 (CAwiki `storyboards.json` 과 같은 필드)

- **장면 머리**: `{id, number, title, core, signature, note, source}` — `core` 는 'A가 아니라 B' 대비 한 줄, `signature` 는 이 장면만의 그림, `note` 는 범위 메모.
- **단계**: `{at, title, copy, detail, target, effect, flow, kind, motion}` — `at` 은 CAwiki 처럼 i×0.92/(n−1) 균등 간격, 단계는 **6개 이상**(CAwiki 빌드 스크립트의 최소값). `motion` 은 구현자를 위한 연출 메모라 화면에 나오지 않는다. `flow: "a>b"` 는 신호가 흐르는 길, `kind` 는 §4.5 의 신호 모양.
- **화면 배치**: CAwiki 와 같음 — 왼쪽 아래 캡션 열(`03 / 07` → 제목 → 문장 → `원리 자세히 ↗`), 아래 단계 막대(44 px 누름 영역), 콜아웃은 3D 의 점에서 글자로 꺾인 선(최대 3개), 끝 단계에서 `처음으로 ↺` · `다른 장면 ↗`.
- **원리 자세히**: 네이티브 `<dialog>`, 열면 진행을 멈추고 닫으면 같은 자리로. 바닥글은 §3-6 의 재현 문장.
- 아래 단계 표기: **제목** · `target` · `effect` · `flow` · `kind` → copy / motion / detail / 화면·음성 / 근거.

### 9.1 선택 체험 — "공룡이 따라 해요" ⚑ Q10

방문자가 원할 때만 켜는 웹캠 체험. 브라우저 안의 MediaPipe(WASM)로 관절 33점을 뽑아 종이 공룡 인형이 따라 움직인다. "이 페이지도 영상을 보내지 않는다"를 **스스로 확인할 수 있는** 가장 강한 증거다(Google Move Mirror, §13 #29).

- 페이지를 열 때 카메라를 요청하지 않는다. `공룡과 해 보기` 버튼 → 설명 한 장 → 브라우저 권한 창.
- 화면에는 영상 대신 뼈대와 공룡만. 녹화·업로드·저장 없음. 끄면 스트림을 즉시 멈춘다.
- **판정은 하지 않는다** — 브라우저의 코드는 앱의 검증된 엔진이 아니므로 자세를 평가하는 말을 하지 않는다(원칙 #2). 무릎 각도 숫자 정도만.
- 사양이 낮거나 권한을 거절하면 조용히 닫고 장면 목록으로.

## 10. 공통 조작·성능·접근성 (CAwiki 에서 그대로 가져올 것)

**조작**
- 하나의 스크롤 시계, 진행률 보간(필름 5.8/s · 장면 8/s), 마우스 끌기 = 스크롤.
- 준비되지 않은 장면으로 스크롤이 앞서가지 않는다(`availableProgress`).
- 휴대폰 진행 제한: **필름 초당 1장면, 장면 초당 2장면**, 100 ms 멈추면 한 장면에 붙음. 건너뛰기·단계 버튼·주소 이동은 제한 밖.
- 키보드: 장면 ↓ → PageDown Space 앞 / ↑ ← PageUp 뒤 / Home End, 필름 ← → 장 이동, 물체 보기 A D W S 회전 · +/- 확대.
- 체험 장면(`view`·`modes`)의 끝 단계에서만 자유 조작이 열린다. 그 전 단계는 스크롤로만 진행.

**성능**
- 품질 예산(CAwiki `quality.js`): 휴대폰 DPR 상한 1 · 절차 텍스처 512 · 라벨 128 · 그림자 기본 끔, `?quality=low|high|still`.
- 변화가 있을 때만 그린다, 숨은 탭은 멈춘다, 장면을 떠나면 자원을 해제한다, 셰이더는 보이기 전에 데운다.
- 포스터 = 진짜 첫 프레임(도구로 생성). 200 ms 안의 준비는 연출 없이, 길면 어두운 막을 360–1200 ms 에 걸쳐 걷는다. 스피너·가짜 진행률 없음.
- `#house` 직접 진입은 Three.js 를 받지 않는다. 데이터 절약·2G/3G 에서는 미리 받기를 하지 않는다.
- 근육 지도 자산(`atlas.js` 약 1.7 MB)은 `#story/muscle` 과 `#object/muscle` 에서만 받는다.
- WebGL 을 잃으면 「3D 화면을 표시할 수 없어 이미지로 이어갑니다」와 정지 그림으로(CAwiki `render-status.js` 문구).

**접근성**
- 캔버스 `role="img"` + 장마다 `aria-label`(= 장 데이터의 `description`), 장·단계마다 화면에 안 보이는 글 영역, `aria-live` 상태.
- reduced-motion: 필름은 장의 쉬는 점에 붙고 카메라 이동 없음, 장면은 단계 끝 프레임으로, 도착 전환 없음. 모든 장의 **끝 프레임이 곧 대체 그림**(Apple 개인정보 페이지 방식, §13 #7).
- 머리말에 `모션 끄기` 토글 하나(시스템 설정과 별개로).
- 소리가 나는 곳은 모두 자막, 44 px 누름 영역, `keep-all`, 경로 이동 뒤 초점 복원.

**기술 선택**: CAwiki 와 같은 바닐라 ES 모듈 + import map + Three.js r170, 번들러 없음, GitHub Pages. 스크롤 엔진은 CAwiki 의 것을 옮겨 쓴다(GSAP·Lenis 는 쓰지 않아도 된다 — 쓰면 Lenis 의 reduced-motion 기본값을 유지).

**만들기 전에 프리비즈**: 회색 상자 애니매틱으로 장 길이·카메라 경로를 먼저 맞춘다(Igloo Inc 의 previs, §13 #25). 카메라 경로는 Blender 곡선 → JSON 으로 빼 두면 화면 크기가 달라도 같은 구도가 나온다(§13 #22).
