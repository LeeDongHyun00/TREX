# ADR-0001: 휴대폰 자세 엔진에 작은 인과형 행동 모델을 결합한다

**Status:** Proposed — 학습/기기 검증 전

**Date:** 2026-09-23

**Deciders:** TREX 프로젝트 책임자와 구현·검증 담당자. 이 문서는 승인 기록이 아니다.

## Context

서비스 운동은 AIHub와 연결된 26종목이다. [M1](../POSTURE_MOTION_ENGINE_IMPLEMENTATION.md)은 방향 관측과 반복 계약을 구현했으나 임의 행동 문맥을 학습하지 않았다. 현재 FULL MediaPipe가 계산량의 큰 부분을 차지한다. 과거 Note10+ 이미지 재생의 추론만 중앙값102ms/p95 120ms였고 현재 카메라 전체 지연은 아직 측정하지 않았다.

사용자는 빠른 반복, 운동 외 행동, 처음부터 또는 후반에 달라진 자세에 구체적인 안내를 원한다. 관절만으로 물체·압력·의도를 전부 알 수 없으며 sparse AIHub clip은 실제 시점/임의 행동의 정답을 충분히 주지 않는다. 신체/촬영 다양성, 구형 Android, 발열, 베타 규칙 음성 제한, 개인에게 맞추지 않는 원칙을 유지해야 한다.

## Decision

[상세 설계](../POSTURE_LEARNED_ACTION_MODEL_DESIGN.md)에 따라 다음을 제안한다.

1. MediaPipe 유지, 원관절/관측 마스크/실제 시각을 보존하는 입력 계약 추가.
2. 작은 공간 인코더+캐시를 쓰는 causal TCN을 우선 후보로 개발. 빠른 단계 경로와 느린 문맥 경로 분리.
3. 문맥·단계·측·관측·낯섦을 분리하고 운동 계약/품질/뷰로 중재. 출력 문장은 검증된 구조화 사건에서 선택.
4. M1에 shadow로 연결한 뒤 문맥 억제→단계→항목별 교정 순으로 권한 부여.
5. CPU INT8 LiteRT CompiledModel을 첫 배포 후보로 검증. 네이티브 호환성에 문제가 있으면 CPU Interpreter 대안을 비교. GPU/NPU는 전체 파이프라인 이득이 입증될 때만 채택.
6. 학습·보정·잠금 시험을 사용자 단위로 분리. 기존 사용자 로그는 검증 전용. 제품 기본 가중치는 사용 권한이 확인된 자료로만 구성.

## Trade-off Analysis

관절 모델은 영상의 세부 의미를 모두 포착하지 못하지만 현재 엔진이 이미 계산한 정보를 재사용한다. 모델을 작게 만들고 운동 계약을 유지하면 지연·낯선 행동·반복 실패를 측정하고 설명하기 쉽다. raw world33/품질을 전달하는 계약 추가와 새 데이터가 필요하므로 단순한 기존 피처 softmax보다 개발 비용은 크다.

공통 모델은 유지비가 낮으나 운동 간 음의 전이가 가능하다. 계열별/종목별 head와 항목별 채택을 사용하고, per-exercise macro 결과로 확인한다. 매 동작에 느린 문맥 확정을 기다리게 하지 않되 새 unknown을 기존 ACTIVE 상태로 무기한 유지하지 않는다. 첫 반복의 보류 비용은 warm 지연과 분리해 공개한다.

CPU 기본안은 MediaPipe GPU 경쟁을 피할 가능성이 있지만 실제 장치에 따라 다르다. INT8도 자동으로 더 빠르거나 정확한 것은 아니다. 기존 MediaPipe와 LiteRT의 동시 로딩 및 전체 세션의 에너지/열 결과로 선택한다. [공식 LiteRT API](https://developers.google.com/edge/litert/android), [연속 추론 연구](https://arxiv.org/abs/2203.11009)

## Consequences

- 기존 MediaPipe·26종목 계약·개인 비교·음성 정책을 재사용한다. 앱에서 상시 영상을 서버로 보낼 필요가 없다.
- 학습용 연속 영상/정답 시점과 원관절 입력을 새로 확보해야 한다. 기존 sparse AIHub나 일부 피처 로그만으로 완성을 선언할 수 없다.
- confidence 보정, unknown 거절, 기능별 관측 가능 범위, 데이터/모델 버전 관리가 제품의 일부가 된다.
- 고급 의미가 필요한 항목은 선택적 ROI 또는 유보를 사용한다. 자원 부족 기기와 미검증 변형은 지원 범위를 축소한다.
- 최고 정확도 하나보다 방향 오지시·off-target 계수·지연·coverage의 균형을 관리해야 한다.

## Revisit Conditions

- graph 공간 인코더가 동일 자원 예산에서 잠금 시험의 방향/단계 오류를 일관되게 줄이면 교체.
- 영상 단서 부재가 주요 오류 원인이고 선택적 ROI가 효과를 입증하면 해당 항목만 활성화.
- FULL이 빠른 동작 관측에 부족하며 LITE 전체 번들의 오차/발열 검증이 완료되면 세트 전 선택을 허용.
- head p95 5ms, 추가 peak PSS 32MiB, 추가 에너지10% 등 후보 예산을 넘으면 구조/빈도/runtime를 재검토. 수치는 현재 실측 결과가 아님.
- 사람 분리 평가에서 새로운 체형/변형 그룹의 coverage나 오지시가 악화되면 데이터와 라벨 정의부터 재검토하고 전역 임계값을 한 사용자에 맞추지 않음.
