## 2. 제1원리 — 사선 카메라에서 한 팔꿈치가 주는 정보

카메라가 사용자 왼쪽 앞 ψ(≈ 30~40°)에 있으면, 가까운(왼) 팔꿈치의 화면 가로 이동은

  **가로 = cos ψ × (옆으로 벌어짐) − sin ψ × (앞으로 나감)**

이다. 보이는 팔꿈치 하나는 가로 숫자 **하나**를 주고 미지수는 둘이다. 그래서
- **앞으로** 와 **몸에서 떨어짐(옆 또는 뒤)** 은 부호가 반대라 **가를 수 있다.**
- **옆으로** 와 **뒤로** 는 같은 부호라 **2D 로는 못 가른다.** 가르려면 깊이가 필요한데 MediaPipe 월드 z 는 학습된 추정이다.

실측이 이를 그대로 보여 준다:
- AIHub(뷰 D/B, 가까운 팔): 2D 앞 성분 = +0.0041 × GT 앞 기울기° − 0.0021~0.0026 × GT 외전° → **외전 1° 가 앞 −0.5~−0.63° 로 읽힌다**(벌림이 '뒤로' 처럼 보인다).
- 폰 D 세트: 벌린 반복에서 가까운 팔 앞 성분이 −0.45 → −0.56~−0.73 으로 내려갔다(뒤로 간 것처럼).
- 월드 3D 로 가르기: 가까운 팔 **외전 변화** ρ(GT) **0.38(D)·0.49(B)** — 못 쓴다. **앞 기울기 변화** 는 ρ 0.84~0.86 — 쓸 만하다(단 절대값은 +14~18° 편향).

결론: 사선에서 가까운 팔 하나로는 **"앞으로" / "몸에서 떨어짐"** 두 갈래까지가 정직한 한계다. "옆이냐 뒤냐" 는 말하지 않는다. 옆 벌림을 제대로 보려면 **정면**, 앞/뒤를 제대로 보려면 **옆**이 최선이다 — 한 카메라로 두 평면을 다 보는 방법은 없다.

## 3. 기준 — 매 반복의 이완→수축 호를 지운다

AIHub 한 클립 안에서 '수축 − 이완' 으로 재면 팔꿈치를 제대로 고정한 클립도 가까운 팔 가로가 크게 움직인다(Δ옆 ≥ 0.20 이 11~15 %) — 컬 한 번마다 팔꿈치가 자연스럽게 호를 그리기 때문이다. **수축끼리 비교**(같은 사람의 정상 수축 위치 대비)하면 호가 지워진다. 앱에서는 **첫 3회 수축 구간 중앙값 = 본인 기준**(ROM 과 같은 방식)으로 두고, 이후 반복의 수축 구간 중앙값을 견준다. 첫 상단 창을 쓰지 않으므로 덤벨 집기 오염(09:59)도 피한다.

AIHub 뷰 D/B, '팔꿈치 위치 고정' 충족 클립(D 664·B 658), 세션 안 고정 충족 수축값 중앙값 대비(단일 프레임 — 앱의 구간 중앙값보다 잡음이 커서 상한):

| 가까운 팔 검사 | 띠 | 정상 오탐 D / B | 앞 내밀기 위반 검출 D / B |
|---|---|---|---|
| 앞으로 | +0.10 | 7.8 % / 4.9 % | 92 % / 86 % |
| 앞으로 | +0.12 | 5.4 % / 3.3 % | 88 % / 80 % |
| 앞으로 | +0.20 | **2.1 % / 1.5 %** | 62 % / 49 % |
| 몸에서 떨어짐(옆·뒤) | +0.25 | 7.4 % / 4.6 % | (라벨 없음) |
| 몸에서 떨어짐(옆·뒤) | +0.30 | 4.1 % / 2.1 % | (라벨 없음) |
| 몸에서 떨어짐(옆·뒤) | +0.40 | **1.7 % / 1.2 %** | (라벨 없음) |

가까운 팔 앞 성분 수축 원값의 앞 내밀기 판별 AUC 0.937(D)·0.928(B) — B1 의 양팔 평균 0.958 과 거의 같다(먼 팔꿈치가 없어도 잃는 게 적다).

폰 D 세트를 같은 방식(첫 3회 수축 중앙값 0.18 대비)으로 보면 정상 −0.04~+0.09(1~3·10~12·18회), 벌림 +0.23~+0.62(4·5·13~17·19~21회).

## 4. 설계

### 설계 1 — 앞 이탈을 가까운 팔로 (가장 먼저, 위험 낮음)
- 피처: 가까운 팔(D = 왼팔, B = 오른팔; 요 부호로 고르고 가시성으로 확인) 앞 성분 `elbow_fwd2d_near`. 양팔 평균 요구(`n == 2`)를 없앤다.
- 기준: 첫 3회 수축 중앙값(본인). 2단 — 코칭 **+0.12**(오탐 3~5 %, 검출 80~88 %), 차단 **+0.20**(오탐 1.5~2.1 %, 검출 49~62 %). 입장 조건 ≤ 2 % 에 차단 띠가 맞는다.
- 문구 그대로("팔꿈치가 앞으로 나갔어요. 팔꿈치를 옆구리에 고정하세요").

### 설계 2 — 사선 벌림 = "몸에서 떨어짐" (가까운 팔)
- 피처: 가까운 팔 바깥 가로 `elbow_lat2d_near`(가까운 어깨 기준, 어깨 가로폭으로 나눔 — 기존 정의에서 가까운 팔만), 수축 구간 중앙값, 본인 기준(첫 3회 수축) 대비.
- 2단 — 코칭 **+0.25**(AIHub 오탐 4.6~7.4 %; 폰 D 세트 벌림 10회 중 7회), 차단 **+0.40**(1.2~1.7 %; 10회 중 4회 — 14·15·16·19회, 큰 벌림만). 정면 벌림 검사(차단 +0.20, 오탐 ≤ 0.6 %)보다 둔하다 — 사선 가까운 팔 가로는 잡음이 정면의 2~3배다.
- 문구는 방향을 단정하지 않는다: **"팔꿈치가 몸에서 떨어졌어요. 옆구리에 붙이세요."** — 옆으로 벌렸든 뒤로 뺐든 고치는 동작이 같다. 월드 3D 로 "옆/뒤" 를 가르는 안은 버렸다(외전 변화 ρ 0.38~0.49).
- 같은 반복에서 '앞으로' 와 동시에 걸릴 수 없다(같은 축의 반대 부호).
- 정면 벌림 검사도 같은 본인 기준(첫 3회 수축)으로 바꾼다 — 09:59 오염 해결.

### 설계 3 — 권장 위치와 앞/뒤 교정
- **권장 위치**: 상완이 거의 수직이고 팔꿈치가 몸통 옆·어깨 아래. AIHub GT 정상의 수축 시 상완 앞 기울기 p5/50/95 = −3 / 14 / 33°, 앞 내밀기 위반 평균 36°. MediaPipe 로는 절대 각을 못 믿으므로(월드 +14~18° 편향, 2D 는 뷰마다 상수가 다름) **"본인의 첫 3회 수축 위치 ± 모집단 띠"** 로 정의한다(설계 1·2 가 그 띠).
- **사선(D/B)**: 앞 = 설계 1, 뒤 = 설계 2 에 합친다(뒤로 뺀 것과 옆으로 벌린 것을 못 가르므로 따로 "뒤로 빠졌어요" 를 말하면 벌림에서 틀린 말이 된다).
- **옆(SIDE, 요 46~82°)**: 앞/뒤를 보는 최선의 뷰다 — 앞 성분이 화면 가로에 거의 그대로(sin ψ ≈ 0.7~1.0) 나오고 벌림은 거의 안 샌다(cos ψ 작음). 여기서는 **"앞으로 나갔어요" / "뒤로 빠졌어요"** 를 따로 말할 수 있다. 다만 SIDE 는 저장소 규약상 미검증 뷰(모든 규칙 유보)이고 AIHub 에 옆 카메라가 없다 → **beta**, 폰 지정 오류 세트로 확정.

### 뷰별로 사용자에게 말할 범위 (PostureScope 한 줄)
- 정면: 옆 벌림·팔꿈치 뜸·상체 숙임 / 앞 이탈은 못 봄
- 사선(왼·오른 앞): 앞 이탈·몸에서 떨어짐(큰 벌림만)·상체 숙임(D) / 옆 벌림의 작은 변화는 못 봄
- 옆: 앞/뒤(참고, 검증 중) / 벌림은 못 봄

## 5. 확정 전에 잴 것
1. 폰 지정 오류 세트 — D 와 B 각각: 정상 10 · 벌림 10 · 팔꿈치 앞 10 · 팔꿈치 뒤 10회(회 번호 기록). 벌림/뒤가 둘 다 '몸에서 떨어짐' 으로 잡히는지, 앞과 섞이지 않는지.
2. AIHub 뷰 B/D 를 앱과 같은 창 통계(수축 구간 중앙값, 첫 3회 기준)로 다시 재서 차단 띠 확정(지금 수치는 단일 프레임 상한).
3. SIDE 앞/뒤는 폰 세트만으로 beta → 오탐 ≤ 2 % 확인 뒤 ship.

## 6. 구현 순서(승인 후)
설계 1(가까운 팔 앞 이탈) → 설계 2 + 정면 벌림 기준 교체 → 뷰별 범위 문구 → SIDE 앞/뒤(beta). 모두 `Arm2d`(가까운 팔 피처)·`RepFormSpecs`(검사)·새 기준 종류(첫 N회 수축 중앙값)로 끝나며 카운터는 건드리지 않는다.
