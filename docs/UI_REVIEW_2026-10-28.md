# 근육 피로도·2D 근육도·탭 스와이프·가이드 여백 변경

사용자 요청(2026-10-28): Android와 iOS를 함께 수정한다. 구현·검토 후 후속 요청으로 로컬 커밋을 승인했다. 푸시·배포는 하지 않는다.
기준: `53c3d332743294800aa2a73679895b35d52f244b`.

## 설계와 구현

### 1. 피로도 목록

`MuscleLoadScreen.kt`의 상체/하체/코어 분류와 근육 선택 칩을 제거했다. `known && value > 0`인 근육을 대표 피로도 내림차순으로 나열한다. 대표 값은 기존과 같이 좌우 중 큰 값이다. 동점은 근육 정의 순서로 고정한다.

목록에서 선택한 근육의 상세 기록과 근육도 강조를 연결한다. 초기 선택은 가장 피로도가 높은 근육이다. 갱신 후 선택한 근육이 목록에서 사라지면 현재 첫 근육으로 대체한다. 사용 기록이 없거나 피로도가 모두 0이면 빈 상태를 표시한다. 로딩·오류일 때는 빈 상태를 중복 표시하지 않는다. 0보다 크지만 1보다 작은 점수는 `1점 미만`으로 표기한다.

전체 `LoadSnapshot`과 피로도 계산·추천 알고리즘은 변경하지 않았다. 필터는 화면 목록에만 적용한다. `근육 상태 / 추천 운동` 탭은 유지한다.

### 2. 공용 2D 근육도

`research/muscle_load/export_atlas_2d.py`가 기존 `atlas.js`를 정사영하고 깊이 버퍼로 가려진 면을 제거한다. 가시 영역 윤곽을 `atlas-2d.js`의 SVG 경로로 저장한다. 모델의 근육 ID와 신체 좌우를 그대로 보존하며, 18개 근육 × 좌우 36개 키가 앞·뒷면 전체에 존재한다. 도형은 46,383바이트다.

`index.html`과 `viewer.js`는 왼쪽 뒷면 / 오른쪽 앞면을 함께 표시한다. 앱 실행 중에는 Three.js, 메시 데이터, WebGL을 불러오지 않는다. 피로도 색상·선택 강조와 완료 화면의 사용 근육 강조를 공용 SVG에 적용한다. 완료 화면은 누적 피로도가 아니라 해당 세션의 사용 부위만 표시한다.

Android는 WebView의 회전용 터치 가로채기를 제거하고, iOS는 UIKit 상호작용을 비활성화해 부모 화면의 세로 스크롤을 허용한다. iOS 프로젝트는 원래 Android의 `muscle_load` 폴더를 번들에 넣으므로 도형 사본을 만들지 않는다. 원본 3D 모델은 재생성용으로 보존하고 파생 표시 자산의 출처·라이선스를 유지했다.

검토용 그림: `outputs/ui-review/muscles-2d.png`. 예시 점수로 렌더링한 공통 뷰어이며 실제 기기 스크린샷은 아니다.

### 3. 메인 탭 스와이프

공통 `MainTabSwipe.kt`를 추가하고 iOS 공유 소스 목록에 포함했다. `MainTabs()`의 콘텐츠에 적용한다. 왼쪽으로 밀면 `홈 → 운동 → 식단 → 내 정보`, 오른쪽은 역순이다. 첫·마지막 탭에서 반대쪽 끝으로 순환하지 않는다. 기본 터치 슬롭 이후 64dp 이상 이동하고 손을 뗐을 때 한 탭을 바꾼다. 취소되거나 거리가 짧으면 유지한다.

자식이 소비한 드래그는 우선한다. 따라서 운동 행의 기존 삭제 스와이프·정렬, 내부 가로 조작은 그대로 동작하고, 그 밖의 콘텐츠에서 탭을 이동한다. 좌우 24dp 가장자리는 시스템 뒤로 제스처에 남긴다. 메인 시트가 열린 동안 비활성화하며 세션·상세 화면에는 적용하지 않는다. 기존 탭 전환 애니메이션을 사용한다(손가락을 실시간 따라가는 pager는 아님).

### 4. 가이드 여백 — 팝업 뒤 화면 비침 방지

사용자 설명을 재확인한 결과, 목표는 투명 여백 자체가 아니라 iOS에서 여백을 통해 팝업 뒤 화면이 보이는 현상을 막는 것이다. 공통 `ExerciseGuideSheet`의 이미지 영역을 불투명한 `c.sheet`로 채운다. iOS GIF의 HTML `html/body`, WKWebView, 내부 scrollView에도 같은 시트 배경색을 적용하고 opaque로 설정한다. 로딩 중에도 네이티브 배경이 뒤 화면을 막으며 라이트/다크 테마 변경 시 HTML과 네이티브 배경을 함께 갱신한다. 정지 이미지/GIF의 비율 유지·가운데 정렬과 원본 픽셀은 유지한다. 온보딩 SVG의 기존 투명 배경에는 영향을 주지 않는다.

## 기기에서 검토할 항목

1. 기록 없는 상태와 운동 후 피로도 목록, 높은 순 정렬, 목록 선택 시 근육도 강조.
2. 앞/뒤 근육도 위에서 세로 스크롤, 완료 화면의 해당 세션 부위 강조.
3. 메인 화면 좌우 이동, 짧은/세로 드래그와 취소 시 유지, 양끝 탭과 시스템 가장자리 뒤로.
4. 운동 행 삭제·정렬과 시트 조작 시 탭이 함께 바뀌지 않는지.
5. 라이트/다크 모드 가이드 GIF·PNG의 비율과 불투명 양옆 여백. 팝업 뒤 화면이 비치지 않는지, GIF 로딩 중·테마 전환 후에도 여백이 팝업 배경과 일치하는지.

### 여백 수정 후 검증

공유 Compose 영역뿐 아니라 iOS HTML·네이티브 뷰까지 불투명 배경을 적용했다. iOS 실제 팝업 합성은 macOS/Xcode 및 기기에서 재확인이 필요하다. 이전 정적 검사 결과는 이 네이티브 합성 동작을 검증한 것이 아니다.
