# 휴대폰 횟수 엔진 설계 — 현재 카운터를 무엇으로, 어떻게 바꾸는가

- 근거: `research/external_rep_replay/README.md` §4·§7(현재 엔진의 MM-Fit 재생과 원인 귀속), 같은 폴더 `prototype_counter.py`(이 설계의 카운터 코어 프로토타입 실측).

## 0. 요약

현재 카운터(`RepCounter(completeOnReturn = true)` = `ReturnRepTracker`)가 실제 연속 동작에서 반복을 놓치는 원인은 촬영이 아니라 **네 가지 설계 선택**이다 — ① 런지 신호(`knee_out_mean`)가 앞으로 딛는 런지에서 거의 움직이지 않고 좌우가 상쇄된다, ② 세트 시작 전에 600ms 이상 멈춘 준비 자세가 있어야 기준을 잡는다(준비 자세가 잘못 잡히면 세트 전체가 0회), ③ 상단에 300ms 이상 머물러야 복귀로 인정한다(빠른 템포에서 탈락), ④ 3점 중앙값 평활이 한 샘플짜리 바닥을 지운다. 이 넷은 모두 카메라와 무관하게 재현됐고, 같은 300ms 신호에 평활·준비 자세 없는 단순 카운터를 돌리면 반복의 99% 가 들어 있다.

설계는 **엔진을 새로 만들지 않고 네 곳을 바꾼다**: 신호 선택 규칙(회전 불변 관절각 우선, 교대 종목은 좌우 개별), 카운터 코어(복귀 히스테리시스 — 안정 준비 자세·상단 체류·평활 요구 제거), 세트 시작 확정(첫 두 사이클 동시 확정), 그리고 카운트의 신뢰 등급을 화면·진행 조건에 연결한다. 나머지(추론 정책, ROM, 로그·라벨 루프)는 보강이다.

| | 현재 엔진 | 제안 코어(프로토타입) |
|---|---|---|
| 스쿼트 세트 정확 일치 / 재현율 | 0.53 / 0.90 | **0.97 / 0.997** |
| 런지 세트 정확 일치 / 재현율 | 0.00 / 0.10 | **0.95 / 0.98** (신호 `knee_mean`) |
| 덤벨 컬 세트 정확 일치 / 재현율 | 0.42 / 0.86 | **0.98 / 0.998** (팔별 카운터) |
| 세트 안 과다 카운트 세트 | 0 | 0 |
| 세트 직전 10초 헛카운트 / 세트 | 0.00 / 0.00 / 0.07 | 0.00 / 0.00 / 0.22 (컬 게이트 50° 면 0.12) |
| 휴식 중 헛카운트 / 분 | 0.20 / 0.19 / 1.53 | 0.03 / 0.03 / 3.0 (컬 50° 면 1.8) |

컬의 음성 구간이 제안 코어의 약점이다. 앱은 사용자가 시작한 세트 안에서만 세므로 "휴식 중" 은 직접 해당하지 않지만, "세트 직전 10초" 는 시작 버튼 뒤의 준비 움직임에 해당하므로 §4.3·§4.4 에서 다룬다.

## 1. "휴대폰에서 쓸 만하다" 의 정의 (수용 기준, 사전 등록)

카운트는 §42 이후 **세트 진행 조건**이다(목표 횟수 도달 → 다음 세트). 그래서 과다 카운트는 세트를 조기에 끝내고, 미달은 사용자가 손으로 고쳐야 한다. 두 오류의 비용이 다르므로 기준도 비대칭이다.

| 지표 | 기준 | 이유 |
|---|---|---|
| 세트 정확 일치 | ≥ 0.90 | 열 세트 중 아홉은 손을 대지 않아야 "자동" 이다 |
| 세트 ±1 | ≥ 0.98 | 나머지는 한 번의 수정으로 끝나야 한다 |
| 세트 안 과다 카운트 | ≤ 2% 세트 | 조기 종료는 미달보다 나쁘다 |
| 세트 시작 뒤 첫 반복 전 헛카운트 | ≤ 0.05 / 세트 | "시작하자마자 1회" 는 신뢰를 바로 깎는다 |
| 마지막 반복 | 다음 하강 없이 확정 | §42 의 복귀형 도입 이유 — 유지 |
| 항상-목표치 기준선 | 같은 표에 병기 | 세트의 94% 가 정확히 10회인 데이터에서는 "항상 10" 이 강한 기준선이다 |
| 통계 단위 | 사람(피험자) | P0·P1 두 명이 MM-Fit 반복의 56% — 세트 단위 신뢰구간은 절반으로 좁게 나온다 |

이 기준을 **MM-Fit 봉인 피험자 → MM-Fit 영상(MediaPipe) → REHAB24-6 경계 → 휴대폰 자가 라벨** 순으로 통과해야 하고(§7), 마지막 단계를 지나기 전에는 카운트가 beta 로 남는다(원칙 #2). 기준값 자체는 제안이며 첫 휴대폰 라벨 세트로 현실성을 재본다.

불응기 1.2s 와 1.5s 끊김 초기화는 비용 0 이었다. 시점 변환 26개에서 스쿼트·컬은 한 세트도 바뀌지 않았다(세 관절 각은 회전 불변). 런지만 IMU 없는 기울기에서 흔들린다(재현율 0.06~0.35, 최선도 `knee_mean` 0.84 에 못 미침).

**AIHub 에서 온 것과 아닌 것.** 횟수를 세는 논리는 AIHub 에서 오지 않았다(반복 라벨이 없다). AIHub 에서 온 것은 신호 선택(설문)과 ROM 임계값뿐이고, 그중 런지 신호가 무너졌다. 스쿼트·컬의 손실은 AIHub 와 무관한 추적기 설계다.

## 3. 설계 원칙

1. **모집단 파라미터.** 게이트·비율·창은 물리 단위의 모집단 값이고, 특정 사용자나 특정 데이터셋(MM-Fit 포함)에 맞추지 않는다. 데이터셋은 선택지 중에서 고르고 효과를 재는 데만 쓴다(README §5, `CLAUDE.md` #4).
2. **판정하지 않은 것을 판정한 것처럼 말하지 않는다.** 카운트에는 신뢰 등급이 붙고, 낮은 등급은 진행 조건에서 빠진다(#1·#2).
3. **카운트와 ROM(가동범위) 유효성은 분리.** ROM 은 카운트에서 빼지 않는다(§42) — 유지.
4. **엔진 파일은 앱 최상위에 의존하지 않는다.** 새 코어는 `posture/` 안, `RepCounter` 의 공개 API(`onFrame → Boolean`, `lastCycleMin/Max`, `periodMs`, `repTimesMs`)를 유지해 `PostureLive` 변경을 최소화한다.
5. **검증 사다리 없이 ship 없음.** 휴대폰 자가 라벨(`rep_truth.csv`)이 최종 게이트다.

```
카메라 → PostureAnalyzer(300ms, IMU up) → 프레임 피처
      → [4.1 신호 계층] 종목별 신호(좌/우/평균) + 물리 범위·가시성 게이트
      → [4.2 카운터 코어] 복귀 히스테리시스 상태기계 (좌우 개별 인스턴스)
      → [4.4 교대 병합] 반대쪽 발화 W ms 안이면 같은 반복
      → [4.3 시작 확정·일관성] 첫 두 사이클 동시 확정, 이후 진폭 일관
      → [4.8 신뢰 등급] 확정 / 감지 중 / 저신뢰(샘플 부족·발열)
      → 세션 진행(확정만) · HUD · 음성 · 세트 로그 · ROM 참고(4.5)
```

### 4.1 신호 계층 — 종목별 신호 선택 규칙

규칙(우선순위 순):
- **R1 회전 불변 관절각 우선.** 세 관절 각(`angle3`)은 카메라 방향·IMU 오차·좌우 반전에 영향받지 않는다. 뷰·중력 의존 신호(`knee_out_*`, `*_h_*`, `palm_*`)는 IMU 가 있고 실기기 검증을 통과한 종목에서만 쓴다.
- **R2 교대 종목은 좌우 개별.** 좌우 평균은 교대 동작에서 진폭을 반으로 줄이고(컬 평균 ~50° vs 팔별 ~95°) ROM 기준에 구조적으로 닿지 못하게 한다. `ExerciseProfiles` 가 교대로 표시한 종목(런지 4종·덤벨 컬·스탠딩 니업)은 좌·우 신호에 카운터를 각각 두고 §4.4 로 병합한다. 양쪽이 함께 굽는 종목(스쿼트, 전진 런지의 무릎)은 평균을 쓴다.
- **R3 진폭 게이트는 물리 단위, 하한은 기기 잡음 바닥.** 각도형 35° 는 플랭크 유지 중 폰 잡음(5초 창 10~30°) 실측에서 온 하한이라 유지한다. 종목별로 더 높은 게이트를 두려면 AIHub 정상 반복의 ROM 분포에서 근거를 대고(§4.4 컬), MediaPipe 가 깊은 굴곡을 얕게 읽는 편향(+10~30°, `docs/bridge-frames.full-sweep.v1.json`)만큼 여유를 남긴다.
- **R4 신호 교체는 연속 데이터에서 검증.** AIHub 0.6초 표본의 "클립 간 일관성" 은 연속 동작에서의 성립을 보장하지 않았다(런지). 후보는 MM-Fit 봉인 피험자에서 재고, 순위가 휴대폰 라벨 세트에서도 같을 때 채택한다.

세 종목의 적용:

| 종목 (앱 → AIHub) | 현재 | 제안 | 근거 |
|---|---|---|---|
| 바벨 스쿼트 | `knee_mean` 35° | 유지 | 0.997 |
| 런지 → 스텝 포워드 다이나믹 런지 | `knee_out_mean` 0.10 | **`knee_mean` 35°** (양 무릎이 함께 굽는다) | 0.10 → 0.98. `knee_minside` 는 0.77 로 열세 |
| 덤벨 컬 | `elbow_mean` 35° | **`elbow_L`·`elbow_R` 각각 + 병합** | 0.86 → 0.998, ROM 팔별 판정 가능 |

나머지 서서 종목 15개는 같은 규칙으로 재검토 대상이다. 특히 R1 에 걸리는 신호(`knee_out`·`hip_below_knee`·`palm_h_sh`·`forearm_vert`·`elbow_wrist_h` 계열)와 R2 에 걸리는 교대 종목(바벨 런지·사이드 런지·크로스 런지·스탠딩 니업)을 먼저 본다. 검증 데이터가 없는 종목은 바꾸지 않고 beta 로 둔다.

### 4.2 카운터 코어 — 복귀 히스테리시스

한 반복 = 휴식 → 하강 → 반전 → 복귀. 준비 자세를 미리 요구하지 않고, 상단에 머물 것을 요구하지 않고, 평활하지 않는다.

```
REST : r = 마지막 발화 이후 최댓값 (휴식 기준). v ≤ r − h → DESC, r0 = r
DESC : m = 최솟값 추적. v ≥ m + h → ASC (반전 확정 = 후보), a = v
ASC  : v ≥ m + (1 − f)·(r0 − m) → 발화 (복귀 f 만큼 남긴 지점, f = 0.25)
       v ≤ a − h (복귀 전 재하강) → 발화 후 곧바로 DESC (불완전 복귀 폴백: 다음 사이클이 시작됐다는 증거)
       그 외 a = max(a, v)
발화 후: 직전 발화와 refractory 미만이면 잡음으로 버림. 사이클 극값 (m, r0) 을 ROM 용으로 노출.
```

| 파라미터 | 값 | 출처 |
|---|---|---|
| h (최소 스윙) | 각도 35° / 거리 0.25~0.30 | 현재와 같음 — 폰 잡음 바닥 실측 |
| f (복귀 잔여 비율) | 0.25 | 설계값. "준비 위치로 돌아왔을 때 완료" 의 완화판 — 상단 체류를 요구하지 않는다 |
| refractory | 0.8 s | 설계값. 현재 1.2 s 는 비용 0 이었으나 1.2 s/반복 템포에 닿는다 |
| maxGap | 1.5 s | 현재와 같음 — 가림·일시정지 뒤 사이클을 잇지 않는다 |
| 평활 | 없음 (각도형) | 3점 중앙값이 재현율 0.997 → 0.975, 컬 정확 일치 0.98 → 0.95 로 깎는다 |

마지막 반복은 복귀 지점에서 확정되므로 다음 하강이 필요 없다(§42 요구 유지). 세트 종료(사용자 종료·시간 만료) 시 ASC 상태의 후보는 **세지 않고** 로그에 "미완 후보" 로 남긴다 — 절반만 올라온 동작을 한 회로 만들지 않는다.

평활을 없애면 한 샘플짜리 튐(예: 관절 추정 실패)이 사이클로 보일 수 있다. 폰에서 이 튐의 빈도는 아직 재지 않았다. 대비책은 평활이 아니라 **문맥 조건부 튐 제거**다: 양 이웃 샘플이 모두 휴식 기준 근처(r − 0.3h 이상)일 때만 가운데 샘플을 이웃 중앙값으로 대체한다. 진짜 바닥의 이웃은 하강·상승 중이라 휴식 근처가 아니므로 살아남는다. 이 필터는 §7 의 영상·휴대폰 단계에서 튐 빈도를 잰 뒤 켠다.

### 4.3 세트 시작 확정과 진폭 일관성

`ReturnRepTracker` 의 "안정 준비 자세" 는 시작 전 오염(걸어오기·기구 잡기)을 막으려는 장치였고, 그 값이 잘못 잡히면 세트 전체를 잃었다. 대신 **사이클 두 개의 일관성**으로 시작을 확정한다:

- 첫 발화는 보류한다. 4초 안에 진폭이 0.5~2배인 두 번째 사이클이 오면 둘을 함께 발표한다(HUD 는 0 → 2). 오지 않으면 버린다.
- 이후 발화는 직전 발표 사이클과 진폭 비 0.5~2배 안이어야 한다. 고립된 한 번의 큰 움직임은 반복이 아니다.

효과(프로토타입): 휴식 헛카운트 스쿼트·런지 0.35 → 0.03/분, 컬 5.6 → 3.0/분. 세트 직전 10초 헛카운트 런지 0.23 → 0.00/세트, 컬 0.56 → 0.22/세트. 세트 재현율은 스쿼트 0.997 유지, 런지 0.990 → 0.981, 컬 1.000 → 0.998. 비용은 첫 반복이 두 번째와 함께 표시되는 지연 하나다 — 음성은 "둘" 부터 세되 화면에는 "첫 두 회는 함께 확정돼요" 를 준비 안내에 넣는다.

### 4.4 교대 종목의 정의와 병합

- 정의: **한쪽 1회 = 1회**(MM-Fit 라벨과 같고, 왼·오른 5+5 = 10). 양쪽을 동시에 하면 1회. 편집기(`WorkoutEditor`)에 "양쪽 1회 = 1회" 옵션을 두되 기본은 한쪽 1회다 — 기본값을 바꾸면 기존 목표 횟수의 의미가 두 배로 달라진다(§42 의 "기존 목표를 임의로 두 배로 만들지 않는다").
- 병합: 좌·우 카운터의 발화가 W = 500ms 안에 겹치면 하나로 센다. 교대 컬의 좌우 간격(약 1.9초)과 동시 컬(≤ 300ms)을 나눈다.
- 컬의 음성 구간: 팔별 카운터는 휴식 중 팔 움직임(물 마시기·기구 조정)에 두 배로 노출된다. 게이트를 팔별 50° 로 올리면 세트 직전 헛카운트 0.22 → 0.12/세트, 휴식 3.0 → 1.8/분이고 세트 재현율은 1.000 이다. **근거는 AIHub 다**: 정상 컬 반복의 팔꿈치 바닥 p90 이 81.3°, 휴식 팔꿈치가 150~160° 이므로 정상 반복의 스윙은 약 70° 이상이고, 50° 는 MediaPipe 가 깊은 굴곡을 얕게 읽는 편향(+10~30°)을 뺀 값이다. 다만 MediaPipe 정면 컬의 실제 스윙 분포는 미측정이라 **35°(잡음 바닥)~50° 사이에서 영상 단계(§7-2) 결과로 확정**한다. 어깨각 < 90° 문맥 게이트는 머리 위 신전 오카운트만 줄이고(26.9 → 2.1/분) 휴식에는 효과가 없어 채택하지 않는다.

### 4.5 ROM 유효성 — 정의를 고치고 기준값은 두지 않는다

- 카운트에서 빼지 않는다(현재와 같음). 리포트의 유효/파셜 표시와 음성은 지금처럼 검증된 5개 바닥 종목만.
- **원값으로 판정.** ROM 임계값은 평활하지 않은 AIHub 값에서 뽑았는데 지금은 평활된 사이클 최저값과 비교한다. 코어가 평활을 없애면 저절로 맞는다(스쿼트 유효 161/576 → 약 346/576, 근사).
- **교대 종목은 쪽별.** 팔별 카운터의 사이클 극값을 그 팔의 ROM 기준과 비교한다(AIHub 81.3° 기준으로 MM-Fit 한 팔 컬 601/604 통과 — 기준값을 바꾸지 않아도 정의만 고치면 맞는다).
- 런지의 ROM 은 신호가 바뀌므로 `knee_out_mean −0.0076` 을 버리고, `knee_mean` 기준은 AIHub GT 3D(사용자 PC)에서 `rep_validity_thresholds.py` 로 다시 뽑기 전까지 **없음(항상 유효 취급)** 으로 둔다. MM-Fit 에서 뽑지 않는다.
- MediaPipe 편향(+10~30°) 때문에 AIHub 3D 기준값은 휴대폰에서 정상 반복을 "얕음" 으로 볼 수 있다. 재보정(§9) 전에는 ROM 이 헤드라인이 되지 않는다.

### 4.6 추론 정책 — 300ms 유지, 필요할 때만 부스트

- MM-Fit 템포(반복당 1.2~4초)에서는 300ms 로 충분했다(200ms 부스트가 결과를 바꾸지 않았다). 반복당 4샘플 미만(≈ 1.2초/반복 미만)에서 카운트가 무너진다는 AIHub 서브샘플링 실측(`REP_SIGNALS.md`)은 유효하다.
- 부스트: 카운터의 주기 추정이 1.5초 아래로 내려오면 RECORDING 간격을 200ms 로 내린다(발열 NONE·LIGHT 에서만). MediaPipe full 이 GPU 에서 약 100ms 이므로 5fps 는 예산 안이다.
- 발열 감속(MODERATE 이상, 간격 ×1.5~3)이나 부스트 불가 상태에서 반복당 샘플이 5 미만이면 카운트를 **저신뢰**로 강등하고 "정확한 카운트를 위해 조금 천천히" 를 한 번 말한다. 카운트를 조용히 놓치는 것보다 낫다(#1).
- 실제 추론 간격·발열 상태를 세트 로그에 남긴다(§4.9).

### 4.7 휴대폰 특유 조건의 처리

| 조건 | 처리 |
|---|---|
| IMU up 벡터 | 각도 신호는 무관. 뷰 의존 신호는 IMU 없으면(`upFromGravity = false`) 카운터를 만들지 않고 "이 종목은 센서가 필요해요" 로 밝힌다 |
| 검출 끊김·가림 | 값이 없으면 카운터 일시정지(현재), 1.5초 초과면 사이클 리셋(현재). 필요한 관절이 화면 밖이면 커버리지 안내가 카운트보다 우선(현재 규칙 유지) |
| 물리 범위 밖 값 | `plausibleMin/Max` 게이트 유지(손목 붕괴 등) |

| 앞·뒤 카메라 | 각도 신호는 좌우 반전에 무관. 교대 병합도 대칭이라 무관 |

| 세트 시작 오염 | §4.3 일관성 확정으로 대체. 준비 카운트다운 중에는 지금처럼 세지 않는다 |

### 4.8 신뢰 등급과 UX

카운트는 세 등급으로 나뉜다.

| 등급 | 조건 | 표시 | 진행 조건 | 음성 |
|---|---|---|---|---|
| 확정 | 일관성 확정 + 반복당 샘플 ≥ 5 + 발열 NONE/LIGHT | 숫자 | 포함 | 숫자 |

- 교대 종목은 준비 안내에 "한쪽 1회를 1회로 세요" 를 넣는다(정의를 미리 밝힌다).

## 8. 미해결과 위험

- **컬의 음성 구간.** 팔별 카운터 + 시작 확정으로도 세트 직전 헛카운트 0.22/세트(35°)·0.12(50°)다. 기준 0.05 에 못 미친다. 남은 후보: 준비 카운트다운 종료 직후 1초 무시, 두 사이클 확정 창 4초 → 3초, 편집기의 교대/동시 선택에 따른 병합창 조정. 휴대폰 라벨 세트에서 실제 발생률을 본 뒤 정한다.
- **평활 제거의 폰 위험.** 폰 튐 빈도가 미측정이다. 튐이 잦으면 §4.2 조건부 필터를 켠다. 그래도 안 되면 "3점 중앙값은 반복당 샘플 ≥ 8 일 때만" (v4 이전 규약)으로 돌아가는 것이 차선이다.
- **MediaPipe 편향.** 깊은 굴곡을 얕게 읽는다. 35° 게이트에는 여유가 있지만 컬 50° 게이트와 모든 ROM 기준에는 직접 영향이다. 단계 2 가 답한다.
- **교대 정의.** 한쪽 1회 = 1회는 MM-Fit 과 일치하지만 사용자 기대와 다를 수 있다. 준비 안내로 밝히고 편집기 옵션으로 연다.
- **런지 ROM 부재.** AIHub GT 로 `knee_mean` 기준을 다시 뽑기 전까지 런지는 ROM 참고 없이 센다.
- **다른 15개 서서 종목.** 이 설계는 세 종목에서만 실측됐다. 같은 규칙(R1~R4)으로 신호를 재검토하되, 검증 데이터가 없는 종목은 바꾸지 않는다.
- **원칙 #4 와의 긴장.** 컬 게이트 민감도 표는 MM-Fit 에서 잰 것이다. 채택 근거는 AIHub ROM 분포이고 MM-Fit 은 확인용이라는 구분을 문서에 남겼다. 이 구분이 흐려지면 그것이 곧 데이터셋 적합이다.
