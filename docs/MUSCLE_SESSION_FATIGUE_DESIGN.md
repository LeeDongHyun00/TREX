# 세션 기반 근육 피로 추정 — 개발 설계 v0

2026-09-28 · 상태: **설계안, 피로 기능 미구현**

## 1. 제품 결정

추정치의 편리함을 우선해 현재 입력으로 동작하는 기능을 만든다. 이름은 **운동 피로 추정**, 수치는 **0–100점**으로 제안한다. 추정 대상은 TREX에 기록한 운동 세션의 잔여 부하다. 수면·영양·스트레스·질병·나이·개인차를 모두 계산한 전체 회복 상태는 범위 밖이다.

사용자는 추가 설문 없이 첫 운동부터 결과를 볼 수 있다. 중량·노력도 입력은 추후 선택 사항이다. 현재 입력이 적으면 평균적 수행을 가정하는 `간편 추정`을 사용한다. 해당 숫자는 신체 능력의 손실 백분율이 아니며, 100점도 근육이 완전히 기능을 잃었다는 뜻이 아니다.

첫 버전은 **맨몸 스쿼트, 맨몸 전방 런지, 서서 덤벨 컬**에 한정한다. 종목 이름이 비슷해도 바벨 스쿼트·스플릿 스쿼트·해머 컬 등에는 별도 프로필 없이 자동 적용하지 않는다. 첫 버전부터 가능한 것은 아래 세 가지다.

1. 이번 세션에서 사용한 대표 근육군과 기록된 횟수·세트.
2. 이전 세션의 잔여량을 합친 현재 피로 추정 색.
3. 시간이 지나며 추정 색이 옅어지는 변화와 각 운동의 기여 기록.

## 2. 연구 근거와 제품 가정의 경계

아래 논문은 모델의 방향을 뒷받침한다. **이 문서의 12회 기준, 근육 가중치, 체격 보정 지수, 6/24시간 반감기, 0–100 변환 계수는 논문에서 검증된 상수가 아니다.** 개발 초기의 공개된 조정값이며 별도 버전으로 관리한다.

빠른 감소와 느린 잔여량을 섞는 아래 두 지수함수는 **TREX가 제안하는 축약 모델**이다. 빠른 항을 젖산, 느린 항을 근손상처럼 특정 생리학적 물질에 일대일 대응시키지 않는다. 기존 Banister의 적응/피로 두 항과도 동일한 모델이 아니다. 적응량에서 피로를 빼는 수행 예측이 아니라, 비음수인 두 잔여 부하를 더하는 표시 모델이다.

## 3. 입력 계약 — 현재 데이터로 시작

|---|---|---|

| 종료 시각 | 경과 시간과 감소 계산 | 과거 날짜만 있으면 시각 범위로 결과 범위 표시, 정오를 실제 시각처럼 만들지 않음 |
| 실제 작업/휴식 시간 | 기록에 보존, v0에서 횟수와 중복 가산하지 않음 | 추정 초/회는 측정값으로 쓰지 않음 |
| 자세 결과 | 별도 관측 정보와 부위 해석의 한계 표시 | null·TRACK·ABSTAIN도 완료 횟수가 있으면 부하 추정 가능 |

`자세 정확도 × 운동량` 계산은 하지 않는다. 잘못 수행한 반복도 신체 부하를 발생시킨다. beta 판정이나 잘 안 보인 세트라는 이유로 피로를 자동으로 낮추지 않는다. 횟수의 가시성 부족은 입력 출처/추정 범위를 바꾸며, 부하량에 신뢰도 점수를 곱하지 않는다.

### 반복 단위

- 스쿼트 양측 동시 12회: 왼다리와 오른다리 각각 12회의 해당 역할을 수행한 것으로 기록한다. 총 24회라고 사용자 기록을 바꾸지 않는다.
- 양팔 동시 컬 12회: 팔 각각 12회. 한 팔 컬과 교대 컬은 독립 변형으로 처리한다.
- 런지 `SIDE_EACH`: 확인된 왼쪽/오른쪽 횟수를 사용한다.
- 런지 `SIDE_PAIR`: 완성 1쌍을 왼쪽 1회 + 오른쪽 1회로 변환한다. 남은 한쪽은 쪽별 로그가 확인될 때 해당 쪽에 더한다.
- 원래 의미를 모르는 과거 ‘12회’는 12쌍으로 간주하지 않는다. 좌우 미상으로 보존한다.

## 4. 계산 구조

### 4.1 기본 수행량

세트 s, 근육군 m, 좌/우 b에 대해:

```text
D[s,m,b] = (n[s,b] / 12) × B[s] × w[exercise,m,role] × E[s]
```

- `D`: 차원 없는 ‘모델 부하 단위’. kg, 칼로리, 근력 손실 %가 아니다.
- `n`: 위 단위를 정규화한 해당 쪽 실제 반복. 0이면 기여 0. 일부 수행 후 건너뛴 세트도 완료한 부분은 남긴다.
- `12`: 표시 스케일을 위한 기준 반복 수. 생리학적 최적 반복 수라는 뜻이 아니다.
- `w`: 아래 근육군 역할 가중치. 전체 합을 1로 정규화하지 않는다. 여러 근육군이 동시에 부하를 받는 모델이다.
- `E`: v0 기본값 1.0, 평균적 노력도를 가정. 중량 미입력 컬도 E=1로 `중량 미반영` 추정을 제공한다.

v0에서는 세트 경계를 보존하지만 같은 총 반복/시각이면 기본 수행량은 같다. 3×10과 6×5의 실제 노력도 차이를 모르는 상태에서 임의로 알아냈다고 하지 않는다. 1차 모델의 명시적 단순화다. 추후 RIR 및 실제 휴식으로 구분한다. 수행 시간·가동범위·정확도를 여기에 동시에 곱하는 방식은 중복 반영과 관측 편향 때문에 v0에 넣지 않는다.

### 4.2 키·몸무게 보정

맨몸 스쿼트·전방 런지의 v0 보정 제안:

```text
B = clamp(((체중kg / 70) × (키cm / 170))^0.25, 0.85, 1.15)
덤벨 컬: B = 1.0
```

같은 상대적 움직임에서 신체를 들어 올리는 외적 일의 대략적인 규모는 `질량 × 중력 × 이동 높이`와 관련된다. 이를 근피로로 직접 환산할 수 없으므로 체격의 영향을 약하게 제한한다. **0.25 지수와 ±15% 제한, 70kg/170cm 기준은 설계 가정**이다. 근육량·근력·BMI를 추정한 공식이 아니다. 추후 데이터에서 체격 보정이 도움이 되지 않으면 B=1 모델로 되돌린다.

컬은 외부 덤벨 중량이 주된 미확인 부하이므로 키·몸무게로 덤벨 무게를 만들어내지 않는다. 추정치를 제공하되 체격 변화에 따라 컬 점수를 임의 변경하지 않는 것이 첫 버전 정책이다. 사용자 체격이 바뀌어도 과거 세트는 당시 프로필 스냅샷으로 계산한다. 성별 모델은 표시 선택이며 기본 피로 상수를 바꾸지 않는다.

### 4.3 근육군 역할의 초기 가중치

**숫자는 모두 제품 초기값이다.** 근육 참여 관계는 [스쿼트 연구](https://pubmed.ncbi.nlm.nih.gov/19075302/), [컬 연구](https://pubmed.ncbi.nlm.nih.gov/30013836/), [런지 연구](https://pubmed.ncbi.nlm.nih.gov/32236133/)와 기존 `outputs/muscle-mode-exercises/EXERCISE_RESEARCH.md`를 따른다. EMG 비율을 가중치로 변환하지 않았다.

| 근육군 | 스쿼트 각 다리 | 전방 런지 앞다리 | 덤벨 컬 각 팔 |
|---|---:|---:|---:|
| 대퇴사두근군 | 1.00 | 1.00 | — |
| 대둔근 | 1.00 | 1.00 | — |
| 햄스트링 | 0.25 | 0.35 | — |
| 중·소둔근 | 0.20 | 0.45 | — |
| 내전근군 | 0.35 | 0.35 | — |
| 종아리 | 0.20 | 0.25 | — |
| 팔꿈치 굽힘군: 이두근·상완근 | — | — | 1.00 |
| 상완요골근 | — | — | 0.50 |
| 전완 그립·손목 안정근군 | — | — | 0.20 |

전방 런지 뒷다리의 위 하체 근육군은 초기값 `앞다리 가중치 × 0.25`로 두어 지지 역할을 남긴다. 이는 실측 앞/뒤 부하 비율이 아니며 별도 검증 대상이다. 완성된 왼쪽/오른쪽 런지는 각 다리가 앞/뒤 역할을 번갈아 받은 것으로 더한다.

체간은 좌우 반복을 합산해 두 배로 만들지 않는다. 실제 동작 사이클당 복벽·척추기립근군에 스쿼트/런지 0.15, 컬 0.05를 적용한다. `—`는 해당 프로필에서 산정하지 않음이며 생리학적 활성 0의 의미가 아니다. 손·발·경부·늑간근 전체에 일괄 피로를 뿌리지 않는다.

첫 버전은 군 단위 추정이므로 대퇴사두근의 네 근육을 개별 측정한 것처럼 표시하지 않는다. 같은 군의 메시에는 동일한 군 지표를 전달하고 선택 시 ‘대퇴사두근군 추정’이라고 명시한다. 모델의 154개 변형 개수를 계산 해상도로 착각하지 않는다.

### 4.4 시간에 따른 감소와 누적

```text
K(Δh) = a × 2^(-Δh / hFast) + (1-a) × 2^(-Δh / hSlow)
L[m,b,t] = Σ D[s,m,b] × K((t - endedAt[s]) / 1시간)
F[m,b,t] = 100 × (1 - exp(-L[m,b,t] / 6))
```

- 기본 `a=0.35`, `hFast=6시간`, `hSlow=24시간`. 반감기이며 완전 회복 시간은 아니다.
- 가산 대상은 해당 시각까지 발생한 세트다. 미래 사건을 포함하지 않는다. 초/시간 단위를 엄격히 나눈다.
- 잔여량 L을 먼저 더하고 마지막에 점수 F로 변환한다. 80점+50점=130점처럼 표시 점수를 더하지 않는다.
- F는 0 이상 100 미만으로 포화된다. 잔여량은 잘라 버리지 않아 많은 세션을 했을 때 더 오래 남는다.
- 새 운동을 하면 기존 곡선을 0으로 초기화하지 않고 해당 부하를 추가한다. 양쪽과 군별로 독립 계산한다.
- v0에서는 운동이 없으면 단조 감소한다. 다음 날 근육통이 더 심해지는 현상을 재현하는 모델은 아니다.
- 하루마다 초기화하지 않는다. 앱을 껐다 켜도 UTC 사건 시각으로 다시 계산한다. 백그라운드 타이머가 필요 없다.

### 4.5 기본값 주변의 민감도 시나리오

| 시나리오 | 수행량 배수 | 빠른 항 비중 a | 빠른 반감기 | 느린 반감기 |
|---|---:|---:|---:|---:|
| 낮은 부하·빠른 감소 가정 | 0.7 | 0.50 | 3h | 12h |
| 기본 가정 | 1.0 | 0.35 | 6h | 24h |
| 높은 부하·느린 감소 가정 | 1.3 | 0.25 | 8h | 36h |

세 시나리오는 **95% 신뢰구간도, 개인차의 상·하한도 아니다.** 선택한 가정에 결과가 얼마나 민감한지 보는 범위다. 실제 회복이 이 범위 밖일 수 있다. 기본 화면에는 기본값을 쓰고 상세에서 ‘가정에 따른 예상 범위’를 보여준다. 노력도 입력이 생겼을 때도 0.7/1/1.3을 검증된 RIR 환산표라고 명명하지 않는다.

## 5. 계산 예시 — 식의 동작 확인용

모든 세트가 같은 시각에 끝난 것으로 단순화한 **가상 예시**다. 70kg·170cm, 맨몸 스쿼트 12회×3세트, 주요 근육군 w=1, 노력도 기본값이면 D=3이다. 실제 사용자 측정 결과가 아니다.

| 종료 후 | 기본 추정 점수 | 낮은/빠른 가정 | 높은/느린 가정 |
|---|---:|---:|---:|
| 직후 | 39.35 | 29.53 | 47.80 |
| 6h | 30.29 | 15.42 | 41.19 |
| 12h | 23.93 | 9.37 | 35.88 |
| 24h | 15.92 | 4.35 | 27.92 |
| 48h | 7.87 | 1.09 | 17.80 |
| 72h | 3.99 | 0.27 | 11.50 |

실제 UI는 소수점 대신 정수나 5점 단위를 사용한다. 예: ‘운동 피로 추정 40/100’. 오늘의 대퇴사두근 상세에는 운동 목록과 완료 횟수도 함께 표시한다.

같은 12회×3세트의 체격 보정 예시: 55kg/160cm는 B=0.9273, 37.10점; 70kg/170cm는 B=1, 39.35점; 90kg/185cm는 B=1.0876, 41.95점. **무거운 사용자가 실제로 더 피로하다는 실험 결과가 아니라 제안한 약한 보정이 만드는 출력**이다.

24시간 뒤 같은 스쿼트를 추가하면 남은 L 약 1.0406에 새 D=3을 더한다. 이때 약 49.00점이 된다. 이전 기록을 삭제하거나 하루가 바뀌었다는 이유로 잔여 부하가 사라지지 않는다.

## 6. 앱 구조와 데이터 흐름

```text
SessionProgress + 선택적 PostureSetReport
              ↓ 세트 확정 시 공통 기록 어댑터
TrainingSetLedger (세트·좌우·프로필·시각·출처)
              ↓ 운동 프로필 + modelVersion
SessionLoadEstimator → 근육군별 D
              ↓ Clock.now()와 사건 시각
ResidualLoadCalculator → L, F, 민감도 시나리오
              ↓
FatigueViewModel → 완료 화면 / 기록 상세 / 3D 색
```

### 저장 모델 제안

`TrainingSetEntity`:

- `setId` 고유키, `sessionId`, `exerciseId`, `variantId`, `ordinal`, `revision`, `status`(완료/부분/취소).
- `startedAt`, `endedAt` UTC, 실제 `workMillis`, `restMillis`, `timestampSource`.
- `completedReps`, `repUnit`, `leftReps`, `rightReps`, `pendingSide`, `countSource`(관측/사용자/계획), `countCoverage`.
- `heightCmAtSet`, `weightKgAtSet`, `profileSource`, `profileMeasuredAt`.
- 선택적 `externalLoadKg`, `loadConvention`, `rir`, `perceivedEffort`; 미입력은 null.
- 선택적 `postureSetId`, `coachMode`, `shipJudged`, `shipOk`, `abstained`, `repEngineVersion`.
- `createdAt`, `updatedAt`, `deletedAt` 또는 세트 수정 이력.

`ExerciseLoadProfile`: 종목/변형/반복 단위/군·역할 가중치/체격 정책/근거 URL/`profileVersion`.

`FatigueModelConfig`: 기준 반복·체격 지수·상하한·감소 파라미터·점수 스케일·시나리오·`modelVersion`. 최초 상태는 `heuristic_v0`이며 임상 검증 여부와 구분한다.

`FatigueSnapshot`: 계산 시각·모델 버전·원장 리비전·군별 L/F·가정·기록 범위. 재생성 가능한 캐시이며 원본 데이터가 아니다. 기록 상세의 ‘당시 결과’에는 당시 버전을 보존하고 현재 재계산과 혼동하지 않는다.

### 모듈 계약

신규 `trainingload/` 패키지에 Android 비의존 순수 계산기를 둔다. `posture` 엔진이 앱 최상위 패키지에 의존하게 만들지 않는다. 세션 계층이 DTO를 전달한다.

```text
recordSet(event, revision) → 저장 성공 / 중복 / 충돌
estimateAt(instant, modelVersion) → MuscleFatigueSnapshot
explainMuscle(muscleGroup, side, instant) → 기여 세트 + 가정 목록
rebuildFrom(earliestChangedInstant) → 캐시 무효화·재계산
```

영속화는 Room/SQLite를 제안한다. 현재 SharedPreferences 날짜 배열은 유지하되 새 세트 원장의 정본으로 쓰지 않는다. 저장소에 Room 의존성은 아직 추가하지 않았다. 한 기기 오프라인 계산을 우선하며 서버·메시지 큐·외부 API는 필요 없다. 클라우드 동기화는 나중에 안정적인 UUID/리비전 기준으로 확장한다.

### 기록 정책 보완

- 현재 `recordCompletedSession → replaceTodayWith`가 같은 날짜를 교체하므로, 새 원장은 세트별 추가/갱신하고 기존 날짜 UI는 그 원장의 조회 결과로 만든다.
- 완료 화면 재진입·회전·재시도로 같은 세트를 두 번 넣지 않는다. `setId` UNIQUE와 트랜잭션으로 멱등성을 보장한다.
- 관측이 없는 세트도 세션 진행 계층에서 기록한다. 자세 JSONL이 존재할 때만 기록하면 안 된다.
- 화면의 7일 조회 범위와 부하 원장 보관을 분리한다. 초기 제안은 원장 90일, 명시적 이력 삭제 시 관련 부하·캐시도 삭제한다. 보관 변경을 사용자에게 알리고 향후 개인화에 필요한 기간을 재검토한다.
- 첫 설치 이전의 부하는 미관측이다. ‘기록 시작 후 운동 기준’으로 표시한다. 가져올 수 없는 오래된 데이터를 0 운동으로 가정하지 않는다.
- 날짜만 있는 구형 이력은 새 원장과 중복 이관하지 않는다. 가져온 횟수·시각의 출처를 유지하고 범위 또는 간편 추정으로 보여준다.
- 현재 체격을 수정해도 과거 기록을 일괄 다시 개인화하지 않는다. 과거 스냅샷 수정은 사용자가 해당 기록을 수정했을 때만 반영한다.

## 7. 3D와 화면 설계

기존 완료 화면 레이아웃을 유지하고 운동 요약 아래에 **이번 운동 사용 부위**를 추가한다. 카드 선택 시 3D 상세를 연다.

상세의 선택지는 두 개다: `이번 운동`(현재 세션의 기여) / `현재 누적`(기존 세션 잔여 포함). 같은 색을 사용하되 제목과 범례를 함께 바꿔 맥락을 구분한다.

- 기본 회백색 `#deded9` → 높은 값의 붉은색 `#d53b35`. v0는 `F/100`로 색을 연속 보간한다. 숫자·근육 이름도 표시한다.
- 0점은 기록된 세션의 잔여량이 표시 기준 이하라는 의미. `회복 완료`, `운동해도 안전`으로 바꾸지 않는다.
- `기록 없음`, `미지원`, `계획 기반`, `중량 미반영`은 별도 상태다. 근육을 선택하면 한 줄 설명으로 가정을 확인할 수 있게 한다.
- 처음부터 긴 경고를 띄우지 않는다. 상단에 ‘기록된 운동 기준 추정’ 한 줄, 상세에 사용 가정을 둔다.
- 과거 운동 상세에는 ‘당시 운동 직후’와 ‘현재 잔여’를 명확히 나눈다. 현재 시간이 흐른다고 과거 완료 결과를 몰래 바꾸지 않는다.
- 154개 메시에는 안정적인 `muscleId → muscleGroupId + side` 매핑을 둔다. 연결층·피부·장비·뼈는 피로 산정 대상이 아니다.
- 근육도 선택/재질만 변경하고 운동 리깅·독립 변형을 피로 때문에 변경하지 않는다.

현재 약 44MB GLB를 그대로 APK의 상시 로딩 자산으로 넣지 않는다. 앱용 LOD·텍스처/정점 압축·메시 ID 보존을 별도 단계로 둔다. Android 뷰어는 GLB를 직접 쓰는 Filament 계열을 후보로 하고, 기존 웹 미리보기 재사용은 검토용 대안이다. 아직 앱의 3D 로딩 성능을 검증하거나 라이브러리를 설치하지 않았다. 로컬 웹 검토와 Android 통합 완료를 구분한다.

## 8. 구현 순서와 검증

1. **세트 원장:** 같은 날 여러 세션, 부분 수행, 좌우 단위, 재진입 중복, 기록 수정/삭제, 구형 이관을 먼저 검증.
2. **순수 계산기:** 3종 프로필·D·감소·점수·모델 버전 구현. Android 화면과 분리한 단위 검증.
3. **기록 결과 연결:** 완료 화면에서 설명 가능한 세트별 기여를 먼저 확인. 자세 점수가 달라도 같은 수행량이면 동일한 기본 부하인지 검사.
4. **3D 색 적용:** 메시 ID 누락·좌우 반전·피부 착색·기존 재질/리깅 손상 없이 군별 색을 적용.
5. **선택 입력/보정:** 중량·RIR·‘예상보다 덜/더 피곤함’ 등을 받아 모델 비교에 활용. 개인별 파라미터를 한두 응답으로 크게 변경하지 않는다.

필수 계산 불변식: 무운동 시 감소, 새 세트 추가 시 증가, 0≤F≤100, 반복 증가 시 감소하지 않음, 취소 세트 미반영, 동일 ID 중복 없음, 기록 삭제/수정 후 재계산 일치, 앱 재시작 후 같은 시각에서 같은 결과, 체격 값 미확인/범위 오류 시 출처 표시, 음수 경과·타임존·시계 역행 처리.

시간 복잡도는 최근 사건 수×영향 군 수이며 90일 로컬 기록에 적합하다. 화면을 열 때 계산하고 분 단위로만 갱신한다. 계산 목표는 보급형 기기에서도 UI 스레드를 막지 않는 것이며 구체적인 성능 수치는 구현 후 측정한다. 원장 쓰기 실패 시 ‘기록되지 않음’을 숨기고 성공 색을 띄우지 않는다.

초기 내부 검토는 수학·기록·색 표현의 정확성을 확인한다. 이후 사용자 평가에서는 추가 입력 없이도 기록 이해/부위 인지가 쉬워지는지와, 같은 조건의 이후 수행 저하·회복 경과에 대한 예측 오차를 **별도**로 측정한다. 횟수만 쓰는 모델과 체격 보정 모델, 한 개/두 개 감소 항을 비교해 복잡도가 실제 이득을 주는지 확인한다. 단순 모델이 더 낫다면 계수를 제거한다. 연구자료가 지지하는 방향과 추정식 자체의 예측 성능을 같은 검증으로 취급하지 않는다.

## 9. 이번 변경 범위

이 문서는 개발 설계다. 앱의 피로 기능·DB·계산기·3D 색 연동을 구현하지 않았다. 별도 모델 작업으로 양손 방향만 이전 결과에서 반전했고 Blender/GLB/PC 미리보기를 갱신했다. 실휴대폰은 사용자가 검증하므로 조작하지 않았다.
