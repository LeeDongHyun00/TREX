# 좌우 반복 관측과 기기 검증

작성: 2026-09-19. 구현 브랜치: `feature/pose-evaluation-engine`.

26개 요청 운동에 반복 관측 계약을 등록했다. 25개는 왕복 횟수, 플랭크는 유지 시간이다. 등록과 합성 신호 테스트 통과는 실제 사람의 운동 정확도·정자세·교정 효과를 검증했다는 뜻이 아니다. 모든 새 반복 프로필은 개발 미리보기 상태다.

## 횟수의 단위

| 수행 방식 | 목표에 더하는 값 | 측별 기록 |
|---|---|---|
| 양쪽 함께 | 양측 복귀 한 쌍에 1회 | 왼쪽·오른쪽 각각 1회와 함께 1회. 두 측 합계를 총수로 쓰지 않음 |
| 좌우 각각 | 한 측 왕복마다 1회 | 같은 쪽 연속도 포함. 목표는 좌우 합계이며 좌우 순서를 강제하지 않음 |
| 왼쪽/오른쪽만 | 선택한 측 왕복마다 1회 | 반대쪽을 선택한 측으로 대체하지 않음 |
| 런지 전체 횟수 | 전체 왕복마다 1회 | 두 무릎이 같이 굽어도 한 번. 앞다리·지지다리는 미확정 |
| 런지 왼쪽/오른쪽 기준 | 사용자가 지정한 기준 다리의 왕복마다 1회 | 자동으로 앞다리를 판별했다는 뜻이 아님 |

덤벨 컬의 기본값은 양쪽 함께, 스탠딩 니업·사이드 크런치는 좌우 각각이다. 런지는 동일한 동작에 두 이름을 붙이지 않도록 ‘양쪽 함께’를 제공하지 않는다. 운동 편집, 준비 안내, 목표, 실시간 HUD, 완료 화면, 저장 이력이 같은 단위를 사용한다. 수동 총횟수 변경은 카메라의 좌우 관측값을 재분배하지 않는다. 각 쪽 N회/좌우 N쌍 목표는 별도 계약이 필요하며 이번 구현에 없다.

## 엔진과 관측 경계

`ExerciseRepTracker`는 각 측의 복귀 FSM을 분리한다. 역위상 컬이 평균값에서 상쇄되는 문제를 피하고 가림·시각 역행·카메라 전환 때 미완료 반복만 폐기한다. 양쪽 함께 방식은 복귀 시각 차이 600ms 이내인 두 반복을 묶는다. 전체 궤적의 동시성이나 정자세를 인증하지 않는다.

`RecentRepView`는 최근 8개 프레임, 최대 3초, 최대 관측 공백 1.5초를 사용한다. 현재 프레임 방향과 창의 방향이 다르면 유보한다. 준비 프레임은 방향 창만 준비하고 반복·자세 평가·로그에 포함하지 않는다. 덤벨 컬 양측 방식은 정면 안내·시범·음성·방향 확인을 함께 적용한다. 서서 하는 운동의 카운트 지원 방향은 C/B/D이며 UNKNOWN·후방·순수 측면은 유보한다. 바닥 운동에 서 있는 사람의 yaw를 적용하지 않는다.

`withLegacySignalConstraints`는 동일한 공통 신호의 물리 범위를 보존한다. 특히 푸시업 손목 거리 붕괴 값을 새 프로필이 받아들이는 회귀를 막는다. 기존 평균 신호의 ROM 임계값을 새 좌우 신호에 옮기지 않는다. 카운트에 포함된 판정 불명 반복을 정자세 ‘유효’ 횟수로 표시하지 않는다.

현재 템포는 연속 구간 안에서만 계산한다. 최종 보고서는 마지막으로 측정 가능했던 연속 구간의 중앙값을 보존하며, 일시정지 전후 간격이나 같은 프레임의 좌우 완료를 주기로 만들지 않는다. 전체 세트 평균이나 측별 템포는 아니다.

## 보존하는 근거

세트 JSON의 기존 횟수 필드에 수행 방식, 관측 총수, 좌우/함께/미구분 수와 측별 이벤트를 추가했다. BOTH의 구형 단일 극값은 null로 남기고 두 측의 피처·완료 시각·원시 극값을 따로 기록한다. 프레임과 이벤트 및 측별 시각은 같은 세트 시작 상대시각을 사용한다. 과거 데이터의 필드 부재를 0으로 복원하지 않는다.

## 2026-09-19 기기 검증 결과

Galaxy Note10+ SM-N976N / Android 12에서 별도 평가 패키지 `com.example.trex_kotlin.replay`로 검증했다. JVM은 383건 통과, 실패·오류·생략 0건이다. 실제 기기의 서로 다른 11개 검사항목은 각 항목의 최종 시도에서 통과했다. 단일 회차에 11건을 모두 실행한 결과는 아니다.

처음 잠금화면 때문에 UI 4건이 실패했다. 잠금 해제 후 카메라·세션 2건은 통과했고, 설정 2건은 화면이 실제로 바뀌었는데 접근성 부모 노드의 오래된 선택 상태를 읽는 테스트 문제였다. 부모 노드를 갱신하고 checkable 노드의 checked 상태를 읽도록 수정한 최종 2건이 통과했다. 최초 실패 결과도 증거 폴더에 보존한다.

기기 검사에서 화면 종료와 추론 중 모델 해제가 겹쳐 task graph 오류가 발생했다. 종료 플래그로 새 분석·결과 소비를 막고, 단일 분석 executor에서 진행 중인 작업 다음에 모델을 닫도록 수정했다. 수정 후 카메라·세션 2건에서 해당 오류는 재현되지 않았다. 모든 종료 시나리오의 무오류 보장은 아니다.

저장 이미지 30회 추론은 중앙값 **90ms**, 95백분위 **100ms**, 최대 104ms였다. JPG 디코드·크기 조절·CameraX/YUV 변환·화면 표시 시간은 이 수치에 포함하지 않는다. 약 6.4초 검사 전후 thermal status는 0, 배터리 온도는 39.2°C였다(USB 충전 중). 이는 장시간 발열이나 실제 카메라 전체 지연 측정이 아니다. TTS 완료는 요청 약 2.225초 후 확인됐다.

카메라·모델·음성 검증 앱 SHA-256은 `7608b754705385632b74503118b8ae2d078b956becbcdbcb15db7cec5707dced`다. 이후 수행 방식 칩 색상과 접근성 테스트를 수정한 최종 설치 앱은 `e92dd47767d5f92784e732ddd0f213e31c28c7478c487fe3a6da9ed76625e4bf`이며 이 빌드에서 설정 2건을 통과했다. 기존 일반 앱 shared preferences 3개는 검증 전후 파일별 바이트 해시가 같았다.

## 남은 검증

- 스탠딩 사이드 크런치는 원본 프레임에서 확인한 같은 쪽 무릎 올림 변형이다. 팔만 내리거나 무릎 없이 측굴하는 반례는 합성 검증했지만, 무릎만 올리기와 정확한 몸통 수축의 구별은 아직 제한된다.
- 준비 위치를 안정적으로 관측한 뒤 움직여야 한다. 시작부터 움직이는 첫 반복, 빠른 반복, 기구 가림, 다양한 체형·의상·조명에서 실제 이벤트 정답 검증이 필요하다.
- 카메라/TTS/화면 전환 기기 테스트와 실제 사람의 횟수 정확도·교정 효과 평가는 별개다. TTS 완료 콜백은 사람이 들었거나 이해했다는 증거가 아니다.
- 스쿼트 37개 세부 이벤트·52개 문구와 26종 147개 설계 항목을 모두 활성화한 변경이 아니다. 자세 규칙의 ship/beta/exclude 상태를 승격하지 않았다.

자동 검증과 실제 기기 결과·회차별 출처는 Codex 작업 폴더의 `outputs/engine-bilateral-device/verification.json`에 기록한다. 저장 이미지 반복은 운동 횟수 정답 영상이 아니고, UI 검사는 실제 사람이 운동한 반복 로그의 증거가 아니다. 이번 검사에서 새 카운터의 실제 사람 정확도는 측정하지 않았다.
