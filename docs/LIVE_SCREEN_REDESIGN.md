## 0. 왜 이 방향이 맞나 (제1원리)

폰은 2~3 m 앞 바닥이나 선반에 놓여 있고 사용자는 운동 중이다. 지금 화면은 "폰을 손에 든 사람"을 위해 설계돼 있다 —
카메라 위에 가는 선, 12~15 sp 문장, 자동으로 접히는 제어판. 2.5 m 에서 읽히는 것은 큰 숫자 하나와 색뿐이다.

카메라 영상은 사용자에게 두 가지만 준다. ① 내가 화면에 다 들어왔나 ② 내 몸이 지금 어떻게 보이나.
②는 뼈대가 더 잘 준다(관절 위치가 영상보다 선명하고, **앱이 못 보는 관절이 그대로 드러난다** — 원칙 #5 가 공짜로 화면이 된다).
①만 따로 해결하면 영상을 치울 수 있다. 그래서 설계의 핵심은 "검은 배경"이 아니라 **①을 영상 없이 해결하는 장치**다(§2).

교정 화살표는 지금 코칭 사건이 이미 갖고 있는 정보(검사 → 부위·방향)를 그림으로 바꾸는 일이다. 새 판정이 아니다.
그래서 화살표의 신뢰 정책은 음성과 **같다**: ship 만, COACH 만. 화면이 "참고"로 남기는 beta 를 화살표로 움직이게 하면
말하지 않기로 한 판정이 몸을 바꾸게 만든다(원칙 #2·#6).

## 1. 한눈에 — 세트 중 화면 (세로)

```
┌──────────────────────────────┐
│ 2/3 세트 · 기본 스쿼트   01:12 │  위 띠: 세트 · 종목 · 세트 경과(끝내는 조건 아님) · COACH 칩
│                              │
│         ○                    │
│        /│\                   │  뼈대: 검은 바탕, 세트 시작에 배율 고정(§2.2)
│        / \   ⇦ ⇨             │  교정 화살표: ship 위반 부위에서 고칠 방향으로 맥동(§3)
│       ▢ 카메라 프레임 테두리   │  희미한 테두리: "화면 밖"을 영상 없이 보여 준다(§2.1)
│                              │
│  무릎을 발끝 방향으로          │  코칭 한 줄(큰 글자). beta 는 작은 '참고' 칩
│                              │
│      7  남음        5 / 12   │  큰 숫자 = COACH 정확 수 기준 남은 수(§4.1)
│      ◯ 들이마시기             │  호흡: 반복 위상을 따라가는 표시(§5), 소리 없음
│  [일시정지] [세트 끝] [⋯]     │  엄지 조작 3개. 나머지는 ⋯ 로 올라오는 기존 패널
└──────────────────────────────┘
```

휴식은 같은 화면 위의 상태다(§6) — 뼈대가 어두워지고 가운데에 큰 휴식 시계와 다음 세트가 뜬다.

## 2. 무대 — 검은 배경 위의 뼈대

### 2.1 영상을 치운 대가: "화면 밖"을 따로 보여 준다
- **카메라 프레임 테두리**를 희미하게(알파 0.18) 그린다. FIT_CENTER 비율 그대로. 사용자는 이 네모가 "폰이 보는 세상"임을 배운다.
- **가시성 낮은 관절**(`visibility < cut`)은 지우지 않고 **빈 원 + 점선 연결**로 그린다 — "앱이 지금 못 보는 곳". 발목·발이 잘리면 다리가 점선으로 끝난다.
  이게 원칙 #5 의 화면판이다. 지금은 안 보이는 관절을 아예 안 그려서 "다리가 없다 = 내가 잘렸다"를 사용자가 추론해야 한다.
- **잘린 쪽 테두리 발광**: 가시 관절의 경계 상자가 프레임 가장자리에 닿으면 그 변이 호박색으로 빛난다 + 한 줄("한 걸음 뒤로").
  이미 `CaptureFraming.inspect` 가 이 판단을 한다 — 준비 단계의 결과를 세트 중에도 쓰면 된다.
- **사람을 잃으면 영상 복귀**: `features.isEmpty()` 가 1.5 s 이어지면(`LivePanelController` 의 absent 와 같은 기준) 카메라 영상이 다시 떠서 자리를 잡게 한다.
  뼈대가 돌아오면 다시 검게. `PoseSample.detected` 는 쓰지 않는다(항상 true — CLAUDE.md 함정).
- **수동 토글**: 상단 띠 길게 누르기 또는 ⋯ 패널의 "카메라 보기". 세션 동안 기억.
- **준비 단계는 지금처럼 카메라 영상**이다. 자리 잡기는 영상이 빠르다. 카운트다운이 끝나는 순간 검게 바뀐다.

### 2.2 크기: 프레임마다 맞추지 않는다
"뼈대를 크게"를 경계 상자에 매 프레임 맞추면 스쿼트 하강에서 키가 줄어 뼈대가 **커지고**, 팔을 들면 작아진다 — 동작이 왜곡된다.
- 세트 시작(카운트다운 종료, 또는 첫 전신 관측 1 s 안정 — `LivePanelController.awaitingInitialFraming` 과 같은 조건)에 **배율·중심을 한 번 잠근다**.
  배율 = 화면 높이 × 0.8 ÷ 서 있는 키(px). 종목 프로필의 ROM 여유(래터럴 레이즈 팔, 런지 걸음 폭)는 `framingRegion` 으로 이미 있다 — 그 영역이 들어가게 배율을 깎는다.
- 세트 중엔 재잠금 없음. 사람을 잃고 돌아오면(§2.1) 다시 잠근다. 잠금 전엔 FIT_CENTER 그대로.
- 미러(전면 카메라)는 지금과 같다. 화살표 방향은 화면 좌표에서 계산하므로 자동으로 따라간다(§3.3).
- 바닥 종목(옆모습, 가로로 긴 몸)은 배율을 폭 기준으로 잠근다. 플랭크 정렬선은 그대로 그린다.

### 2.3 색
배경 `#000`. 뼈대 기본 흰색(알파 0.9), 연결선 4 dp. ship 위반 부위 붉음(기존 `warn`), beta 호박(기존), TRACK 비교 부위는 기존 비교 색.
이 셋의 의미는 바꾸지 않는다 — 인수인계 §7 의 판단과 같다(붉음 = 말하는 판정, 호박 = 말하지 않는 판정).

## 3. 교정 화살표

### 3.1 어휘 — 검사마다 "부위 + 방향" 하나
반복 검사(`RepFormCheck`)와 세트 창 규칙(`CoachCues`)에 **그림 사양** `FormMotion` 을 붙인다. 코드가 정본, `FAULT_LINES.md` 에 열 하나가 더 생긴다.

```
FormMotion(anchor: 관절 패턴("knee_{side}", "ankle_L","ankle_R", "shoulder_mid", "hip_mid", "elbow_{near}"),
           kind: TOWARD_MIDLINE | AWAY_MIDLINE | UP | DOWN | TOWARD_TORSO | ROTATE_IN | ROTATE_OUT,
           both: Boolean)           // 양쪽 동시(발 간격·무릎)인지, 위반 쪽만인지(런지 앞무릎·컬 가까운 팔)
```

| 검사(상태) | 위반 방향 | 화살표 |
|---|---|---|
| 발 간격(SHIP) | HIGH 넓어짐 | 양 발목에서 **안쪽으로** — 사용자 예시 "다리 벌어지면 모으라고" |
| 발 간격 · 좁음(BETA) | LOW | (화살표 없음 — beta 는 호박 점만) |
| 무릎 안쪽 모임(SHIP) | LOW | 양 무릎에서 **바깥으로**(발끝 방향) |
| 상체 숙임(SHIP, 스쿼트·컬·런지) | HIGH | 어깨 중점에서 **위로** |
| 발끝 방향(SHIP) | HIGH 바깥 / LOW 안 | 양 발 끝에 **회전 호**(안으로 / 바깥으로) |
| 팔꿈치 뜸·앞 이탈·옆 벌림·몸에서 떨어짐(SHIP, 컬) | HIGH | 해당 팔꿈치에서 **몸통 쪽으로**(엉덩이 중점 방향) |
| 런지 앞무릎 깊이(SHIP) | LOW | 뒷무릎에서 **아래로** |
| 척추의 중립(SHIP 세트 창) | drift | 어깨 중점에서 위로 + 가슴 열림(어깨 두 점 바깥으로) |
| 처음부터 알림(§90) | 시작 자세 | 같은 어휘, 첫 반복 전 정지 화살표 |

beta 검사·exclude 는 화살표가 없다. 표의 나머지는 구현 시 검사 목록(`trex-rep-replay --checks`)에서 채운다.

### 3.2 정책 — 음성과 같은 문턱
- **COACH 만, ship 만.** TRACK 은 화살표 없음(앱이 가르치지 않는다 — 원칙 #3). beta 는 호박 점 + 작은 '참고' 칩(지금과 같다).
- **한 회에 화살표 하나.** 음성이 한 문장이듯(§63 후속 2). 음성 문장을 만든 그 사건이 화살표도 만든다. 두 채널이 다른 부위를 가리키면 안 된다.
- **반복 검사는 반복이 끝난 뒤에 판정된다** — 화살표는 "방금 회"가 아니라 "다음 회에 이렇게"다. 3회 맥동(약 1.8 s) 뒤 정지 화살표로 남고, 다음 반복이 그 검사를 통과하면 사라진다. 통과 없이 12 s 가 지나면 흐려진다(음성 쿨다운과 같은 숫자).
- 유보(ABSTAIN)·판정 0건은 아무것도 그리지 않는다(원칙 #1). "깨끗" 표시도 없다.
- 길이는 고정(관절 간 거리의 0.35). 양을 말하지 않는다 — 우리는 "얼마나" 를 모른다(임계는 스튜디오 기준, §9 전).

### 3.3 그리기
- 방향 벡터는 **화면 좌표**에서 계산한다: TOWARD_MIDLINE = 엉덩이 중점 x 쪽, UP = 화면 위, TOWARD_TORSO = 엉덩이 중점 방향. 미러·뷰에 자동으로 맞는다.
- 애니메이션: 관절에서 벡터 방향으로 0 → 길이까지 600 ms 이동 + 페이드, 3회. 시스템 애니메이션 배율 0 이면 정지 화살표만.
- 앵커 관절이 가시성 cut 아래면 화살표를 그리지 않고 문장만 — 못 보는 관절에 화살표를 붙이면 거짓 확신이다.

### 3.4 검증
- `RepFormLinesTest` 와 같은 자리에 **ship 검사마다 FormMotion 이 있는지** 잠그는 테스트. `fault_lines.py` 가 열을 뽑는다.
- 방향은 (검사, 방향, 쪽) 의 결정적 함수라 **재생으로 검증된다**: 폰 지정 오류 세트(발 벌림·무릎 모임·발끝) 로그를 `run_replay.py` 로 돌려 `repForm` 사건에서 화살표 사양을 뽑고 의도한 오류와 대조.
- 실기기: 2.5 m 에서 화살표 방향이 읽히는지(사용자 1명, 스쿼트·컬·런지 각 1세트).

## 4. 숫자와 글자 — 2.5 m 에서 읽히게

### 4.1 큰 숫자 = 남은 수
- COACH: 남은 수 = 목표 − **정확 수**(§62b). 작은 글자로 `정확 5 / 감지 6 / 목표 12`. 자세로 뺀 회가 있으면 그 줄이 보인다(지금 `countNote`).
- TRACK: 남은 수 = 목표 − 감지 수. 정확/감지 구분 없음.
- 쪽별(런지 §63): `왼 3 · 오 4 남음`. 좌우 짝(SIDE_PAIR): 쌍 단위 + '반대쪽 차례'(화면 전용 — 쪽을 모르므로 말하지 않는다).
- 시간 목표: 남은 초 + 링(지금 HUD 의 링을 키운다).
- 검증 모드(§61): 숫자 대신 "검증 중"(지금과 같다).
- **함정 — 카운터가 마지막 회를 구조적으로 놓친다**(CLAUDE.md). "1 남음"에서 멈출 수 있다. 그래서 `세트 끝` 이 엄지 자리의 큰 버튼이고, "1 남음" 이 8 s 이상 멈추면 그 버튼이 맥동한다. 남은 수를 자동 종료 약속으로 격상하지 않는다.

### 4.2 크기 (6.5" 세로, 2.5 m 기준 — 구현 시 실기기로 조정)
| 요소 | 크기 |
|---|---|
| 남은 수 | 128 sp, Bold |
| 코칭 한 줄 | 28 sp, 최대 2줄, 그 이상이면 `cue`(짧은 단서)로 대체 |
| 세트·종목·시간 띠 | 18 sp |
| 보조 수(정확/감지/목표) | 16 sp |
| 참고 칩(beta) | 14 sp, 호박 |

세트 경과 시간은 **보조 정보**다(THUMB_FIRST §1: 반복 운동의 시간은 끝내는 조건이 아니다). 재촉하는 표현 없음.

### 4.3 조작
엄지 줄에 셋 — 일시정지 · 세트 끝(직접 횟수 기록으로 연결) · ⋯(기존 패널: 모드·음성·카메라 전환·운동 방법·나가기). 자동 접힘 로직(`LivePanelController`)은 그대로.
한 손이 아니라 **다가와서 누르는** 상황이므로 세 버튼 모두 높이 64 dp 이상.

## 5. 호흡 표시

- **위상을 따라가는 표시**이지 메트로놈이 아니다. `RepHysteresis.Phase`(REST·DESC·ASC)가 이미 있다: DESC = 들이마시기, ASC = 내쉬기(표준 — 신장성에 들숨, 단축성에 날숨; `ExerciseGuides.breathing` 문장과 같다). 종목 프로필에 위상 → 호흡 매핑 하나(예외: 컬은 신호가 반대 — 올릴 때 각이 줄어든다. 종목별 `concentricPhase` 한 필드).
- 홀드(플랭크)는 "자연스럽게 호흡" 과 느린 맥동 링.
- **소리 없음.** 음성과 겹치고(원칙 #6 채널 보호), 앞서 지시하면 재촉이 된다. 우리는 다음 위상을 예측하지 못한다 — 히스테리시스는 뒤따른다.
- **보이지 않는 경우**: 카운터가 없는 종목(직접 기록), 검증 모드, 사람을 잃었을 때, 위상이 REST. 카운터는 beta 라 위상도 beta 다 — 표시는 작게(링 + 단어), 큰 숫자 옆.

## 6. 휴식 — 같은 화면의 상태

지금 휴식은 별도 라우트(`SessionTransitionScreen`)라 `PostureLive` 가 컴포지션에서 빠지고 **카메라가 끊긴다**. 다음 세트는 다시 준비·자리 잡기다.
- 제안: 휴식을 `PostureLive` 안의 상태로 둔다. 뼈대 알파 0.25, 가운데 큰 링 시계(`RingGauge`) + `다음: 3/3 세트 · 12회`, 아래 `휴식 끝내기`(크게) · 일시정지.
- 세트 마감(`finalizeRef`)은 휴식 **진입 시** 지금처럼 호출한다 — §31b 의 정리 동작(폰으로 걸어옴)이 엔진에 들어가지 않게 휴식 중엔 분석 결과를 엔진에 **보내지 않는다**(프레임은 뼈대 그리기에만).
- 휴식 0 초면 "다음 세트" 카운트다운 3 초 → 바로 세트. 사용자가 프레임 밖이면 카운트다운이 서고 §2.1 영상 복귀.
- 이것은 `TrexAppState` 의 세션 단계(`SessionPhase.REST`)를 라우트가 아니라 라이브 화면의 입력으로 바꾸는 **구조 변경**이다. 가장 큰 일이라 마지막 단계(§8 P4). 그 전까지는 휴식 화면만 같은 시각 언어(검정·큰 링)로 맞춘다.

## 7. 소리 간소화

지금 소리: 회마다 숫자 TTS("일곱"), 코칭 문장(COACH·ship·한 회 한 문장·`speakLatest`), 쪽·방향 안내, 남은 수 알림, 바닥 피드백, TTS 전엔 비프.

| 층 | 지금 | 제안 | 이유 |
|---|---|---|---|
| 횟수 | 숫자 TTS | **짧은 틱 1개**. COACH 에서 자세로 뺀 회는 **낮은 틱**(다른 음) | 숫자는 길고(한국어 두 글자 ~0.5 s) 코칭과 부딪힌다. 숫자는 화면 큰 글자가 맡는다. "이 회는 세지 않았어요" 문장도 낮은 틱 + 화면 표시로 대체 |
| 코칭 | 진단 + 고치는 말 | 첫 위반: **고치는 말만**("무릎을 발끝 방향으로"). 12 s 안 재위반: `cue`. 정책(COACH·ship·한 문장·speakLatest) 불변 | "어디가"는 화살표가 가리킨다. 말은 "어떻게"만 |
| 경계 | 세트 시작·완료·휴식 끝 | 그대로(짧은 문장 + 톤) | 바닥 종목은 고개를 못 든다(CAPTURE_PREPARATION_UX §4) |
| 남은 수 | "3회 남았어요" | 마지막 3회에만 틱 2개(이중 틱) | 문장 대신 소리 패턴 |
| 호흡 | 없음 | 없음 | §5 |
| 설정 | 음소거 하나 | 음소거 하나 유지 + ⋯ 패널에 "숫자 읽어 주기" 토글(기본 끔) | 숫자 TTS 를 좋아하는 사용자가 있다. 바닥 종목은 화면을 못 보므로 거기선 기본 켬 |

틱은 `ToneGenerator` 가 아니라 짧은 샘플(`SoundPool`, 40 ms) — 비프는 "오류" 처럼 들린다. 오디오 포커스는 `SpeechCoach` 가 지금 잡는 방식 그대로.

| 단계 | 내용 | 닿는 파일 | 검증 |
|---|---|---|---|
| P0 무대 | 검은 배경·프레임 테두리·못 보는 관절 점선·배율 잠금·영상 복귀·토글·숫자 재배치(§2·§4) | `PostureLive.kt`(cameraArea·HUD 호출), `LivePoseOverlay` → 새 `SkeletonStage.kt`, `LiveWorkoutHud.kt`, `AdaptiveLayout.kt` | 배율 잠금·복귀는 순수 함수 `SkeletonFit` 로 빼서 유닛 테스트. 실기기 2.5 m 가독성 |

| P4 휴식 | 같은 화면 상태(§6) | `TrexAppState.kt`, `WorkoutSession.kt`, `SessionScreens.kt`, `PostureLive.kt` | `WorkoutSessionTest` 확장, 실기기 3세트 연속 |

**함정(구현 전에 알 것)**
- `RepForm.kt` 는 재생기 소스 목록(`replay-jvm/build.gradle.kts` engineFiles)에 있다. `FormMotion` 을 거기 쓰면 새 파일도 목록에 넣고 안드로이드·Compose 를 쓰지 않는다. Compose 색·애니메이션은 `SkeletonStage.kt`(앱 패키지)에만.
- `PostureLive` 는 종목이 바뀌어도 재컴포지션되지 않는다 — 배율 잠금·화살표 상태는 `remember(workout.id)` 가 아니라 세트 시작 사건에서 초기화한다.
- 세트 로그는 바뀌지 않아야 한다. 화살표·호흡·틱은 로그에 넣지 않는다(판정이 아니라 표시다). 넣는다면 `display` 블록 하나로, 골든 픽스처 앞 줄 불변 확인.
- 영상을 안 보여도 `Preview` 유스케이스를 끊지 않는다(일부 기기에서 `ImageAnalysis` 단독 바인딩이 프레임률을 바꾼다). `PreviewView` 를 검은 Box 뒤로 보내기만 한다. 끊는 최적화는 실기기 프레임률 측정 뒤.

## 9. 사용자가 정할 것
1. 휴식을 같은 화면에 두는 구조 변경(P4)을 할지, 휴식 화면만 같은 시각 언어로 맞출지.
2. 횟수 소리: 틱 기본(권장) vs 숫자 TTS 기본.
3. 영상을 완전히 치울지, 구석 작은 영상(PiP 96 dp)을 남길지 — 권장은 치우고 §2.1 복귀·토글.
4. 화살표를 beta 에도 줄지 — 권장은 아니오(§3.2). 주면 "참고" 라벨이 무의미해진다.
