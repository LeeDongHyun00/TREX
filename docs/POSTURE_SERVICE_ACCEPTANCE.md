## 1. 모든 시험의 공통 기록

입력 파일 해시, 출처, 시간의 실제/합성 여부, 사람/날짜/클립/뷰, 라벨의 의미와 출처, 모델/엔진/프로필/정책 해시, 장치·delegate, 기대 결과, 실제 결과, 실패 원인과 재시도 이력을 남긴다. 이전 실패를 최종 통과로 덮어 지우지 않는다.

동일 자료에서 나온 프레임·증강 이미지·여러 뷰를 독립 사람 수로 세지 않는다. 알고리즘이 만든 약한 라벨은 원래 라벨과 분리한다. 평가 라벨이나 미래 프레임을 보고 기준선 정책·단계 모델·허용 뷰·임계값을 선택하지 않는다. 사전에 고정된 정책이 평가 세션의 과거/현재 입력만으로 초반 기준을 수집하거나 현재 단계·뷰를 추론하는 것은 허용하며, 수집 조건과 평가 구간을 함께 보고한다.

## 4. 변환·재생 파리티

| 변환 | 확인할 관계 |
|---|---|

| 미러 + 관절 ID·좌표 메타데이터 변환 | 사용자 기준 좌우·문구·방향이 규약대로 교환 |

| yaw 변화 | 허용 뷰와 유보가 바뀌어야 하는 항목 확인. 모든 결과 불변 요구 금지 |
| 시간 원점 이동 | 동일 상대 시간에 동일 사건·취소 |
| 시간 확대/축소 | 지원하는 속도 범위 안에서 사건 보존, 범위 밖은 확신 감소/유보 |
| 관절 삭제 | 필요한 항목만 유보, 점수/정상 회복으로 보상하지 않음 |
| 같은 원본의 밝기·압축·블러 변화 | 피처 직접 변환과 이미지 모델 재추론을 별도 집계 |

연구 계산과 JVM의 수치 오차 허용값은 피처별 단위·정밀도로 사전 정의한다. JVM과 Android의 동일 엔진 재생은 사건·유보·측·규칙 ID가 같아야 한다. GPU/CPU 관절 출력이 달라지는 경우에는 프레임 비트 일치를 요구하지 않고 차이·판정 민감도·유보 변화를 보고한다.

## 5. 데이터 재평가와 통계

1. 기존 AIHub 라벨이 실제 표현하는 동작을 감사하고 직접 관측/대리 관측/관측 불가를 분리한다. 라벨명과 연기 설명 충돌은 미해결 상태로 기록한다.
2. 사람 분리 외부 fold와 날짜 분리 평가를 각각 만든다. 모든 뷰·프레임·증강은 원본 그룹과 함께 이동한다.
3. 안쪽 fold에서 피처·뷰·통계·threshold·calibration·유보 정책을 선택한다. 그룹 ID 부족을 일반 무작위 CV로 조용히 대체하지 않는다.
4. 기존 연구가 이미 노출한 자료는 재검증으로 표시한다. 과거 노출을 알 수 없으면 untouched test 인증 금지.
5. 각 셀의 원본 사람 수/클립 수, 클래스별 판정률, 조건부 및 전체 정상 오탐, 유보 포함 전체 위반 검출률을 낸다.
6. 수행자/클립 군집을 반영한 구간을 사용한다. 같은 사람의 수천 프레임으로 신뢰구간을 인위적으로 줄이지 않는다.
7. 현재 엔진·새 관측 엔진·제안 후보를 같은 데이터·같은 전달 수준으로 비교한다. 모든 교정을 꺼서 오탐 0인 결과와 유용한 관측 기능을 별도 평가한다.

전체 설계의 5%/60%/50% 숫자는 연구 후보 리스크 예산 제안이다. 어떤 셀도 이번에 달성했다고 선언하지 않는다. 통과해도 공개 서비스의 사람별 정확도나 행동 지시 자격은 증명되지 않는다.

## 6. 기기·서비스 상태 시험

- 권한 거부/영구 거부/실행 중 권한 취소: 같은 계획·세트를 직접 기록으로 완료할 수 있다.
- 카메라 초기화 실패/GPU 실패/CPU 전환: 작동하지 않는 카메라를 ‘관측 중’으로 표시하지 않는다.
- 가림/회전/전후면 전환/백그라운드/전화: 입력 구간과 음성 큐를 정리하고 기록을 보존한다.
- 추론 지연/열화: 입력→추론→판정→화면→TTS의 시각을 각각 측정한다. 오래된 결과를 현재 자세로 말하지 않는다.
- 세트 종료→즉시 취소→계속: 중복 반복·저장·음성 없음. 관측 구간을 새로 연다.
- 저장 용량 부족/쓰기 실패/앱 중단: 원자적 종료 또는 중단 상태가 남고 ‘저장됨’ 오표시 없음.
- TalkBack/큰 글자/좁은 화면/폴더블/애니메이션 감소: 시작·정지·종료·횟수 수정이 가려지지 않는다.
- 음소거/TTS 없음/이어폰 해제: 운동을 막지 않고 필수 상태가 화면에도 남는다.
- 기기 내 분석만 선택: 진단 원시 데이터와 영상이 저장/전송되지 않는다.
- 삭제/내보내기: 사용자 선택 범위와 실제 파일 범위가 일치한다.

초기 성능 시험 목표는 지원 기기에서 5Hz 분석, 입력→결과 p95 350ms, 오래된 관측 안내 0건이다. 수치 목표 실패 시 빠른 동작 지원을 유지한 채 결과만 늦게 내보내지 않고 지원 범위/관측 모드로 정직하게 내려간다. 장시간 시험은 기존 이미지·합성 입력으로 반복할 수 있으나 실제 카메라 열화와 모든 현실 촬영 조건을 검증했다는 뜻은 아니다.

## 7. 승인 판정

| 단계 | 승인 가능한 것 | 아직 승인할 수 없는 것 |
|---|---|---|
| 구조·상태 검사 통과 | 안정된 기록/복구/권한/상태 흐름 | 자세 정확도 |
| 반례·파리티·근거 검사 통과 | 해당 지원 조건의 관측 기능 | 26종 전체 사람별 정확도 |
| 분리된 기존 라벨 평가 통과 | 제한된 자세 참고 후보 | 새로운 가정 환경의 오탐 보장 |
| 신규 실제 사람 검증 없음 | 위 범위의 기능과 한계 표시 | 신규 개인화 교정 명령, 교정 효과·만족도 인증 |

이 문서의 목적은 기능을 중단하는 것이 아니라 검증 가능한 범위까지 완성하고, 검증하지 않은 결과를 완료로 표시하지 않는 것이다. 필수 계약 위반은 해당 기능을 숨기거나 전달 자격을 낮추되 운동 가이드·수동 기록·완료 복구는 유지한다.
