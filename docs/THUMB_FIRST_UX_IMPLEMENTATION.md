# TREX — 목표 진행과 엄지 중심 UX 구현

2026-09-11 · 정본 스펙 §42

사용자가 §41의 반복 운동 시간 종료를 철회하고, 운동마다 자세 비교와 종목·횟수·시간·세트·휴식을 편집하도록 요청했다. [설계안](THUMB_FIRST_UX_DESIGN.md)을 아래 범위로 구현했다. 이전 개인 비교 엔진과 자세 규칙의 임계값·등급은 이번 UX 작업에서 바꾸지 않았다.

## 운동 목표와 진행

`WorkoutTarget.Repetitions`와 `Duration`을 저장한다. 예전 `12회`, `30초`, `3분` 기록도 읽으며 저장할 때 명시적 단위를 함께 남긴다. 반복 속도로 계산한 시간은 계획 예상치에만 남기고 실제 종료 조건에서 제거했다.

| 단계 | 완료 조건 | 표시·조작 |
|---|---|---|
| 준비 | 사용자가 시작 | 종목별 촬영 위치, 오른쪽 아래 시작 |
| 반복·자동 측정 | 검출 수 또는 수정한 수가 목표 도달 | 큰 횟수, 아래 횟수 수정·메뉴·일시정지 |
| 반복·직접 기록 | 세트 후 실제 수행 횟수 입력 | 오른쪽 아래 횟수 기록, 목표 미달은 부분 수행 |
| 시간 운동 | 사용자가 시작한 목표 시간 소진 | 원형 진행률과 남은 시간, 일시정지 |
| 휴식 | 설정 시간 소진 | 원형 타이머, 일시정지·휴식 끝내기 |

세트 사이에만 휴식을 넣는다. 마지막 세트 뒤와 0초 휴식에는 휴식 화면이 없다. 다른 종목으로 넘어갈 때는 촬영 준비를 기다린다. 앱 비활성·일시정지·운동 메뉴/횟수 편집 중에는 측정과 시간이 멈춘다. 세트 건너뛰기는 메뉴에 있다.

부분 반복은 실제 횟수를 기록하고 전체 종목을 완료로 만들지 않는다. 중간 종료에서도 현재 반복 수를 먼저 보존한다. 세트 고유 토큰으로 늦은 카운트·타이머 이벤트의 중복 전환을 막고, 자세 리포트를 확정한 뒤 다음 단계와 기록으로 넘긴다.

## 자동 카운트의 범위

기존 카운터는 다음 하강이 있어야 직전 반복을 확정하므로 마지막 한 번을 놓쳤다. 라이브에서는 `ReturnRepTracker`를 연결해 시작 위치를 관측하고, 최소 이동 뒤 그 위치로 돌아와 잠시 안정된 사이클을 확정한다. 가림·일시정지 전후 움직임을 하나로 잇지 않는다. 연구 재생은 기본값인 기존 카운터를 유지해 과거 수치와 섞지 않는다.

**자동 카운트는 여전히 beta이며 사람별 정확도를 새로 검증하지 않았다.** 앱의 동작 이벤트를 종료 조건으로 쓰는 것은 사용자가 요청한 정책이다. 메뉴에서 참고 측정임을 알리고 횟수 수정 경로를 제공한다. 자세 가동 범위 참고 판정 때문에 검출한 수행 횟수를 지우지 않는다. 카메라 관측을 지원하더라도 등록된 반복 신호가 없는 종목은 직접 기록한다.

## 운동별 편집

운동 페이지의 각 행에서 종목·목표·자세 비교 상태·휴식을 읽고, 하단 `루틴 편집`에서 항목을 선택한다.

- 종목 변경, 추가·삭제·순서 변경
- 목표 단위 횟수/시간, 목표 수, 세트 수, 세트 간 휴식
- 선택한 운동만의 자세 비교 켜기/끄기
- 저장 전 초안, 닫으면 취소

현재 57개 프로필 중 55개는 카메라 관측을 제공한다. 혼합 동작 묶음 2개와 등록되지 않은 구형 종목은 미지원 이유를 표시한다. 비교 스위치가 있다는 이유로 미지원 자세를 채점하지 않는다. 종목 변경 시 새 종목의 기본 목표 단위를 적용하고 계획 항목 ID는 보존한다.

좌우 각각 목표와 자동 좌우 전환은 이번 구현에 포함하지 않았다. 기존 `10회`를 임의로 `20회`로 늘리지 않는다. 시간 운동을 중간에 건너뛴 경우 실제 유지 시간을 별도 부분 세트로 저장하는 기능도 후속이다.

## 화면과 모션

운동 페이지의 중첩 확장 카드를 평면 목록으로 바꿨다. 첫 진입의 의도적 260ms 대기, 400ms 폭 변화·300ms 높이 변화를 제거하고 짧은 이동/페이드로 전환한다. 자세 규칙 상세를 목록에서 바로 읽고 확장하던 경로도 제거했다. **단말 최초 진입 지연의 전후 수치를 계측한 결과는 아니다.**

운동·식단·내 정보의 하단 내비게이션은 각 화면의 기능 조작으로 전환된다. 오른쪽에 운동 시작/사진 기록/설정, 왼쪽에 편집/직접 입력/운동 기록을 둔다. 메뉴에서 화면 이동을 다시 열 수 있다. 상단은 정보를 보여 주고, 식단 중복 버튼과 내 정보의 동작하지 않는 항목을 제거했다. 기록 날짜 선택도 하단 시트로 이동했다.

실시간 화면은 목표와 한 가지 안내를 우선 표시한다. 카메라 방향·음소거·모드·세부 비교는 아래 메뉴로 옮겼다. 관측 불가·방향 오류 표시는 유지한다. 준비 안내는 종목에 맞는 촬영 위치를 알려 주고 세트 시작은 짧은 신호음을 쓴다.

가이드 사진의 외곽 상자·테두리·그림자를 제거하고 넓게 배치했다. 사진 아래에 테마 배경색으로 이어지는 그라데이션과 짧은 자막을 겹친다. 큰 글자 설정에서는 자막을 사진 밖으로 분리한다. 로그인은 원본 공룡 PNG의 투명 여백만 그릴 때 제외해 비율을 유지하고, 키보드가 열리면 로고를 작게 전환한다. 원본 이미지 파일은 수정하지 않았다.

원형 진행률은 240ms로 보간하고 시간/완료 판단 자체는 실제 시계를 따른다. 밝은 테마의 시스템 상태 표시줄 대비를 바로잡고 버튼 그림자를 줄였다. 완료 화면은 부분 수행을 끝까지 완료한 것으로 표현하지 않고, 실제 세트 수·경과 시간·예상 소모를 보여 준다. 홈 버튼은 아래에 고정했다.

## 검증

JVM 223건과 분리 앱/Android 테스트 APK 빌드가 통과했다. 운동 목표·부분 기록·이전 토큰·마지막 반복·가림/일시정지 경계를 검사한다.

Note10+의 `.replay` 앱에서 7개 검사 항목을 통과했다. UI 5개(운동별 설정 저장·검색/종목 교체, 하단 메뉴/식단/설정/날짜 선택, 시간 목표 완료, 준비·반복 비만료와 휴식 정지/재개·건너뛰기, 가이드/로그인)와 플랭크 자산 2개다. 자동 검사의 전환 대기와 검색 필드/결과의 동일 이름 구분을 수정했다. 최종 앱의 전체 실행에서 6개가 통과했고, 실패했던 편집 검사는 테스트 선택자를 수정한 뒤 단독 재실행으로 통과했다. 이것은 실제 사람의 운동을 새로 촬영한 카운트 정확도 검증이 아니다.

실기기 화면 캡처 13장, 빌드·검사 로그, 일반/분리/검사 APK는 무시되는 `research/aihub_fitness/outputs/thumb_ux/`에 보존한다. 일반 APK `trex-thumb-ux-debug.apk` SHA-256: `f73bc1c98b13af017be8846cf70df5842bf3516b2f2c3de46d0a6262087b94d1`.

Note10+의 일반 `com.example.trex_kotlin` 앱에 `install -r` 업데이트하고 실행을 확인했다. 설치 APK SHA-256이 위 빌드와 일치한다. 업데이트 전에 설정 3파일을 백업했고, 이후 `trex_store.xml` 14,307바이트와 `trex_posture.xml` 301바이트를 포함한 3파일 모두 바이트가 동일하다. 자세 기준선/외부 로그를 삭제하지 않았다. 정확한 설치 시각·파일 해시·검사별 결과는 같은 폴더의 `verification.json`에 있다.
