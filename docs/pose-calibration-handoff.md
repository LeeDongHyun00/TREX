- 상태: 진행 중 작업의 이어받기 문서. 계약이 아니며 SHA pin이 없다.
- 작성일: 2026-08-12
- 목적: 컨텍스트 전환 시점의 확정 사실·미완 작업·함정을 한 곳에 모은다. **이 문서 + 아래 아티팩트만으로 이어서 진행할 수 있어야 한다.**

## 0. 지금 당장 알아야 할 것 세 가지

1. **출시된 상수가 틀렸다.** 앱의 스텝 포워드 런지 `reachedAngleDegrees = 129`는 잘못된 카메라 뷰로 측정한 값이다. 올바른 뷰에서 재측정하면 **116°**다(§3). 13° 관대한 쪽 오차라 안전하지만, 이 상수가 `rangeUrgingSealed = false`를 푸는 유일한 근거다.
2. **스크래치패드에만 있던 측정값을 §4 표로 옮겼다.** 원본 JSON은 세션 종료로 사라진다. 표의 숫자가 유일한 기록이다.
3. **§4 표의 "구기준" 행은 전부 폐기 대상이다.** 뷰 기준과 정확도 지표가 모두 바뀌었으므로 재측정 없이 채택하면 안 된다.

## 2. 확정된 데이터 사실 (재조사 불필요)

- 라벨 전체 **34,468 clip**, 41 운동, 816 type code, **24 keypoint**(포털 설명의 COCO 17은 오기), 뷰 5개(A~E), 클립당 라벨 16프레임 + 이미지 32장(**희소 키프레임, 타임스탬프 없음**).
- 조건 라벨은 사후 평가가 아니라 **촬영 대본**이다(포털이 "정자세, 오류자세를 구분하여 취득"이라 명시). 대본 준수도가 운동마다 달라 푸시업은 3D 정답으로도 50%(우연)다.
- **Back·Waist 관절은 MediaPipe에 대응이 없다.** 척추 중립류 조건을 브리지할 수 없는 근본 원인이며, 바벨 스쿼트의 4개 조건이 5개 체인 어디서도 분리되지 않는 이유다.
- **반복 카운트 정확도는 이 데이터로 측정 불가**(연속 영상 아님). 실기기 촬영이 유일한 경로.
- 오염: type `062/101/109`, 촬영일 **`Day28_201030_F`**(2D↔3D 대응 파손, 전 뷰에서 ~100° 어긋남).

## 3. 회귀 결과 — 출시 상수의 정정 (최우선 반영 대상)

Day05, 8명, 232클립. 뷰만 바꿔 재측정한 결과다.

| | 구: 뷰 A 가정 | **신: 뷰 E (기준 교체 후)** |
|---|---:|---:|
| 임계값 | 129° | **116°** |
| LOSO | 93.5% (raw) | **92.7% (balanced)** / raw 91.8% / baseline 77.2% |
| 클립 편차 | 16.6° | **2.9°** |
| 폴드 범위 | 129~133° | 113~116° |

**해석**: 129°는 "MediaPipe 편차를 보정한 값"이 아니라 **잘못된 뷰의 편차를 흡수한 값**이었다. 뷰가 옳아지자 편차가 5분의 1로 줄고 정확도는 오히려 올랐다.

**미완**: 스텝 백워드 런지(현재 코드 `reached 123°`)는 같은 결함이 있을 가능성이 높으나 **아직 재측정하지 않았다.** 두 런지를 함께 정정해야 정책 문서 개정이 한 번으로 끝난다.

## 5. 이번에 고친 방법론 결함 (되돌리지 말 것)

| # | 결함 | 수정 | 증거 |
|---|---|---|---|
| 1 | 뷰 A를 측면으로 가정 | 촬영일별 뷰 판정 도구 | Day33 뷰 A는 높은 사선 전경 샷 |
| 2 | raw accuracy로 퇴화 분류기 통과 | balanced accuracy 게이트 | "몸통 발 무릎 방향" 81% 전 체인 → 106개→24개 |
| 3 | 극값을 방향에서 유도 | 극값·방향 분리 | 컬 50.0% → 75.6% |
| 4 | **뷰 기준이 프레임 평균** | **클립 통계량 오차로 교체** | 니업 뷰 C 오차 4.3°(허위) → **43~52°(실제)** |
| 5 | 브리지 raw vs 조사 balanced 혼용 | 브리지도 balanced 산출 | 니업 raw 85.2% ↔ bal 80.1% |
| 6 | 임계값 180 = 전건 참 | 탐색 범위에서 제외 | 잠복 상태였음 |

**4번이 가장 컸다.** 니업 클립의 24.6%가 굴곡 극단에서 최악인 뷰 C로 측정되고 있었고, 그 오염을 클립 중앙값 편차(1.63°)가 가려주고 있었다.

## 6. 미완 작업 (우선순위 순)

1. **백워드 런지 재측정** → 두 런지 상수 정정 → provenance `MEDIAPIPE_NATIVE_DAY05_FIT_V2` 신설(뷰 선택·balanced 기준 명시) → 정책 §4 표·SHA 재핀
2. **랫풀 다운 문구 분리 후 채택**: 드라이버를 ELBOW→SHOULDER로 바꾸면 앱이 "어깨가 66도까지 **굽혀졌어요**"를 출력한다. 팔꿈치-어깨-엉덩이 각이 닫히는 건 **모음(내전)**이고, 한국어에서 "어깨가 굽혀졌어요"는 **굽은 어깨(자세 평가)**로 읽힌다. 원인은 `FormCheckWorkingDirection`이 **검출기 방향과 사용자 동사를 한 enum에 묶은 것**. 동사를 체인별로 분리("모아졌어요"/"모아짐이 얕아")하고 문장 검증 테스트를 추가한 뒤 66° 채택.
3. **니업 12일 재스윕** (신기준). 이미지: `body_01/02/04/05/14/16`, 코드 033-048, 뷰 A/D/E
4. **컬 45명 재측정**. 이미지 6일 전부 확보됨(`babel_01/03/05/07` = Day04/26/12/30 + 기존 Day08/16)
5. **바벨 런지**(라벨 77.1%, `babel_02/04/06/08/09`) · **라잉 트라이셉스**(라벨 83.0%·64명, `babel_10/11/12`)
6. 브리지 아티팩트 `docs/mediapipe-aihub-bridge.v1.json` 재생성 + `--check` 모드 + 거버넌스 해시 핀. 현재 저장본은 커밋 `1ef1879` 이후 갱신된 적 없고 `"cameraView": "A"`와 "Eight subjects"를 담고 있어 **현행 방법론과 모순**
7. `measure_mediapipe_aihub_bridge.py:104-109`의 "Deliberately absent" 주석 정리 — 바로 아래 `EXERCISE_PROFILES`에 그 넷이 다 있다(같은 편집 안에서 생긴 실수)

## 7. 함정 (반복하기 쉬움)

- **증분 빌드가 소스셋 이동을 놓친다.** `src/testDebug` 추가 후 첫 실행에서 테스트 6개가 조용히 누락됐다. 소스셋을 옮겼으면 `--rerun-tasks`.
- **`gradlew test`는 양 variant를 돈다.** `testDebugUnitTest`만 돌리고 "전체 녹색"이라 하면 안 된다. `compileReleaseUnitTestKotlin`도 함께.
- **정책 문서·SHA·거버넌스 미러는 같은 커밋에서.** CRLF→LF 정규화 후 SHA-256.
- **AGENTS.md**: 작업 범위 파일만 stage. `git add -A`로 사용자의 무관한 변경을 함께 커밋한 적이 있다.
- **환경**: MediaPipe는 Python 3.12 venv 필요(`py -V:3.12 -m venv`, `pip install mediapipe opencv-python-headless`). 시스템 3.13에는 없다. 한글 경로 때문에 `cv2.imread` 대신 `cv2.imdecode(np.frombuffer(...))`.
- **원시 이미지**: `T:/trex_allData/...`(body/furniture/babel_13~15) + `data/013.피트니스자세/1.Training/원시데이터/`(babel_01~12). Day05는 라벨 디렉터리에 이미지가 함께 있어 추출 불필요.
