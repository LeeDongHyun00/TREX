# Android 체험판 1.3.0-preview.6

2026-10-06 · 브랜치 `redesign` · 태그 `v1.3.0-preview.6`

1.3.0-preview.5(검은 무대·교정 화살표)에 **한 다리 계열 네 종목의 횟수·자세 재설계(v3)** 와 **앱 내 업데이트**를 더한 체험판이다. preview.5 와 서명이 같아 **삭제 없이 업데이트로 설치**되고 기록이 유지된다.
설계 근거는 [SINGLE_LEG_FAMILY_DESIGN.md](SINGLE_LEG_FAMILY_DESIGN.md), 구현 기록은 spec §97·§98.

## 앱 내 업데이트

- 앱을 열면 6시간에 한 번 GitHub 릴리스를 확인해 **새 체험판이 있으면 대화상자로 알린다**. "업데이트" 를 누르면 APK 를 내려받아(진행률 표시) 해시를 확인한 뒤 설치 화면을 연다. "나중에" 는 하루 동안 다시 묻지 않는다.
- 처음 한 번은 Android 의 **"이 출처의 앱 허용"** 을 켜야 한다 — 앱이 그 설정 화면을 열어 준다. 운동 중에는 묻지 않는다.
- 릴리스의 `BUILD_INFO.json` 이 정본이다(`versionCode` 가 설치본보다 클 때만, `apkSHA256` 으로 파일 검증, `certificateSHA256` 이 설치본과 다르면 설치 대신 경고).
- **이 버전부터** 동작한다. preview.5 이하에는 이 기능이 없어 이번 한 번은 직접 설치해야 하고, 다음 체험판부터는 앱 안에서 한 번에 올라간다.

## 한 다리 계열 — 크로스 런지 · 사이드 런지 · 스탠딩 니업 · 스탠딩 사이드 크런치

횟수를 **다리 기하의 사이클**로 센다(무릎각·허벅지각·발목 교차). 발 위치 앵커를 쓰던 이전 판은 발을 옮기며 하는 사람의 런지를 0회로 셌다. 네 종목 모두 **왼쪽 한 번 + 오른쪽 한 번 = 1회**이고, 아래 동작은 세지 않고 이유를 말한다.

- 공통: **허리를 숙이면** 세지 않는다(니업·크런치는 서 있을 때보다 10°, 런지는 힙 힌지를 허용해 출발 22°·바닥 32°).
- 사이드 런지: 무릎이 95° 아래로 굽고 골반이 그 발 쪽으로 옮겨가야 센다. **무릎이 발끝을 넘으면** 세지 않는다.
- 크로스 런지: 발이 교차하고 더 굽은 무릎이 110° 아래·골반이 충분히 내려가야 센다.
- 스탠딩 니업: 무릎을 **접은 채** 골반 높이까지 올려야 센다. 다리를 뻗어 차면 세지 않는다.
- 스탠딩 사이드 크런치: 무릎을 굽힌 채 **옆으로** 올리며 옆구리를 접어 **팔꿈치가 무릎에 닿아야** 센다. 다리만 올리거나 앞으로 올리면 세지 않는다. 순간 접촉을 놓치지 않게 접촉 거리는 85 ms 추론 프레임에서 읽는다.
- 자세 교정(가슴 펴기·골반 균형/고정·지지 무릎·반동·가슴 정면·머리 당김·옆구리 접힘·무릎 발끝)은 **검증 전 참고(beta)** — 화면에만 보이고 음성·점수에는 쓰지 않는다. 척추 분절과 근육의 힘은 못 본다고 밝힌다.

## 알려진 한계

- 네 종목의 띠는 사용자 1명·2세션의 잠정값이다(라벨 없이 값의 군집으로 정했다). 크로스 런지에서 오른발 뒤 회가 전부 얕게 읽혀 오른쪽이 0짝이 될 수 있다 — 좌우 차이인지 3D 추정의 편향인지 다음 세트로 가른다.
- 사이드 런지의 '무릎 발끝 넘김' 은 카메라 깊이 추정에 기대므로, 깊게 앉는 회가 자주 걸릴 수 있다.
- 앱 내 업데이트는 네트워크가 없으면 조용히 건너뛴다. 설치 자체는 Android 패키지 설치기가 한다.

## 검증

- JVM 단위 테스트 **557건 통과**(실패 0), 재생기(replay-jvm) 66건, `setlog_captures.py --self-test` 50/50
- 실기기(SM-N976N): release APK 를 debug 설치본 위에 업데이트로 설치(같은 서명, versionCode 10 → 11), 기록 19개 보존, `cmd package compile -m verify` 거부 없음, 실행·크래시 없음, 업데이트 확인 로그("설치본이 최신") 확인
- 오늘 폰 세트 재생(2차 세트): 사이드 런지 24 → 4, 니업 25 → 19, 크런치 24 → 8, 크로스 런지 6 → 3 — 빠진 회의 이유는 설계 §7 표

## 빌드

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleRelease
```

release 빌드는 기존 체험판과 같은 개발 인증서(debug 키스토어)로 서명된다(`app/build.gradle.kts` `signingConfigs.getByName("debug")`). 운영 배포용 별도 서명키는 쓰지 않는다. 릴리스 자산은 `TREX-<버전>.apk`, `SHA256SUMS.txt`, `BUILD_INFO.json`(앱 내 업데이트의 정본 — **빠뜨리면 앱이 그 릴리스를 건너뛴다**).

## 업데이트와 문제 발생 시

동일 서명의 기존 설치본은 삭제 없이 업데이트한다. 설치 실패·실행 불가·기록 손실이 확인되면 릴리스를 초안으로 전환해 다운로드를 중단한다(앱은 초안을 보지 않는다). 낮은 버전 강제 설치나 앱 삭제 대신 같은 서명의 더 높은 versionCode 로 수정판을 배포해 개인 기록을 보존한다.
