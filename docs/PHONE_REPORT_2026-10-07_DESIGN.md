## 2. 공통 원인 — 네 종목이 같은 모양으로 틀린 이유

1. **횟수 입장 문턱이 '움직임이 있었다' 수준이다.** 크런치 4.5°, 레그 레이즈 20°(진폭 30°), 스쿼트 35°. 설계가 그렇게 둔 이유는 원칙 #7(모집단 정상 회 기각 ≤ 2 %)인데, 그 모집단(AIHub 16프레임 클립, MM-Fit 윗몸일으키기 5명)이 얕은 회를 많이 담고 분할 의존이라 문턱이 낮게 잡혔다.
2. **회를 지우는 사유가 거의 다 꺼져 있다.** 레그 레이즈 `knee_bent`·`one_leg`·`feet_touch`, 크런치 `shallow`. 위반 표본이 없어 검출률을 못 재서 끈 것인데, **이번 폰 세트가 바로 그 위반 표본**이다(한 다리 4회, 무릎 접기 4회, 절반 높이 2회, 어깨만 4회, 골반 내림 15 s).
3. **beta 는 침묵한다**(원칙 #2). 스쿼트 깊이(참고 ROM)·플랭크 정렬·바닥 전부. 사용자가 듣는 것은 숫자뿐이라 "교정이 없다" 가 된다 — 엔진이 본 것(9/12 범위 미달, 판별 유보 12회)은 로그에만 있다.
4. **기준 오염.** 스쿼트 발끝 시작 기준 35° vs 같은 세트의 본인 정상 블록 26~27°.
5. **측면 게이트가 조용히 전부 유보한다.** 크런치 `fc_yaw` 0.16~0.23 → 12회 유보 → 통과. 사용자는 "폰이 비스듬하다" 는 말을 듣지 못했다.
6. **문턱이 위반값 위에 있다**(플랭크 0.10 vs 골반 내림 0.086~0.107) — 위반 표본 없이 "AIHub 정상 프레임 0.16 %" 로만 정한 값.

### 3.1 스쿼트 — 깊이

**신호**: 바닥 무릎각 `knee_mean`(지금 ROM 신호). 고관절각 `hip_mean` 은 상체 기울기에 끌려 깊이 측정이 아니다(오늘 4·5·6회 무릎 86~104° 인데 고관절 126~133°).

**모집단 수치(이번 측정, MM-Fit·REHAB 스쿼트 재생 `data/*_mp_results_repform/replay.jsonl`, 바닥 무릎각)**:

| | 회 | p50 | p90 | p95 | p98 | p99 | > 110° | > 120° | > 125° |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| MM-Fit 64세트 | 498 | 93.4 | 112.2 | 116.2 | 121.1 | 124.4 | 12.9 % | 3.0 % | 1.0 % |
| REHAB24-6 18세트 | 208 | 92.9 | 116.6 | 119.9 | 124.2 | 125.0 | 20.2 % | 4.8 % | 1.0 % |

- 참고 ROM 97.9°(AIHub 90 %)는 이 두 모집단에서 40 % 를 기각한다 → 게이트 불가.
- ≤ 2 % 선은 약 125° — **그 선에서는 오늘의 얕은 회(123.6°·112.5°)가 통과한다.** MM-Fit w19 는 22회 중 91 % 가 110° 위. 즉 이 모집단은 '정상 깊이' 라벨이 아니라 '사람들이 하는 깊이' 라, 절대 깊이 문턱을 모집단 오탐으로 정할 수 없다.

**설계 — 둘을 OR 로**:

1. **본인 기준 비율**(덤벨 컬 ROM §62c 와 같은 틀). 깊이 = 사이클 최대 − 최소, 기준 = 처음 3회 중앙값, 비 < **0.75** 면 '덜 앉음'. 모집단 측정(4회째부터): 비 < 0.7 → MM-Fit 1.3 %(4/319)·REHAB 2.6 %(4/155); < 0.75 → 1.9 %·3.2 %; < 0.8 → 3.1 %·5.2 %. 최악 세트 20~33 %(세트 안 깊이가 들쭉날쭉한 사람). 오늘 세트: 기준 깊이 62°(처음 3회) → 0.75 → 바닥 > 119° 가 미달 → 9회(123.6°) 걸리고 11회(112.5°, 기준의 85 %)는 통과. 11회가 '얕게' 블록이었는지는 라벨이 없어 모른다.
2. **절대 문턱**은 AIHub 정상 클립(코치가 정상으로 라벨)의 **98 % 통과 분위수**를 폰 모델 재추출로 다시 잰다(지금 97.9 는 90 %). 재기 전에는 쓰지 않는다.

**정책**: COACH 는 미달 회를 세지 않고 "더 깊이 앉아 주세요. 이 회는 세지 않았어요"(`romCue`, 한 회 한 문장, 12 s 쿨다운 — 컬과 같다). TRACK 은 세고 '범위 미달 N회' 참고. 처음 3회가 얕으면 기준이 얕아진다 — 폰 프로토콜 '정상으로 시작' 전제이고, 절대 문턱이 생기면 "처음부터 얕아요" 시작 알림. 등급 beta → 폰 지정 세트(정상:4 얕게:3 정상:2, 2명) 검출 ≥ 80 % 뒤 ship.

### 3.2 스쿼트 — 발끝

**측정 한계부터.** 2D 발목→발끝 각은 카메라 기하에 종속이다. 발이 지면에 있고 카메라가 발을 내려다본다고 두면 실제 발끝 각 θ 와 화면각 φ 는 대략 tan φ ≈ tan θ / sin α(α = 발을 내려다보는 각). 오늘 배치(높이 0.79 m·거리 1.81 m → α ≈ 24°):

| 실제 θ | 10° | 15° | 20° | 30° | 45° |
|---|---|---|---|---|---|
| 화면 φ | ≈ 24° | ≈ 34° | ≈ 42° | ≈ 55° | ≈ 68° |

사용자 기준 '45° 이내' 를 화면각 45 로 쓰면 실제 20° 에서 걸린다. 게다가 넓게 서면 발을 안 돌려도 +14~26° 읽힌다(MediaPipe 가 발끝을 무릎 쪽으로 끈다 — `SQUAT_FOOT_RULES_RESEARCH.md` §2.2). 그래서 절대 판정은 지금도 안 쓰고 **시작 대비 변화**로 본다 — 유지한다.

**오늘 놓친 이유와 처방**:

1. **시작 기준 오염.** 기준 35.4°(처음 1.2 s) vs 본인 정상 블록 26~27°(10~15 s·30~45 s) → +8°. 처방: 기준 = **처음 3회 상단 창 중앙값 중 가장 앞을 향한 값**(최솟값). 이 세트면 ≈ 27° → 4·5·6회 Δ +14/+15/+23, 2·11회 +26/+29 (2·11 은 3번). 첫 회는 지금처럼 사이클 최대 기준으로 판정하고 3회 뒤 기준이 바뀌면 1·2회를 다시 판정하지 않는다(소급 금지 — 이미 말한 회).
2. **띠 ±15 는 그대로.** ±10 은 MM-Fit C 정상 오탐 8~9 %(연구 §2.6). 한계를 말한다: 범위 문장에 "발끝 10° 안쪽 변화는 못 봐요".
3. **발 너비 연쇄 유보는 유지**(넓게 서면 발끝 판독이 오염된다). 그 회는 발 너비로 이미 빠지므로 횟수 손해는 없다. 다만 지금은 로그에만 남으므로 HUD 에 "발끝은 발이 넓어져 못 봤어요" 를 세트에 한 번.
4. **시작 알림 띠** −5~50° → 상한 **40°**(오늘 35° 는 여전히 통과 — 이 사용자의 정상 26~35 와 벌림 41~56 의 경계). 모집단 서 있음 13~46°(연구 §2.4)에서 40 은 p90 근처로 추정 — `A7b` 재생으로 p90 을 잰 뒤 확정.

### 3.3 크런치 (엔진 `floorcycle`, 다른 작업 폴더)

- **회 인정은 진폭으로**: `shallow` 켬, 진폭 < max(**10°**, **0.6 × 처음 3회 중앙값**) 이면 세지 않고 "어깨를 바닥에서 더 들어 올려야 세요". 오늘: 기준 median(16.6, 26.1, 5.6) = 16.6 → 10° → 3·6·7·11·12회 기각(5.6~9.9), 13~15회(11.3~14.1) 통과, 좋은 회(2·4·5·8·9·10, 진폭 18~31) 전부 통과. 출발 4.5° 는 그대로 둔다(목만 당김 탐침이 '주 신호가 출발하지 않음' 에 기대고 있다).
- **모집단**: AIHub C `shallow` 8° 가 9.2 % [6.0, 13.4] 인데 16프레임 분할 의존이라 이 수치로 켜고 끌 수 없다(`floor.md`). 비율형은 분할과 무관하게 잴 수 있다 — MM-Fit 윗몸일으키기 5명(크런치형 w20 포함)의 **세트 안** 비 < 0.6 빈도로 입장 측정(스쿼트에서 같은 틀이 1.3~3.2 %), 폰 블록 세트로 확정.
- **측면 게이트는 사유별로**: 진폭 비율은 투영에 둔감하므로 `shallow` 는 `fc_yaw` ≤ **0.35** 까지 판정, 절대각 사유 `sit_up`(80°)만 0.15 유지. 그리고 유보를 **말한다**: 세트 처음 5 s 동안 정점 yaw > 0.15 가 이어지면 "폰을 몸과 나란히 두면 자세도 봐요" 한 번(지금은 로그 '판별 유보 12회' 뿐).
- '초반' 과 '중반' 의 차이는 엔진이 아니라 사용자 동작이었다(초반 3회가 5.6·16.6·26.1 로 들쭉날쭉). 처음 3회 중앙값 기준은 첫 회 하나가 약해도 버틴다.

### 3.4 레그 레이즈 (엔진 `floorcycle`, 다른 작업 폴더)

- **`one_leg` 켬**: 정점 무릎 간격 `fc_knee_gap` > 0.45(오늘 한 다리 회 0.7~1.3, 양다리 ≤ 0.1, 양다리 무릎 접기는 먼 무릎 미관측 → 유보). 위반 표본: **이 작업 폴더의 FMS 누워 한 다리 들기 90회**(`data/fms_mp_captures/back/*.cap`, 15명, CC0) — 그쪽 재생기 바닥 경로로 돌려 검출률을 잰다(캡처에 `U` 줄이 없어 up 미확인 폴백으로 돈다). 정상 기각은 AIHub C 0/298. 이 폴더의 §99 ③(`hip_ang_maxside` 20°, 같은 질문)과 합칠 때 하나로.
- **먼 다리만 든 동작은 말한다**: 지금은 무음(주 신호 = 가까운 허벅지). `fc_thigh_far` 가 20° 넘게 올랐다 내렸는데 `fc_thigh` 가 출발하지 않았으면 `one_leg` 사유로 말한다 — 크런치 `neck_only` 탐침과 같은 틀(회를 지우지 않는 사유라 2 % 입장선 대상이 아니다).
- **`knee_bent` 켬**, 상단 무릎각 중앙값 < **100°**(상수 110 → 100 으로 내려 입장 여유: AIHub C 110° 에서 1.5 % [0.3, 4.4], 진입·이탈 제외 2.7 %). 오늘 무릎 접기 48~85° 전부 걸리고 정상 회 131~149° 통과. 사용자 결정 Q10 을 이 세트가 대신한다.
- **절반 높이**: `shallow` 절대 30°(AIHub p1)는 유지하고 **본인 비율** 추가 — 진폭 < 0.7 × 처음 3회 중앙값(오늘 92° → 64°) → 7·8·10·11회(52~55°) 기각, 12회(82°) 통과.
- **좌우 뒤바뀜 한 프레임**(39.8·43.5·43.8 s: 가까운 −7 ↔ 먼 +80): 사이클이 그 프레임에서 닫히거나 열린다. 주 신호에 중앙값-3 을 쓰거나 '한 프레임 ±40° 점프 뒤 복귀' 를 교체로 보고 버린다.
- **사유 순서**: `trunk_up` → `knee_bent` → `one_leg` → `shallow` → `feet_touch`. `one_leg` 를 `shallow` 앞에 — 한 다리는 보통 높이도 모자라 얕음이 먼저 걸리면 엉뚱한 말이 나간다.

### 3.5 플랭크 (엔진 `plankhold`, 다른 작업 폴더)

- **`hips_low` 문턱 0.10 → 0.20~0.25.** 오늘 골반 내림 0.086~0.107, 버팀 0.38~0.53. AIHub C 정상 프레임의 0.10 미만은 0.4 % — 0.25 에서의 정상 프레임 비율을 `floor_replay_tables.py` 로 다시 잰 뒤 확정(무릎 ≥ 145° 프레임만, 무릎 댄 프레임은 `knees_down` 이 먼저 거른다).
- **확정 규칙**: '1 s 연속 위반' 은 한 프레임만 문턱 위로 튀어도 리셋된다. '최근 1 s 판정 칸의 70 % 이상 위반' 으로 바꾸고 이력을 둔다(멈춘 뒤 복귀는 문턱 + 0.05 위). 적립의 단조 증가는 유지.
- **음성**: STOP 사유는 두 모드 말하게 돼 있고 13.9 s 에 STOP 사건은 났다 — 실제로 들렸는지는 로그로 모른다. **발화를 세트 로그에 남긴다**(`cues[]`: 시각·문장·채널) — 다음 보고에서 "말했는가" 를 가릴 수 있게. 네 종목 공통.
- **모순 표시 정리**: 리포트에 "멈춤: 골반 8초" 와 "(참고) 정렬 이탈 0건" 이 나란히 선다. 정렬은 HOLD 칸만 보므로 "유지 구간에서 본 정렬" 로 문장을 바꾼다.
- 머리 들림(골반 내린 동안 고개 30~35°)은 참고 그대로.

## 4. 공통 설계 — 회를 지우는 사유의 입장 조건을 다시 쓴다

지금 조건은 하나다: 모집단 정상 회 기각 ≤ 2 %(원칙 #7). 바닥 모집단은 분할 의존(AIHub 16프레임)·대리(MM-Fit 윗몸일으키기)·소수(5명)라 이 조건을 **잴 수 없는** 사유가 많고, 잴 수 없으면 꺼지고, 꺼지면 사용자에게는 "아무거나 센다" 다. 사유를 셋으로 나눈다.

| 종류 | 입장 조건 | 예 |
|---|---|---|
| 절대 사유(모집단으로 잴 수 있음) | 지금 조건 그대로 | 크런치 `sit_up`, 레그 레이즈 `trunk_up` |
| 비율형(본인 처음 3회 대비) | 모집단 **세트 안** 일관성(스쿼트 1.3~3.2 %) + 폰 블록 세트 검출 ≥ 80 % | 스쿼트 깊이, 크런치·레그 레이즈 `shallow` |
| 위반 표본이 없던 사유 | **끄지 않고 켠다 — 단 회를 지우지 않고 화면 참고 칩 + 세트 끝 요약만**("무릎이 굽은 것 같은 회 4 · 참고"). 폰 블록 세트로 검출률을 잰 뒤 회를 지우는 사유로 승격 | 이번 세트 이후의 `knee_bent`·`one_leg` 는 표본이 생겼으므로 바로 켠다 |

음성 원칙은 바꾸지 않는다(beta 무음, 원칙 #2·#6). 바뀌는 것은 "엔진이 봤다" 를 화면과 세트 끝 요약에 드러내는 것이다 — 지금은 로그에만 있어 사용자가 엔진이 보는지조차 모른다.

## 5. 검증 계획

폰 블록 프로토콜(`docs/EXERCISE_TIERS.md` CSV 형식, 블록 이름 = 기각 사유, 두 세트씩, 가능하면 다른 날 한 번 더):

```
바벨 스쿼트,1,정상:4 얕게:3 발끝밖:3 정상:2
크런치,1,정상:5 어깨만:3 정상:2
라잉 레그 레이즈,1,정상:4 한다리:3 무릎접기:3 절반:2 정상:2
플랭크,1,버팀:10s 골반내림:5s 버팀:5s
```

오프라인(구현 전에 끝낼 것): 스쿼트 AIHub 정상 98 % 분위수 재측정 · 레그 레이즈 FMS 90회 `one_leg` 검출률 · 플랭크 `fc_hip_floor` 정상 분포(무릎 ≥ 145°) · 크런치 MM-Fit 비율형 오탐. 상수를 바꿀 때마다 전후 표(`floor_replay_tables.py` / `tracker_ab.py`).

## 6. 구현 순서와 자리

1. 플랭크 문턱·확정(가장 단순, 수치가 이미 있다) → 2. 레그 레이즈 사유 켜기(`one_leg`·`knee_bent`·비율형) → 3. 크런치 비율형·측면 게이트 완화 → 4. 스쿼트 깊이(새 ROM 틀, 컬 §62c 재사용) → 5. 발끝 기준 → 6. 발화 로그(`cues[]`).
- 바닥 셋의 정본은 다른 작업 폴더의 엔진이다. 그 폴더와 이 폴더(§99 ②③, FMS 데이터·`hip_ang_maxside`)를 먼저 합친다 — §99 번호 충돌을 풀고, 양다리 판별은 하나만 남긴다.
- 모든 변경은 두 모드 중 **COACH 의 횟수**만 바꾼다(TRACK 은 전부 세고 참고 표시). 사용자 결정 2026-09-25(`coach-mode-counts-only-correct-reps`)와 같다.

## 7. 이 문서가 말하지 않는 것

- 폰 1명 1세션의 수치다. 문턱은 전부 잠정이고 §5 뒤 확정한다.
- "그냥 다리만 올려도" 는 절반 높이(7·8회)로 읽었다. 다른 뜻(허리를 띄운 채 올림 등)이면 허리 뜸은 2D 로 못 보는 범위다(`leg_raise.md` '못 보는 것').
- 음성이 실제로 나갔는지는 어느 세트도 로그로 확인할 수 없다 — §3.5 의 발화 로그가 먼저다.
