# 홈·루틴 요약·항목별 카드 (2026-09-12)

사용자가 선택한 기준은 현재 배포 브랜치 `edf5641`이다. 폴더블 브랜치를 합치지 않는다.

## 화면 범위

- 홈: 최근 7일 운동한 날짜, 칼로리 목표/섭취, 오늘 루틴 이미지·중심·예상 시간, 식단 기록 버튼만 표시한다. 날짜 표시는 기존 운동 기록을 사용하며 앱 접속을 운동 출석으로 만들지 않는다. `운동하기`는 운동 목록으로, `식단 보기`는 식단 탭으로, `식단 기록하기`는 현재 끼니 입력 시트로 연결한다.
- 운동: 제목 아래에 공통 루틴 요약을 추가한다. 목록은 각 행을 독립적인 둥근 카드로 구분한다. 행의 이름·목표·완료·자세 교정 토글·수정 버튼과 길게 누르기/스와이프/삭제 확인은 유지한다. 요약은 기존 단일 헤더 안에 넣어 드래그 슬롯 인덱스를 바꾸지 않는다.
- 식단: 기존 끼니 이름·음식 목록·열량을 카드로 감싼다. 영양 요약·목표 수정·최근 기록·하단 입력 흐름은 변경하지 않는다.

## 중심 분류

`routineOverview`는 각 운동의 설정을 `timing()`으로 해석하여 **세트당 운동 초 × 세트 수**를 카테고리별로 합산한다. 반복 운동의 설정 속도, 시간 운동 목표를 반영하며 휴식 시간은 부위 비중에 넣지 않는다. 이는 훈련 강도나 개인별 운동 효과에 대한 평가가 아닌 목록 요약이다.

하체 / 상체(가슴·등·어깨·팔) / 코어(복근) / 유산소 / 회복으로 묶는다. 본운동이 있다면 회복 시간을 분류에서 제외한다. 회복만 있으면 회복 중심이다. 최대 비중이 45% 이상이고 2위와 차이가 10%p 이상일 때만 해당 중심을 표시한다. 동률·혼합·알 수 없는 카테고리는 전신 이미지로 표시한다. 기준은 제품용 분류 정책이며 생리학적 검증 수치가 아니다.

예상 시간은 `workout.timing().totalSeconds`를 전체 합산한 뒤 한 번만 분 단위 올림한다. 모든 운동과 세트 사이 휴식은 포함한다. 촬영 준비·장소 이동 시간은 포함하지 않으므로 `약`으로 표시한다. 완료·순서 변경으로 오늘 루틴의 중심이 바뀌지는 않으며 종목/목표/세트/속도 편집 시 다시 계산한다. 빈 목록은 0분 루틴인 것처럼 표시하지 않고 추가 안내를 한다.

## 이미지

내장 image_gen으로 하체·상체·코어·유산소·회복·전신의 6종을 제작했다. 따뜻한 아이보리 배경, 올리브색 운동복, 절제한 스튜디오 일러스트를 공유한다. 원본은 생성 도구 보관 위치에 남겨 두고 앱용 파일을 `app/src/main/assets/routine/`에 복사했다. 프롬프트는 `ROUTINE_IMAGE_PROMPTS.json`에 기록한다. 이미지는 루틴 종류를 구분하는 장식이며 자세 판정의 정답 자료가 아니다.

이미지는 IO 작업에서 절반 해상도로 디코딩하고 최대 3개를 메모리에 캐시한다. 같은 이미지로 탭 이동할 때 반복 디코딩하지 않으며 이미지를 불러올 때 텍스트/버튼 레이아웃은 고정된다. 220ms 교차 전환을 사용한다. 이미지 자체의 설명/글자는 없고 화면의 실제 텍스트가 루틴 의미를 전달한다.

검증 증빙은 `research/aihub_fitness/outputs/routine-overview/`에 보관한다.

- JVM 250건 통과(추가한 루틴 분류·시간 계산 6건 포함). 빈 목록, 카테고리별 이미지, 회복 제외, 비슷한 비중, 휴식 제외, 합산 후 올림, 횟수/속도 편집, 완료 상태 불변을 확인했다.

- 새로운 이미지는 카테고리 장식만 제공한다. 실제 자동 준비·자세/횟수 정확도에 대한 추가 검증 또는 성능 향상을 주장하지 않는다.
