# TREX 화면 디자인 감사 — 그림·움직임·배치의 기준과 전 화면 평가 (2026-11-07)

사용자 요청: "Liftoff·Nike 같은 피트니스 앱처럼 **동적인 애니메이션**, **텍스트 대신 다른 요소**, **보기 좋은 레이아웃·배치**로 **한눈에 들어오고 쓰기 좋게** 바꾸고 싶다. 자료를 먼저 찾고, 그 자료와 내 바람을 지지하거나 박살내서 기준을 만든 뒤, 그 기준으로 모든 페이지와 팝업을 평가해라."

이 문서의 순서: §1 자료 → §2 바람을 자료로 지지/박살 → §3 기준(K1~K10) → §4 전 화면 평가표 → §5 조치 목록(우선순위) → §6 하지 않을 것 → §7 검증 방법 → §8 사용자가 정할 것. 화면 목록은 코드 전수 조사(2026-11-07, `feature/design-v2-pages` `55a6115d`)와 실기기(SM-N976N) 스크린샷을 근거로 했다.

## 0. 한 장 요약

**판정.** 바람 넷 가운데 셋은 자료가 지지하고, 하나는 절반만 지지한다.

| 바람 | 판정 | 근거 한 줄 |
|---|---|---|
| 동적인 애니메이션 | **조건부 지지** — "무엇이 바뀌었나"를 알리는 움직임만, 100~400 ms, 한 번에 하나 | NN/g: 애니메이션은 피드백·방향·상태 변화에만, 장식·반복·겹침은 사용성을 깎는다. 자주 보는 것일수록 짧고 미묘하게 |
| 텍스트 대신 다른 요소 | **절반 지지, 절반 박살** — 글을 *없애는* 게 아니라 *둘째 자리로*. 아이콘엔 라벨, 안전·불확실성·파괴 행동은 글이 1차 | NN/g 아이콘 연구: 보편 아이콘은 홈·검색·프린트 정도, 나머지는 라벨 없이는 못 알아본다. 우리 실측: 운동 거리 2.5 m 에선 어떤 글자도 안 읽힌다(§129) ↔ 날씨 이모지는 오독돼 아이콘으로 되돌렸다(#64) |
| 보기 좋은 레이아웃·배치 | **지지** — 상단은 읽고 하단은 조작(엄지), 둘러보기는 그림 카드·비교는 목록, 같은 제목 반복 금지 | Hoober 1,333명 관찰: 49 % 한 손; NN/g 카드 vs 목록; 우리 THUMB_FIRST 설계 |
| 한눈에 들어오고 쓰기 좋게 | **지지, 단 정직성 제약** — 화면마다 큰 숫자 하나 또는 채움(링·막대) 하나; 유보·미측정은 채우지 않는다 | Apple 링("숫자 대신 시각", 닫힘/안 닫힘), Blascheck: 막대·도넛은 ~160~250 ms 에 읽힘·방사형은 1.5 s; 원칙 #1·#2·#5 |

**박살난 것(자료가 반대한 바람의 일부).** ① "Liftoff 처럼 XP·랭크·마스코트를 전면에": 게임화 효과는 메타분석에서 '작음·단기'(걸음 +489/일, 중앙값 7주)이고 NTC 비평은 트로피를 '과한 기능'으로 꼽는다 → 보상은 **보조 칸**, 기록 사실이 1차. ② "글을 아이콘으로": 라벨 없는 아이콘은 실패한다 → 아이콘 + 짧은 라벨, 글리프 어휘는 3개 이내. ③ "움직이는 화면": 세션 무대의 무한 루프·장식 등장은 금지, reduced-motion 존중. ④ "링으로 점수": 자세 점수를 링으로 채우면 유보가 '깨끗'으로 보인다(원칙 #1) → 자세는 색 칩 + 분모.

**기준 10개.** K1 한눈 지표 · K2 글은 둘째 자리 · K3 색 = 뜻 · K4 움직임 = 변화 알림 · K5 엄지 줄 · K6 둘러보기는 그림, 비교는 목록 · K7 운동 거리 가독(세션) · K8 정직한 시각화 · K9 보상은 보조 · K10 상태 완결(빈·로딩·오류·파괴 확인).

**평가 집계(§4 표 55행 — 화면·시트·대화상자, 개발용 제외).** 바꿀 것 없음 24 · 작은 손질 21 · 다시 짜야 함 10. 다시 짜야 할 10개 중 6개는 **§131(격차 페이지)로 새로 만든 화면**이다 — 디자인 캔버스 v2 가 글 중심 카드였기 때문이고, 세션(카메라·HUD·무대)은 이미 기준을 가장 잘 지킨다.

**우선순위 상위 8(§5).** A15 세션 '이 회 제외' 기호(§125a 승인) · A14 휴식 화면 남은 시간 1차 · A21 완료 화면 순서·글 절반 · A6/A7 운동 탭 행 글리프 · A8 카탈로그 부위 그림 칩 · A11 종목 상세에 근육도 · A4 하단 내비 모핑 애니 · A5/A24 값 변화 애니 묶음(물·XP·막대).

## 2. 바람을 자료로 지지하거나 박살내기

### 2.1 "동적인 애니메이션"
- **지지하는 부분.** 값이 바뀔 때의 움직임(횟수가 오르고, 바가 차고, 링이 돌고, 탭이 어디서 왔는지)은 NN/g 의 '피드백·방향·상태 변화' 목적에 정확히 맞고, Nunes & Drèze 의 진행 가시성과도 이어진다. 완료 화면 XP 바(2026-11-07)가 이 종류다.
- **박살내는 부분.** ① 등장 장식(카드가 날아들기, 파티클, 흔들림)은 "애니메이션은 관련 없어도 주의를 끈다 — 사용성을 실질적으로 깎는다"(NN/g). ② 반복·무한 루프는 운동 무대에서 뼈대·화살표와 경쟁한다 — 우리 큐 맥동이 1.8 s 뒤 **정지**하는 설계가 맞다(호흡 링만 기능이라 예외). ③ 500 ms 이상은 끌림; 자주 보는 전환(탭·휴식)은 200 ms 대. ④ 여러 애니 동시 금지(완료 화면에서 숫자 카운트업·XP 바·배지가 한꺼번에 움직이면 안 된다 — 순서대로). ⑤ reduced-motion 을 켠 사용자에겐 끝 상태로 바로.
- **결론 → K4.** "움직임은 '무엇이 바뀌었나'를 알릴 때만, 100~400 ms, 한 번에 하나, 반복 없음, 시스템 설정 존중."

### 2.2 "텍스트 대신 다른 요소"
- **지지하는 부분.** 운동 중(2.5 m)과 '한눈' 화면에서는 글자가 정보가 아니다(§129 실측, Apple HIG). 선택 목록에서 그림·글리프는 둘러보기를 빠르게 하고(NN/g 카드), 기억을 돕는다(Bateman).
- **박살내는 부분.** ① 아이콘 단독은 실패한다(NN/g: 라벨 필수, 5초 규칙; 우리 이모지 오독). ② 뜻이 있는 숫자는 숫자가 낫다(NRC: 거리 플랜은 숫자). ③ **글이 1차여야 하는 곳**이 있다 — 되돌릴 수 없는 행동 확인(삭제·탈퇴·동기화 방향), 법적 동의, 그리고 우리 원칙 #1·#2·#5 의 불확실성 고지("판정하지 못했다", "beta", "추정"). 이것을 그림으로 바꾸면 거짓 안심이 된다. ④ 세트 기록·댓글 같은 **비교·입력**은 표와 목록이 맞다(Strong).
- **결론 → K2.** "글을 둘째 자리로: 화면당 설명 문장(≤ 13 sp)은 2개 이하이고 없어도 행동할 수 있어야 한다. 아이콘엔 라벨. 예외 셋(파괴 확인·법적 동의·불확실성 고지)은 글이 1차." 그리고 **K3**: 색과 글리프에 뜻을 고정하고 화면마다 다르게 쓰지 않는다(§125 가 이미 세션에서 한 일을 앱 전체로).

### 2.3 "레이아웃과 배치를 보기 좋게"
- **지지.** '보기 좋다'를 검사 가능한 말로 바꾸면 셋이다: 엄지가 닿는 곳에 주 행동 하나(Hoober·THUMB_FIRST), 읽는 것은 위·조작은 아래, 같은 모양의 카드가 줄줄이 반복되지 않음(NN/g 목록·우리 §132 의 목표별 묶음).
- **박살.** "카드를 더 둥글고 크게"는 기준이 아니다. 행마다 둥근 상자·그림자는 THUMB_FIRST 시각 언어가 이미 금지했다(여백·정렬·얇은 선으로 묶기). 필터·탭·칩을 늘리는 것은 NTC 비평의 '압도'로 간다 — 필터 줄은 2개까지.
- **결론 → K5·K6.**

### 2.4 "한눈에 들어오고 사용하기 좋게"
- **지지.** 화면마다 '3초 안에 아는 것' 하나: 큰 숫자 또는 채움 하나(Apple 링, Wear hero metric, Blascheck 도넛·막대).
- **박살.** ① 자세·판정을 링이나 점수 채움으로 만들면 유보가 '깨끗'으로 보인다(원칙 #1) → 자세는 **색 칩 + 분모**(지금 완료 화면 방식)로 남긴다. ② 추정·미측정을 채우지 않는다(빗금·회색·빈 칸). ③ 링은 '닫아라'로 재촉하지 않는다(Apple 링 비판, NN/g 다크패턴).
- **결론 → K1·K8.**

### 2.5 "Liftoff·Nike 처럼" 자체에 대해
두 앱의 **장치**(그림 카드·수준 라벨·시범 애니·진행 바)는 가져오되 **구조**(랭크·마스코트·트로피 전면, 페이월, 필터 과잉)는 가져오지 않는다. 게임화는 효과가 작고 단기라(Nishi 2024·Yang 2022) 기록 사실보다 앞에 둘 이유가 없고, NTC 조차 트로피가 '과하다'는 평을 받았다. 우리 XP·배지는 서버 권위도 없다(`docs/SERVER_REQUIREMENTS_PAGES_V2.md` §2-2). → **K9 보상은 보조.**

## 6. 하지 않을 것(자료가 반대하거나 우리 원칙과 충돌)

1. **마스코트·랭크·트로피를 전면에** — 게임화 효과는 작고 단기(Nishi 2024, Yang 2022), NTC 비평 '과한 기능'. 보상은 한 칸.
2. **아이콘 단독 표기** — NN/g; 우리 이모지 오독. 아이콘엔 라벨, 글리프 어휘는 ✕·화살표·점 셋 이내(§125a).
3. **등장 장식·파티클·무한 루프·배경 사진 애니** — NN/g '관련 없는 움직임은 사용성을 깎음'. 호흡 링·GIF 시범·1.8 s 맥동만 예외.
4. **500 ms 이상 전환, 여러 애니 동시** — NN/g.
5. **자세 점수를 링·채움으로** — 유보가 '깨끗'으로 보임(원칙 #1). 자세는 색 칩 + 분모.
6. **세션 중 글자 키우기** — 2~3 m 에선 어떤 크기도 안 읽힘(§125a). 숫자·색·기호만.
7. **'링 닫기' 재촉·끊김 공포 문구** — Apple 링 비판, NN/g 다크패턴, Lally.
8. **필터·탭·칩 줄 늘리기** — NTC '압도'. 필터는 2줄까지.
9. **가짜 진행률·추정값을 채워 그리기** — K8.
10. **`PostureLiveSessionScreen` 에 지역 상태 추가** — VerifyError(§108c).

## 7. 검증 방법

| 검사 | 방법 |
|---|---|
| 3초 테스트(K1) | 화면을 3초 보여 주고 덮은 뒤 "운동 몇 세트 남았나 / 물 몇 잔 / 오늘 했나" 답하기 — 본인 + 1명 |
| 5초 규칙(K2) | 새 글리프마다 "이게 뭘 뜻하나" 5초 안에 답이 안 나오면 라벨 추가 |
| 글자 수(K2) | `grep -c "fontSize = 1[0-3]" <파일>` 로 ≤ 13 sp Text 수를 세고, 문장형(마침표·요/룡)만 추려 화면당 ≤ 2(1회성 화면 ≤ 5) |
| 색 대조(K3) | 화면마다 쓰인 색을 K3 표와 대조 — 같은 색 다른 뜻이 있으면 위반 |
| 애니 표(K4) | 새 애니마다 (무엇이 바뀌나, ms, 동시 수) 세 칸을 PR 설명에 적기. `adb shell settings put global animator_duration_scale 0` 으로 '애니메이션 제거' 상태를 실기기에서 확인하고 되돌리기(`1.0`) |
| 엄지(K5) | 실기기 한 손으로 주 행동만 눌러 세션 한 바퀴 |
| 2.5 m(K7) | `research/aihub_fitness/DEVICE_VALIDATION.md` 의 거리 절차 — HUD 숫자 72 vs 128 sp 비교(A18) |
| 정직(K8) | 기록 0 · 유보 세트 · 추정 세트만 있는 날을 만들어 화면이 '좋음'처럼 보이지 않는지 |
| dex 검증 | 세션 화면을 건드린 뒤 `adb shell cmd package compile -m verify -f com.example.trex_kotlin` → `failed to verify` 0 |
| iPhone | `bash gradlew -PiosOnly=true :ios-ui:compileKotlinIosArm64`(Mac) — 공통 API 만 썼는지 |
