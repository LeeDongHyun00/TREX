# 남은 종목 등급표·온보딩 절차

*2026-09-27. 사용자 결정: "남은 운동들을 효율적으로 피드백하고 개선" — 계열 단위·등급 먼저·오프라인 거름·폰은 계열당 한 번.*

## 왜 이 절차인가

스쿼트·덤벨 컬·런지는 한 종목씩 개발했다. 폰 세트를 찍고, 말로 설명하고, 원본 로그를 분석하고, 재설계하고, 다시 폰으로 돌아가는 순환에 사흘이 걸렸다. 비용의 상당 부분은 **공용 기반**을 처음 만드는 값이었다.

- 음성 경로
- 뷰 잠금
- 본인 기준 오염 방지
- 반복 창
- 2단 차단
- 쪽별 카운트
- 크래시 수정
- 자동 진행 대기

이 기반은 이제 다 있다. 그래서 남은 23종목은 다음과 같이 진행한다.

1. **등급(끝)을 먼저 정한다.** 23종목 모두를 같은 깊이로 만들지 않는다.
2. **계열로 묶는다.** 완료 종목의 검사 틀을 재사용한다.
3. **오프라인 표(`family_scorecard.py`)로 먼저 거른다.**
4. **폰 검증은 계열당 한 번**이다. 대화에는 원본 로그 대신 표를 주고받는다.

## 등급과 완료 기준

| 등급 | 사용자에게 주는 것 | 완료 기준 |
|---|---|---|
| **A** | 횟수 + ship 반복 검사 1~3개(음성 교정, COACH 에서 틀린 회 제외) | ① 모집단 정상 반복의 차단 오탐 ≤ 2 %(원칙 #7) ② 폰 지정 오류 세트 검출 ≥ 80 % ③ 폰 정상 블록 오탐 없음 ④ 횟수 ±1 |
| **B** | 횟수 + beta 반복 검사(화면 '참고'만) + 못 보는 것 문장(`PostureScope`) | 표 ①② + 폰 한 세트로 횟수·유보 확인 |
| **C** | 횟수(또는 시간·직접 기록) + 못 보는 것 문장 | 폰 한 세트로 횟수 확인 |

C 는 실패가 아니다. 카메라로 못 보는 것을 밝히는 정직한 등급이다(원칙 #1·#5).

## 계열 온보딩 절차

1. **새 세션.** 이 문서와 가까운 완료 종목의 `docs/exercises/<종목>.md` 만 읽는다. 긴 대화를 이어 쓰지 않는다.
2. **검사 정의.** 완료 종목의 검사 틀을 종목 인자로 재사용한다. 예: `RepFormSpecs.curl(ex)`·`lunge(ex)`.
   - 새 검사는 AIHub 조건에서 1~2개만 만든다.
   - `family_scorecard.py` 의 `PROXIES`·`CONDITIONS`·`PHONE_BLOCKS` 에 그 종목 줄을 더한다.
3. **오프라인 표.** 약 2분 걸린다. 입장 ✗ 인 검사는 beta 로 시작한다.

   ```
   python research/external_rep_replay/family_scorecard.py --exercise "<AIHub 이름>" --out <폴더>
   ```

4. **폰.** 계열 전체를 아래 형식의 프로토콜로 한 번에 찍는다(15~20분).

   ```
   python research/aihub_fitness/pull_logs.py
   python research/external_rep_replay/family_scorecard.py --exercise ... --phone <로그 폴더> --protocol <csv> --since <날짜>
   ```

   대화에는 `scorecard.md` 표만 붙인다.
5. **고치기.** 표에서 튀는 것만 고치고 표를 한 번 더 돌린다. 다중 에이전트 검토는 **계열 끝에 한 번**만 한다.
6. **기록.** spec 에 절 하나를 쓰고, `docs/exercises/<계열>.md` 와 이 표의 '상태' 를 갱신한다.

## 폰 지정 오류 세트 프로토콜 (CSV)

```
exercise,order,blocks
바벨 컬,1,정상:5 팔꿈치앞:3 정상:2
바벨 컬,2,정상:4 숙임:3 팔꿈치벌림:3
바벨 런지,1,정상:4 얕게:3 숙임:3
```

- **`order`** 는 그날 로그에서 그 종목의 몇 번째 세트인지다(시각 순, `--since` 이후).
- **`blocks`** 는 순서대로 `이름:반복 수` 다. 블록 이름은 `family_scorecard.PHONE_BLOCKS` 에 있다.
- **세트는 정상 반복으로 시작한다.** 본인 기준 검사의 기준이 정상 자세에서 서야 한다.
- **센 반복 수가 계획과 다르면** 그 세트는 '정렬 불확실' 로 채점에서 빠진다. 블록 사이에 1~2초 멈추면 카운터가 덜 틀린다.
- **런지류의 반복 수는 걸음 수다**(쪽별 카운트의 사이클 = 걸음).

## 토큰 규칙 (이 절차를 만든 이유)

- 계열마다 새 세션을 연다. 인수인계는 이 표의 '상태' 와 spec 절이다.
- 원본 로그·긴 문서를 대화로 읽지 않는다. 표와 필요한 줄만 읽는다.
- 여러 에이전트를 쓰는 조사·검토는 계열 끝에 한 번만 한다. 종목마다 하지 않는다.
- 재생·채점·문서 정리 같은 기계 작업은 가벼운 모델·낮은 노력으로 한다.
- `CLAUDE.md` 는 공통 원칙·함정만 둔다. 모든 세션과 하위 에이전트에 매번 들어가기 때문이다. 종목 세부는 `docs/exercises/` 에 둔다.
