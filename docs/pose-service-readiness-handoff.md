## 0. 한 줄 진단

> **엔진은 서비스에 근접했고, 그것을 감싼 앱이 아직 데모다.** 남은 것은 ML도 거버넌스도 아니라 평범한 앱 만들기 — 저장하고, 말하고, 가짜를 치우는 일이다.

## 1. 현재 위치 (정직한 평가)

무엇이 완성됐고 무엇이 미완인지 구분해야 판단이 선다.

| 축 | 상태 |
|---|---|
| 안전·거버넌스 | 상위권. fail-closed가 타입 시스템 수준에서 강제되고, 기권 규율·언어 seal·provenance 표기가 작동한다 |
| 코어 알고리즘 | 견고. 16종, 4개 체인, 굽힘/폄 양방향, 홀드 모드, 개인 기준선, 다중인물 방어 |
| 테스트 | 412개(Android) + 199개(tools), 양 variant 컴파일 |
| **임계값 근거** | **16종 중 2종만 데이터 보정, 그마저 정정 필요**([보정 문서](pose-calibration-handoff.md) §3) |
| **실기기 동작 확인** | **0회.** 실제 폰에서 끝까지 도는 걸 아무도 본 적이 없다 |
| **반복 카운트 정확도** | **미측정.** AI Hub로는 원천 측정 불가(희소 키프레임) |
| **앱으로서의 완성도** | **데모 수준.** §3 참조 |

**"틀린 말을 하지 않는 시스템"은 완성했고, "맞는 말을 하는 시스템"인지는 검증 전이다.** 전자는 설계로 만들었지만 후자는 측정으로만 얻는다.

## 2. 필수 — 이것 없으면 서비스가 아니라 데모 (약 2주)

### ① 영속화 (최대 격차, ~4일)

**앱이 아무것도 기억하지 못한다.** 운동 기록은 `TrexData.kt`의 시드 데이터 + 메모리뿐이라 재시작하면 전부 사라진다. 사용자가 두 번째로 앱을 열었을 때 어제 기록이 없으면 그 순간 서비스가 아니다.

- Room 또는 DataStore로 운동 기록·오늘 계획·온보딩 선택 저장. **로컬 전용이라 오프라인 원칙 불변** (INTERNET 권한 없음이 이 앱의 강점이지 약점이 아니다)
- **결정 필요**: 자세 체크의 반복 수를 기록에 넣을지. 현재 정책 §5-2가 금지하므로 넣으려면 **문서 개정 + SHA 재핀 선행**. 권고: 반복 수만(각도·좌표 제외) 허용으로 개정 — 리텐션의 최소 조건이다

### ② 실기기 스모크 검증 (반나절, 유일하게 촬영이 필요)

`DevPoseCapture.ENABLED`를 켜고 본인이 스쿼트·런지·푸시업 각 1세트 → 캡처를 리플레이 fixture로 승격(`src/testDebug/resources/formcheck/`).

이건 데이터 수집이 아니라 **1회성 검증**이다. IMAGE 모드·스튜디오에서 적합한 값이 실제 폰 VIDEO 모드에서 성립하는지 확인하는 것. 이것 없이 실사용자에게 주는 것은 "아마 되겠지"로 배포하는 것이다.

### ③ 세션 UX 마감 (~3일)

- **음성 반복 카운트** — 스쿼트 중에 화면을 볼 수 있는 사용자는 없다. 지금은 시작 안내만 발화하고 카운트·관찰은 화면 전용이다. 이 카테고리 앱의 표준 UX가 빠져 있다. 호스트 `onAnnounce` 경로가 이미 있어 배선만 하면 된다
- **세트 종료 요약 카드**(메모리 전용) — 반복 수·미집계 사유·최저점 범위. v2 계획 §1.6에 설계만 있고 미구현
- 16종 전부 토글이 실제 세션 화면까지 도달하는지 수동 확인 1회

### ④ 가짜 화면 정리 (~2일)

- `AuthScreens.kt` 2,226줄이 **아무 값이나 통과시키는 가짜 로그인**이다. 가짜 인증은 없느니만 못하다 — 로컬 프로필(이름+목표만)로 대체하거나 제거
- 식단 탭(2,036줄, 목 데이터) — ①의 저장소에 연결하거나 v1에서 숨김. 눈에 띄게 가짜인 탭 하나가 앱 전체의 신뢰를 깎는다

### ⑤ release 빌드 정비 (~1일)

서명 설정, `isMinifyEnabled = true` + MediaPipe keep 규칙, versionCode 체계. 현재 release는 컴파일만 확인된 상태다.

## 4. 임계값 근거의 장기 구조 (권고)

지금은 provenance가 두 개뿐이라 "문헌 근거 있음"과 "근거 없음"이 구분되지 않는다. 사다리로 만들 것:

```
LITERATURE_STANDARD    문헌 표준          → 배포 자유, 즉시 적용 가능
        ↓ 검증·교정
SELF_DEVICE_FIT        자체 실기기 적합    → 최종 소유권. VIDEO 모드·실환경·권리 clean
        ↕ 교차검증(참고)
MEDIAPIPE_NATIVE_*     AI Hub 연구 범위    → 문서 근거. 앱의 최종 출처가 아님
```

**`LITERATURE_STANDARD` 신설이 시급하다.** 현재 스쿼트·푸시업·플랭크가 `HEURISTIC_DEFAULT`(근거 없음)로 표기되지만 실제로는 문헌 표준 기반이다.

확인된 외부 근거:

| 운동 | 문헌 기준 | 출처 |
|---|---|---|
| 스쿼트 | 평행 = 무릎 굴곡 ~90°(내각 ~90°), 깊음 110~135° | [IJSPT 생체역학 리뷰](https://ijspt.scholasticahq.com/article/94600-a-biomechanical-review-of-the-squat-exercise-implications-for-clinical-practice) |
| 푸시업 | 팔꿈치 90° 굴곡 후 완전 신전 | 군·체력검정 표준 |
| 플랭크 | 머리~발뒤꿈치 일직선, 엉덩이 처짐 시 종료 | 표준 검사 프로토콜 |

**중요**: 문헌 대조 결과 현재 스쿼트 105°는 **평행 스쿼트를 정확히 겨냥한 값**이다(문헌 내각 90° + 측정된 MediaPipe 편차 +13° ≈ 103°). 이전에 "과엄격 의심"이라 적은 추정은 문헌 대조로 정정됐다.

**단안 자세추정의 물리적 한계**: 무릎 각도 MAE **2D 9.3~21.9°, 3D 14.1~25.8°**([Scientific Reports](https://www.nature.com/articles/s41598-025-22626-7)). 우리 측정치 13.4°는 정상 범위이며 폰 1대 구성에서 개선 여지가 거의 없다. 따라서 **임계값을 정밀하게 만드는 것보다 관대하게 두고 정직하게 고지하는 것**이 옳은 방향이고, 현재 설계가 이미 그렇다.

## 5. 경쟁 위치 (조사 완료)

| 서비스 | 접근 |
|---|---|
| **Peloton Guide** | **반복을 세지 않는다.** 세트 시간의 80% 동안 움직였는지만 본다 — 정확한 카운트 문제를 회피 |
| Kemtai | 111포인트를 Vicon 대조 검증. 단 그건 **관절 위치 정확도**이지 판정 임계값의 타당성이 아님 |
| 업계 전반 | 독립 평가: *"정확도 주장을 느슨하게 한다"* |

학계의 임계값 방식 반복 카운트 기대 성능: **80~95%**(OBO 79%). 이것이 우리 방식의 사전확률이며, 우리 구현의 실제 값은 §2-②로만 얻는다.

**우리 위치**: 임계값 출처를 운동별로 명시하고 미보정을 고지하는 것은 이 업계에서 이례적이다. 커버리지·정확도는 열위지만 정직성은 우위다.

## 6. 명시적 비목표

- **정식 판정(SL-3)** — 외부 Gold·수백 명 표본·서명 인프라 필요. 캡스톤 범위 밖. release 체인 봉인 유지가 올바른 상태
- **백엔드 서버** — v1에 불필요. 완전 오프라인은 약점이 아니라 가장 강한 이야기다
- **AI Hub 추가 발굴** — 깔때기가 닫혔다(41종 → 조건 있음 → 분리됨 → 제품 효과 있음). [보정 문서](pose-calibration-handoff.md) 참조

## 7. 권장 순서

```
① 영속화 ─┬─ ③ UX 마감(음성 카운트·요약) ─ ④ 가짜 화면 정리 ─ ⑤ release 정비
          └─ (병렬) ② 실기기 스모크 검증 ─ 반복 정확도 실측 ─ SELF_DEVICE_FIT 도입
```

③④가 ①의 저장소를 전제하므로 **①부터**. ②는 ①과 독립이라 병렬 가능하며, 보정 트랙의 잔여 작업보다 우선순위가 높다 — **이미 배포된 상수의 실기기 재현성이 아직 나오지 않은 숫자보다 중요**하기 때문이다.
