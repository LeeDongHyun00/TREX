# 고정 휴대폰 촬영 준비 구현 (§46)

2026-09-11. 사용자가 이전 설계안의 구현을 요청했다. 자세 비교를 켠 카메라 지원 운동의 PREPARE 단계에 적용한다. 자세 비교가 꺼진 운동의 수동 준비, 반복/시간 목표, 휴식, 세트 건너뛰기 확인은 유지한다.

## 사용자 흐름

운동 시작 → 실제 카메라 미리보기와 방향 시범 → ‘준비 시작’ → 사용자가 자리 잡기 → 촬영 범위 안정 확인 → 원형 카운트다운 → 운동.

- 시범은 고정된 휴대폰 표식 앞에서 인물이 회전하는 코드 기반 그림이다. 정면·오른쪽 앞·왼쪽 앞·측면·바닥 측면·바닥 사선 프로필을 처리한다. 전면/후면 미리보기의 반전과 같은 방식으로 시범도 반전하며 오른어깨/왼어깨 문구는 사용자 본인 기준이다. 시스템 애니메이션 비활성화 시 목표 방향 정지 그림을 보여 준다.
- 프로필 문구를 기기를 옮기는 지시에서 몸을 움직이는 지시로 바꿨다. 예: ‘오른어깨가 휴대폰에 더 가까워지도록 몸을 돌려 주세요.’ 운동 중 기존 방향 안내도 같은 문장을 사용한다.
- 미리보기는 FIT_CENTER를 유지한다. 준비 중 모서리 표식은 실제 분석 이미지의 4% 여백을 나타내며, 몸의 윤곽이나 올바른 자세 기준선은 아니다. 준비 중에는 자세 오류 하이라이트를 표시하지 않는다.
- 하단 오른쪽은 준비 시작/취소, 왼쪽은 나가기다. 긴 설명 영역만 스크롤하며 핵심 버튼은 고정한다. 바로 위에 10초/15초 선택과 직접 카운트다운 시작, 음성, 카메라 전환을 둔다.
- 자동 카운트다운은 서서 3초, 바닥 5초다. 직접 카운트다운은 기본 서서 10초/바닥 15초이며 둘 사이를 바꿀 수 있다. 직접 시작은 촬영 범위 인식을 기다리지 않는 명시적 선택이다.
- 플랭크 등 바닥 운동에서는 무릎을 대거나 편하게 앉아 준비하도록 안내한다. 준비 감지는 플랭크 버티기를 요구하지 않는다. 시간 운동의 시계는 카운트다운 종료에 시작하며 실제 버티기 시작을 검출했다고 표시하지 않는다.
- 마지막 5초는 음성 숫자를 제공하고 TTS를 사용할 수 없으면 짧은 톤으로 대체한다. 음소거에서는 원형 진행률·숫자·문장이 시작 시점을 전달한다. 방향/촬영 범위 안내가 계속 바뀌며 음성을 끊지 않도록 대기 간격을 둔다.

## 준비 감지의 범위와 한계

`CaptureFraming`은 유효한 피처와 관절 가시성을 사용한다. `PoseSample.detected`만으로 준비 완료로 판단하지 않는다. 정면/사선은 양쪽 어깨·팔꿈치·손목·골반·무릎·발목·발끝과 머리를 확인한다. 측면은 같은 쪽 관절 사슬 전체와 머리를 확인한다. 좌우의 가려진 관절을 섞어 한 몸으로 인정하지 않는다.

현재 기준은 visibility 0.55, 화면 여백 4%, 몸의 세로 크기(바닥은 긴 축) 35% 이상이다. 바운딩 범위 변화가 정규화 좌표 0.035 안에서 1.6초 이상 안정되어야 하고, 준비 시작 후 최소 2초를 기다린다. 동일한 프레임을 여러 번 읽어 안정 시간이 쌓이지 않는다. 최신 프레임이 1.2초 이상 오래되거나 관절이 가려지면 자동 카운트다운을 중단하고 준비 대기로 돌아간다.

**이 수치는 초기 구현값이며 다양한 체형·공간에서 검증된 제품 성능 수치가 아니다.** 촬영 방향의 정확성, 운동 자세의 올바름, 부상 위험을 판정하지 않는다. SIDE/UNKNOWN 등 기존 방향 추정의 한계 때문에 방향을 자동 시작의 필수 조건으로 만들지 않았다. 인식이 어려운 경우 직접 카운트다운으로 시작할 수 있고 카메라/모델 오류나 권한 거부에서는 직접 기록으로 이어갈 수 있다. 이 선택이 기존 자세 엔진의 유보를 정상으로 바꾸지는 않는다.

## 카메라와 기록 경계

- `TrexApp`은 카메라 운동의 PREPARE와 WORK를 같은 PostureSession 경로로 보낸다. `AnimatedContent.contentKey`는 같은 세트 ID를 사용하므로 첫 세트의 준비→운동에서 카메라·분석기·전후면 선택을 유지한다.
- `PostureLiveSessionScreen`의 준비 플래그는 샘플을 미리보기/촬영 범위로만 보낸다. 추론 시작 당시 준비였던 프레임은 추론이 운동 전환 뒤에 끝나도 엔진으로 넘기지 않는다. 기준선·카운터·바닥 접지선·자세 집계·세트 로그를 갱신하기 전에 반환한다.
- 세트 마감 콜백은 WORK에서만 등록한다. 준비 취소로 세트가 마감되거나 준비 프레임이 리포트에 남지 않는다. 같은 세트의 첫 운동 프레임부터 기존 엔진의 앵커/초반 비교 정책을 따른다.
- 준비의 경과 시간은 `SessionProgress.elapsedMs`나 목표 시간에 포함하지 않는다. 전환은 기존 토큰 검사와 함께 한 번만 호출한다.
- 앱 비활성화/종료 확인, 카메라 전환, 준비 취소는 시작 대기를 해제한다. 복귀만으로 다시 카운트다운하지 않는다. 프로세스가 재생성되어도 자동 시작 의사는 복원하지 않는다.
- 카메라를 떠날 때 해당 Preview/ImageAnalysis만 해제한다. 준비→운동에서 재바인딩하지 않았는지 `TrexCamera`의 bind 로그로 확인할 수 있다.

## 검증

- JVM 236건 통과: 새 10건은 명시적 준비 시작, 안정 프레임, 가림/오래된 프레임, 움직임, 중복 프레임, 취소, 직접 카운트다운, 관절 부족, 측면 가림, 잘린/비정상 좌표를 검사한다.
- 최종 Note10+ UI 검사 3건 통과(98.822초). 준비 중 목표 시간 미소모, 가로 화면의 버튼 가시성, 취소, 앱 비활성화 후 복귀, 카메라 전환 시 취소, 음소거, 카운트다운 후 시간 운동 완료와 기존 세트/휴식/건너뛰기 회귀를 검사했다. 최종 설치 결과는 `research/aihub_fitness/outputs/capture_preparation/verification.json`을 따른다.
- `camera-continuity.json`/`camera-bind.log`: 검사한 두 세트 각각 바인딩 2회(준비 최초 진입 + 명시적 전후면 전환). 준비→운동과 가로/세로 회전, 비활성화 후 복귀에서는 새 바인딩이 없었다. 검사 중 임시로 사용한 충전 중 화면 켜짐 설정은 원래 값으로 복원했다.
- 일반/분리 APK의 DEX·자산 일치와 이전 §45 APK 대비 자세 자산 5개의 바이트 불변을 확인했다. 캡처는 `screenshots/capture-preparation.png`, `capture-landscape.png`, `capture-countdown.png`에 남긴다.
- 첫 실기기 시도는 잠금 화면 때문에 3건 모두 첫 내비게이션에서 진행하지 못했다. 로그는 `device-tests-locked.log`로 보존했다. 최종 재실행 결과와 구별한다.

## 후속 검증

관측 안정 시간과 가시성 기준의 체형별 편차, 바닥 준비 자세에서 실제 동작으로 넘어갈 때 손발이 계속 들어오는지, 작은 그림만 보고 좌우 방향을 이해하는지, 음성 안내 간격과 실제 숫자 발화 타이밍은 사람을 대상으로 확인해야 한다. 본 구현/자동 테스트 통과를 자세 정확도나 실제 사용자 자동 준비 성공률로 표현하지 않는다. 휴대폰 높이를 실제로 바꿔야 하는 공간까지 몸 회전만으로 해결한다고 약속하지 않는다.
