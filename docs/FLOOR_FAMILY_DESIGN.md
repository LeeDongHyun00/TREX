## 0. 한 줄

세 종목 모두 **몸 옆에서 보이는 쪽 한 사슬**로 본다. 크런치는 **어깨–골반 현이 들린 사이클**, 레그 레이즈는 **허벅지가 들린 사이클**로 센다(지금의 머리 높이·3점 고관절각은 다른 동작으로도 채워진다). 플랭크는 벽시계 대신 **카메라가 확인한 플랭크 시간**을 잰다. 이 종목이 아닌 동작 — 목만 당김·끝까지 일어남·상체 들기·얕은 다리 들기, 무릎 대기·골반 내려감·과도한 솟음·화면 밖 — 은 두 모드 모두 **세지 않거나 시간을 멈추고 이유를 말한다**. 자세(처짐·솟음·고개·무릎 굽힘)는 전부 beta 이고 화면 '참고' 로만 보인다. 바닥에만 있던 beta 음성 예외(REP_ENGINE_DESIGN #22)를 닫는 안이다.

### 3.5 측정 필요 — 지금 데이터로는 못 정하는 것

플랭크 처짐 하한·엎드려 쉼의 `fc_hip_floor`·누움/엎드림의 중력 축각 띠(30°)·바닥 높이 폰의 `fc_yaw` 분포·`up` 뒤집힘 빈도·플랭크 유지 시간 정확도·정상 블록 거짓 멈춤률 / 크런치 정상 회의 폰 300 ms 기각률·휴식 중 고개 들기 오발화·손을 가슴에 둔 목 관측성 / 레그 레이즈 전부(연속 영상 0): 출발·최대 사이클·체류, 편 다리·한 다리·발 닿음 띠, 상단에서 발목 잘림 비율.

### 3.6 분할 의존 — 모든 AIHub '회 단위' 수치의 한계

AIHub 바닥 클립은 16프레임·시각 없음(600 ms 가정)·서 있는 높이 카메라·연기된 위반이다. 같은 크런치 θ=4° 가 귀 봉우리 분할로 1.8 %, 돌출 1.0 분할로 27.3 % 가 된다. 평균 2 % 도 특정 수행자에게 몰린다(θ=5° 에서 Z4 18 %). 그래서 **판별 띠는 전부 '잠정'** 이고, 확정 전에 실제 엔진(`FloorCycleTracker`)으로 AIHub `.cap` 을 재생해 엔진이 나눈 회로 다시 잰다(§7.1 b). 표에는 수행자별 최댓값과 95 % 신뢰구간 열을 둔다.

## 4. 엔진

### 4.1 공유 — 관측 층 `posture/FloorChain.kt`(신규, 안드로이드 의존 없음)

- **입력**: 정규화 xy·vis(= min(visibility, presence), `PostureAnalyzer.kt:212-214`)·이미지 W/H·**중력 up**. `s.upFlipped` 면 `−s.up` 으로 되돌린 원래 중력 벡터를 쓴다(뒤집힘 보정은 3D 관절 배치 휴리스틱이라 누운 자세에서 믿을 수 없다 — 추측). 수평 대비 각은 **부호 없는 축각(0~90°)** 으로 정의해 180° 튐에 둔감하게 한다.
- **좌표**: px 로 바꾸고 aspect 등방화, `LegGeometry.rollDeg(up)`(`LegCycle.kt:88`)만큼 화면을 세운다(09-27 롤 90.7° 대응). up 을 믿을 수 없으면(폰이 바닥에 평평히 누움 등) 롤 의존 피처만 유보하고 몸 내재 각은 그대로 낸다.
- **쪽 잠금**: 세트 첫 1.5 s 동안 L/R 각 쪽의 min(vis 어깨·골반·무릎·발목) 중앙값이 큰 쪽. 반대쪽이 0.2 넘게 큰 상태가 2 s 이어질 때만 바꾼다(잠정 — 폰에서 세트당 교체 횟수를 센다). `PlankAlignmentTracker` 가 쪽이 바뀌면 상태를 끊으므로(`PlankAlignment.kt:94`) 깜빡임을 막는다.
- **가시성**: 사슬 관절 ≥ 0.5. 먼 어깨·골반은 `fc_yaw` 에만 ≥ 0.2(`PlankAlignment.kt:27` 과 같은 값). 먼 무릎·발목은 두 다리 확인에만 ≥ 0.35. 먼 쪽 외삽 좌표는 평균하지 않는다.

### 4.3 유지 계열 — `posture/PlankHold.kt`(신규): `PlankHoldClock`

300 ms 칸마다 상태 하나: `HOLD` 후보 / `STOP(사유)` 후보 / 관측 없음.

- **적립(단조 증가)**: `OUT` 상태에서 HOLD 조건이 1 s 연속이면 `HOLD` 로 확정하고 그 1 s 를 소급 적립한다(카운트다운 끝이 아니라 실제 진입부터). `HOLD` 안에서는 조건을 만족하는 칸을 바로 적립(dt ≤ 750 ms 로 자름). 조건이 깨진 칸은 보류했다가, 1 s 안에 회복하면 적립하고 1 s 이어지면 `STOP` 확정과 함께 버린다 — 시계가 거꾸로 가지 않는다(`WorkoutSession.kt:106` 과 맞음).
- **출력**: `heldMs`, `wallMs`, 사유별 `stopMs`, `firstStop{t, reason}`, `segments[[t0, t1, state]]`, `source = camera|clock`.
- **폴백**: WORK 단계에서 20 s 안에 `HOLD` 가 한 번도 없고 **그동안 대부분(처음 버티기 전 시간의 절반 넘게) 화면 밖**이면 clock 으로 넘긴다(한 번 말하고, 그 세트는 리포트에 '카메라 미확인'). 몸을 보면서 멈춤 사유로 기다린 세트는 폴백하지 않고 사유를 말한다(§4.7, 리뷰 2026-10-07). HOLD 후보를 확인하는 중이면 기다린다. 로그 `hold` 에 시계 시작·마지막 판정 칸(`start_t_ms`·`end_t_ms`)·대기 사유별 시간(`wait_ms`)을 남겨 재생기가 앱의 '사람 없음' 칸을 다시 만든다.
- **브리지**: tick 루프는 TrexApp 에 있다(`TrexApp.kt:300-309`). 분석 스레드의 `heldMs` 를 홀더 객체 하나(`HoldBridge`)로 넘기고, `SessionProgress.tick` 에 `heldDeltaMs` 경로를 더한다 — 바닥 유지 종목이고 `source = camera` 일 때만 `remainingMs` 를 그 증분으로 줄인다. `elapsedMs` 는 벽시계. 화면 파라미터는 홀더 하나만 더한다(VerifyError, §9.1).
- 죽은 `HoldTracker`(`FloorTemporal.kt:24-76`)를 플랭크 경로에서 대체한다. 시계는 `PostureRule` 에 의존하지 않는다(재생기 컴파일).

- 폴백: "카메라가 플랭크를 확인하지 못해 이번 세트는 시계로 잴게요." — **촬영 실패에만**: 20 s 동안 한 번도 확인 못 했고 그동안 처음 버티기 전 시간의 절반 넘게 화면 밖이었을 때, HOLD 후보를 확인하는 중이 아닐 때. 몸을 보면서 무릎·골반·솟음·서 있음으로 기다린 것은 폴백하지 않는다(리뷰 2026-10-07: 무릎 플랭크가 시계로 플랭크 시간이 됐다 — Q3·원칙 #1 우회). 폴백 뒤에는 폴백 안내만 말한다(시작·멈춤·안내 무음 — 남은 시간이 벽시계로 줄어드는데 '멈췄어요' 라고 하면 사용자가 시간이 멈춘 줄 안다). 세트 마감(종료 확인 취소 포함)에 남은 시간 다리를 풀어 이어지는 시간은 벽시계, 분석 소식이 20 s 끊겨 다리가 벽시계로 넘어가면 HUD·리포트가 '카메라 미확인'. 세트 가동 시간(기록·근육 부하)은 인정 시간.
- 지지 방식(`fc_elbow`: 전완 / 팔 편 ≥ 150°)은 **게이트가 아니라 로그**다. 팔 편 플랭크를 시간에서 빼는 것은 사용자 결정 없는 스타일 삭제다(**Q3**). 무릎 플랭크는 기본으로 멈춤(**Q3**).
- **축소 관측**(발목만 빠졌을 때 최대 3 s 이어 셈)은 기본안에 넣지 않는다 — 못 본 시간을 세는 것은 원칙 #1 과 부딪친다. 폰에서 발목 결측 빈도를 잰 뒤 정한다(**Q5**).
- 준비 조건 ratio ≥ 8 은 시간 게이트에서 쓰지 않는다(§2 #8).

## 6. 단위·화면·음성

- **단위**: 크런치·레그 레이즈 = CYCLE(양측 동시 — 왼 1 + 오른 1 은 해당 없음). 플랭크 = 인정 시간.
- **HUD**: 크런치·레그 레이즈 큰 숫자 = 센 회, 아래 '세지 않은 동작 n · {사유}'(구현은 마지막 기각의 사유, 지금은 `sideTallies` 분기에만 있다 → CYCLE 분기 신설, `PostureLive.kt:1490-1495`). 플랭크 큰 숫자 = 인정 시간 / 목표, 아래 상태 줄('멈춤 · 무릎이 바닥에 닿음', 멈춘 동안 숫자 회색)과 작게 '경과 1:02'.
- **강조 색**: 판별 사유 부위는 흰 외곽선, beta 자세는 provisional(호박색) 채널(`PostureLive.kt:1369`), 빨강은 ship 전용. 바닥의 빨강 채널 사용(`PostureLive.kt:1368`)은 Q1 결정 뒤 옮긴다.
- **리포트**(`PostureSetReport` 바닥 분기 L171·191·223·232·253 교체): 플랭크 "버틴 시간 32초(카메라 확인) · 경과 51초 · 멈춤: 무릎 6초 · 골반 4초 · 화면 밖 9초 · 처음 멈춤 21초 · (참고) 정렬 이탈 k건"(구현 — `PlankAlignmentTracker` 는 시간이 아니라 사건을 센다. 처음 버티기 전 시간은 '확인 전: 무릎 n초'). 정렬 판정이 0건이면 '정렬 확인 못 함' — '깨끗' 금지(원칙 #1). clock 폴백이면 '카메라 미확인 · 시계 기록'. 반복 종목 "센 회 n · 세지 않은 동작 m(목만 당김 a · 끝까지 일어남 b)".

'무엇이 있어야 세는가' 를 먼저 말한다(한 다리 계열 §6).

### 7.2 폰 세션 — 계열당 한 번, 좌표 기록 빌드, 두 번째 폰으로 영상 라벨

### 7.3 통과 기준

- **크런치·레그 레이즈 판별**(잠정 → 확정): 정상 블록 놓침 ≤ 1/20 회, 오류 블록(목만·끝까지일어나기·상체들기·얕게, 켠 경우 무릎굽힘·발바닥닿음) 세지 않음 ≥ 90 %, 말한 사유가 블록 이름과 일치 ≥ 90 %, 세트 횟수 ±1, 앉아서 시작한 세트도 ±1, 쉬며화면보기 오발화 0. 모집단 쪽은 §7.1 b 의 ≤ 2 % 를 함께 만족해야 한다.
- **플랭크 시간**: 블록별 인정 시간이 영상 라벨 대비 ±1.5 s(1 s 확정 지연 + 300 ms 격자), 무릎내림·엎드려쉼 블록의 시간 제외 ≥ 90 %(1 s 지연 뒤), 정상 블록 거짓 멈춤 ≤ 2 % 시간, 비스듬한 폰에서도 시간은 센다(자세는 유보), 팔 편 블록도 센다.
- **배치**: 측면 블록 `fc_yaw` 통과 ≥ 95 %, 발쪽 25° 블록에서 자세 판정이 유보로 떨어진다.
- 실패한 판별은 꺼서 beta 참고로 내린다(원칙 #7 — 오탐 하나가 한 회를 지운다). 띠는 한 사람 값이라 확정 뒤에도 '잠정' 표기(원칙 #4).

### 7.4 beta → ship

EXERCISE_TIERS A 등급을 바닥에 맞춘다: ① AIHub MP 측면 정상 오탐 ≤ 2 %(엔진 재생 회 단위, 유지형은 2연속 클립) ② 폰 지정 오류 검출 ≥ 80 %(방향 일치 포함, 2세션 합 n ≥ 6) ③ 폰 정상 블록 오탐 0 ④ 횟수 ±1 / 시간 ±1.5 s. 모집단이 없는 항목(플랭크 처짐 하한, 편 다리, 발 닿음)은 ①을 낼 수 없으므로 **2명 이상·2세션** 폰 정상 블록으로 대체한다.
- 1순위: 레그 레이즈 머리 들림 > 40°(① 1.0~1.3 %). 2순위: 플랭크 골반 띠(솟음 쪽은 AIHub, 처짐 쪽은 폰만).
- ship 이 되면 그 검사만 COACH 에서 말하고(`speakLatest`), 정확 수/정확 유지 시간에서 뺀다 — 반복은 `PostureLive.kt:1074` 의 `!refs.floorRef[0]` 를 'ship 바닥 검사가 있을 때' 로 풀고, 플랭크는 COACH 시간 = HOLD ∧ 정렬 OK. TRACK 은 기록만(원칙 #3).
