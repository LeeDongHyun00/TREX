# 실사용 식단 사진 커버리지 측정 (2026-09-23)

사용자가 모은 **실제 식사 사진 16장**(장당 평균 3.3개 음식, 총 52개)의 기대 음식이 모델 클래스에 존재하는지 대조했다. **추론 전 단계의 사실 확인**이다 — 애초에 맞힐 수 없는 음식을 못 맞혔다고 세면 안 되기 때문이다.

도구: `training/local_prep/check_coverage_detail.js`. 사진 목록은 사용자 로컬(`Documents/카카오톡 받은 파일/식단`)에 있고 저장소에는 넣지 않았다.

## 정정 (2026-09-23 새벽) — 아래 46% 는 과장이었다

처음 셀 때 **"정확히 같은 이름의 클래스가 있는가"** 로 셌다. 앱은 그렇게 찾지 않는다 — `searchFoods` 는 부분일치를 쓰고 별칭 표도 본다. 그래서 다음이 "없음"으로 잘못 분류됐다:

- **우동** → `일식우동` 이 342종에 **이미 있었다**. "AI Hub 에 아예 없다"는 서술은 틀렸다.
- **장국 / 된장국** → `미소된장국`·`배추된장국` 에 부분일치로 닿는다. 실제로 photo16·photo14 에서 모델이 `미소된장국` 을 0.85·0.87 로 잡았다.
- **양배추** → `양배추구이` 에 닿는다.
- **초밥** → `농어초밥`·`광어초밥` 등에 닿는다(총칭 클래스가 없을 뿐이다).

앱의 실제 규칙(부분일치 + `TrexData.kt` 의 별칭 표)으로 다시 센 결과 — `training/local_prep/recount_coverage.js`:

| 기준 | 도달 가능 | 못 닿음 |
|---|---:|---:|
| 342종 (현재 탑재) | **63%** (31/49) | 37% |
| 400종 (수신 완료) | **67%** (33/49) | **33%** |

분모가 52→49 로 준 것은 `물`·`국`·`그 외 반찬` 을 뺐기 때문이다 — 음식 이름이 아니라 셀 수 없다.

**못 닿는 16개**: 연어덮밥(2) · 생강(2) · 새우덮밥 · 가라아게 · 모듬초밥 · 오징어순대 · 피자 · 토마토스파게티 · 덴푸라 · 찐대게 · 칼제비 · 다데기 · LA갈비 · 고로케.

**"도달 가능"과 "검출"은 다르다.** 위 수치는 *그 음식에 해당하는 클래스가 존재하는가* 이고, 모델이 실제로 잡는지는 별개다 — 342종 실측 검출률은 **36%** 였다(`FOOD_EVAL_RESULTS.md`). **클래스는 67% 가 있는데 검출은 36%** 라는 이 간격이 타일 추론을 1순위로 만드는 근거다. 데이터를 더 넣어도 이 간격은 안 줄어든다.

**데이터셋에 없는 24개**: 피자, 우동, 덴푸라, 가라아게, 초밥(총칭), 물회, 연어덮밥, 새우덮밥, LA갈비, 고로케, 칼제비, 다데기, 찐대게, 꼬치, 오징어순대, 양배추(생), 생강, 물 등.

일본식 외식 메뉴(우동·덴푸라·가라아게·초밥·냉모밀)와 양식(피자·스파게티)이 큰 몫이다. AI Hub 74번은 **한식 표준 메뉴 400종**이라 구조적으로 이쪽이 비어 있다.

## 따로 드러난 문제 — 이름이 달라서 못 찾는다

사용자가 쓰는 이름과 데이터셋 클래스명이 자주 다르다. **모델은 맞혔는데 검색으로는 못 찾는** 상황이 된다.

| 사용자 표현 | 클래스명 |
|---|---|
| 흰쌀밥 | 쌀밥 |
| 돈까스 | 돈가스 |
| 장국 / 된장국 / 국 | 미소된장국 등 |
| 야채무침 | 무생채 |
| 냉모밀 | 메밀국수 |
| 단무지 | 단무지무침 |
| 양념고기 | 불고기 |

이건 모델이 아니라 **앱 검색의 별칭 문제**다. 직접 기록에서 "흰쌀밥"을 쳐도 "쌀밥"이 안 나온다.

## 이 결과가 방향에 주는 함의

1. **사용자 직접 등록(개인 음식 DB)은 33% 를 받는다.** 데이터를 아무리 늘려도 안 나오는 몫이다(정정 전에는 46% 로 봤다). 비중이 줄었을 뿐 방향은 그대로다 — 피자·덴푸라·가라아게처럼 한식 데이터셋이 구조적으로 못 담는 것들이라 다른 길이 없다. 사용자가 처음 제안한 방향이 수치로 뒷받침된다.
2. **남은 묶음(25GB)은 2026-09-23 받았다. 실측 효과는 +4%p**(63%→67%, 물회·깍두기). 예상했던 6% 와 비슷한 규모다. 400종 데이터셋은 준비됐고 재학습 여부는 타일 실험 결과를 보고 정한다 — 클래스를 늘려도 검출 간격은 안 줄기 때문이다.
3. **별칭 매핑은 싸고 효과가 크다.** 데이터·모델을 건드리지 않고 검색 품질만 올린다.
4. 남은 48%에 대해 **실제 검출률**은 아직 모른다 — `eval_heldout_colab.ipynb` 의 실사용 평가 섹션으로 잰다(`eval_real.tar`).

## 한계

- 사진 16장은 통계적으로 적고, **한 사람의 식습관**(일식 외식 비중이 높다)에 치우쳐 있다. 다른 사용자에게 그대로 일반화하면 안 된다.
- 기대 음식은 파일명에 사람이 적은 것이라 판단이 섞여 있다(예: "그 외 반찬").
- 별칭 표(`check_coverage_detail.js` 의 `ALIAS`)는 손으로 만든 것이라 누락이 있을 수 있다.
