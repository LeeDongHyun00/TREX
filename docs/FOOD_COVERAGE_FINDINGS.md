# 실사용 식단 사진 커버리지 측정 (2026-09-23)

사용자가 모은 **실제 식사 사진 16장**(장당 평균 3.3개 음식, 총 52개)의 기대 음식이 모델 클래스에 존재하는지 대조했다. **추론 전 단계의 사실 확인**이다 — 애초에 맞힐 수 없는 음식을 못 맞혔다고 세면 안 되기 때문이다.

도구: `training/local_prep/check_coverage_detail.js`. 사진 목록은 사용자 로컬(`Documents/카카오톡 받은 파일/식단`)에 있고 저장소에는 넣지 않았다.

## 따로 드러난 문제 — 이름이 달라서 못 찾는다

사용자가 쓰는 이름과 데이터셋 클래스명이 자주 다르다. **모델은 맞혔는데 검색으로는 못 찾는** 상황이 된다.

| 사용자 표현 | 클래스명 |
|---|---|
| 흰쌀밥 | 쌀밥 |
| 돈까스 | 돈가스 |
| 장국 / 된장국 / 국 | 미소된장국 등 |
| 야채무침 | 무생채 |
| 냉모밀 | 메밀국수 |
| 단무지 | 단무지무침 |
| 양념고기 | 불고기 |

이건 모델이 아니라 **앱 검색의 별칭 문제**다. 직접 기록에서 "흰쌀밥"을 쳐도 "쌀밥"이 안 나온다.

## 이 결과가 방향에 주는 함의

1. **사용자 직접 등록(개인 음식 DB)이 가장 큰 몫을 차지한다.** 실사용 음식의 46%는 데이터를 아무리 늘려도 안 나온다. 2026-09-23 구현한 개인 목록이 이 46%를 받는 자리다. 사용자가 처음 제안한 방향이 수치로 뒷받침됐다.
2. **남은 묶음(25GB)의 효과는 6%다.** 김치·깍두기뿐이라 우선순위가 높지 않다. 다만 김치는 한국 식단에서 빈도가 높아 장당 등장 횟수로 보면 체감은 더 클 수 있다.
3. **별칭 매핑은 싸고 효과가 크다.** 데이터·모델을 건드리지 않고 검색 품질만 올린다.
4. 남은 48%에 대해 **실제 검출률**은 아직 모른다 — `eval_heldout_colab.ipynb` 의 실사용 평가 섹션으로 잰다(`eval_real.tar`).

## 한계

- 사진 16장은 통계적으로 적고, **한 사람의 식습관**(일식 외식 비중이 높다)에 치우쳐 있다. 다른 사용자에게 그대로 일반화하면 안 된다.
- 기대 음식은 파일명에 사람이 적은 것이라 판단이 섞여 있다(예: "그 외 반찬").
- 별칭 표(`check_coverage_detail.js` 의 `ALIAS`)는 손으로 만든 것이라 누락이 있을 수 있다.
