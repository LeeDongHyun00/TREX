# 준비·운동 목록·최근 기록 수정 (§47)

2026-09-11. §46의 준비 시작 버튼과 서서 3초/바닥 5초 정책을 이 문서로 대체한다.

## 준비와 진행

- 카메라 준비 화면에 들어오면 자동으로 관찰한다. 유효한 피처·머리·손발 범위가 약 0.4초 안정되면 모든 종목에서 원형 5초 카운트다운을 시작한다. 기존 몸 회전 시범·사용자 기준 방향 문장을 유지한다.
- 카운트 중 짧게 가려지거나 움직이면 시간을 멈추고 남은 초를 보존한다. 다시 0.3초 안정되면 이어 센다. 이탈이 1.2초 이어지면 안내로 돌아가 다시 인식한 뒤 새 5초를 준다. 프레임 수신이 끊기면 마지막 프레임 이후 0.75초부터 정지하고, 끊김이 이어지면 초기화한다.
- 카운트 중 바운딩 범위 변화 0.075 또는 서서 방향 벡터 변화 약 25° 이상은 재확인 대상으로 처리한다. 준비 전 안정 범위는 0.05다. 수치는 UX 초기값이며 체형별 성공률이 검증된 기준이 아니다.
- 서서 정면·오른쪽 앞·왼쪽 앞만 기존 방향 추정기의 8프레임 일관성 R≥0.9일 때 안내와 크게 다른 방향을 재안내한다. 바닥·순수 측면·불명에 임의의 방향 합격을 부여하지 않는다. 촬영 범위 확인은 올바른 운동 자세 인증이 아니다.
- 반복 초기화 시 직접 `5초 후 시작`을 사용할 수 있다. 대기/인식 보류 중에 선택할 수 있으며 이 선택은 촬영 인식을 기다리지 않는다. 이탈 유보가 자세 정상으로 바뀌지는 않는다.
- 하단은 나가기·일시정지/재개다. 앱 비활성화와 카메라 전환은 이전 카운트를 취소한다. 복귀 시 다시 관찰하므로 화면 밖에서 지난 카운트가 끝나 운동이 진행되는 일을 막는다.
- 자세 교정 OFF/미지원/권한 폴백은 카메라 없이 원형 5초 준비를 제공한다. `준비 시간 +5초`(최대 30초), 일시정지/재개, 바로 시작, 나가기를 제공한다. 준비 시간은 운동 목표와 기록 경과 시간에 포함하지 않는다.
- 일반 운동도 하단에 종료와 건너뛰기를 직접 표시하고 같은 건너뛰기 확인창을 사용한다. 반복 운동은 횟수 기록으로, 플랭크 등 시간 운동은 목표 시간으로 완료한다. 운동 시간을 임의로 추정해 반복 운동을 넘기지 않는다.

## 완료 표시와 드래그

완료한 운동은 체크 아이콘·연한 배경·강조색 이름으로 구분하고 상단에 `전체 N종목 중 M종목 완료`를 보여 준다. 위치를 자동으로 바꿔 사용자의 순서를 흐트러뜨리지 않는다.

기존 구현은 같은 행에 드래그 이동과 목록 배치 애니메이션이 함께 적용되고, 행 안의 수정/스위치 입력이 부모의 길게 누르기와 경합했다. 기존 APK에서 수정 버튼을 길게 눌러 아래로 드래그했을 때 순서가 그대로인 실패를 재현했다(`drag-before.log`). 첫 수정에서도 애니메이션 중 화면 좌표를 정렬 판단에 사용해 한 칸 덜 이동하는 실패가 나왔다(`device-tests-first.log`).

수정 방식:

1. 들고 있는 행은 조작 불가한 별도 오버레이로 그리고 목록에는 같은 높이의 자리를 남긴다.
2. 항목을 선택할 때는 실제 화면 좌표를 사용하되 순서 교환은 애니메이션과 무관한 목록 배치 좌표를 사용한다. 순서와 배치가 불일치하는 한 프레임에는 재교환하지 않는다.
3. 첫/마지막 행 여부를 현재 계획의 ID로 다시 계산하고 모서리 상태가 바뀔 때 행의 그리기 상태를 재생성한다. 순서만 맞고 둥근 모서리가 이전 위치에 남는 문제도 수정했다.
4. 길게 누른 뒤 부모가 Initial 입력 단계에서 이동과 손가락 떼기를 소비한다. 놓은 뒤 280ms 동안 하위 버튼 입력을 막고 ID로 편집 대상을 다시 찾는다.
5. 놓을 때 한 번만 저장하고 취소 시 원래 순서로 복귀한다. 하단 고정 조작부 앞에서 자동 스크롤하며 접근성 위/아래 이동과 스와이프 삭제 확인은 유지한다.

## 최근 7일 기록

- 운동 기록의 기준은 오늘부터 6일 전까지의 **달력 7일**이다. 기존 `takeLast(7)`은 운동한 날 7건을 남겨 오래된 기록이 계속 쌓이는 문제가 있었다.
- 앱 생성·전면 복귀·전면 사용 중 30초 간격으로 날짜 경계를 확인한다. 운동 저장 때도 같은 기간을 적용한다. 세션 중에는 날짜가 바뀌어도 루틴의 완료 플래그를 초기화하지 않는다.
- 만료 정리는 저장 JSON의 오래된 날짜 항목만 제거한다. 남은 항목의 알 수 없는 부가 필드도 보존한다. 시계가 뒤로 바뀌었을 때 미래 날짜 기록은 지우지 않는다. 원본 자세 로그·자가 라벨·연구 데이터는 이 정리 대상이 아니다.
- 식단의 `최근 7일 식단 기록`에서 날짜를 누르면 해당 날짜의 섭취 합계·탄수화물/단백질/지방·끼니별 음식과 수량을 보여 준다. 날짜 이동에 짧은 페이드/슬라이드를 사용하고 돌아가는 버튼은 오른쪽 아래에 둔다.
- 음식 기록이 없는 날에는 `기록된 식사가 없어요.`를 표시한다. 과거 식단을 오늘 식단으로 채우거나 현재 영양 목표를 과거 날짜에 소급하지 않는다. 식단 데이터에는 새 삭제 정책을 추가하지 않았다.

## 검증과 남은 범위

JVM 242건, 최종 Note10+ UI 회귀 7건(133.673초) 통과. 드래그 중간/복귀 화면도 직접 확인했다. 최종 빌드·실기기·설치 증거는 `research/aihub_fitness/outputs/preparation_records/verification.json`을 정본으로 한다. 초기 실패 로그와 최종 통과 로그를 구분한다. 일반 앱 교체 전 SharedPreferences를 백업했고, 최종 APK 설치/실행 후 최근 기록·식단·설정 보존과 설치 APK 해시 일치를 확인했다. 마지막 표시 보완 업데이트 전후 `trex_store.xml`·`trex_posture.xml`은 바이트가 같다. 최초 업데이트에서 만료된 기록 6일분만 제거됨을 JSON 비교로 확인했고, 그 이전 원본은 `device_preinstall/`에 보관했다. 마지막 표시 보완 직전 원본은 `device_preinstall_final/`에 따로 보관한다. 자세 모델·규칙·기준 자산 5개는 §46 APK와 바이트가 같다.

단위 테스트는 자동 준비 5초, 잠깐의 가림과 지속 이탈, 마지막 프레임 끊김, 회전/이동, 취소, 관절 부족, 방향 보조, 날짜 경계를 검사한다. 실기기는 수정 버튼 위 길게 누르기·상하 정렬·삭제 확인, 완료 표시, 카메라 유무별 진행, 준비 중 앱 복귀·카메라 전환, 식단 날짜/수량/빈 화면, 영속 기록 정리를 검사한다.

사람이 실제 운동 준비를 하는 상황의 자동 시작 성공률, 체형·가림별 초기화 빈도, 음성 체감 지연은 별도 실사용 검증이 필요하다. 상태 전이 테스트와 UI 회귀 통과를 자세 판정 정확도 향상으로 표현하지 않는다.
