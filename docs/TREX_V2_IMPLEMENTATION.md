# trex_v2 구현 및 설치

2026-09-20 · 브랜치 `codex/trex-v2-engine` · 기반 `origin/feature/pose-evaluation-engine` (`2cd4d94`)

기존 TREX의 운동 계획·식단·기록·세션 화면에 공유 관측 엔진을 연결했다. 별도 설치 패키지는 `com.example.trex_kotlin.v2`, 런처 이름은 `trex_v2`다. 기존 `com.example.trex_kotlin`의 설치·데이터는 건드리지 않는다. 새 패키지는 독립 저장 공간을 사용한다.

## 실행 구조

`CameraX → MediaPipe FULL 원본 33점 → LandmarkFeatures → PoseEvaluationEngine → 기존 세션/기록 UI`

- 루트 Gradle의 `:pose-engine`은 `engine-lab/engine`을 직접 컴파일한다. 독립 실험 앱과 제품의 실제 관측 엔진 소스가 같다. `LabEngine`은 공유 클래스의 호환 별칭이다.
- 제품 실행 경로는 `PostureV2Live.kt`다. 기존 `LiveCoach`/규칙 JSON/구형 기준선 감산은 이 경로에서 실행하지 않는다. 이전 연구·개발 도구는 보존한다.
- `ExerciseCatalog`의 고유 26종으로 추가·대체·저장 계획·세션 진입을 제한한다. 기존 별칭은 정규화한다. 범위 밖 과거 운동 기록은 변환하거나 삭제하지 않는다.
- 추론 목표 간격은 200ms다. 실제 간격은 발열·추론 시간에 따라 늘어난다. 1초 초과 지연, 가림, 카메라·회전·일시정지 경계에서 진행 중 왕복과 비교 기준을 폐기하고 완료 횟수는 보존한다.

## 관측 정책

완료 왕복과 사용자가 입력한 최소 왕복 변화량 충족 횟수를 분리한다. 기본값은 범위 목표 없음이다. 임의의 초기 값을 정자세로 인증하지 않으며, 범위가 없는 세트에 파셜/정상 등급을 만들지 않는다. 범위를 선택했다면 목표 진행은 범위 충족 횟수로 표시하고 전체 관측 횟수를 함께 보여 준다. 직접 수정한 실제 횟수는 별도로 저장하며 자동 원본을 덮지 않는다.

스쿼트·런지·힌지·컬·레이즈에는 넓은 출발 구간과 이탈 방향 조건이 있다. 예를 들어 기본 스쿼트의 90→130→90°는 선 자세 출발 조건을 만족하지 않는다. 이 수치는 검출 경계이며 보편적인 정자세·안전 각도가 아니다. 데드리프트는 사용자가 선 자세 출발/숙인 자세 출발을 설정한다.

푸시업은 손목–어깨 거리 붕괴를 버리고 팔꿈치 움직임을 함께 요구한다. 크런치는 머리 대신 몸통의 화면 기울기를 관측한다. 레이즈는 위팔과 운동면, 사이드 크런치는 무릎·팔꿈치 접근·몸통 변화, 니업은 같은 측 무릎 높이, 힌지는 고관절과 몸통 변화가 필요하다. 시저크로스는 간격만으로 교차를 인증하지 않고 부호 변화와 큰 좌표 점프를 검사한다. 이는 관측 휴리스틱이며 운동 종류를 영상에서 완벽히 식별한다는 뜻이 아니다.

좌우 채널은 독립이다. 동시 방식은 완료 시간뿐 아니라 움직인 시간 구간의 겹침도 요구한다. 런지의 공통 신호는 1회로 세며 수행 측을 추정하지 않는다. 한쪽 설정의 런지 좌우는 사용자 선언이다. 바닥은 직접 촬영 확인과 몸통 투영을 요구하고, 보이는 측이 바뀌면 진행 동작을 취소한다.

플랭크는 반복을 세지 않는다. 경과 시간과 관측 가능한 유지 시간을 구분하고 정렬 평가 시간은 미제공으로 표시한다. 같은 구간·측·피처에서 초반 3회와 최근 3회의 왕복 범위를 비교한다. 기준이 달라지거나 관측이 끊기면 비교를 다시 준비한다.

## 사용 흐름

- 기존 운동별 준비 화면에서 촬영을 맞춘다. `관측 설정`에서 범위·데드리프트 출발·진단 저장을 설정한다.
- 세트는 목표 횟수/시간에 도달해도 계속된다. `세트 완료`를 직접 누르면 기록한다. 휴식은 타이머로 다음 순서로 넘어간다.
- 실시간 화면에는 관측 상태·카메라 횟수·선택 범위 횟수를 표시한다. 횟수 수정·일시정지·완료는 하단에서 조작한다.
- 세트 기록에는 관측 프레임 수, 마지막 관측값, 비교가 가능한 경우의 변화, 측정하지 않는 범위가 남는다.

**전체 자세 점수·정상/완벽 판정·개인화된 교정 명령 음성은 제공하지 않는다.** 바벨 검출, 척추 곡률, 접지 압력, 통증/안전은 관측하지 않는다. 기존 `ship` 이름만으로 이 자격을 승계하지 않는다. COACH/TRACK 모두 같은 엔진과 수치를 사용하며 저장 모드·안내 정책만 구분한다.

## 데이터

기본은 세트 요약만 저장한다. 진단 좌표는 세트마다 명시적으로 켰을 때만 원본 xy/world/visibility, 시각, 피처, 구간, 사건과 엔진·모델 정보를 저장한다. 앱의 `no_backup/pose_v2`에 두어 Android 클라우드 백업/기기 이전 대상에서 제외한다. 원본 진단 보관 한도는 7일/20MB다. 영상 저장·업로드·온라인 임계값 학습은 없다.

사용자 기록, 모델의 관측 결과, 정자세 정답은 별개다. 향후 학습에서는 이 데이터를 자동 정답으로 복사하지 않는다. 현재 AIHub 147개 자세 후보의 통계 재보정·전체 항목 구현·새 사람 검증·장기 발열 검증은 완료하지 않았다. 이 설치본은 [설계](POSTURE_SERVICE_DESIGN.md)의 **신규 사람 검증 없이 제공하는 관측 단계**를 구현한다.

## 검증

- 공유 엔진 JVM 95건, 앱 JVM 390건: 실패·오류·생략 0.
- `:app:assembleDebug`, `:app:assembleDebugAndroidTest` 성공.
- 연결 Note10+ (`SM-N976N`, Android 12): 수동 세트 종료, 카메라 일시정지/전환/재개/저장, 실제 MediaPipe GPU 추론 및 공유 엔진 재생의 세 가지 instrumentation 검사 통과.
- 기존 AIHub JPEG 3개를 5회씩 재사용한 15개 추론에서 피처 생성 15건. 단일 이미지 반복 재생이므로 사람의 실제 반복 정확도·교정 효과·카메라 처리 지연을 뜻하지 않는다.
- 최종 APK 식별 및 실행 증거: `research/aihub_fitness/outputs/v2_implementation_20260920/verification.json` 및 같은 폴더의 로그·화면 캡처.

합성 반례는 `V2AcceptanceTest`에 있다. 설계 명세의 모든 항목을 외부 검증 완료로 승격하지 않는다. 다른 체형·운동 속도·촬영 환경에서의 정확도와 실제 만족도는 여전히 측정해야 한다.
