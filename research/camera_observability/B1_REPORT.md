## 요약
- **'팔꿈치 위치 고정' 위반 = 팔꿈치를 앞으로 내미는 것**이다(설명문 "팔꿈치 내밀고", GT 수축 시 상완 앞 기울기 정상 9.5° vs 위반 36°). 현 규칙 `elbow_torso_R__mean > 0.193`(월드, D)은 이 모집단(1,354클립)에서 AUC 0.906, **오탐 16.1 %·검출 82.2 %** 다. 같은 거리의 **부호 있는 앞 성분**(`elbow_torso_fwd`)이 GT3D 0.945(세션 중심화 0.990), **MediaPipe 2D 사선 뷰 0.958~0.961(0.983~0.984)** 로 가장 좋고, 오탐 5 % 고정 검출률 0.79~0.84 다. 정면(C)에서는 앞 성분이 깊이 축이라 어떤 후보도 0.85 를 못 넘는다.
- **세트 평균 ≥ 수축 프레임 값 > 반복 안 변화량**(GT3D 0.945 / 0.930 / 0.775). 성긴 프레임에서 "이완 프레임"을 빼면 잡음만 는다.
- **사용자 제안 ①(팔꿈치 좌표 이동)은 절반만 맞다.** 이동 크기 자체는 AUC 0.76~0.84 — 정상 컬도 팔꿈치가 몸통의 10 %(p95 26 %)를 움직인다. 판별하는 것은 이동의 **앞 방향 성분**이다. 월드 좌표의 이동량은 진실의 3배로 부풀어(정상 중앙값 0.28~0.34 vs GT 0.10) 띠를 GT 로 정하면 오탐 65~83 % 다.
- **제안 ②(팔꿈치 너비 벌어짐)는 AIHub 라벨이 반박한다** — 팔꿈치를 내밀면 간격은 오히려 **좁아진다**(위반 1.13 vs 정상 1.27 어깨폭, 벌어짐 방향 AUC 0.16~0.45). 정상 분포·잡음만 있고(세트 최대 ≥ 1.8 띠: 정상의 3~4 %), 라벨 근거는 없다 → 폰 라벨 세트 전까지 beta.
- **몸통 반동은 AIHub 에 없다**(정상 수축–이완 기울기 변화 p5/p95 −4.0/+2.5°, 세트 범위 p95 13°; 위반 연기자도 몸통을 안 썼다). 잴 수는 있다 — 사선 뷰 2D 기울기 비는 ρ 0.76~0.81·보정 잔차 2.5~2.8°(GT° ≈ 75~88 × 비), **월드 기울기는 못 쓴다**(편향 −4~−12°, 정면 세트 범위 p95 31°). 띠 후보: 세트 범위 ≥ 14°(비 0.17) 정상 초과 3.5~4 %, 수축–이완 변화 ≥ 8°(비 0.10) 0~1 %.
- **가동 범위: MediaPipe 월드 팔꿈치각은 수축에서 +33~+39° 편향, ρ 0.25~0.47** 이다. 앱 ROM 기준 81.3° 는 **GT 3D 로 정한 값**(REP_VALIDITY.md)인데 월드 신호에 적용하면 정상 AIHub 클립의 세트 최소각이 같은 프레임에서 B 50 %·C 95 %·D 85 % 가 81.3° 를 넘는다(GT 2 %). "반쯤 들어도 1회" 문제 이전에 **기준 자체가 척도가 다르다.** 비율 개인화(제안 ③)는 원리상 맞지만(사람 간 SD 9.5° ≈ 사람 안 7.2°) 지금 신호의 사람 안 잡음(2D 사선 7~8°, 월드 8~10°)이 사람 안 진실 산포(8.3°)와 같아 10° 차이를 못 가른다.
- **횟수 차단(제안 공통)은 반대**: 최선 후보도 오탐 5 % 에 검출 0.8 이고 현 규칙 운영점은 정상 세트의 16 % 를 찍는다. CLAUDE.md 원칙 7 그대로 — 자세 위반은 세트 판정·리포트로.

## 1. 자료·방법
- 덤벨 컬 1,439클립·44명·6일·5뷰·16프레임, GT 3D(cm)·GT 2D(px). **양팔 동시 컬**(좌/우 팔꿈치각 시간 상관 중앙값 0.99, < 0.5 는 25클립). 5조건(팔꿈치 고정·손목 중립·척추 중립·으쓱 없음·이완 시 긴장 유지) 각 50 %, 설명문↔라벨 1:1(1439/1439).
- 실제 촬영 방향(DLT, 재투영 3.8 px): B −33°(사용자 오른쪽 앞), C −0.5°, **D +39°(사용자 왼쪽 앞 = 왼팔꿈치가 카메라 쪽)**, 높이 82~103 cm, 거리 4.0~5.8 m, 피치 ≈ 0. 코드와 실제가 일치하고(C 코드가 뒤를 보는 53클립은 제외) 뷰별 n = 1,354~1,356.
- MediaPipe full **IMAGE 모드**, 뷰 B·C·D × 16프레임 = 69,072장, 검출 99.1~100 %. 팔꿈치 가시성 < 0.5 는 D 의 먼(오른) 팔꿈치 6.1 %, 나머지 ≤ 1.3 %; px 오차 어깨·팔꿈치·손목 몸통의 0.02~0.03, 좌우 뒤바뀜 ≤ 0.3 %.
- 반복 단위 = 클립의 GT 팔꿈치각 평균 최소 프레임(수축 c)·최대(이완 e), 범위 ≥ 60° → **1,370클립·45세션**. 통계 `_c`·`_e`·`_d`(c−e)·`_mean/_max/_range`(유효 프레임 전체 ≈ 앱 세트 통계). 표현: GT3D(진실)·GT2D(같은 뷰 주석 = 상한)·MP2D(px)·MPW(월드 cm, y 위·골반 원점, 앱과 같은 변환) — 모두 **GT 와 같은 프레임**. AUC 는 원값/세션(수행자×날짜) 중심화, 오류 = 1.
- 앱과 같은 정의(`elbow_torso`·`upperarm_vert`·`elbow_h`·`torso_incl`·`ear_shoulder_gap`)는 `features.py` 와 수치가 같음을 확인(최대 차 0). 새 후보: `elbow_torso_fwd`(같은 수직거리의 z_b 앞 성분, 부호 있음), `ua_fwd`(상완 시상면 앞 기울기 °), `shoulder_ang`(팔꿈치–어깨–골반 각), `elbow_disp_sh`(수축–이완 팔꿈치 이동 거리 ÷ 몸통, 어깨 기준), `elbow_gap`(팔꿈치 간격 ÷ 어깨 간격), `torso_pitch`(앞 숙임 +), `hip_ankle_fwd`. 2D 의 앞/뒤 부호는 **뷰 방위각 부호가 필요**하다(정면 C 는 미정의).

- 월드 편향의 실체: 월드 전완 길이는 유지되지만(24.8 vs 24.5 cm) **수축 시 상완이 짧아진다**(B 19.7 vs 이완 24.3 cm; GT 25.5/27.0) — 깊이 압축이 아니라 들어 올린 팔의 3D 복원 오류다. 폰 거리(더 가까움)·VIDEO 모드에서 크기는 달라질 수 있다.

## 5. 결론 — 사용자 제안에 대한 수치 근거
1. **팔꿈치 좌표 이동 → 반동**: 부분 지지. 이동 크기는 .76~.84 지만 **앞 성분**은 .95~.96(2D 사선)이다. 구현 후보: 사선 뷰(B/D) **2D** `elbow_torso_fwd` 양팔 평균의 세트 평균(뷰 등급으로 부호 결정), 정면은 유보. 월드로 하려면 먼 팔꿈치 `shoulder_ang_R__mean`(D .918/.968)이 현 규칙보다 낫고 가까운 팔꿈치 편향(+0.068)을 피한다. 반복 안 변화량은 쓰지 말 것.
2. **팔꿈치 너비 벌어짐**: 라벨 반박(내밀면 좁아짐). 정상 띠(세트 최대 ≥ 1.8 어깨폭, 오탐 3~4 %)만 가능 — 사용자 실기기 라벨로 검출률을 재기 전엔 beta·화면 참고.
3. **횟수 차단**: 반대. 오탐 5 % 운영점에서도 검출 0.8, 현 규칙은 정상 세트 16 % 오탐 → 세트 판정·리포트 채널(원칙 7).
4. **비율 기반 ROM 개인화**: 원리 지지(사람 간 ≈ 사람 안). 단 **먼저 고칠 것은 척도** — 81.3° 는 GT 척도이고 월드 신호에서 정상 반복의 50~95 % 가 미달로 찍힌다(같은 프레임 기준). 재보정(MP 척도 또는 세트 시작 창의 개인 기준)과 사선 2D 각으로의 교체를 검토하고, 그 전엔 ROM 판정을 횟수·점수에 연결하지 말 것.

## 6. 가정·한계·못 한 것
- 스튜디오 카메라(골반 높이·4~6 m·수평)·IMAGE 모드·1920×1080 이고 폰(가까움·VIDEO 추적·480×640)이 아니다. 2D 비율·각 임계는 폰 좌표 로그로 다시 정해야 한다. 앞/뒤 부호는 뷰 등급(`PostureView`)에 의존한다.
- 16프레임 성긴 표본이라 수축·이완 프레임이 진짜 극값이 아닐 수 있다(GT·MP 에 공통). 연기자의 과장 오류라 자연 오류 검출률은 이보다 낮다.
- 몸통 반동·팔꿈치 벌어짐 라벨이 없어 검출률은 못 쟀고 정상 분포·잡음·예상 오탐만 냈다. 순수 측면 뷰·A/E 뒤 사선은 이번 범위 밖. `MPWg`(DLT 중력) 는 카메라가 수평이라 생략(A2 에서 차 ≤ 0.05).
- 정상 5조건 전부 충족은 42클립뿐이라 조건별 충족 집합으로 대신했다(교차 설계라 다른 조건의 오류가 잡음으로 섞인다).
