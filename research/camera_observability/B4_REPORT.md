# B4 — 덤벨 컬 정면(C) 뷰 2D 단서: 옆 벌림·반동·가동 범위의 모집단 정상 분포와 게이트 임계 (2026-09-26)

코드 `B4_lib.py`(2D 피처·반복 통계·띠) · `B4_aihub.py` · `B4_mmfit.py` · `B4_phone.py` · `B4_tables.py` → `outputs/B4/`(클립·반복·사이클별 CSV, `tables.md` 전체 표). 앱 코드 수정 없음, 커밋 안 함. MM-Fit 파생물은 측정 전용.

## 0. 요약
1. **옆 벌림은 정면 2D 로 깨끗하게 갈린다.** 정상 수축 `lat_c`(팔꿈치 바깥 오프셋 ÷ 어깨폭, 두 팔 중 큰 값) p50/p95/p99 = MM-Fit 0.16/0.29/0.36(598회·11명), AIHub 정상 0.18/0.29/0.34(170클립); 시작 대비 변화 p95 0.12~0.16. 후보 띠 **Δ ≥ 0.15 & 절대 ≥ 0.28** 은 MM-Fit 0.7 %·AIHub 정상 4.7 %, **Δ ≥ 0.20 & ≥ 0.35** 는 0.0 %·0.6 %. 폰 정답 세트: 벌림 4/4 검출(lat_c 0.44~0.46, Δ 0.33~0.35)·나머지 9회 오탐 0, 정답 없는 14회 세트에서는 앱 월드 팔꿈치 간격 위반 5회(5·11·12·13·14)와 **같은 회**를 잡았다.
2. **반동(어깨로 들어 올림)은 팔꿈치각 최소보다 335~670 ms(1~2프레임) 뒤에 정점**이 온다 → 수축 프레임 값이 아니라 **창 최대**로 봐야 한다(수축 ±1 중앙값의 Δ 는 0.15~0.17, 창 최대 Δ 는 0.26~0.33). 단서 두 개: **(a) 손목이 어깨 위 `wrist_h_max ≥ 0.15`** — MM-Fit 1.5 %(전부 w20, 나머지 10명 0), AIHub 정상 1.8 %, 폰 3/3 검출(0.20~0.24)·오탐 0; **(b) `rise_max − 시작 ≥ 0.20 & rise_max ≥ −0.30`** — MM-Fit 3.2 %(w20 43 %·w17 29 %, 둘을 빼면 1.1 %), AIHub 정상 2.4 %, 폰 3/3·오탐 0. 벌림 회는 팔꿈치가 0.12~0.17 올라오므로 Δ 0.15 단독 띠면 벌림 4회 중 2회가 반동으로 겹친다.
3. **'팔꿈치 내밀기'(AIHub 위반)는 정면 반동 단서로 샌다.** 내밀기 679클립의 43 %(손목 띠)·48 %(rise 띠)가 반동 띠를 넘고(AUC `wrist_h_max` 0.85, `rise_max` 0.80), '으쓱' 라벨도 `rise_c` AUC 0.93 으로 잡힌다. 정면에서 rise·손목 높이는 **"상완이 수직에서 떠남(앞·위·으쓱)"** 을 통틀어 보는 단서다 — 화면 문구는 "팔꿈치가 몸에서 떠요" 로, '반동' 단정은 금지. 벌림 띠는 내밀기에 거의 안 샌다(2.4~7.8 %; 내밀면 간격이 오히려 좁아짐, AUC 0.73 역방향).
4. **가동 범위.** 월드 진폭 비율(같은 팔 첫 2회) 0.7/0.8/0.85/0.9 의 정답 유지율 0.945/0.926/0.910/0.863; 폰 '짧게' 2회는 비율 0.87~1.01 이라 0.85 까지 0 검출, 0.9 면 2/2 지만 MM-Fit 14 % 를 버린다. **2D 손목 창 진폭 비율**(`wrist_h` 창 최대 − 최소, 같은 팔 첫 2회 대비) 은 0.7/0.8/0.85/0.9 → **0.988/0.980/0.965/0.943**, 폰 짧은 회 비율 0.71~0.81 → **0.8 에서 2/2 검출·1~11회 오탐 0**(0.9 부터 벌림 회 3개가 오탐). AIHub GT 3D 대비 정면 2D 손목 높이는 수축각과 |ρ| 0.53, 손목 상승은 진폭과 0.62 — 같은 뷰 월드 수축각은 0.28(B1). 정면에서는 2D 손목이 월드각보다 진실에 가깝다.
5. **"신체 비율로 위·아래 끝" 은 아래 끝만 된다.** 창 안 손목 최저 ≤ −0.75 몸통: MM-Fit 99.5 % 유지(사람 최소 96 %), 폰 정답 13회 전부 통과(최저 −0.81~−1.00), 정답 없는 세트의 진짜 부분 반복 4회(7·12·13·14, 손목 최저 −0.71~−0.28, 앱은 2회만 무효)를 정확히 잡는다(−0.80 이면 −0.79·−0.80 인 6·11회가 더 걸림). 위 끝은 불가 — 폰 짧은 회 손목 최고 −0.21~−0.26 vs 정상 −0.07~−0.10 인데 MM-Fit 는 "≥ −0.30" 만 걸어도 82 %(w19 18 %·w12 40 %), 짧은 회를 자르는 −0.20 이면 50 % 만 남는다. 위 끝은 본인 첫 2회 대비 비율로만.
6. **제안 검사 셋(정면 C 전용, 전부 beta, 횟수 차단 아님·'정확 M' 채널)** — §6 표. 모집단 오탐 ≤ 2 % 조건은 벌림(0.20/0.35)·손목 위(0.15)·아래 끝(−0.75)·2D 진폭 비율 0.8 이 충족하고, rise 띠는 MM-Fit 의 상완 스윙 습관 2명(w17·w20) 때문에 3.2 % 다.

- 구현 메모: 2D 피처 3개(`elbow_lat2d_{L,R}`·`elbow_rise2d_{L,R}`·`wrist_h2d_{L,R}`) 를 좌표에서 계산(현 `PostureCore` 에 2D 팔 피처 없음), 팔별 사이클 창 = `ArmCycle [startMs, tMs]`, 시작 = 첫 상단 창(§62a). **뷰 게이트 C 전용** — 사선에서는 어깨 x 간격이 줄고 앞 성분이 x 로 섞여 `lat` 의 부호·크기가 깨진다(B/D 는 기존 '앞 이탈'). 좌우는 골반 x 순서로 정하므로 전면 카메라 미러 여부와 무관.

## 7. 가정·한계·못 한 것
- 정면 2D 비율은 카메라 거리·높이에 따라 값이 다르다(AIHub 4.5 m 골반 높이 vs 폰 근접 가슴 높이). 폰에서 정상 수축의 `rise` 가 시작보다 **낮게**(−0.54 vs −0.48) 보이는 것은 원근(팔꿈치가 카메라로 다가옴) — AIHub 는 +0.01. 절대 임계(0.35·0.15·−0.30·−0.75) 는 두 모집단이 같은 방향으로 갈렸지만 폰 배치가 크게 다르면(위에서 내려찍기 등) 재확인이 필요하다.
- MM-Fit '정상' 은 라벨 없는 전부(가벼운 덤벨·교대·11명, 2명이 상완 스윙 습관)라 초과율은 오탐률의 상한이자 "습관을 오류로 볼지" 의 문제(원칙 3, COACH/TRACK). AIHub 정상 170 은 수행자당 4클립뿐이라 사람별 p95 는 못 냈고, AIHub 의 '시작' 은 서 있음이 아니라 클립 안 이완이다(16프레임 성긴 표본).
- MM-Fit 3D 는 영상 기반 추정이라 ROM 대리의 진실로 약하다. 폰 짧은 회의 창 하나(38~42 s)는 3 s 부분 정지 + 깊은 굽힘이 한 사이클로 묶였다 — 카운터 창 정의에 따라 값이 달라질 수 있다.
- 폰 truth13 의 반동 첫 시도(29 s, 앱 기각 `upperarm_vert_R` 66°)는 회 번호에 없어 검출률에서 뺐다(손목 최고 +0.20·+0.35 로 띠는 넘음). 반동·벌림·짧게의 자연 발생 표본, 다른 사람, 무거운 중량, 사선 뷰의 같은 단서는 이번 범위 밖.
