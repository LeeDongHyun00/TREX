# TREX 스쿼트의 세부 편차와 교정 멘트 명세

2026-09-17 · 기존 26종 설계의 스쿼트 세부 확장 · 연구 단계

## 1. 무엇을 바꾸어야 하는가

기존 스쿼트 6개 대표 규칙만으로는 한쪽 발 전체 들기, 발 가장자리 들기, 바깥 무릎 경로, 발 옆 이동 등을 구별하기 어렵다. 이번에는 **37개 원자 이벤트와 좌우별 문구**로 확장했다. 이것은 가능한 모든 인간 움직임의 완전한 목록도, 37개가 모두 자동 검출 가능하다는 주장도 아니다. 미관측과 측정 실패 이벤트도 포함한다.

정답 사진 한 장과 다른 모든 점을 오류로 삼지 않는다. 정상 스쿼트에는 발 간격·발끝 방향·몸통 기울기·깊이 등의 차이가 있다. 준비 동작·선택한 변형·개인에게 합의한 목표를 먼저 알아야 한다. 발 간격과 발끝 방향에 따라 운동학이 달라지는 점은 [Lorenzetti 등의 원연구](https://pubmed.ncbi.nlm.nih.gov/30026952/)를 참고했다. 해당 논문의 내반/외반 서술에는 [정정문](https://pubmed.ncbi.nlm.nih.gov/32021692/)이 있어 본 설계는 특정 방향의 보편적 정상성·빈도 주장에 사용하지 않는다. 백스쿼트 기본 동작은 [ACE 지침](https://www.acefitness.org/resources/everyone/exercise-library/11/back-squat/)을 참고했다. 아래 이벤트·멘트·우선순위는 자체 공학 설계이며 이 출처에서 자동 교정 효과를 검증한 것은 아니다.

**고의 여부를 알아낼 필요는 없다.** 일부러 한 동작도 동일한 관찰 규칙으로 처리한다. 실수·균형 회복·장난·테스트인지 카메라만으로 단정하지 않는다. 사용자가 테스트 모드를 선언한 경우에만 별도 메타데이터로 기록한다.

## 2. 모든 항목에 필요한 계약

`운동 변형 × 수행 구간 × 신체 부위 × 해부학적 좌우 × 편차 종류·방향 × 관찰 근거 × 정상 예외 × 발화 시점 × 교정 행동 × 재평가`로 정의한다. 가능한 조합을 무작정 곱하지 않고 해당 운동에서 성립하는 조합만 등록한다.

| 판단 | 예 | 처리 |
|---|---|---|
| 허용된 차이 | 준비 중 발 간격 조정, 등록한 와이드 스쿼트 | 잘못이라고 말하지 않음 |
| 선택 과제에서 벗어남 | 양발 고정형 반복 중 발 이동, 합의한 깊이 미도달 | 원인·위험을 단정하지 않고 해당 행동을 안내 |
| 측정 불확실 | 발 가림, 좌우 ID 교환, 카메라 이동 | 측정 안내만 제공 |
| 관찰 불가 | 복압·발바닥 압력·근육 긴장 | 자동 정오·교정 성공 제외 |
| 목록 밖 패턴 | 스쿼트 도중 등록되지 않은 동작 | 평가 보류·운동 확인. 근거 없는 교정문 생성 금지 |

각 세부 이벤트의 멘트는 미리 작성하되 **관측되는 모든 움직임을 즉시 읽지는 않는다.** 작은 변화가 측정 오차보다 작은 경우, 정상 변형인 경우, 구간이 불분명한 경우에는 자세 교정 음성을 내지 않는다. 상세 피드백 설정은 설명의 양을 바꾸며 정오 기준을 임의로 바꾸지 않는다.

## 3. 사용자 예시 세 가지의 처리

### 한쪽 발만 올림

`발 전체 이격`, `뒤꿈치 이격`, `앞꿈치 이격`, `가장자리 이격`을 다른 이벤트로 기록한다. 발목점의 상승만 보고 발이 떨어졌다고 말하지 않는다. 신발 윤곽과 실제 지지면이 필요하다. 가림으로 알 수 없으면 미관측이다.

일반 양발 스쿼트의 반복 구간에서 왼발 전체 이격이 확인되면 “왼쪽 발 전체가 지지면에서 떨어졌어요”라고 관찰을 말한다. 명확한 이격과 큰 흔들림이 동반되면 일반적인 여러 반복 확인을 기다리지 않고 별도 안정성 분기로 연결한다. 불확실한 단일 좌표 점프로 갑작스러운 중단 지시를 내리지 않는다.

### 무릎이 바깥으로 움직임

무릎 간격이 커졌다는 사실만으로 오류가 아니다. 발 방향·발 위치·같은 깊이·현재 몸 방향을 기준으로 **검토된 경로를 벗어났는지** 본다. 관찰 가능한 경우에도 영상 투영을 실제 관절 내반이나 손상으로 부르지 않는다.

정상적인 발 방향 추종이면 조용히 통과한다. 검증된 허용 경로보다 과도한 바깥 이탈이 지속되면 “무릎을 더 벌리려 하지 말고 발이 향한 방향을 따라 움직여 보세요”를 후보로 쓴다. “무릎을 안으로 모으세요”는 반대 방향 과교정을 일으킬 수 있어 기본 문구로 쓰지 않는다.

### 발을 옆으로 옮김

발 중심의 이동과 발끝 회전을 분리한다. 준비/랙 출입이면 허용하고, 양발 고정 반복 구간이면 과제 이탈로 기록한다. 미끄러짐인지 들어서 디딤인지 과정이 안 보이면 “발 위치가 바뀌었어요”까지만 말한다.

발 기준이 바뀐 구간에는 그 기준에 의존하는 무릎 경로 규칙을 잠시 보류한다. 같은 사건을 “발 이동·무릎 오류·골반 오류”로 연속 발화하지 않는다. 안전하게 하중을 해제하고 재설정한 뒤 새 관찰 구간을 시작한다. 옮긴 발 위치를 자동으로 올바른 자세 기준으로 받아들이지 않는다.

## 4. 판정과 발화 흐름

```text
운동 선택 → 랙 출입/준비 → 발·뷰 안정 확인 → 반복 활성
  → 규칙별 관찰 가능성 확인
  → 정상 예외 검사 → 방향·크기·지속성 확인
  → 사건 기록 → 우선순위와 발화 시점 결정
  → 관찰 사실 1개 + 행동 1개
  → 같은 조건의 다음 수행에서 개선/유지/악화/미관측
```

반복 사이 기립은 무조건 준비 상태가 아니다. 직전 반복·다음 하강·사용자 재설정 여부와 발 안정 상태를 함께 본다. 상태가 불명확하면 교정도 보류한다.

`support`는 관찰된 지지 불안정에 대한 별도 대응, `setup`은 안전한 하중 해제 후 재설정, `form`은 안정된 시점의 다음 수행 안내, `detail`은 과제 목표·템포 등의 상세 안내, `measurement`는 측정 복구, `unobservable`은 요청 시 범위 설명이다. 높은 우선순위 하나를 먼저 말하고 관련된 중복 문구는 억제한다.

현재 자세에서 갑자기 발을 옮기게 하거나 그 자리에서 무조건 멈춰 버티라고 하지 않는다. 모든 기구·발 배치 변경은 안전하게 하중을 해제한 뒤 수행한다. 일반 양발 백스쿼트 기준이며, 맨몸·한발·점프·와이드·다른 바 위치는 별도 프로필이다.

## 6. 모든 멘트가 실제로 동작하도록 만드는 검증

1. 각 이벤트에 정상 영상, 허용 변형, 단일 편차, 복합 편차, 카메라 오차, 회복 구간을 연결한다. 임의 좌표 변형만으로 사람의 실제 오류를 재현했다고 보지 않는다.
2. 무부하·통제된 시범으로 의도적인 동작을 수집할 수 있지만, 무거운 바벨을 든 채 위험한 편차를 재현하도록 요청하지 않는다. 자연 발생 편차도 별도로 평가한다.
3. 운동 지도자가 구간·편차·좌우·관찰 가능성·문구 적절성을 검토한다. 특히 바깥 무릎 경로의 정상 예외를 충분히 포함한다.
4. 사람·세션을 나누어 오류별 오탐·미탐·좌우 혼동·유보율과 잘못된 방향의 안내 비율을 측정한다. 카메라 해상도·거리별 최소 검출 변화량을 검증한다.
5. 한쪽 발 들림 → 양발 복귀, 옆 이동 → 재설정, 안쪽 무릎 안내 → 과도한 바깥 이동 등 **시간 순서와 과교정**을 시험한다.
6. 복합 상황에서 지지 문제보다 무릎 안내가 먼저 나오는지, 발 이동 후 무릎 기준이 잘못 유지되는지, 가림이 교정 완료로 바뀌는지를 회귀 검사한다.
7. 지원 범위를 `목록/문구 작성 완료`, `새 영상 검출 검증`, `교정 효과 검증`, `실제 발화 허용`으로 나누어 관리한다. 문구가 있다는 사실을 검출 가능 또는 교정 효과의 증거로 쓰지 않는다.

현재 JSON은 상세 명세와 좌우별 문구 목록이며 검증된 실행 규칙이 아니다. 모든 자동 코칭은 false, 임계값은 null로 두었다. 수치와 발화 허용 상태는 실제 검증 후 채워야 한다.

## 7. 26개 운동에 적용하는 방법

공통 이벤트 사전(접촉·위치·회전·범위·동시성·속도·측정 실패)에 운동별 허용 상태와 예외를 연결한다. 예를 들어 한발 지지는 양발 스쿼트와 스탠딩 니업에서 의미가 다르다. 동일 발 들림 검출기를 공유해도 정오와 문구는 운동 프로필별로 결정한다.

새 사례가 발견되면 기존 원자 이벤트의 조합인지 먼저 검토한다. 조합이면 발화 우선순위·억제 규칙을 추가하고, 새 관찰 유형이면 ID·신호·예외·문구·영상·검증 결과를 함께 추가한다. 지원 밖 움직임에는 준비된 판정 보류 문구를 사용한다. 이를 통해 목록을 확장할 수 있지만, 유한한 목록으로 모든 가능한 동작을 검출한다고 약속하지 않는다.

## 8. 실행 계약 보강: 37개 사건을 조합하는 방법

2026-09-17 독립 검토 후 JSON을 `squat-fine-events-research-2`로 보강했다. 기존 37개 이벤트와 좌우별 52개 문구는 그대로 보존했다. 새 필드는 실행 시 지켜야 할 조건을 구조화한 것으로, 검출기 구현·정확도·교정 효과가 검증됐다는 뜻은 아니다. 자동 코칭은 계속 전부 false이며 임계값·최소 해상도·최소 변화량·지속시간은 null이다.

각 사건에는 다음 계약이 붙는다.

| 필드 | 역할 |
|---|---|
| `gate_profile` | 자세 평가, 측정 실패 안내, 운동 불일치, 기능 범위 설명을 분리한다. 발이 가려졌다는 안내에 ‘발이 보여야 함’을 요구하지 않는다. 카메라 이동 안내에 ‘카메라 안정’을 요구하지 않는다. |
| `observation_contract` | 증거 종류, 허용 뷰, 위상, 세부 유형, 검증할 해상도·오차·지속 조건. Pose, 발 RGB, 지지면, 바벨 추적을 구분한다. |
| `excludes` | 준비·랙 출입·허용 변형·측정 분해능 미달 등 정상 예외 및 판정 제외를 구조화한다. |
| `suppresses` | 같은 사건에서 음성 중복을 막는다. 기록은 남기되 한 시점에 행동 하나만 말한다. |
| `invalidates` | 발 기준이나 카메라 기준이 바뀌어 더는 유효하지 않은 후속 규칙을 보류한다. 보류를 정상·개선으로 처리하지 않는다. |
| `reference_contract` | 승인한 운동 프로필·버전·참조 출처·뷰·위상/깊이를 기록한다. 사용자의 평균 동작을 자동으로 바른 자세의 기준으로 삼지 않는다. |
| `delivery_contract` | 발화 직전 현재성·좌우·위상·기준 버전을 다시 확인한다. 오래된 음성은 취소하거나 검토한 과거형 요약으로 바꾼다. |
| `recheck_contract` | 같은 조건에서 개선, 유지, 악화/과교정, 미관측, 새 조건의 결과를 구분한다. 신호 소멸만으로 완료 판정하지 않는다. |

`global_gates`는 `form_evaluation`에만 적용한다. SM01~03의 측정 진단은 별도 게이트, SM04의 운동 불일치는 충분한 유효 동작 증거를 요구하는 게이트, SU01은 실제 센서 구성에 맞는 기능 설명 게이트를 쓴다. 측정 진단도 근거와 검증이 필요하며, 원인을 모르면 카메라 이동·조명 부족 등의 구체적 원인을 추측해 말하지 않는다.

현재 52개 문구를 무조건 TTS에 연결하면 안 된다. 예를 들어 SP01·SP02의 기존 문구는 상승 구간 전용이고, SR04는 정한 템포보다 빨라진 경우 전용이다. SM01의 기존 문구는 발이 보이지 않는 경우 전용이다. 다른 구간·방향·가림 부위에는 별도 검토 문구가 생기기 전까지 해당 문구를 사용하지 않는다. SU01의 `action_template`는 구현자용 설명이므로 그대로 읽는 음성이 아니다.

### 세부 기능의 활성화 단위

자동 발화는 이벤트 이름만으로 켜지 않는다. `이벤트 × 검토한 운동 프로필 버전 × 촬영 뷰 × 촬영 조건 × 검출기 버전 × 문구 정책 버전`에 검증 결과가 연결되어야 한다. 발 안쪽 가장자리처럼 현재 각도에서 보이지 않는 항목은 RGB가 존재하더라도 미지원 또는 미관측이다. [MediaPipe 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)는 33개 관절점 추정과 발목·뒤꿈치·발 앞부분 점을 제공하며, 신발 밑면 접촉이나 발바닥 압력을 직접 제공하지 않는다. 접촉 이벤트에 별도 검증이 필요하다는 것은 이 출력 범위에서 도출한 공학적 해석이다.

횟수, 자세 편차, 항목별 관찰 가능 범위도 따로 저장한다. 발 품질을 못 봤다고 독립적으로 보이는 모든 반복을 자동 취소하지 않지만, 발 지지를 통과로 기록할 수도 없다. 반복의 필수 위상 자체를 못 봤다면 별도의 검증된 복구 정책 없이 카운트 전이를 추측해 연결하지 않는다.

## 9. 고의적 동작을 포함한 최소 회귀 시나리오

고의성 추정은 없다. 테스트 모드 true/false만 바꾼 동일 영상은 같은 관찰·정오 판단을 내고 테스트 라벨만 달라야 한다. 무부하·작은 범위의 통제된 시범으로 수집하며 무거운 바벨에서 발 들기·바 미끄러짐·큰 흔들림을 재현하도록 요청하지 않는다. 좌표 주입은 상태기계 시험이고 실제 영상 검출 검증을 대신하지 않는다.
